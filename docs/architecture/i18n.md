# Мультимовність (i18n)

Мови: `uk` (за замовчуванням) і `en`; `next-intl` 4, без префікса мови в URL (крім лендингу: `/` — `en`, `/uk` — `uk`). Spec ядра: `docs/archive/superpowers/specs/2026-10-28-i18n-core-design.md`, план: `docs/archive/superpowers/plans/2026-10-28-i18n-core.md`. Частина 1 (помилки API, спільні UI): `docs/archive/superpowers/specs/2026-10-28-i18n-part1-design.md`.

## Файли

- `messages/{uk,en}/<namespace>.json` — тексти; ключі англійські, dot-нотація, ICU-плюралі. Namespace-и (`NAMESPACES` у `lib/i18n/config.ts`; серверні — `SERVER_NAMESPACES`): `common`, `validation`, `errors` (**лише серверний**), `auth`, `landing`, `onboarding`, `whatsNew`, `help`, а з частини 3 — `races`, `skills`, `classes`, `feats`, `backgrounds`, `artifacts`, `music`, `choices` (вантажить `app/campaigns/layout.tsx`). `whatsNew` вбудований у статичний бандл root-layout разом із `common`/`validation` (його читає `WhatsNewButton` у `Header`); Тексти редакторів (`editors`, у т.ч. форми спел-only ефектів `editors.spellEffects.*`) і `spellEditor` вантажить кампанійний скоуп (`CAMPAIGN_NAMESPACES`); `rules.customConditions.*` — видалення власних станів. `onboarding` і `help` вантажать `app/campaigns/layout.tsx` та `app/help/layout.tsx`. Форма help-блоків — у [onboarding.md](onboarding.md).
- `lib/i18n/config.ts` — `LOCALES`, `DEFAULT_LOCALE`, `LOCALE_COOKIE = "NEXT_LOCALE"`, `NAMESPACES`.
- `source.ts` / `local-source.ts` — `MessageSource` (зараз динамічний `import()` JSON; придатний для заміни на віддалене джерело), `messages.ts` — `loadMessages(locale, namespaces)`.
- `request.ts` (`getRequestConfig`), `request-locale.ts` (`getRequestLocale`), `resolve-locale.ts`, `cookie.ts` (`setLocaleCookie`, `httpOnly: false`).
- `translator.ts` — `getTranslator(locale, ns?)` для не-React коду; `use-translator.ts` — `useTranslator(ns?)` для динамічних ключів на клієнті.
- `translate-issue.ts` (`translateIssue(t, issue)`), `zod-errors.ts` (`zodErrorMap` → `validation.*`, див. «Помилки API і Zod»).
- Провайдери: `locale-scope.tsx` (серверний `<LocaleScope namespaces>`), `client-locale-provider.tsx` (root-chrome), `fixed-locale-provider.tsx` (лендинг), `html-lang.tsx` (модульне сховище `{ locks, root }`: заблокована мова сторінки — лендинг — перекриває cookie-мову root-провайдера, блокування стекуються і витримують StrictMode).
- `time-zone.ts` (`TZ_COOKIE`, `isTimeZone`, `resolveTimeZone`), `request-time-zone.ts` (`getRequestTimeZone`, server-only), `use-time-zone-cookie.ts` (клієнтський запис cookie `TZ`), `language-name.ts` (`languageName(locale)`).
- `lib/i18n/test/` — `makeT` (мок) і `renderWithIntl`; `scripts/i18n/extract-cyrillic.ts` (`pnpm i18n:extract <dir>`) — чернетка JSON з кириличних літералів.

## Потік мови

1. Cookie `NEXT_LOCALE` → `Accept-Language` (за q) → `uk`. Невалідне значення cookie ігнорується. Запит із Bearer-токеном (MCP/зовнішні клієнти) без cookie й `Accept-Language` отримує `en`; поза запитом (скрипти, тести) — `uk`.
2. `User.locale` (nullable, міграція `20261109000000_user_locale`) на кожному запиті не читається. `PUT /api/locale` пише cookie і (для залогіненого) `users.locale`; `GET /api/locale` при вході повертає профільну мову й виставляє cookie. `User.locale = null` cookie не перезаписує. `syncUserLocale(userId, cookieLocale)` (`lib/server/users/locale.ts`) переносить мову, обрану до входу, у профіль (`where: { locale: null }`, наявну профільну не чіпає); викликається з `/api/locale` і `auth/callback`. Cookie ставиться з `secure` за `isSecureRequest` (перший елемент `x-forwarded-proto`). Хук `useSetLocale` (`lib/hooks/common`) після зміни шле `LOCALE_CHANGE_EVENT`, щоб `ClientLocaleProvider` (cookie → `navigator.languages` → `uk`) перечитав мову.
3. Root layout **не читає cookies/headers** (інакше всі сторінки стають динамічними, див. `landing-auth.md`): `<html lang="uk">` статичний, `HtmlLang` оновлює `document.documentElement.lang`.
4. Динамічні сегменти (`(auth)`, `settings`, `campaigns`, `help`) мають `layout.tsx` із `<LocaleScope namespaces>`. Root-chrome (лінивий `Header`, `ConfirmProvider`, `error.tsx`, `not-found.tsx`) бере мову з `ClientLocaleProvider`: статичний HTML — `uk`, після монтування — cookie; повідомлення `common`+`validation` обох мов вбудовані в чанк.
5. Fallback: locale → `uk` → ключ (без винятку). Типи ключів — із `uk`-JSON через `global.d.ts`, неіснуючий ключ ламає `tsc`.

## Лендинг

Два статичні URL з `LANDING_PATH` (`lib/constants/site.ts`): `/` (`en`, x-default) і `/uk` (`uk`) — схема редизайну лендингу v2. `<LandingPage locale>` обгортається `FixedLocaleProvider` (клієнтський, не залежить від request-конфіга); тексти — `messages/*/landing.json`, серверні секції отримують `t` пропом, списки перебираються через `t.raw` (`keysOf`/`listOf`). `proxy.ts` робить rewrite `/` → `/uk` (`landingRewriteTarget`) лише за явним вибором — cookie `uk` або `Accept-Language` з `uk` (`negotiateLocale`, без fallback на `DEFAULT_LOCALE`), тож краулери бачать англійський `/`. `LocaleSwitcher hrefs` рендерить посилання з `hrefLang`, клік пише cookie (інакше rewrite повернув би мову назад). `buildLandingMetadata(locale)` додає `canonical` і `hreflang`; `sitemap.ts` — обидві URL з alternates. Початковий HTML `/` має `<html lang="uk">` (обгортка лендингу — `lang="en"`, `HtmlLang lock` виправляє на клієнті) — прийнятий компроміс.

## Межі коду

- Не-React код (реєстри, константи, сервер) віддає **ключі**, не рядки; переклад — на межі: `t()` у компоненті, `getTranslator` на сервері, `translateIssue` для Zod.
- Повідомлення Zod-схем — ключі (`"validation.passwordMismatch"`); клієнт показує `translateIssue(t, issue)` (потрібен кореневий `t`, ключі повні).
- Помилки API (`API_ERRORS`) — ключі `errors.*` (див. нижче); текст у JSON-відповіді вже перекладено.
- Контент із БД лишається як є; лог бою — ключі (частина 6); `world_travel_log` — структурні поля, підписи ключами (див. частину 5).
- Текст для моделі (промпти, `title`/`description` тулів, OpenAPI, `.describe()`) — англійською в коді, без ns.

## Помилки API і Zod

- `API_ERRORS` (`lib/constants/api-errors.ts`) — значення-ключі `errors.*` (або `validation.*`/`common.*`); `API_ERROR_PARAMS` — значення плейсхолдерів за замовчуванням (ліміти, формати), виклик додає свої через `params` (`errorResponse(key, status, issues, params)`, `ContentError(key, status, issues, params)`, `BattleRuleError`). Тест `api-errors-coverage` перевіряє наявність ключа в обох мовах і що кожен ICU-аргумент є в `API_ERROR_PARAMS`. Складені повідомлення — окремим ключем з параметрами (`SLIDE_IMAGE_FAILED` = «Слайд {index}: {detail}»), а не конкатенацією; параметр, що сам є ключем, перекладається перед підстановкою.
- Переклад — на межі відповіді: `apiErrorJson` (`lib/utils/api/translate-error.ts`) повертає `NextResponse` зі **стрімом, що ліниво перекладається**: `start` виконується синхронно в конструкторі, тож контекст запиту (cookies/headers) ще активний. Тіло: `{ error: <переклад>, errorKey: <ключ>, issues?, ...rest }`; `code`/`version`/`retryAfterSeconds` зберігаються; `params` у JSON не потрапляють (ні верхнього рівня, ні в `issues[]`). Рядок, якого нема в каталозі (`t.has` = false), проходить як є (застарілі літерали, контент). Усі помилкові відповіді — через `errorResponse`/`apiErrorJson`/`handleApiError`/`battleErrorResponse`/`rateLimitResponse`, не `NextResponse.json({ error })`.
- `issues[]`: повідомлення перекладається `translateIssue` (мінімум/максимум із Zod-issue + `API_ERROR_PARAMS` + `issue.params`), додається `pathLabel` (`errors.fields.<segment>`, числа як `#N`).
- Namespace `errors` **серверний**: його не вантажить жоден `LocaleScope`/клієнтський провайдер, `translate-error.ts` — `server-only`. Ключ, текст якого показує клієнтський код без запиту на сервер (блокери легендарних дій/лігва, редактор треків, помилка завантаження файлу), має жити в `validation.*`/`common.*`; тест `client-api-errors` обходить граф імпортів `"use client"`-файлів і падає на `API_ERRORS.*` з префіксом `errors.` (виняток — перевірений список файлів). `renderWithIntl` за замовчуванням вантажить лише `common`+`validation`, щоб такі помилки ловилися тестами.
- Всередині процесу (`operation-runner`: асистент, character-операції) `apiErrorJson` додає до відповіді символ `API_ERROR_SOURCE`; `errorStatusMessage` перекидає `ContentError` з неперекладеним ключем і `params` замість розбору перекладеного тіла (інакше параметри губляться).
- Звіт імпорту контенту (200-відповідь) перекладається `translateImportReport` у route і в асистентському `content.import`; `ImportIssue` несе `params`/`minimum`/`maximum`.
- Zod: **серверний** глобальний `z.config({ customError: zodErrorMap })` (`lib/zod/locale.ts`, з `instrumentation.ts`) дає повідомленням ключі `validation.*` (явний `message` має пріоритет; невідомий код → `validation.invalid`); відповідь перекладається на межі. **Клієнтський** бандл (`instrumentation-client.ts`) підключає той самий `lib/zod/locale.ts`: клієнтські Zod-issue (редактор ефектів заклинань) — ключі `validation.*`, показ через `translateIssue` з `params` `minimum`/`maximum` (тест `zod-config-split`). Редактори, що збирають issue заздалегідь (`validateAbilities`, `spellFormIssue`), кладуть `issueParams(issue)` у `params`, інакше `validation.min/max` показується сирим ключем (тест `FieldErrors.bounds`).

## CRUD-домени (частина 3)

- Константи-підписи, які читає імпорт CSV/аркуш/бій (`UNGROUPED_LABELS`, `ABILITY_LABELS` тощо), лишаються українськими; компоненти показують **ключі** з enum-реєстрів (`artifacts.rarity.*`, `slots.*`), їх покриває `lib/i18n/__tests__/label-keys.test.ts`. Значення з БД поза реєстром показується як є.
- Zod `.describe()` — англійською (підказки для AI/MCP, не UI).
- Спільні підписи: `common.actions`, `common.form`, `common.dndSkills`.
- Маркери груп музики «Битва»/«Інше» — дані з БД, лишаються літералами з `eslint-disable`; підпис групи — `trackGroupLabel`.
- Серверні Zod-повідомлення — ключі `<ns>.validation.*` з `params` у issue (`ErrorIssue`); імпорт переносить `params`/`minimum`/`maximum` у `ImportIssue`.
- Globs у `i18n-exempt.json` (`[{ glob, reason }]`) пишуться з `*` замість `[id]`.

## Великі домени (частина 5)

Spec і план: [spec](../archive/superpowers/specs/2026-10-29-i18n-part5-design.md), [план](../archive/superpowers/plans/2026-10-29-i18n-part5-large.md).

- **Namespace-и.** Клієнтські (у `CAMPAIGN_NAMESPACES`, `ai` ще й у `app/settings/layout.tsx`): `scenario`, `show`, `acquaintances`, `world`, `ai`, `compendium`, `contentImport`, `gameTerms`. Серверні (`SERVER_NAMESPACES` у `lib/i18n/config.ts`): `errors`, `assistant`, `compendiumReport` — їх не вантажить жоден `LocaleScope`, читає лише `getTranslator`; тест `server-namespaces` і `client-api-errors` ловлять ключі цих префіксів у клієнтському графі.
- **`gameTerms`** — ігрові терміни, винесені з `common` (`abilities`, `stats`, `spellLevels`, `dndSkills`, `ungrouped`, `damageTypes`, `monster`, `weaponTraits`, `creatureTypes`, `abbreviations`): `gameTerms` іде в `CAMPAIGN_NAMESPACES` і в `ROOT_NAMESPACES` (`lib/i18n/scopes.ts`, статичний бандл root-layout: `AbbreviationsInfoDialog` у `Header` стоїть поза кампанійним скоупом; тест `server-component-hooks` стежить, щоб `Header` читав лише root-namespace-и). Серверні компоненти не можуть викликати синхронний `useTranslations` для namespace поза `common`/`validation` (request-config) — такі компоненти мають `"use client"` або `getTranslator`; `dmSections`/`dmMenu` лишаються в `common`. Динамічні ключі покриває `label-keys-gameTerms` в обох мовах.
- **Текст для моделі vs для людини.** Людині — ключі й переклад на межі. Моделі — англійською в коді без ns: системні промпти, `title`/`description` тулів `lib/ai/tools/**`, `.describe()`, OpenAPI, промпт AI-мапінгу. Мова відповіді — рядок `Reply in <мова>` з `languageName(locale)` (`lib/i18n/language-name.ts`).
- **Локаль асистента.** `AssistantCaller.locale` / `AiToolContext.locale` визначає маршрут один раз на старті; тули й дії не викликають `getRequestLocale` (стрім виконується після повернення відповіді). Чат — мова cookie. MCP/Bearer (`app/api/mcp/route.ts`): cookie / `Accept-Language` → профільна `locale` власника токена (`verifyApiToken` повертає її без зайвого запиту) → `en`. REST-маршрути з Bearer лишаються на `en` — відкладено.
- **Результати асистента** — ключі ns `assistant` (`actionResult` приймає ключ підпису), summary/warnings/`effects[].description`/handoff-причини перекладаються на межі дії через `getTranslator(caller.locale, "assistant")`; помилки `ai-ops` — `TextRef`. `preconditions` інтентів зберігають неперекладений звіт, тому дайджест (`requestDigest`) не залежить від мови.
- **Що пишеться в БД.** `assistant_intents.summary`/`preview` і системні частини `ai_proposals` — мовою автора на момент створення (старі рядки не перекладаються). Назви за замовчуванням (новий розділ сценарію, легенда сцени, набір показу/карта/тред) — `t()` у локалі автора при створенні. Вміст сценарію/показу, нотатки світу, відповіді моделі, імпортований контент (5etools/homebrew) — контент, не перекладається. `world_travel_log` — структурні поля (`kind`, `rest`, маркер), підписи — `world.travel.kinds.*` на клієнті. `compendium_import_runs.report` — issue з `code` + `params`; повідомлення будує сервер на читанні (`compendiumReport.issues.<CODE>`), legacy-рядки без коду показуються як є.
- **Zod і константи.** Повідомлення `lib/schemas/{world,show,scenario,ai}.ts` — `<ns>.validation.*` з `params`; підписи констант скоупу — id, UI бере ключі (`scenario.pageKinds.*`, `world.markerKinds.*`, `ai.modes.*`), тест `label-keys-<ns>`.
- **Часова зона.** Cookie `TZ` (IANA-зона) замість сталої `APP_TIME_ZONE`: `use-time-zone-cookie.ts` пише її після монтування, `request-time-zone.ts` читає на сервері, `time-zone.ts` валідує (`isTimeZone`) з fallback на `APP_TIME_ZONE`. Перший візит — `Europe/Kyiv`. Профільне `User.timeZone` — відкладено.
- **CSV-імпорт.** Підписи полів — `labelKey` → `contentImport.fields.<kind>.<key>`; issue — `contentImport.issues.*` з `params` через `translateImportReport`. Псевдоніми заголовків, слова «так/ні» і приклади — дані розбору в `lib/constants/import-aliases.ts` (поза храповиком; мають розпізнавати українські таблиці за будь-якої мови UI).
- **Генератор героя.** Офлайн-генератор — контент у локалі автора: таблиці `backstory.{uk,en}.ts`, `names.{uk,en}.ts`, `generateCharacter({ locale })`; каталог `lib/utils/characters/generate` поза храповиком. AI-передісторія (`generate-backstory.ts`) — мовою автора запиту (`getRequestLocale`, англійський промпт з `Reply in`).
- **Хвости ч.4.** `getHeroMaxHpBreakdown` віддає `TextRef[]` (`characterProfile.sheet.heroHp.*`); дублі кнопок зведені до `common.actions.*`.
- Розмір скоупу — тест `scope-size`; нові клієнтські ns додаються в `CAMPAIGN_NAMESPACES`.

## Частина 6: бій

Spec і план: [spec](../archive/superpowers/specs/2026-10-29-i18n-part6-design.md), [план](../archive/superpowers/plans/2026-10-29-i18n-part6-battle.md).

- **Модель тексту.** Не-React код віддає `TextRef { key, params }` (`types/text.ts`; `textRef(key, params)`, `dynamicTextRef`, `joinLines`, `capitalizeLine`, `lineKey` у `lib/i18n/text-ref.ts`), `LogLine = string | TextRef` (рядок = легасі/контент). Рендер на межі: `formatText(t, line)` або клієнтський `useText()` (`lib/i18n/use-text.ts`); параметр, що сам `TextRef`, перекладається перед підстановкою. Тести: `textOf`/`logTextOf`/`textMatching` (`lib/i18n/test/text.ts`).
- **Лог бою.** Нові події пишуть `details.log: LogLine[]` і `resultText = ""` (`logFields`, `withLines`, `withPrefix` у `lib/utils/battle/log/lines.ts`); `snapshotHash` не залежить від мови. Старі рядки з БД (`resultText` без `log`) розбирає `lib/utils/battle/log/legacy.ts` (uk-рядок як є). Мова логу — **глядача**, не автора події: переклад у момент показу.
- **Скоуп бою.** Окремий набір ns `BATTLE_NAMESPACES` (`lib/i18n/scopes.ts`: `battleCommon`, `battle`, `battleWizards`, `battleDm`, `battleSetup`, `battleLog`, `battleActions`) підвантажує `ExtendLocaleScope` (`lib/i18n/extend-locale-scope.tsx`) у `app/campaigns/[id]/battles/layout.tsx` і `dm/battles/layout.tsx`; `battleTerms` — у `CAMPAIGN_NAMESPACES` (термінологія бою потрібна й у профілі/редакторах). Тест `battle-scope-imports` не дає не-бойовим сторінкам імпортувати бойові ns.
- **Описи здібностей — Segments.** Як у [abilities.md](abilities.md): `Segment { key, params }` у ns `abilityRegistry` (`renderSegment`/`joinSegments`/`useAbilityText`, `describe*` без TextRef). Ns `abilityText` лишився лише для **логу рушія**: `abilityText.log.*` (урон, лікування, DoT/HoT, імунітет, стани, слоти, мораль, штовхання тощо) і `thisAction`; вбудований у рядок логу опис ефекту (`applied`, `grantAction`) — через `logText` (`lib/utils/abilities/log-text.ts`), синхронний uk-рендер сегментів, тож цей фрагмент лишається українським.
- **Імпорт компендіуму.** Текст, що імпорт пише в БД (`derived.*` у `compendiumReport`), — локаль імпортера: `derivedTranslator(locale)` (`lib/server/compendium-import/derived-text.ts`), `ctx.t` в адаптерах (`race-traits`, `equipment`, `feat-prerequisites`, `feat-spells`, `item-effects`, `spell-derive`, `subraces`).
- **Храповик на весь код.** `i18n-exempt.json` (див. «ESLint-храповик»); тимчасового `I18N_LEFTOVERS` більше нема.
- **Розмір скоупу** (`scope-size`, gzip, ліміт 100 KB): кампанія uk 73,6 / en 59,2 KB; кампанія + бій uk 91,8 / en 74,1 KB.

## Тести

- Глобальний мок у `vitest-setup.ts`: `t("a.b")` → `"ns.a.b"`, з параметрами → ключ + JSON параметрів. Тести перевіряють **ключі**, не тексти.
- `await renderWithIntl(ui, { locale, namespaces })` — справжній провайдер з реальними JSON (для кількох i18n-тестів); за замовчуванням `common`+`validation`, інші namespace-и (`auth`) передаються явно.
- `lib/i18n/__tests__/parity.test.ts`: `en` має всі ключі `uk`, ті самі ICU-плейсхолдери, зайвих ключів немає.

## ESLint-храповик

Кирилиця заборонена в **усьому** коді: `eslint.config.mjs` вмикає `no-restricted-syntax` на `Literal`, `JSXText`, `TemplateElement` у `**/*.{ts,tsx}` (`__tests__` і коментарі не перевіряються), крім шляхів з `i18n-exempt.json` — масив `[{ glob, reason }]`, кожен виняток з причиною (`scripts/**`, `tests/**`, `data/**`, `prisma/**`, генератор героя, `lib/constants/import-aliases.ts`, `vitest-setup.ts`, `eslint/**`, `*.config.*`). Тест правила — `eslint/__tests__/cyrillic-rule.test.ts`. Виняток у коді — лише `// eslint-disable-next-line no-restricted-syntax -- <причина>` (контент, що пишеться в БД/знімки, імпортні регекси, дефолтні назви: перелік — `git grep -n "eslint-disable.*no-restricted-syntax" -- '*.ts' '*.tsx' ':!*__tests__*'`, станом на ч.7 лишилось 15 файлів, усі з причиною: `lib/constants/{abilities,artifacts,choices,classes,main-skills,spells,ungrouped}.ts` (довідники — дані для імпорту/зіставлення, UI читає ключі `gameTerms.*`), `lib/constants/{critical-effects,save-critical-effects}.ts` і `battle/conditions/registry.ts` (name/description копіюються в збережені `activeEffects`; UI читає `battleTerms.crits.*`/`battleCommon.conditions.*`), `lib/constants/ai.ts` (авто-назва старих тредів), `lib/utils/audio/playlist-groups.ts` (конвенція назв треків у БД), `lib/utils/units/unit-parsing.ts` і `types/import.ts` (ключові слова/колонки CSV-імпорту), `LocaleSwitcher` (рідні назви мов).

## Як перенести домен

1. `pnpm i18n:extract <dir>` → чернетка; створити/доповнити `messages/{uk,en}/<ns>.json`, додати `<ns>` у `NAMESPACES`.
2. Замінити літерали на `t()`/`getTranslator`; реєстри й константи — на ключі; Zod-повідомлення — на `validation.*`.
3. Додати `<LocaleScope namespaces={[…]}>` у `layout.tsx` сегмента (якщо його ще немає).
4. Переписати тести домену на ключі; `pnpm test:related <files>`.
5. `pnpm lint`, `pnpm exec tsc --noEmit` (новий каталог одразу під правилом; `i18n-exempt.json` — лише для скриптів/даних).
6. Дати `en`-переклад усім ключам (тест паритету), ICU-плюралі `uk` (`one/few/many/other`) — з паралельними `en` (`one/other`).

## Частина 7: закриття перекладів

Spec і план: `docs/superpowers/specs/2026-10-30-i18n-part7-design.md`, `docs/superpowers/plans/2026-10-30-i18n-part7.md`.

- **Збережений лог.** Подія пише `details.log: LogLine[]` (ключі; мова — на читанні, глядача) у компактному кодеку `{m,p}` з аліасами ns/параметрів (`lib/utils/battle/log/codec.ts`); легасі-рядки (довга форма `{message, params}`, `resultText` без `log`) читаються як раніше.
- **Fallback-лог.** `BATTLE_LOG_TEXT_FALLBACK = true` (`lib/constants/battle.ts`): рендер логу в локалі ДМ дублюється в `resultText`, щоб відкат деплою на код до `log` ще показував текст. Це тимчасово: прапорець вимикається окремим кроком після вікна відкату (див. STATUS); без нього `resultText=""`.
- **Розмір логу** (`scripts/sim/log-size.ts` на prodcopy-боях `battle-sweep --keep-battles`). M1 = Σ байтів `JSON(details.log)` / Σ байтів uk-рендеру того ж логу (гейт ≤1,30): було 1,767, після відкидання порожніх params і плаского `withChance` (538a1c4c6) та кодека (49ef7df24) — 1,160. M2 = (лог + fallback) / fallback — ріст текстової частини рядка БД, поки fallback увімкнений: 2,160.
- **Клієнтська дельта не кодується.** Див. нижче «розмір дельти бою (T2c)»: різниця <2%, кодек лише для запису в БД.
- **Часовий пояс.** `User.timeZone` (нуллable): профіль → cookie `TZ` → UTC (`APP_TIME_ZONE`); сторінка налаштувань профілю, `useTimeZoneSetting`, `lib/i18n/time-zone.ts`.
- **`i18n-exempt.json`** — `[{ glob, reason }]`; лишкові `eslint-disable no-restricted-syntax` перелічено в «ESLint-храповик».
- **Серверні компоненти.** Синхронний `useTranslations` у серверному компоненті дозволений лише для ns із `ROOT_NAMESPACES` (`common`, `validation`, `whatsNew`, `gameTerms`; `lib/i18n/scopes.ts`); інакше — `"use client"` або `getTranslations`. Тест `server-component-hooks.test.ts` сканує код; без цього в dev показуються сирі ключі.
- **Тести.** `untranslated.test.ts` ловить непереклад­ені рядки; `scope-size.test.ts` рахує бюджети. `WHATS_NEW_BUNDLED = 15` — у root-бандл входять лише останні 15 записів `whatsNew`. Розміри (gzip): root 11,8 KB; кампанія + бій uk 94,6 / en 76,3 KB (ліміт 100 KB).
- **Похідні тексти.** Кеш `info-reference` зберігає структуру фасетів заклинань, а не uk-рядки; `derived.spell.*` — ключі для спел-патернів імпорту; похідні мітки здібностей — `label: LogLine` з id-подібним `name`; архетип героя — `archetypeKey` у `abilities` (мова-незалежний множник шкоди), назви архетипів — ключі.
- **Відкладено (лише контент/дані).** Текст імпортованого компендіуму лишається в мові джерела; старий збережений `resultText` у легасі-подіях; `CastableSpell.name` лишається рядком, тож безіменні запасні назви беруть `spellId`/ім'я носія; параметри логу все ще передають `ability.name`.
- **Не перевірено в браузері:** вигляд гравця, карта з небезпеками (hazard), діалог крита.

## Частина 7 — розмір дельти бою (T2c)

Виміряно `scripts/sim/delta-size.ts` на ~1500 реальних дельтах battle-sweep (prodcopy; збір — `DELTA_DUMP=<файл>` у `battle-sweep.ts`).
