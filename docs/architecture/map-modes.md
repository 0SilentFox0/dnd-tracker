# Map modes

`lib/utils/battle/modes`: one mode per battle, `activeMapMode(map)` from `MAP_MODE_REGISTRY` (server/engine/client hooks, `NORMAL_MODE` neutral) + `MAP_MODE_UI` (`components/battle/modes`, UI slots) + mode hooks in `lib/hooks/battle/modes/<key>`. Core never imports a mode directly (ESLint). Rule systems follow the same pattern but with a stricter zone, roots and a generator — see [rule-systems.md](rule-systems.md#як-додати-базу).

**New mode** = a folder in the three places + a row in both registries (+ `satisfies Record<MapModeKey, …>` objects in `lib/hooks/battle/modes/tools.ts`).

Engine hooks include `lineBlocked({ config, map, line })` — a mode wall on a ranged line of fire (see [battle.md](battle.md)); optional, default `false`.

`areHostile({ config, map, a, b })` — режим може оголосити двох учасників ворожими всупереч `side` (`true`; `undefined` = за сторонами). Ядро викликає лише через `isHostile(map, a, b)` з `modes/engine.ts`, режим не імпортує.

## Maze

The first mode: pure geometry/vision/generator, server wake-up in `afterMutation`, hiding client-side in `modes/maze/view.ts`; the server sends the full scene.

**Підміна (illusion swap):** `MazeConfig.illusionSwap.pairs` — пари героїв, які бачать один одного ворогами під масками (`aSees`/`bSees`). Операція ДМ `op:"illusion"` замінює весь список (порожній = «Повернути союзників»); `areHostile` повертає `true` для пари; `pruneIllusion` в `afterSettle` (після перемоги) знімає пару, коли хтось помер/покинув мапу або бій не ACTIVE (DM-подія); `onReset` очищає. Маска — клієнтська: `view.disguiseOf` + `maskMazeScene`/`maskMazeFxAction`/`maskBattleBy` (`illusion-mask.ts`); ДМ бачить справжні особи й позначку маски (`view.maskedIds`, `ParticipantRow`). Деталі межі — [battle.md](battle.md#підміна-в-лабіринті-ishostile).

## Spell terrain (P4)

Difficult terrain, `obscured` cells, spell walls and `spellZones` are core: they live in `map.terrain` / `map.spellZones` and are read by `grid/*` and `spell/zone-*`. Map modes neither import nor change them; the maze never fires zone triggers.

## Стіни й ґрати (core, етап B)

`map.walls` / `map.bars` — ребра `"x:y:e"` / `"x:y:s"` (ліміт 7200 разом із `maze.walls`); ядро, не режим. Примітиви ребер — `grid/walls.ts` (`edgeKey`, `canStep`, `cornerOpen`; `modes/maze/walls.ts` лишився обгорткою над `maze.walls`). Читання лише через `grid/edges.ts`:

- `wallsOf(map)` = `map.walls ∪ modeWalls(map)`; хук режиму `walls?` у `ModeEngineHooks` (диспетчер у `modes/engine.ts`) віддає стіни режиму (maze віддає `maze.walls`; хук мусить повертати стабільний за посиланням масив — memo `wallsOf` ключується ідентичністю), тож рух/постріл/зір по лабіринту ідуть тим самим шляхом. `barsOf(map)` — ґрати.
- `edgeBlocks(map, a, b, kind, mover?)`, `kind`: `move` (стіни + ґрати), `sight` і `fire` (лише стіни). Діагональ блокується, якщо закритий хоч один кутовий шлях. `cellsConnected` — пряма лінія між наборами клітинок.
- Споживачі: `searchPaths` (рух; ранній вихід без ребер), `lineOfFire` (`wallBlocked`: постріл крізь стіну, зокрема лабіринту, заборонений через `attackReachError`, а не укриття) і `rayCells`/`templateCells` (`fire`), `grid/sight.ts` (`sightedTargets`, ланцюгові цілі, вибір цілей заклинань/здібностей), `grid/adjacency.ts` (`isAdjacentOnMap`/`cellsAdjacentOnMap` — ближній бій, cleave, fire-burst, move-self, оборонні реакції, opportunity-атаки; `sight`-блок скасовує сусідство). Геометричні `footprintDistance` (аури, ауди, розстановка) не чіпали.
- Модифікатор `passesWalls` (flag): `edgeBlocks(..., 'move', mover)` ігнорує стіни й ґрати для власника; зір і постріл не змінюються. Враховує лише власні здібності мувера (`collectModifiers([mover])`), без аур інших. Контент (Etherealness, привиди) не прив'язано — у «хвостах» STATUS.
- Редактор ребер вимкнено, поки активний maze (`REJECT.mapEdgesInMode`) і на touch-пристроях.
- Руйнування ребер у бою — `map-edge-remove` поверх `battle_map_state` (див. «Зберігання карти» нижче); двері — див. «Двері (B6)» нижче.

## Map motion («Рух»)

`BattleMapConfig.motion?: { axis: "x" | "y"; speed } | null` — окреме поле конфігу карти за зразком `weather`, **не** запис у `MAP_MODE_REGISTRY` (реєстр — для режимів, що змінюють правила; рух суто візуальний і сумісний із лабіринтом). `speed` — клітинки/с зі знаком, `|speed| ≤ 6`, `0` = зупинено, відсутнє = вимкнено.

- Операція `map-motion` (`mutations/map-motion`, лише ДМ, активний бій); по мережі лише `axis` і `speed`, фаза **не** синхронізується — кожен клієнт крутить власну в `requestAnimationFrame` через `lib/utils/canvas/ticker`. Жодного полінгу.
- `MapBackground` при `map.motion` віддає рендер `components/battle/map/motion/MotionBackground`: доріжка з парної кількості тайлів (непарні віддзеркалені вздовж осі), період = 2 тайли; `backgroundCols` і `gridOffset` у цьому режимі ігноруються. Фон лишається статичним, доки не відома пропорція картинки; `prefers-reduced-motion` і прихована вкладка анімацію не запускають.
- Мобільний поворот карти (`rotated`): вісь і знак перераховує `motionInMapSpace`, тож напрям лишається екранним.
- Чиста математика (clamp, розгін, обгортання фази, кількість тайлів) — `lib/utils/battle/map-motion/`; панель ДМ — `MapMotionPanel`, хук `useMapMotionTool` (палітра взаємовиключна з режимом/місцевістю/погодою).
- Налаштування при створенні бою: `useBattleMapEditor` тримає `map.motion` і віддає `motionTool` (той самий `useMapMotionTool` з локальною мутацією), `BattleFormMap` рендерить `MapMotionPanel`; прев'ю їде вживу, `battleMapSchema.motion` зберігається в бою, а `resetMutation` не чіпає `motion` (покрито тестом).

## Зміна фону в бою

- Операція `map-background` (`mutations/map-background`, лише ДМ, активний бій): пише `map.background` і скидає `backgroundCols`/`backgroundRows`/`gridOffset` (як `setBackground` у налаштуванні). Файл/data-URL вантажиться в bucket `battle-maps` через `resolveMapBackgroundForPersistence` у самій мутації (`campaignId` береться з `params.id`), у сцені лежить лише URL.
- Для гравців перехід робить `MapBackground`: старий шар лишається, новий монтується з `opacity: 0` і з'являється після `onLoad` (800 мс, `BACKGROUND_FADE_MS`), старий одночасно зникає й знімається. `prefers-reduced-motion` — миттєва заміна. Те саме працює з `map.motion` (`MotionBackground.onReady`).
- Панель ДМ — `MapBackgroundPanel`, хук `useMapBackgroundTool` (палітра `background` у `palettes.ts` взаємовиключна з рештою). У реєстрі асистента — `handoff` (потрібне завантаження файлу).

## Калібрування сітки (setup)

`BattleMapConfig.backgroundRows?` — окрема висота фону в клітинках (неквадратні клітинки зображення; без неї береться з пропорцій). `backgroundBox` враховує її. Чисті `fromCellRect`/`nudge` у `lib/utils/battle/grid/calibration.ts`; стан у `useGridCalibration`, застосування через `applyCalibration` у `useBattleMapEditor`; UI — `components/battle/setup/GridCalibration.tsx`. При заміні фону калібрування пропонується зберегти лише за того самого розміру зображення. Автодетект сітки відкладено: [спайк](../superpowers/research/2026-11-14-grid-autodetect-spike.md).

## Зберігання карти (етап 0)

Карта бою складається з шарів; ядро й клієнт читають лише **ефективну** карту.

- **Базова карта** — що лежить у `battle_scenes.map` (inline-бій: заголовок + власні `walls`/`bars`) або заголовок бібліотечної карти (linked-бій). **Ефективна** = `composeEffectiveMap(base, state, libEdges?)` (`lib/utils/battle/map-storage/effective-map.ts`): база + ребра бібліотеки − `state.removedEdges`; модові стіни (`modeWalls`) не чіпає; результат стабільний за ідентичністю входів (кеш `WeakMap`, потрібно `wallsOf`). `loadBattle` складає її в `meta.map`.
- **Запис назад** — `persistedMap(meta, patched, state)` (`map-storage/persisted-map.ts`): linked-карта пишеться лише заголовком (`withoutEdges`), для inline ребра, яких мутація не торкалась, лишають збережену форму (`meta.mapBase` = власні `walls`/`bars` із БД), тож видалені станом ребра не «запікаються» у базу. `clientMapOf` — карта, як її тримає клієнт (заголовок + власні ребра, ще без шару стану).
- **Бібліотека** — `battle_maps` (заголовок JSON, `cols/rows`, `map_version`) + `battle_map_chunks` (ребра чанками 16×16, 2 біти на ребро: стіна/ґрати; `encodeEdges`/`decodeEdges` у `edge-chunks.ts`) + `battle_map_versions` (знімок payload кожної версії). Сервіс `lib/server/battle-maps/library-service.ts`, схеми `lib/schemas/battle-maps.ts`. API: `GET/POST /api/campaigns/[id]/maps`, `GET/PUT/DELETE …/maps/[mapId]`, `POST …/maps/[mapId]/clone`. `GET` карти віддає слабкий ETag `weakEtag(id, version)` + `ifNoneMatch` → 304 (`lib/utils/api/etag.ts`; egress); видалення використаної карти — 409 `BATTLE_MAP_IN_USE`. Читає будь-хто з доступом до кампанії, пише лише ДМ. Клієнт: `lib/api/battle-maps.ts`, `lib/hooks/battle-maps` (`useBattleMaps`, `useBattleMapEdges`).
- **Linked-бій:** `battle_scenes.map_id` + `map_version` = `mapRef { mapId, version }`; `scene.map` — лише заголовок (рантайм-поля `terrain`/`spellZones`/`weather`/`motion` і поля режимів лишаються в бою). Ребра клієнт бере з бібліотеки за `mapRef` (`useBattleScene` → `useBattleMapEdges`, ETag), сервер — з `effectiveMapOf` у `loadBattle`. Редагувати ребра linked-карти в бою не можна: `REJECT.mapEdgesLinked` (`map-walls`) — лише `map-edge-remove` (стан).
- **Стан бою** — `battle_map_state` (1:1 з боєм): `removed_edges`, `doors`, `fog` (резерв під B6/D), `version`. У сцені — `scene.mapState`; у дельті — `ClientBattleDelta.scene.mapState` (`MapStateDelta`: `removed {add,remove}` через `diffEdges`, `doors`; `diffMapState`/`applyMapStateDelta`). Клієнт зливає в `applyBattleDelta`; ефективну карту перераховує `useBattleScene`.
- **Мутації:** `map-edge-remove` (ДМ, активний бій; `{ edges, restore? }` — прибрати/повернути ребра; валідує наявність ребра в ефективній карті або в `removedEdges`: `REJECT.mapEdgeNotFound`/`mapEdgeNotRemoved`) і `map-update` (ДМ; linked-бій підтягує нову версію бібліотечної карти: відхиляє, якщо учасник опиняється на непрохідній клітинці — `REJECT.mapUpdateCollision`; або версія понад `battleMaxSide` — `BATTLE_MAP_TOO_LARGE`; прибирає з `removedEdges` ребра, яких у новій версії нема; відповідь — нова `map` + `mapRef`). Шапка зливається `mergeLibraryHeader(oldLib, newLib, battle)` (`map-storage/merge-header.ts`, три сторони: pinned-версія `getMap(mapId, mapRef.version)`, нова, бойова): незмінене бібліотекою лишається бойовим (також покомірково `terrain`), змінене береться з бібліотеки; клітинки з `zoneId`/`untilRound`, `spellZones`, `weather`, `motion` і ключі режимів завжди бойові.
- **Перепривʼязка в редагуванні бою:** `PATCH` бою приймає `mapId: string | null` (xor з `map`), лише для `status = prepared` (інакше 409 `BATTLE_MAP_RELINK_STARTED`). Інша карта — шапка бібліотеки (`headerForOtherMap`: зберігаються лише `weather`/`motion`), `battle_map_state` видаляється; та сама карта — `mergeLibraryHeader`; `null` — ребра pinned-версії стають inline (`materializeEdges`, понад `inlineMaxEdges` — 422 `BATTLE_MAP_TOO_MANY_EDGES`). Усе під `lockMapRow('share')` у транзакції (`record-service.ts`). Клієнт: `useBattleLibraryMap(campaignId, { linked, isEdit, status, hadMap })` (confirm при зміні, `isLocked` для активного бою), `useBattleForm` шле `mapId` лише коли вибір змінено.
- **Редактор бібліотеки (P3)** — `MapEditorScreen`: права панель із вкладками «Фон/Клітинки/Ребра»; секції `MapBackgroundSection` (фон, калібрування, розмір клітинки/зсув/прозорість) і `MapCellToolsSection` (стіни/блок/складна/hazard) спільні з `BattleFormMap`. `battleMapInputSchema` приймає data-URL фону (сервіс заливає в bucket і пише URL; після збереження чернетка підміняє data-URL на URL через `replaceBackground`) і лише статичну місцевість (без `zoneId`/`untilRound`/`damage.spellId|casterId|concentrationOf`, без `spellZones`; 400 `libraryTerrainRuntime`).
- **Двері (B6):** `BattleMapConfig.doors: Record<EdgeKey, DoorState>` — початковий стан у базі (заголовок inline-карти або шапка бібліотечної; ≤ `doorsMax`, не збігаються з `walls`/`bars`: `battleSetup.validation.doorOnWall`/`tooManyDoors`), бойовий стан — `battle_map_state.doors` поверх бази (зберігається лише різниця від бази). `composeEffectiveMap` зливає `base.doors ⊕ state.doors` (стан діє лише на двері, що є в базі; двері з `removedEdges` — виламані — зникають) у `map.doors` зі стабільною ідентичністю; `baseDoorsOf(map.doors)` повертає базу, з якої складено, тож `persistedMap` пише в БД базові, а не ефективні двері. `wallsOf` = стіни ∪ `modeWalls` ∪ `closedDoorsOf(map)` (двері з `open !== true`, memo за ідентичністю `map.doors`): зачинені блокують рух/зір/вогонь/шаблони/ближній бій/суміжність уже наявними шляхами; `passesWalls` проходить і крізь них. Мутація `map-door-toggle` (`MEMBER`, `blockedByMode`, активний бій; `{ edge, open?, locked?, actorId? }`): ДМ — будь-які двері, замкнути лише зачинені (`doorOpenLock`), відчинення замкнених знімає замок; гравець — лише `open`, свій учасник у свій хід (`canActNow` + `assertCanAct`), одна з клітинок ребра в footprint (`doorNotAdjacent`), не замкнені (`doorLocked`), `locked` від гравця — `doorDmOnly`; ключ стану прибирається, коли значення дорівнює базі; подія — актора (`battleLog.door.opened/closed`) або DM (`battleLog.dm.door*`). `map-edge-remove` ламає/відновлює й двері. `map-update`: `mergeLibraryHeader` зливає `doors` покомпонентно (як `terrain`), `pruneState` лишає `state.doors` лише для дверей нової версії, двері за межами нової карти відсікаються. UI: `DoorsLayer` (гліф + хітбокс ≥30px, замок бачить лише DM; `useMapDoors` — клік гравця шле toggle з `actorId` поточного героя, ДМ відкриває `DoorMenu`), пензель `edge-door` (`paintDoors`, перемикач «Замкнені») у `useBattleMapEditor` для setup і редактора бібліотеки; у бою нові двері не ставляться. `locked` приходить у сцені всім (лише UI ховає).
- **Ліміти** — `lib/constants/map-limits.ts` (`MAP_LIMITS`): `inlineMaxEdges` 7200 (inline), `libraryMaxEdges` 80000, `chunk` 16, `photoMaxSide` 60 / `tileMaxSide` 200 (бібліотека), `doorsMax` 500. **Тимчасово `battleMaxSide = 60`**: у бій потрапляє карта до 60 клітинок за стороною, доки етапи C/D не дозволять більші.

## Бібліотека карт: UI (етап 0b)

- **Сторінки:** `app/campaigns/[id]/dm/maps` (список: створити, клон, видалити) і `dm/maps/[mapId]` (повноекранний редактор, лише desktop); обидві за `requireMapLibrary` (`lib/server/campaigns/access.ts`: ДМ + прапорець, інакше redirect на кампанію). Прапорець `campaigns.mapLibraryEnabled` (перемикач у налаштуваннях кампанії; читає `useMapLibraryEnabled` у `lib/hooks/campaigns`, `useUpdateCampaign` інвалідує `campaignKeys.detail`). Шаблони не блокуються (`templateVisible: false` ховає лише пункт навігації).
- **API `/maps` свідомо без прапорця:** GET потрібен гравцям (ребра linked-бою) і linked-боям при вимкненому прапорці; записи — лише ДМ.
- **Конфлікт редактора:** PUT приймає опційне `expectedVersion` (сумісно зі старими клієнтами); `saveMap` робить `updateMany where mapVersion = base`, розбіжність або `count 0` → 409 `BATTLE_MAP_CONFLICT`. `useMapEditorDraft` тримає `version` (старт — `source.version`, далі `brief.version` із відповіді) і на 409 показує «змінено деінде, перезавантажте». Збереження з ідентичним payload (лише `name`) не підвищує версію й не знімає снапшот. Після збереження `detail` інвалідується з `refetchType: 'none'` (чернетка не перезавантажується).
- **Вибір карти при створенні бою:** `BattleMapLibraryPicker` + `useBattleLibraryMap`; створення шле рівно одне з `mapId` / `map`; редагування linked-бою не шле жодного. Карта з боком > `battleMaxSide` недоступна.
- **Оновлення карти в бою:** `useMapUpdateTool` (лише ДМ у linked-бою) порівнює `mapRef.version` з версією списку бібліотеки (`staleTime: 0`, `refetchOnWindowFocus: 'always'`); кнопка активна, коли є новіша, → confirm → операція `map-update`. Інструменти ребер у linked-бою приховані (`edgeSource` не передається, `MapTerrainToolbar edgesLinked`), ребра правляться на сторінці «Карти» з наступним «Оновити карту»; `REJECT.mapEdgesLinked` каже те саме.
- **Ребра на сервері для сторінки бою:** `battles/[battleId]/page.tsx` читає `getMap(mapRef)` (помилка → `null`, клієнт дотягне сам) і віддає ребра через `PrefetchedQuery` із ключем `battleMapKeys.edges`, тож немає водоспаду «сцена → ребра». Лише якщо `campaignId` карти збігається з кампанією. Під час `map-update` `useBattleScene` тримає старі ребра (`heldEdges`) лише доки вантажиться нова версія.
