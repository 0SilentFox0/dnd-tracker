# Лендінг і авторизація

## Лендінг (`/` і `/uk`)

- Дві статичні сторінки: `/` (`en`, x-default) і `/uk` (`uk`) — `○` у збірці, CDN-кеш. `proxy.ts` робить rewrite `/` → `/uk` (`landingRewriteTarget`) лише за явним вибором: cookie `NEXT_LOCALE=uk` або `Accept-Language` з `uk`; без них (зокрема краулери) `/` лишається англійським; сторінка обгорнута `FixedLocaleProvider` (клієнтський `NextIntlClientProvider`, без request API). Root layout **не читає cookies/headers**, `<html lang="uk">` статичний, `HtmlLang` оновлює атрибут (деталі — [i18n.md](i18n.md)). Root layout **не читає сесію**: email у шапці береться на клієнті (`useSessionEmail`, `getSession` з cookie — лише для показу), тому будь-який `cookies()`/`getClaims` у `app/layout.tsx` знову зробить усі сторінки динамічними.
- Проксі на `/` не ходить у Supabase (`lib/supabase/middleware.ts`); виняток — `/?code=` / `/?token_hash=` (Supabase повертає на Site URL, якщо `redirectTo` не в allow-list) → редірект на `/auth/callback`.
- «Гість / учасник» у CTA — `SessionSwitch` + `useHasSessionCookie` (наявність cookie `sb-…-auth-token`), без supabase-js у бандлі.
- Код: `components/landing/`. Тексти — namespace `landing` у `messages/{en,uk}/landing.json` (next-intl): серверні секції отримують `t` (`getTranslator(locale, "landing")`) пропом, списки — нумеровані або іменовані об'єкти, які перебирають `keysOf`/`listOf` (`components/landing/messages.ts`, через `t.raw`); id панелей, іконки й картинки — у коді (`media.ts`). Тест `__tests__/messages.test.ts` заборонює кирилицю в EN і зайву латиницю в UK, паритет ключів — `lib/i18n/__tests__/parity.test.ts`. Маршрути `/` (EN) і `/uk`, перемикач мови — `LocaleSwitcher` з `hrefs={LANDING_PATH}` (посилання з `hrefLang`, клік пише cookie й переходить). Назва продукту — лише `BRAND` (`lib/constants/site.ts`), у повідомленнях — плейсхолдер `{brand}`. `lang` ставиться на обгортку лендінгу (`<div data-landing lang=…>`) і `HtmlLang lock`; root `<html lang="uk">` лишається, щоб не ламати статичність. Секції — `sections/*` (Hero, Problem, Combat, Mechanics, Prep, AiSection, Players, HowItWorks, Faq, FinalCta), картинки й іконки — `media.ts`, прапорець блоку шаблонів — `flags.ts` (`LANDING_TEMPLATES`, зараз `false`: нотатка про офіційні шаблони не рендериться). Секція Combat — живе демо бою (`sections/CombatDemo.tsx`) поверх одного справжнього кадру `SHOWCASE_MEDIA.combat`: 12-секундний цикл (ініціатива → кидок d20 → влучання → Вогняна куля з рятівними кидками → журнал). Увесь таймінг — один зареєстрований `--ld-p` (0→1, `landing-motion.css`, блок «Combat demo»), кожен елемент рахує свій стан із `--s` і власного `--t`; спокійне значення `--ld-p: 1` = фінал бою, тож reduced-motion, телефони (≤768px) і сторінка без JS бачать статичний кінцевий стан. Цикл іде лише на екрані: `PlayInView` (клієнтський, один IntersectionObserver) ставить `data-play`, CSS перемикає `animation-play-state`. Координати токенів/чипів/журналу — `ANCHORS` у `CombatDemo.tsx` (% кадру), їх треба переналаштувати при заміні скріну; портрети ворогів — `public/landing/demo-portraits.webp` (вирізані з того ж кадру). Під заголовком hero — скрін `HERO_SHOT` (`media.ts`, зараз `world`). Скріни продукту — `public/landing/screen-*.webp`.

**Як перезняти скріни** (`pnpm landing:screens --profile=<name> [--only=battle,hero]`, скрипт — `scripts/landing/capture-screens.mjs`, профілі й кадри — `scripts/landing/shots.json`). Профіль = `{ locale, db, campaignId, battleId?, scenePageId?, deckId?, heroId?, sheetId?, mapId?, uiLocale?, shots[] }`; плейсхолдери `{battleId}` тощо в `path`/`steps` підставляються з профілю, кадри з `TODO` пропускаються з попередженням (заповнити id з БД). Профілі: `en-srd` (БД `landingshots`, усе крім `hero`), `en-homm` (клон HOMM5, `hero`+`sheet`, UI en), `uk-homm` (клон HOMM5, усі кадри, UI uk). Текст кнопок у `steps` — рядок або `{en, uk}` за мовою UI (cookie `NEXT_LOCALE`). Знімає desktop 1920×1200 DPR 2 (4K, 3840 px) і phone 390×844 DPR 3 (1170 px), webp q82 (якщо 4K-кадр > 450 КБ — повтор з q76, потім q70) у `public/landing/<locale>/screen-<name>.webp`; лише localhost, порт 3140 (`--port`/`--base`), сервер `next start` скрипт піднімає сам на `profile.db` (порт має бути вільним). Підготовка (один раз): окрема локальна БД (`CREATE DATABASE landingshots` у контейнері `pnpm db:local`, `prisma migrate deploy`), рядок у `users` для вашого Supabase-id, `pnpm template import srd-5.2 --publish --allow-untranslated --owner <id>`, `pnpm seed:example-demo <id>` (усе з `DATABASE_URL`/`DIRECT_URL` на `landingshots`), потім у БД `update campaigns set kind='campaign', visibility='private' where id='example-demo-5e'` і рядок `campaign_members` (role `dm`) — інакше демо лишається read-only. Сесія: `pnpm landing:screens --login` (достатньо сервера на `landingshots`) відкриває звичайний Chrome з профілем `.landing-auth/` (Google не пускає в автоматизований браузер), після входу Enter — стан у `.landing-auth/state.json` (gitignore). Потрібна збірка `build:local` з `NODE_OPTIONS=--max-old-space-size=8192`; після перезасіву БД сервер перезапускається скриптом. Бій скидається й програється через API лише якщо в профілі є `battleId`. Ховає банер «No connection»/«Немає зв'язку», Next dev overlay і підказки. Після деплою Telegram кешує прев'ю — оновити через @WebpageBot.
- Шляхи лендінгу — `LANDING_PATH`/`LANDING_PATHS` у `lib/constants/site.ts`; їх читають проксі (без Supabase), `HeaderGate`, `Breadcrumbs`, метадані й sitemap. Нова мова = запис у `LOCALES` (`lib/i18n/config.ts`) і `LANDING_PATH` + `messages/<locale>/landing.json` + `app/<locale>/page.tsx`.
- Hero (`sections/Hero.tsx`): без панелі — текст ліворуч над мапою `vey-strait` (затемнення лише ліворуч, `.ld-hero-scrim`), нижче `.ld-below` додає затемнення секціям. Туман — `LandingFog.tsx`: у hero той самий WebGL2-шейдер хмар, що й на мапі світу (`acquireCloudMotion`, спільний refcount-контекст; єдиний WebGL на лендингу — виняток власника лише для цього шару, `mode.webgl`), кадр проходить через `coverClouds` (`lib/utils/canvas/fog/cloud-cover.ts`: найтемніша частка видимої області стає просвітами, ~65 % покриття, на телефонах ~45 %); без WebGL2 або при `useFogQuality() === 'flat'` — 2D `cloudTexture`. Стартує після `load`/idle, курсор «розганяє» туман маскою-слідом (destination-out, відновлення ~2 с); поза екраном — лише відписка від `ticker` (контекст лишається, без перекомпіляції шейдера при поверненні); прихована вкладка / unmount / втрата контексту — `release()`; `(pointer: coarse)` — без курсора, reduced-motion/`still` — один кадр `render(0)` і одразу release. Читабельність тексту дає `.ld-hero-scrim` (м’який темний градієнт під колонкою, ≥ 4.5:1), а не затемнення туману; полотно туману виходить за в’юпорт на ±56/40 px (паралакс курсора) і м’яко згасає донизу. Скрол: туман розходиться (`scroll(root)`), скрін бою випрямляється з нахилу (`view-timeline --ld-shot`); на ≤ 768 px і reduced-motion — статично.
- Хореографія секцій — `components/landing/landing-motion.css` (мотив «шлях загону мапою»): `TrailMark` (пунктирний слід + вейпоінт над заголовком секції), «чорнильне» проявлення h2 (`.ld-ink`, mask), Problem — розкидані нотатки збираються, Replace — рядки «вливаються» в золоту колонку, Combat — нахил демо + фішки ініціативи на різній глибині, Features — 3D-нахил карток за курсором (`trackTilt` у `PointerParallax`, `--tx/--ty`), Systems — кубики d20/d100/d6 (`Dice.tsx`) і лічильники (`@property --ld-n` + CSS counter, справжнє число в `sr-only`), Prep/AI/Players — розгортання, поява повідомлень, телефон, HowItWorks — намальований маршрут між кроками, FinalCta — туман (`LandingFog variant="final"`, завжди 2D `cloudTexture`, без WebGL; отвір у центрі) змикається навколо CTA. Combat — живе CSS-демо бою (`sections/CombatDemo.tsx`): сцена на кожну мову (`SCENES[locale]`: якорі в % кадру `showcaseMedia(locale).combat`, раунд, вороги; спрайти `public/landing/{en,uk}/demo-tokens.webp` з `scripts/landing/make-demo-tokens.mjs`), анімація лише transform/opacity і лише ≥ 1024 px (нижче — статичний фінал бою), журнал — плаваюча панель, записи від старих до нових, нові знизу. Після перезйомки кадру бою — переналаштувати `SCENES`. Усе — CSS scroll-driven у `@supports (animation-timeline: view())` + `prefers-reduced-motion: no-preference`; базові стилі = кінцевий стан (Firefox/reduced-motion — статично й видимо); 3D/глибина лише ≥ 769 px.
- Нижні секції — `.ld-lazy` (`content-visibility: auto`), щоб спрайти й картинки не вантажились до першої відмальовки. Шапка застосунку (`HeaderGate` → dynamic `Header`) і діалог `ConfirmProvider` — ліниві чанки.
- `experimental.inlineCss` у `next.config.ts` — CSS у HTML, без блокуючих запитів (діє на всі сторінки).
- SEO: `buildLandingMetadata(locale)` (canonical, hreflang en/uk/x-default, og locale) і `buildLandingJsonLd(t, locale)` (WebApplication + FAQPage) у `components/landing/landing-metadata.ts`, сторінки `app/page.tsx` і `app/uk/page.tsx`; `app/sitemap.ts` — обидві URL з hreflang; `app/robots.ts`. Індексація вимкнена, доки не задано `SITE_INDEXING=1`; домен — `NEXT_PUBLIC_SITE_URL` (`lib/constants/site.ts`).
- Скріни — `public/landing/{en,uk}/screen-*.webp`, шлях дає `showcaseMedia(locale)` (`media.ts`); hero — `dashboard`, Features — 6 карток із кадрами (редактор мап на лендингу не показуємо).
- Lighthouse: цифри для старого лендінгу (desktop 100/100/100/100, mobile 91/100/100/100) — для v3 не перемірювано.

## Авторизація

- Способи: Google OAuth і email + пароль (Supabase Auth, підтвердження пошти обов'язкове).
- Тексти екранів — `messages/{uk,en}/auth.json`. Екрани (`components/auth/AuthScreens.tsx`): `/sign-in`, `/sign-up` (→ «Перевірте пошту» + повторний лист), `/forgot-password`, `/reset-password`; налаштування `/settings/password` (Google-користувач може додати пароль). Supabase-виклики — лише в `lib/hooks/auth/useEmailAuth.ts`; схеми — `lib/schemas/auth.ts`; тексти помилок за кодами Supabase — `AUTH_ERRORS` у `lib/constants/auth.ts`.
- `/auth/callback` приймає всі посилання: OAuth `code`, листи (`code` для PKCE або `token_hash` + `type`). `next` — лише внутрішні шляхи (`safeNextPath`); recovery → `/reset-password`, помилки recovery → `/forgot-password?error=…`. Тут же `ensureDbUser` створює рядок `users` (ім'я з `user_metadata.full_name`).
- PKCE: посилання з листа треба відкрити в тому ж браузері (інакше `flow_state_not_found` з поясненням).
- Налаштування Supabase (вручну): власний SMTP (вбудований шле лише учасникам команди проєкту), Redirect URLs `https://<домен>/**` і `http://localhost:3000/**`.
