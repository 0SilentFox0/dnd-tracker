# Battle data flow

The most complex part of the app. Related: [balance.md](balance.md), [map-modes.md](map-modes.md), [abilities.md](abilities.md).

## Page → mutation

Page `app/campaigns/[id]/battles/[battleId]/page.tsx` (server: `userId` from `getClaims`, the scene from `readBattleScene` — the same code as `GET /` — seeded into the query cache with `PrefetchedQuery`, so the first HTML has the battle and the client does not GET on mount) → `BattlePageClient` → `useBattleSceneValue` + `BattleSceneProvider` (`lib/hooks/battle`, read with `useBattleScene()`) → `BattleScreen` (`components/battle/scene`: mobile layout < 1024 px, desktop three columns ≥ 1024 px) → mutations: `useX = makeBattleHook(battleOps.x)` (`lib/hooks/battles`, through `useBattleAction`; per-operation defaults `invalidate`/`retryOnConflict`/`mapResponse` live in the registry) → `callBattleOp` over the `battleOps` registry (`lib/api/battle-ops.ts`; a new operation = one registry row + one hook line + its `BattleSceneActions` instance) → route in `app/api/campaigns/[id]/battles/[battleId]/<action>/route.ts`.

## Читання сцени

`readBattleScene` (`lib/server/battles/read-battle.ts`) — окремий read-path без фейкового `Request`: сесія → `loadBattle` → 404/403 → `readScenePreview` (`lib/utils/battle/pipeline/run-battle-mutation.ts`: ті самі нормалізації, що отримала б порожня мутація — порядок ходу, чистки, перемога, — без rate limit і запису) → повна сцена з останніми подіями й `knowledge`. Читання, як і раніше, іде через `deps.withWrite` (серіалізація із записами кампанії, помилка `CAMPAIGN_NOT_FOUND`). `readBattleVersion`/`readBattleEvents`/`readBattleSummary` діляться `authorize` і `BattleReadDeps`.

## Клієнтська сцена

- `useBattleScene` (`lib/hooks/battle`) складає значення сцени з `derive-scene` (`lib/utils/battle/view`, чиста похідна: черга, склад сторін, глядач) і `useBattleActions` (мутації з реєстру `battleOps`; з барелю не експортується). Типи: чисті (`ResultFx`, `StrikeFx`, `ActionResultFx`, `BattleLogState`, `BattleSceneTurn/Roster/Result`) — у `types/battle-scene.ts` без імпортів хуків; типи, що залежать від хуків (`BattleSceneValue/Data/Actions/Intents/Dialogs`) — у `lib/hooks/battle/types.ts`.
- `BattleMap` (`components/battle/map`) — оболонка: `MapStage` (жести, масштаб, шари), `MapLayers` (сітка, токени, накладки), `RangedHint` (підказка дальнього пострілу), `useStrokePaint` (малювання місцевості, `lib/hooks/battle`). Вид карти складає `composeMapView` (`lib/utils/battle/grid/map-compose.ts`).

## Дії асистента над боєм

`lib/server/battles/action-service.ts` — таблиці замість ланцюжків `if`: `COMMAND_CHECKS` (передперевірки команд `attack`/`spell`; пошук лише через `Object.hasOwn`), `OPERATIONS` (`operations.ts`, доступ `BattleAccess.*`). Нова команда з передперевіркою = рядок у `COMMAND_CHECKS`.

## Mutation pipeline

Every battle route is a Zod schema + `runBattleMutation` (`lib/server/battles/run-mutation.ts`, pure engine in `lib/utils/battle/pipeline/`) with a `<action>-mutation.ts` in `lib/server/battles/mutations/<action>/`. The pipeline:

- does auth (`getClaims`);
- loads the battle in one query (`lib/utils/battle/store/loadBattle`). Participant snapshots — ~75 % of the bytes — come from a per-instance content-addressed cache keyed by `snapshotHash`, and only misses are read, so **anything writing `battle_participants.snapshot` must write its `snapshotHash` too**, as `saveBattle` does;
- checks access (`dm` / `turnController` / `currentController` / `member`) and status;
- runs `mutate` (pure engine code from `lib/utils/battle/*`, `lib/utils/abilities/*`), checks victory once;
- saves with an optimistic `version` lock (`saveBattle`: changed `battle_participants` rows in one `UPDATE … FROM (VALUES …)` without reading rows back, append-only `battle_events`, `battle_snapshots` for rollback — pruned to the last 20 when the battle completes);
- answers `{ delta, response? }` (`ClientBattleDelta` from `pipeline/client-delta.ts`: new participants and those whose snapshot changed go in `upserted`, the rest as `patched` with only the column/state fields from `PATCHABLE_PARTICIPANT_FIELDS`);
- sends Pusher `battle-delta` (or `{ refetch: true }` above 9 500 bytes) after the response (`after()`).

`GET /` and `dryRun` still return the full `BattleScene` with the last 30 events; older ones come from `GET /events?before=<seq>` («Показати раніші», `useBattleLogHistory`), and `GET /?versionOnly=1` answers `{ version }`.

## Turn advance

One engine: `lib/utils/battle/turn/advanceTurn` (used by next-turn and attack with `endTurn`).

## Client cache

`applyBattleDelta` (`lib/utils/battle/client`) patches the cached `BattleScene` (old version ignored, gap or patch for an unknown id → one GET). After a Pusher gap or a tab hidden > 15 s, `usePusherBattleSync` asks for the version and refetches only when it is newer. `useBattleAction` sends `expectedVersion`; 409 → refetch + battle toast. `actionIndex` in the client log is the event `seq` (rollback target).

## Player UI logic

Wizards (attack, spellbook, player turn) are reducers in `lib/utils/battle/flows` driven by hooks in `lib/hooks/battle`. What a player may see (health states instead of enemy HP, AC known from attacks, observed traits from `actionDetails.damageSteps`, turn queue with morale extra turns) is `lib/utils/battle/view`. Hiding is client-side.

## Attack: cover, chain shot, cleave

- **Cover** is computed by the server (`grid/line-of-fire.ts`) per target of a ranged attack: a living, non-airborne participant, `wall`/`barrier`, `blocked` cells, or a mode wall (`lineBlocked`) on the line. Not applied to melee, chain jumps or secondary targets of piercing shots. The wizard and the map show the same result.
- **Target limit**: `attack/max-targets.ts`, shared by client and server; auto-targets (chain, cleave, piercing, hits-all) are outside it.
- **Chain shot**: ability flag `chainShot` (`attack/process/chain.ts`) — the player picks one target, the server jumps to the nearest enemy in range (`grid/nearest.ts`) from the previous target's cell.
- **Cleave**: a melee attack with `maxTargets > 1` (`attack/process/cleave.ts`) also hits enemies adjacent to both attacker and target; the server rolls d20/damage for them (`attack-phase/targets.ts`).
- **FX**: `originId` on a spec is where the projectile starts (chain jumps); secondary victims get a splash spec (`fx/impact.ts`); the queue is trimmed by whole actions. The result card lists every target (`view/volley-results.ts`).

## 5e: стани, рятівні кидки, смерть, концентрація

Усе вмикається в `rules` кампанії (`saves.proficiency`, `deathSaves`, `concentration`, `conditions`; default — поведінка HOMM5 без змін, бій читає зафіксовану копію `battle.rules`). Стани 5e рушій обробляє незалежно від `conditions.enabled` — вони приходять лише з даних.

- **Стани** (`lib/utils/battle/conditions/`): `CONDITION_5E_REGISTRY` — стан → наявні маркери (`skip_action`, `immobilized`, …) + прапорці `abilityEffects` (`implies` розгортає, напр. paralyzed → incapacitated). `applyCondition5e` пише один `ActiveEffect` (`type: "condition"`) з маркерами й прапорцями, враховує `conditionImmunity` (перевіряється лише ключ, що накладається). Читання/зняття — `query.ts`: `hasCondition`, `conditionSourceIds`, `removeCondition5e`. **Зняття ефектів — лише через `removeEffects`** (повертає зняті ефекти; після нього синхронізується виснаження та HP).
- **Виснаження**: ефекти беруться із сумарного рівня (`syncExhaustion`), варіант 2014/2024 зберігається на самому ефекті (з `rules.conditions.exhaustion` на момент накладання); повторне накладання додає рівні до 6 (на 6 — смерть); 2014 рівень 4 ділить макс. HP, `restoreExhaustionHp` повертає його при знятті.
- **Рятівні кидки**: `rollSave` (`lib/utils/battle/saves/`) — автопровал, перевага/перешкода (`saveAdvantage`/`saveDisadvantage`, `vsSpells`, виснаження), бонус = модифікатор + майстерність (`saveProficiency` або `Character.savingThrows` при `saves.proficiency`) + стат `savingThrow`; `presetRoll` клієнта — перший d20. `rollSave` викликають заклинання, маневри, концентрація, `saveEnds`. `rollSaveEnds` — повторні кидки ефектів з `saveEnds` наприкінці ходу цілі (проти СК накладача, успіх знімає стан).
- **Наслідки шкоди**: кожен примітив шкоди → **одразу `applyDamageConsequences`** (`damage/consequences.ts`): юніти падають у `dead` на 0 HP (`unitsDieAtZero`), герой на 0 HP стає `unconscious` + `battleData.deathSaves`, масивна шкода, провал кидків смерті від шкоди (крит = 2), перевірка концентрації. У флоу заклинань/атак це робить `applyFlowDamage` (`common/action-flow.ts`). Без правил (`rules` не задано) або з вимкненими механіками повертає `after` без змін. `settleStatusChange` — ті самі наслідки для ручних змін ДМ (HP, воскресіння, вбивство).
- **Кидки смерті** (`lib/utils/battle/death-saves/`): d20 кидається в циклі пропуску ходу (`processEndOfTurn`) для непритомного нестабільного героя; 10+ успіх, 1 — два провали, 20 — 1 HP і прихід до тями; 3 успіхи — `stable`, 3 провали — `dead`. Лікування знімає стан `unconscious` і скидає лічильники. Лічильники — у `battleData.deathSaves` (кружечки в картці учасника). Герой при смерті (`isDying`: `UNCONSCIOUS` + `deathSaves`) не вважається полеглим (`isFallen`): зберігає ефекти, лишається на клітинці мапи й може бути ціллю ворожої атаки (`isAttackable`). HOMM-учасники без `deathSaves` поводяться як раніше.
- **Концентрація** (`lib/utils/battle/concentration/`): прапорець зберігається в існуючій колонці `Spell.concentration` (не в JSON `definition`). Каст створює на кастері ефект «Концентрація: …» (`concentration: { castId }`), а ефекти й зони цього касту — тег `concentrationOf`; новий каст спершу знімає попередню (`beginConcentration`, `dropConcentration`). Шкода → `concentrationCheck` (Вит проти `max(10, ⌊шкода/2⌋)`, межа `dcCap`); провал, недієздатність, смерть, 0 HP — концентрація зникає з усіма ефектами. **Зони згасають лениво**: `isZoneConcentrationLive` — зона скинутої концентрації просто перестає діяти, не видаляючись одразу. `castId` унікальний на каст: `uniqueCastId` (`castIdFor(caster, spell, round, seq)`, перший вільний `seq`; зайнятим вважається id у зонах мапи, inline-учасниках, грантах, ефектах) — а не довжина логу. Носії концентрації, крім ефектів: зони й небезпеки мапи (`spellZones`, `TerrainDamage.concentrationOf`), предмети (`battleData.object`), гранти (`grants[].concentrationOf`, до `expiresRound`), перетворення (`transform.concentrationOf`); `dropOrphanedConcentration` скидає маркер `tracksEffects`, коли жодного носія не лишилось. Схема бою обмежує id довжиною `SPELL_ID_MAX = 200` (`lib/schemas/battles.ts`).
- **Роут `conditions`** (`POST …/battles/[battleId]/conditions`, Zod `apply|remove` + `runBattleMutation`): лише ДМ (`BattleAccess.DM`), бій `ACTIVE`, не дозволений, поки чекає рішення ДМ про перемогу (`awaiting_dm`). UI — `components/battle/dm/ConditionsDialog.tsx` (меню станів у швидких діях ДМ).

## 5e: базові дії

Вмикається `rules.actions` (`{ enabled: false, opportunityAttacks: true, variant: "2014" | "2024" }`); `enabled: false` — жодних кнопок і атак при відході, HOMM без змін. Рушій у `lib/utils/battle/actions/`.

- **Каталог**: `CORE_ACTION_REGISTRY` (`registry.ts`) — `dash`, `disengage`, `dodge`, `help`, `hide`, `ready`, `standUp`, `grapple`, `shove`, `escape` (підпис, вартість, тип цілі). `validateCoreAction` / `coreActionAvailability` (`availability.ts`) — єдине джерело причин відмови для сервера й діалогу.
- **Роут `core-action`** (`POST …/battles/[battleId]/core-action`, Zod `discriminatedUnion("action")` + `runBattleMutation`, `BattleAccess.MEMBER`, `blockedByMode`): `core-action-mutation.ts` перевіряє права й хід, `runCoreAction` (`run.ts`) — чистий рушій. Керує власник учасника або ДМ. Виняток — `readiedAttack`: **реакція поза ходом**, доступна керівнику й ДМ у будь-який момент.
- **Ефекти** (`effects.ts`): «Відхід» (маркер `disengaged`), «Ухилення» (`disadvantageForAttackers` + перевага СПР; згасає з недієздатністю чи швидкістю 0), «Допомога» (перевага на одну атаку), «Схований» (маркер `hidden`, знімається після атаки/заклинання). Ключ — `coreTimedKey(action, participantId)`.
- **Рух**: Ривок додає базовий рух (`baseMovement` + `battleData.extraMovement`, `grid/path.ts`); `standUp` коштує половину базової швидкості й неможливий при швидкості 0. Без мапи дії руху лише пишуться в лог.
- **Реакції** (`reaction.ts`): `reactionBlocker`/`canReact` — витрачена реакція, недієздатність, `no_reaction`.
- **`rollCheck`** (`checks/roll-check.ts`): `rollCheck`, `checkBonus`, `passivePerception` — навичка чи характеристика, майстерність, `checkAdvantage`/`checkDisadvantage`, виснаження. «Сховатися» — Скритність проти найбільшої пасивної Уважності ворогів. Ту саму функцію візьме 4d.
- **`resolveServerAttack`** (`attack/server-attack.ts`): серверна ближня атака без гравця, спільна з HOMM-відплатою (`retaliation`); мітки `retaliation | opportunity | readied`.
- **Атаки при відході** (`opportunity.ts`, `movement.ts` → `resolveMovement5e`, викликається з `move-mutation`): шлях будує сервер (`pathTo` у `grid/path.ts`, один BFS, той самий граф, що `reachable`). Атаки автоматичні (реакція ворога, ближня атака), провокує вихід із досяжності; `disengaged` блокує; якщо мувер падає — рух зупиняється в цій клітинці. Рух ДМ у режимі розстановки не провокує.
- **Схоплення** (`grapple.ts`, `conditions/grapple-links.ts`): зв'язок — ефект `grappled` з ключем `core:grapple:<grapplerId>`. 2014: змагання Атлетики з більшим з Атлетики/Акробатики; 2024: рятівний кидок проти СК. `shove` — `prone` або відштовхування на 5 фт (якщо клітинка вільна). `escape` знімає зв'язок. Рух схоплювача тягне ціль у звільнену клітинку (`planDrag`) і коштує подвійно. **Зняття зв'язків** — `releaseInvalidGrapples` у пайплайні (`run-battle-mutation.ts`) після кожної мутації: схоплювач упав/недієздатний/не суміжний → ціль вільна.
- **Хід**: у 5e хід не завершується автоматично, поки на мапі лишається рух (`view/turn-exhausted.ts`).
- **UI**: `components/battle/turn/CoreActionsDialog.tsx` (плитка «Дії» в `ActionGrid`), `ReadiedAttackButton.tsx` (картка учасника з `readied`, поза ходом), хук `lib/hooks/battle/useCoreActions.ts`, клієнт `lib/api/battles`. Вкладка «Дії 5e» на `dm/rules`.
- **OpenAPI**: бюджет тесту розміру збільшено до 120_000.

## 5e: класи й рівні

Вмикається `rules.classes { enabled: false }`; без нього і для персонажа з порожнім `classes` — шлях HOMM без змін (архетип, HP за формулою, слоти раси). Чисті функції — `lib/utils/characters/classes/`, слоти — `lib/utils/spells/class-slots.ts`.

- **Дані персонажа**: `Character.classes [{ classId, subclassId?, level }]` (перший запис — стартовий клас). Змінює лише ДМ; при вимкнених правилах — 422. Сервер виводить `level` (сума), текстові `class`/`subclass` і `spellSlots` (`apply-classes.ts`, `applyClasses`; для порожнього списку повертає `data: null` і пише лише `classes: []`). Невідомий `classId` пропускається.
- **Режим класів у бою** — лише якщо розв'язано ≥ 1 запис класу (`resolveClassEntries`); інакше (усі невідомі) учасник збирається по-HOMM-івськи. Архетип ігнорується (множники 1).
- **HP** — середнє за кістками: 1-й рівень стартового класу — максимум кістки + мод. Тіл, далі `кістка/2 + 1` + мод. Тіл, мінімум 1 за рівень; нічого не зберігається.
- **Рятівні**: стартовий клас ∪ ручні `Character.savingThrows`.
- **Слоти** (`classSpellSlots`): рівень заклинача = Σ (`full` — рівень, `half`/`third` — ⌊·⌋; єдиний клас — ⌈·⌉ з 2-го/3-го рівня), таблиця мультикласу 5e → кола 1–9; пакт — окремо за рівнем класу `pact` (кілька різних pact-класів сумують рівні). Слот пакту — `spellSlots.pact { level, max, current }`; `spellSlotKey` для каста кола N бере слот кола N, а якщо немає — пакт з колом ≥ N. Вибір слота й підсилення вищим колом — 4c-2.
- **Вміння**: джерело `class` (див. [abilities.md](abilities.md)); `limits.perRest` = `perBattle` до 4d.
- **Кола заклинань 0–9** по всьому стеку (Zod, форми, `SlotGrid`, `.circle-0…9`); кантрип = коло 0. Обмеження HOMM (раса 1–5, крива до рівня 10, відкриття кіл школою) лишаються даними HOMM.
- **Підвищення рівня** (`POST …/level-up`, ДМ): у режимі класів тіло `{ classId, subclassId? }` — наявний клас або мультиклас; підклас обов'язковий на `subclassLevel` і заборонений раніше; `campaign.maxLevel` — на суму; випадкового +1 до характеристики немає; слоти перераховуються.
- **Карта класу**: `buildClassProgression` (`lib/utils/characters/classes/progression.ts`) — чиста функція, що з `GameClassData` (+ рівень героя) будує `ClassProgression` — рядки по рівнях з пунктами `ProgressionItem` (вміння з описом, підклас, вибори, колонки чисел, open-вибір). Рендерить `ClassProgressionMap` (`components/classes/progression/`) у трьох місцях: вкладка «Карта» у `ClassForm` (ДМ, `onOpenLevel` веде до вкладки вмінь/підкласів), `SkillsTab` листа героя (`sheet.classProgression`, поточний/наступний рівень і невибрані вибори) та діалог `ClassLevelUpDialog`. Вибір підкласу з листа не робиться — лише через level-up.

## 5e: атаки й заклинання

Режим 5e для героя вмикає `abilities.damageModel: "5e"` (`from-character.ts`, коли клас резолвиться); без нього — HOMM-шкода, кидки й валідація без змін (герой кампанії з `classes.enabled`, але без класів, лишається HOMM).

- **Характеристика й модифікатор** — `lib/utils/battle/attack/ability.ts` (`isFiveE`, `hasTrait`, `attackAbilityFor`, `attackRollModifier`, `attackDamageModifier`). Формула шкоди 5e = кубик зброї (+ кубик `versatileDice`, коли клітинка «Щит» порожня) + модифікатор; без кубиків героя й рівня. Метальна зброя лишається ближньою. Безоружний удар героя 5e (`default-melee`) = плоска «1» + Сил; дальня атака без зброї лишається без кубиків (лише модифікатор).
- **Властивості зброї** (`lib/constants/weapon-traits.ts`): `light`, `finesse`, `twoHanded`, `versatile`, `reach`, `thrown`, `ammunition`. У артефакті — модифікатор `traits` (рядок через кому) + `versatileDice`; у юніта — поля атаки. Текстове `properties` — лише примітка.
- **Досяжність і дальність** — `grid/attack-reach.ts`: `meleeReachCells` (2 клітинки зі зброєю `reach`), `rangeBands` («80/320»), `rangeDisadvantageReasons` (`bonus.ts`: «Далека дистанція», «Ворог поруч»). Атаки по можливості (`actions/opportunity.ts`) використовують ту саму досяжність.
- **Додаткова атака** — стат `attacksPerAction`; `attack/attacks-left.ts` (`spendAttack`, `canAttackFromPool`, `attacksLeft`, `attackedWithLight`). Атака з лічильника не витрачає ні дію, ні пул HOMM `pendingExtraActions`; захоплення/штовхання беруть з того ж пулу; скидання — `turn/turn-state.ts`.
- **Друга рука** — `offHand: true` у запиті атаки: бонусна дія, легка ближня зброя з клітинки «Щит» (`hand: "off"`, id `<id>:off`), потрібна попередня атака легкою; без прапорця `twoWeaponFighting` модифікатор шкоди не додається. `canEquipOffHand` (`lib/utils/artifacts/off-hand.ts`) перевіряє вдягання (stash і `update-inventory`, лише змінена клітинка щита); помилки `OFF_HAND_*` у `api-errors.ts`.
- **Криті** — `rules.criticals.doubleDice`: сервер (`attack/crit-dice.ts`) докидає відсутній другий набір кубиків і позначає його в лозі; без прапорця прев'ю лишається ×2 (HOMM).
- **Заклинання**: `casterSpellDice(caster, spell, castLevel?)`, кантрип масштабується `spellDice5e` (×1/2/3/4 на рівнях 1/5/11/17), підсилення слотом — `upcastDice` на крок і `upcastTargets` (одиночна ціль: 1+N×кроків; площа/шаблон: `maxTargets`+N×кроків). Слот обирається `slotKey` у запиті касту (`spell/slot.ts`, `resolveChosenSlot`; нижче кола, порожній чи відсутній слот → 422; HOMM-герой із `slotKey` = автовибір). `castLevel` пишеться в `actionDetails` лише за явного вибору слота. Запитний `castLevel` діє лише з грантом предмета (`upcast`); без гранта ігнорується, рівень визначає слот. Підпис у логу каста: `шкода: N (Ім'я a, Ім'я b)` — сума за всіма зачепленими істотами з розбивкою, коли їх кілька.
- **Атака заклинанням** — `resolution: "attack"`: кидок проти AC (`attackRolls` у запиті), крит додає кубики з `doubleDice`; цілі не-вороги — автоматично.
- **Володіння бронею й зброєю** (`lib/utils/battle/proficiency/`): `abilities.proficiencies { armor, weapons }` — вільні рядки першого класу SRD (є лише в героя 5e з непорожніми списками; без поля — жодних перевірок), розбір за ключовими словами. Мартіал/сімпл береться з опису предмета (`BattleAttack.weaponCategory`; невідомо = володіє): без володіння атака не додає майстерність (`calculateAttackBonus`). Броня/щит без володіння (`armorPenalty`): перешкода на Сил/Спр атаки, перевірки й рятунки (`rollModeReasons`, `rollCheck`, `rollSave`) і заборона каста (`spell-mutation`). Раси й риси (Lightly/Heavily Armored…) поки не враховуються.
- **Ініціатива** — `rules.initiative.mode` (`static` за замовчуванням, SRD-пресет `roll`): `calculateInitiative(p, all, { rules, rng })` на старті бою і при додаванні учасника; `roll` = d20 + мод. DEX + запечені бонуси (`abilities.initiativeBonus`), «завжди перший» (≥1000) лишається статичним.
- **Відсіч HOMM** — `rules.actions.retaliation` (default `true`, SRD-пресет `false`): вимкнено — ціль не відповідає й не витрачає реакцію (провокована критом відсіч лишається).
- **Шкода вмінь при влучанні** (Sneak Attack тощо, `attack/process/hit.ts`): різниця HP цілі навколо події `hit` додається в `damageBreakdown` рядками «Вміння: +N», у `totalDamage`/`hpChanges`/`finalDamage`.
- **Cunning Strike**: the attacker may forgo Sneak Attack dice for a rider effect; the choice reaches the engine as `cunningDice` on the `hit` event (`attack/process/hit.ts`), and the Sneak Attack effect (`registry/effects/hp.ts`) subtracts those dice from its damage roll.
- **UI**: лічильник «Атака N/M», «Атака другою рукою» у `BonusActionPicker`, вибір слота в `SpellCastDialog` (лише 5e), d20-поля для атаки заклинанням.

## 5e: поза боєм

Усе керується `rules.outOfCombat` (`persistResources`, `longRestHitDice`, `xp`, `inspiration`); за замовчуванням вимкнено, від `classes.enabled` не залежить. Вимкнене правило → 409 на відповідних роутах.

- **Зберігання** — `characters.resources` тримає витрачене (`lib/utils/characters/resources/`: `schema` з толерантним `readResources`, `hp` — `currentHp`/`withHp`/`compactResources`), `characters.inspiration`; журнал `character_logs` (`writeCharacterLog` у `lib/server/characters/log.ts`, види — `lib/constants/character-log.ts`).
- **Старт бою** — `createBattleParticipantFromCharacter` → `applyCharacterResources` (HP з обрізанням, 0 HP → непритомний/умирає, `dead`, слоти й пакт, заряди `perRest` → `abilityUsage`, виснаження через `applyCondition5e`, `battleData.inspiration`); той самий шлях використовують лист і баланс.
- **Завершення** — `saveBattle` (гілка `completing`) → `persistCharacterResources` (`store/persist-resources.ts`): лише герої в полі, один раз на `sourceId`, журнал `battle_result`; натхнення записується назад лише коли витрачене (`inspirationSpent`). Перемога при `persistResources` повертає непритомних з 1 HP (`completeBattle(…, rules)`). Відомо: відкат завершеного бою повторно виконує запис (зайвий рядок `battle_result` у журналі).
- **Роути** — `POST /rest` (ДМ), `…/hit-dice`, `…/roll` (власник або ДМ, `rollCheck`/`rollSave` з `advantage`), `POST /experience`, `…/inspiration`, `PATCH …/resources` (ДМ), `GET …/log`.
- **Блокування під час бою** — `lib/server/characters/battle-lock.ts` (`assertNotInActiveBattle`): герої на мапі чи в резерві активного бою → кидає `ContentError` 409 `CHARACTER_IN_BATTLE` для відпочинку, кісток хітів, натхненного кидка, правки ресурсів і видачі натхнення (досвід дозволено). Інакше запис після бою перезаписав би правки.
- **Паралельність** — read-modify-write іде в транзакції з `lockCharacters` (`lib/server/characters/lock.ts`, `SELECT … FOR UPDATE` по відсортованих id).
- **Натхнення в атаці** — `useInspiration` → причина переваги «Натхнення» в `rollModeReasons` (лише перший удар), знімається в мутації; клієнт — `SET_INSPIRATION` у майстрі атаки.

## 5e: монстри

- Юніт з `cr` (`isMonster5e`, `lib/utils/units/monster.ts`) у `createBattleParticipantFromUnit`: `damageModel: "5e"`, СК = `saveDcBase` + майстерність + найкращий мод. Інт/Мдр/Хар (`spellcastingAbility` — ця характеристика), `saveProficiencies` (читає `rollSave` за `rules.saves.proficiency`), мультиатака — синтетичне пасивне вміння `unit:<id>:multiattack` (`modifyStat attacksPerAction`), `basicInfo.xp` (`unitXp`), `battleData.legendary { actions, actionsLeft, resistLeft }`. Юніт без `cr` — нульова зміна (HOMM5).
- Легендарні дії: тіло `{ action: "legendary", participantId, option }` роуту `core-action` (`legendary-mutation.ts`), лише ДМ, поза ходом монстра, не залежить від `rules.actions`. Атака — `legendaryAttack` (`actions/legendary.ts`) → `resolveServerAttack` (`label: "legendary"`, одна атака); вміння — `limits.legendaryCost` через `runAbilities` подією `action`. Відновлення — у `resetTurnState`. UI — `LegendaryActionDialog` (кнопка-корона в панелі ДМ), значок `legendaryBadge`.
- Легендарна атака, як і підготовлена, не запускає тригери до/після атаки і HOMM-відповідний удар (властивість `resolveServerAttack`): HOMM-юніт, по якому влучила легендарна ближня атака, не відповідає.
- Легендарний опір: `resolveSave` (`saves/legendary.ts`) у заклинаннях (лише ціль з іншого боку), концентрації, `saveEnds`, Схопленні/Штовханні 2024, Вогняному вибуху; лист не зачіпає.
- Дії лігва — вміння `roundStart` + `perRound: 1`.
- Заговори монстра масштабуються з `unit.level` (`spell/caster-dice.ts`), а не з CR: монстр CR 10 із `level: 1` кидає заговори в один кубик. Заклинання монстра поза межами 4e — ДМ виставляє `level` під потрібний масштаб.
- Авто-досвід: `completeBattle` додає «⭐ Досвід: N кожному», `saveBattle` (гілка `completing`) → `persistBattleXp` (`store/persist-xp.ts`: `battleXpAward`, `lockCharacters`, журнал `xp` з `battleId`). Лише перемога, `encounters.autoXp && outOfCombat.xp`; відкат завершеного бою повторює нарахування (як запис ресурсів 4d).

## 5e: броня, числа класів, пули (етап 4f-2)

- **КЗ героя з класами** — `lib/utils/characters/classes/armor-class.ts`: після `bakePassives` `applyClassArmor` пише в `combatStats.armorClass` базу: вдягнений артефакт зі `armor` у клітинці «Броня» → `base + min(мод. Спр, межа)` (межа за категорією: легка — без межі, середня — 2, важка — 0; `dexCap` перекриває), інакше `10 + мод. Спр`. `Character.armorClass` у режимі класів не читається; HOMM-герой і герой без класів — без змін. Щит, Unarmored Defense, Shield, магічні +N — `modifyStat armor` через `collectModifiers`. Наслідки броні — синтетичне вміння `armor-penalties` з джерелом-артефактом: `checkDisadvantage stealth` і −10 швидкості при Силі нижче вимоги (швидкість змінюється одразу, бо запікання вже минуло). Лист показує розклад (`armorTotal` → `classArmorBase`), форма персонажа в режимі класів — КЗ лише для читання.
- **Статичні умови** — `armorWorn` (`isStaticCondition`): `bakePassives`/`bakedStatSources` і перевірка вміння дозволяють її на запечених статах (Unarmored Movement, Fast Movement).
- **Числа класу** розв'язуються при збиранні (`applyClassScale` у `classResolved`, `lib/utils/abilities/class-columns.ts`): `{ scale }` → значення колонки на рівні в цьому класі (у `Flat`/`perRest.uses` — число, у `Amount` — число або кубики), `class_level` у формулах → рівень класу, `limits.pool.key` → `pool:<classId>:<key>`. Формульні `perRest.uses` — після запікання (`resolveLimitFormulas`, мінімум 1). Рушій бачить звичайні числа; нерозв'язане — 0 / вміння недоступне.
- **Пули** — `battleData.pools: Record<key, { label, max, rest }>` (`classPools`), лічильник `abilityUsage[poolKey].battle`; `withinCountLimits`/`recordUse` враховують `limits.pool { key, cost }`; нестача — відмова `ABILITY_POOL_EMPTY`, вміння зникає з вибору; плитка й картка героя показують залишок. При `persistResources` пул переживає бій у `resources.charges[poolKey]` і скидається відпочинком за `rest` колонки.
- **Події атаки** `hit` і `attack` (after) несуть `rollMode` (лише перевага/недолік) — для умов `attackRollMode` і `allyAdjacent` (Sneak Attack). **`evasion`** — рятівний Спр з половиною: успіх 0, провал половина; не діє на недієздатного (`spell/cast/outcome.ts`, `maneuvers/fire-burst.ts`).

## Інгредієнти заклинань

- **Правило** `rules.spellIngredients { enabled, autoPay }` (default вимкнено). Заклинання має `ingredients` (`SpellIngredient[]`, `focus: true` не відстежується) і `componentFlags`; герой отримує `battleData.ingredientStock` (`buildIngredientStock`, `from-character.ts`, лише для героїв під контролем гравця, коли правило ввімкнене; DM-персонажі/NPC не перевіряються; порожній інвентар дає порожній stock): мінімальний набір, бо бойовий стан бачать усі глядачі — лише предмети `SpecialItem` (`worthGp`, `ingredient`) без `artifactId`, гаманець у мідних лише при `autoPay` (інакше `purseCp: 0`). Це scoped-стан, не snapshot (`store/split-participant.ts`), тож списання не чіпає `snapshotHash`; `refresh-from-source` зберігає `used`/`usedCp`.
- **Перевірка** — `ingredientsGate` (`lib/utils/battle/spell/ingredients.ts`) у `createSpellMutation` після вибору слота й до гілки long-cast: чистий `planIngredients` (`lib/utils/spells/ingredients/plan.ts`: найдешевший придатний предмет з `worthGp >= minGp`, доплата з гаманця при `autoPay` лише для витратних; невитратні (`consumed: false`) мають лише бути в наявності: не списуються, без доплати, бракує — відмова). Нестача — `BattleRuleError` `BATTLE_SPELL_INGREDIENTS_MISSING` (422, `{ list }`) без жодної зміни стану. Пропускають: `free`-каст ДМ, гранти, легендарні дії, учасники без stock (юніти, DM-персонажі/NPC). `toCastableSpell` читає `ingredients` терпимо (`readStoredIngredients`: невалідні елементи відкидаються, перевірка не вимикається). Імена ключів без початкового артикля (a/an/the).
- **Списання** — `finalizeCast` (`spendIngredients` + рядок логу `battleLog.spell.ingredientsSpent`); прев'ю й початок long-cast нічого не списують. При завершенні бою `persistIngredients` (`store/persist-ingredients.ts`, та сама транзакція `saveBattle`, лише з `persistResources`) зменшує кількість предметів і гаманець героя та пише `inventory_log`.
- **UI** — `useIngredientPlan` (мемо `planIngredients` по `ingredientStock` і правилу з `scene.battle.rules`) → `IngredientsLine` у підсумку `SpellCastDialog` («Потрібно / Бракує / буде сплачено N gp»), кнопка «Застосувати» блокується при нестачі (сервер лишається арбітром). `BookSpell` несе `ingredients`/`componentFlags`; `SpellComponentsLine` (картки заклинань) показує «V S M · інгредієнти» без «бракує», або старий рядок `components`, коли `componentFlags` порожні.

## 5e: магічні предмети (етап 4f-3)

- **Ref предмета.** Значення `character_inventories.equipped`/`stash`/`attuned` — `"<artifactId>"` або складений `"<baseId>+<propertyId>"` (`lib/utils/items/ref.ts`). Єдиний вхід для читачів — `resolveItemRow(s)` (`lib/utils/items/resolve.ts`): розбирає ref, складає синтетичний рядок `composeItemRow` (id = ref, назва за шаблоном властивості, статі бази + `overrides`, `bonuses`/`damageBonus` — сума, уміння бази ++ уміння властивості з префіксом `p-`), тихо пропускає видалене. Тест-сторож `lib/__tests__/item-readers-guard.test.ts` не пускає нових читачів `.equipped`/`.stash` повз `lib/utils/items`.
- **`rules.items.enabled`**: предмети слотів `item`/`ring` зі сховища носяться (`activeItemRefs`, `carried`), налаштування (`attuned`, ліміт `attunementLimit`) — неналаштований предмет з `attunement` дає лише статі бази (складений) або нічого (унікальний), витратні з `artifactId` потрапляють у бій. Вимкнено — усе як HOMM (налаштування ігнорується).
- **Унікальність** — `findHolder(…, isUnique)`: перевіряються лише артефакти без `item.unique === false` і не-властивості; унікальна база в складеному ref — одна на кампанію. Дублікати в клітинках — лише неунікальні (`uniqueConflict`); сховище лишається множиною (`ITEM_ALREADY_IN_STASH`).
- **Атаки**: id атаки = ref (`:off` — друга рука), `BattleAttack.damageBonus` додається у `weaponFlatOf` (прев'ю й сервер); події `attack`/`hit` несуть `attackSourceId` (ref без `:off`) для умови `withThisItem`. `critImmunity` скасовує крит після кидка (`cancelCritIfImmune`).
- **Заряди** — пул `pool:item:<ref>` (`itemPools`, лише активні предмети з `charges`; однакові ref ділять пул); уміння з `limits.pool.key: "charges"` отримують цей ключ при збиранні. `rest: null` — не відновлюються (довгий відпочинок їх лишає). ДМ правит витрачене через `PATCH …/resources { charges }`.
- **Витратні** — `SpecialItem.artifactId`, пул `pool:consumable:<itemId>` (max = кількість, `rest: null`), у `resources.charges` не пишеться; `saveBattle` (гілка `completing`, та сама транзакція) віднімає витрачене (`persistConsumables`), запис на 0 видаляється, журнал `item_use` від `campaigns.dmUserId`.

## 5e: риси й вибори (етап 4f-4)

Передісторія — додатковий власник чинних Choice/Picks: `backgroundId`, `backgroundChoices`, `backgroundFeatPicks`; `Character.background` лишається біографією. Спільний `planChoices` розраховує ASI при виборі, заміні та знятті; `maxPerAbility` обмежує розподіл очок. PUT/PATCH читають refs через ту саму транзакцію, що й заблокований рядок персонажа. Навички та інструменти зливаються при читанні без зміни ручних полів. Origin feat передісторії використовує чинні вкладені picks, spell grants і pools; ключ гранту містить backgroundId та featId і не залежить від назви. Ручні спорядження/гроші імпорт або вибір передісторії не змінює.

- **Модель** — `Choice` (`types/choices.ts`; Zod — `lib/schemas/choices.ts`): `kind` `option | feat | skill | expertise | abilityScore | spell`, `count` — число або колонка класу `{ scale }`, `level` (рівень у класі / загальний), `lineage` (лише раса, ≤ 1; назва опції → `Character.subrace`). Власники: `races.choices`, фічі класу/підкласу `{ level, abilities, choices }`, `feats.choices` (без виду `feat`). Піки — `Picks = Record<choiceId, ChoicePick[]>` у `Character.raceChoices`, `Character.classes[i].choices`, `Character.feats [{ id, picks?, source: origin | dm }]`.
- **Чисті функції без zod** — `lib/utils/characters/choices/`: `resolveChoiceCount`, `validatePicks`, `visitPicks`, `pendingCount`, `abilityScoreDelta`/`capIssues`, `planChoices` (закриті вибори — `CHOICE_LOCKED`, права на риси ДМ, походження ≤ 1, межа ASI лише для характеристик з додатною дельтою), `choiceSelections` (групи вмінь для рушія), `prunePicks`.
- **Збереження** — `resolveCharacterChoices` (`lib/server/characters/choices/`) для створення, чернетки, `PUT …/characters/[id]/choices` (ДМ або власник при `allowPlayerEdit`; 409 в активному бою; журнал `choices_edit`) і level-up з `choices` (без — як раніше). ASI пишеться в базові колонки дельтою в тій самій транзакції. Класовий PATCH ігнорує вхідні `classes[].choices` (`keepStoredPicks`).
- **Рушій** — `createBattleParticipantFromCharacter`: `choiceSelections` → `collectCharacterAbilities({ choiceGroups })`: опції раси — джерело `race`, опції класу — `class` з `applyClassScale`, риси — `feat`, навички й експертиза — синтетичні `flag skillProficiency`/`skillExpertise` (джерело `character:choices`); заклинання опцій раси (до загального рівня) і вибори `spell` зливаються з `knownSpells`. Риси вантажаться (`loadFeatsById`, кеш `getCachedFeats`) лише коли є піки чи `Character.feats` у режимі класів. Невідомі опції/риси/заклинання тихо пропускаються. У snapshot нічого нового.
- **`"slots"`** у виборі `spell` = найвище коло слотів цього класу самого (`maxSlotLevelFor`; пакт — коло пакту).
- **Лист** — `identity.subrace`, `choices: SheetChoices` (риси з піками, опції класів, джерела заклинань, `pending`), навички з експертизою (`expertise: true`, подвійна майстерність).

## 5e: повні монстри й площі (етап 4f-5a)

- **Snapshot монстра** (`participant/from-unit.ts`): юніт із `cr` отримує `abilities.creatureType`, чуття, мови й телепатію зі `statblock`, а з `spellcasting` — гранти із власними `dc`, `attackBonus`, `castLevel`, `legendaryOnly`. Універсальних слотів у монстра немає; `knownSpells` додаються як гранти за бажанням. Юніти без CR зберігають три універсальні слоти.
- **Гранти й перезарядка**: обмежений грант використовує `pool:spell:<spellId>`, визначення в `battleData.pools`, витрату в `abilityUsage[key].battle`; `slotKey` для гранту відхиляється. `perBattle` — ліміт одного бою. На початку власного ходу витрачений пул із `recharge` кидає d6 і скидається при результаті ≥ порога; результат пишеться в лог. Оновлення з джерела зберігає витрати. `fixedDice` вимикає масштабування кубиків заклинання, `damageBonus` додає сталу шкоду у прев'ю й на сервері.
- **Легендарні дії**: `perform` виконує конкретну атаку за назвою або заклинання за id. Каст із `legendaryKey` перевіряє вміння й грант, працює поза ходом і витрачає легендарний бюджет замість звичайної дії; грантові обмеження лишаються чинними.
- **Лігво** (`actions/lair.ts`): ДМ перемикає активність лігва; вміння `limits.lair` обираються вручну раз на раунд, без повторення тієї самої опції два раунди поспіль і без витрати легендарних дій. Стан зберігає `baseResistances`/`resistSpent`, тому перемикання максимуму опорів не повертає витрачені використання. Старі `roundStart`-вміння продовжують працювати.
- **Чуття**: прапорець `sense` і чуття статблоку читаються через `collectModifiers`. Сліпочуття/істинний зір у межах дальності прибирають штраф від невидимості цілі; сліпочуття дозволяє атакувати під час осліплення. Темнозір і вібровідчуття лишаються даними для показу.
- **Площі**: спільна `templateCells` обчислює клітинки для сервера й клієнта. `circle.exact` — диск (радіус 20 фт дає 49 клітинок), `emanation` відштовхується від усіх клітинок кастера й не потребує вибору `targetCell`. HOMM-коло без `exact` лишається квадратним.
- **UI**: редактор юніта має статблок і таблицю заклинань, редактор заклинання — сталі кубики/бонус і точну площу; у бою показуються чуття й ресурси, режими легендарного касту та лігва.

## 5e: гранти героя, предметні заклинання й час накладання (4f-5b)

- Вибори раси/класу/риси містять `SpellGrantPolicy`; snapshot зберігає окремі `SpellGrant` зі стабільним ключем власника/вибору/опції/заклинання. Назви й порядок не впливають на витрати. `slotSpells` окремо визначає право каста слотами; наявність предметного гранту цього права не додає.
- Cast API приймає `grantKey` або `slotKey`; неоднозначне джерело, застарілий ключ, недозволений рівень і нестача ресурсу відхиляються без списання. Ціну/підсилення/сталі DC та attack сервер бере зі snapshot. `item.spells` використовує спільний `pool:item:<ref>`; ціна 0 працює без пулу й за порожнього пулу. Сувій використовує `pool:consumable:<stackId>` та списує тільки вибраний стек.
- Пули грантів зберігаються в `Character.resources.charges`; завершення бою переносить витрати, наступний snapshot їх відновлює. Короткий/довгий відпочинок очищає лише відповідні ресурси; витрачені сувої не відновлюються. ДМ може коригувати лічильники у діалозі ресурсів.
- `cost: reaction` перевіряє власника, блокери й одну реакцію та дозволяє каст поза ходом. Умову реакції підтверджує користувач; уже оброблені влучання/події не переграються ретроактивно.
- `cost: long`, `casting: { rounds, text?, trigger? }` та `battleData.pendingCast` описують підготовку. Початок/продовження потребує дії й концентрації кожного ходу; слот/заряд списується лише після успішного завершення. Втрата концентрації чи пропуск дії перериває підготовку. Лише ДМ може явно зарахувати решту часу через `castingRounds`.
- Dragonborn має два Breath Weapon (конус 15 фт / лінія 30×5 фт) зі спільним proficiency/long пулом, CON DC, DEX/half і 1/2/3/4d10 на рівнях 1/5/11/17. Заміною однієї атаки керує ДМ; рушій витрачає дію.
- Ref предмета має формат `<base>[+<property>][~<parameter>]`; усі читачі використовують канонічний parser/resolver. Параметр і вибране заклинання входять в ідентичність витратного стека та проходять import/export/remap. `targetCreatureType` перевіряється окремо для кожної цілі; невідомий тип не підходить, герой типово humanoid.
- SRD: 498 заклинань, 333 артефакти; підтримані предмети та явно непідтримана проза перелічені в `data/templates/srd-5.2/coverage-4f5b.json`. Випадкове відновлення/знищення предметів та право читати сувій визначає ДМ. Реакції й тривале накладання мають runtime-підтримку.

## 5e: покриття заклинань (P1–P6)

Епопея «рушій заклинань до 100 % native» (спек `2026-10-28-spell-engine-coverage-spec.md`, план `…-plan.md`); P1–P6 готові (Obojima: 50/50 native; P6 — криті атак заклинанням, редактор спел-only ефектів, видалення власних станів). Імпортер розпізнає шаблони тексту 5etools generic-но (`lib/server/compendium-import/adapters/spell-patterns/`, кожне правило — з позитивним і негативним тестом); розпізнавачі йдуть **до** каскаду блокерів `deriveSpell`.

- **Фільтр цілей** — `targeting.filter` (`creatureTypes`, `maxCr`, `maxCrPerLevel`, `movement: "fly"`) на `ally/enemy/area/template`; `spell/target-filter.ts` (`matchesTargetFilter`) стоїть в `resolveRaw` (обрана ціль → помилка `BATTLE_SPELL_TARGET_FILTER`, шаблон/еманація → мовчки відкидає) і на клієнті (`invalid-target` на мапі, превʼю шаблона). CR читається з `abilities.cr` у snapshot (пишуть `from-unit` і `refreshFromSource`), політ — з `battleData.movement.fly`. Вміння-розширення цілей (`all`/радіус) і ланцюг фільтр не застосовують.
- **`chooseOne` і `optionIndex`** — спел-only ефект (2..7 варіантів); запит касту несе `optionIndex`, без нього 422 `BATTLE_SPELL_OPTION_REQUIRED` до будь-яких змін; `castSpell` розгортає вибраний варіант (`expandChosen`), решта рушія бачить звичайні ефекти. Клієнт: `SpellPick.options`, `OptionPicker` у підсумку, «Застосувати» заблоковано без вибору.
- **`inputCount` / `inputDice`** — спел-only маркер `{ kind: "inputDice", label, max }` у `spellEffects` (нова колонка не потрібна; `expandChosen`/`flatEffects` його викидають, рушій не бачить). Кастер вводить кількість кубиків (висота падіння): запит `inputCount` (0..40), сервер бере `min(inputCount, max)` кубиків граней `dieSides`, без `inputCount` — 422 `BATTLE_SPELL_INPUT_REQUIRED` (прев'ю — 1). Клієнт: `SpellPick.inputDice`, `SET_INPUT` перераховує `diceSlots`, числове поле в кроці кидків.
- **`dealDamage.byDistance`** — таблиця `{ maxFeet, dice }[]` (2..6, зростає). `dealSpellDamage` бере відстань `footprintDistance × CELL_FEET` до цілі, перший діапазон з `maxFeet ≥ d`, далі останній; без мапи — перший (+ рядок у лозі). Кубики кидає сервер (`rollDice(…, state.rng)`) у порядку цілей, `upcastDice` додається до кожного діапазону, результат іде через `computeSpellPower` (бонуси кастера) і далі звичайним `outcome` (рятунок/крит/раса). Заклинання з таблицею має `dice: 0` — клієнт нічого не кидає.
- **`push`** — `{ kind: "push", feet: 5..30, from: "caster" }`; `grid/push.ts` (`awayStep` спільний із `runShove`, `pushAway` зупиняється перед першою клітинкою, де не можна стати). Після приземлення — `hazardUnder` → `hazardHit` (сам викликає `applyDamageConsequences`, `hazardHitRound`: раз за раунд). Без мапи — лише рядок у лозі; цілі, що врятувалися, не штовхаються (`push` не читає `spellRoll`, тож пропускається при `skip/factor<1`).
- Самошкода: `dealDamage.target:"self"` + `heal` з `percentOf: "eventDamage"` (`SpellCastState.dealt`; цільові ефекти, що читають шкоду касту, виконуються після нецільових).
- **Зони заклинань і місцевість (P4)** — `targeting.zone` += `terrain: ("difficult"|"obscured")[]`, `side`, `onEnter/onTurnStart/onExit: { save?, effects (≤4), pull?: "centre" }`. `spellZoneHazard` ставить на клітинки `hazard` + прапорці `difficult`/`obscured` + `zoneId` і, коли є тригери чи концентрація, пише `map.spellZones[zoneId]` (`SpellZoneRuntime`: кастер, СК, центр, тригери; клієнту не шлеться — `baseOf` у `client-delta` їх ігнорує, осиротілі прибирає `replaceTerrain`). Зона без шкоди — це `hazard` із `zoneId` без `damage`: без вогню на мапі й без «небезпеки» у підсвітці руху (`isDamagingCell`). Виконання — `spell/zone-triggers.ts`: `zoneMove` (у `move-mutation`, по шляху: вихід → рятівний проти СК зони, провал + `pull` ставить мувера на найближчу до центру вільну клітинку зони й забирає решту руху; вхід), `zoneTurnStart` (у `turn-start.ts`, після небезпеки). Вхід/вихід — раз на зону за раунд (`battleData.zoneHits`), ефекти — `applyEffect` із синтетичним вмінням `spell:<id>`; crit-choice тут не пропонується (як для небезпек); примусове переміщення (`push`, ДМ) зон не тригерить. Концентрація: `sweepDeadZones` у `runBattleMutation` після кожної мутації прибирає клітинки зон, чия концентрація скінчилась. Пензель ДМ «Стерти зону» (`MapTerrainData.eraseZone`, `useMapTerrainTool` `erase-zone`) знімає клітинки зони з `zoneId`, запис `spellZones` і шкоду; звичайний «Стерти» і пензлі місцевості клітинки зон не чіпають (зберігають `zoneId`/`obscured`). Спел-only `createTerrain { terrain: wall|difficult, shape: cell|line, cells, rounds }` — `spellTerrainEffects` (клітинки шаблону касту або лінія кастер→перша ціль; стіна пропускає клітинки з учасниками); місцевість зі строком (`untilRound`) згасає в `pruneExpiredTerrain` для будь-якого виду.
- **Складна місцевість і заслонення (P4)** — `TerrainCell.difficult` (або `kind:"difficult"`, лише пензель ДМ) подвоює вартість входу в клітинку: `grid/path.ts` `searchPaths` — Dijkstra з вагою, бюджет руху в UI й на сервері однаковий; вимушене переміщення (`push`, притягання зони) її ігнорує. `TerrainCell.obscured` діє як сліпота: атакувальник у заслоненій клітинці має перешкоду, ціль у ній дає перевагу; `blindsight`/`truesight` скасовують. Прапорці не блокують лінію (`lineBlocked`). Лише core: режими мапи (`map-modes.md`) не чіпаються.
- **`dealDamage.delayIfBeyond` і `battleData.pendingHits` (P4)** — `{ feet, perRoundFeet }` (спел-контекст, разом із `byDistance`): `dealSpellDamage` при відстані > `feet` (на мапі) замість шкоди кладе на **кастера** `PendingHit { id, targetId, atRound = round + ⌈d/perRoundFeet⌉ − 1, amount, damageType, spellName, school }` — число вже кинуте й помножене на outcome при касті, тож реплей/rollback детерміновані. `spell/pending-hits.ts` `resolvePendingHits` у `applyStartOfTurnDamage` (перед перевіркою статусу — удар прибуває, навіть якщо кастер упав): `atRound ≤ round`, ціль жива й не `escaped` → `applyResistance` (`fromSpell`, школа) → `applyRawDamage` → `applyDamageConsequences` → `resolveDowned`; недоступна ціль — запис зникає без шкоди. Без мапи удар миттєвий. `pendingHits` зберігається як `zoneHits` (`ParticipantState`, `split/joinParticipant`, `participant-patch`). Атаки по рою в польоті не моделюються (rider у імпорті).
- **Власні стани (P2)** — `rules.conditions.custom` (`{ key: "custom:<slug>", name, description, markers, abilityEffects? }`, до 50, злиття патча за `key`). `applyCondition5e`/`removeCondition5e` приймають 5e-ключ або `custom:*`: визначення береться з `ctx.rules`, ключ-маркер ставиться першим, невідомий ключ — no-op з рядком у лозі. Два нові маркери в `CONDITION_KEYS`: `no_hostile_spells` (`pacifiedBlock` у `spell-targeting.ts`: `spell-mutation` відхиляє ворожий каст до і після резолюції цілей — 422 `BATTLE_CASTER_PACIFIED`; лікування союзників дозволене) і `no_damage_dealt` (`dealsNoDamage`, читається через `hasEffectMarker`: нуль шкоди в `dealSpellDamage`, `computeHitDamage` і `hazardHit`; `TerrainDamage.casterId` пише `spellZoneHazard`). ДМ знімає/накладає власні стани в `ConditionsDialog` (проп `custom`). Імпорт 5etools: корінь `condition` → `recommendedRulesPatch.conditions.custom` (`adapters/custom-conditions.ts`; текст шаблонами «can't attack» → `disable_melee/ranged_attacks`, «cast a spell that affects an enemy» → `no_hostile_spells`, «deal damage» → `no_damage_dealt`, «can't move»/«speed is 0» → `immobilized`, «can't take actions» → `skip_action`; нерозпізнане → `MANUAL_CONDITION_TEXT`); `{@condition X}` з кореня — не блокер, а `applyCondition custom:x` (+ `saveEnds` із «repeat the saving throw», `upcastTargets` з «one additional humanoid», фільтр `creatureTypes:["humanoid"]` із «a humanoid you can see within range»).
- **`grantCast` (P3)** — спел-only ефект: носій (кастер або `target:"eventTarget"`) отримує у `spellcasting.grants` запис із `inline` (визначення підкасту: `targeting`/`resolution`/кубики/`effects`, без вкладених `grantCast`), `castCost` (`action`/`bonusAction`/`reaction`), `expiresRound` і `concentrationOf`; ключ `cast:<castId>:<i>`, `uses` → пул `pool:cast:*` (не зберігається в `Character.resources`). `spell-mutation` підміняє визначення (`withInlineDefinition`, коло 0) **до** перевірок режиму/ціни; слот не витрачається. Згасання лінивe (`isGrantLive`), фізичне прибирання — у `turn-start.ts` власника. Клієнт показує живі inline-гранти плитками (`inlineSpellTiles`); нове поле `InlineCast` додавати і в `withInlineDefinition`, і в `inlineSpellTiles`.
- **`anchoredZone` (P4)** — спел-only ефект: аура на цілі заклинання (`ActiveEffect.anchoredZone`: радіус у футах, `side` enemies/allies/all, `excludeBearer`, `onEnter`/`onTurnStart` як `ZoneTrigger`, `endsWhenStartOutside`, СК кастера). Тригери: `anchored-zone.ts` — `anchorMove` (з `zoneMove`: вхід у радіус і коли рухається істота, і коли носій; раз за раунд на ауру) і `anchorTurnStart` (з `zoneTurnStart`: поза радіусом + `endsWhenStartOutside` знімає накладене, в радіусі — `onTurnStart`); примітив `fireTrigger` у `zone-fire.ts` спільний із зонами мапи. Накладені ефекти несуть `anchorOf` (id ефекту-ауры, може бути на іншому учаснику) і копію `concentrationOf`; `sweepOrphanedAnchored` у `withPlacement` прибирає їх, коли аура зникла (спливла тривалість). Не спрацьовує на DM free placement, push/forced move, maze. Предмети заклинань (`battleData.object`) аура не зачіпає ні як мішень, ні як рухомого.
- **Розпізнавачі P5** — `spell-patterns/summon-transform.ts`: `summonObject` («create a Small animated X in an unoccupied space… can't move… hostile creature moves within N feet for the first time / starts its turn… ranged attack, spell attack modifier… bonus action») → шаблон `circle 5` + `summonInline` (з аурою) + `grantCast` з `perObjectFeet`; `transformSpell` («transforms a beast… statistics replaced by the statistics of a {@creature X}… drops to 0 hit points») → `transform` + `targeting.filter` за типом + рятівний кидок. `unitId` — ref `kind: "monster"` із `path: ["spellEffects", 0, "unitId"]`, який авто-зв'язувач імпорту підставляє юнітом кампанії/SRD (`DerivedSpell.refs` → `refs` адаптера); без юніта імпорт дає `UNRESOLVED_REF`, у бою невідомий юніт — рядок у лозі. Тривалість понад 99 раундів обрізається (rider «тривалість обрізана до 99 раундів»).

## Crit choice (DM-chosen critical effects)

Campaign setting `critChoiceByDm` (off by default). Triggers: natural 20/1 on an attack and on a **target's saving throw** of a spell (`SAVE_SUCCESS_EFFECTS` / `SAVE_FAIL_EFFECTS` in `lib/constants/save-critical-effects.ts`; spells have no to-hit roll). With the setting off, every trigger gets a random effect (also for saves).

- **Gate:** `attack-mutation` / `spell-mutation` (`lib/server/battles/mutations/`; the `crit-choice` operation is registered in the `OPERATIONS` table of `lib/server/battles/operations.ts`) run inside `runWithCritChoice` (`lib/utils/battle/crit-choice/`). All server rolls go through a seeded `rng` (`mulberry32`, `lib/utils/common/rng.ts`) and `CritPicker`; each trigger gets a stable `key` (`source:actor:target:n`) and always consumes exactly one `rng()`, so a replay with the same seed gives the same dice. **Limitation:** the stream stays aligned only until outcomes diverge — if the chosen effect changes who dies (`double_damage`/`max_damage`), retaliation, cleave/chain shot, morale and downed handling take other branches that consume other rolls, and triggers the DM never saw (not in `choices`) resolve randomly without a pause. A scripted `ctx.rng` (tests, sweep/sim scripts) is used directly on the first run, so such a run is not replayable by seed.
- **Spell attacks:** nat 20/1 of a spell attack (`resolveSpellAttack`) goes through the same picker (source `attack`, one `rng()` before the bonus-dice roll) and the attack tables; `double_damage` ×2, `max_damage` dice to maximum, `additional_damage` +1d6, self/target effects via `applyAttackCritToFlow` (a reaction cast grants no `free_attack`/`combo_attack` action); `ignore_reactions`/`simple_miss`/`provoke_opportunity_attack` only log. Auto-reactions (Rageful Nimbus) inherit `flow.ctx.crit`. Without a picker a random effect is rolled (one `rng()`), so scripted-rng tests with a nat 20/1 spell attack shift by one roll.
- **Not gated:** saving throws of on-hit spells (`attack/process/hit-spell.ts` casts without `crit`), berserk attacks during `advanceTurn` (`turn/berserk.ts`) and zone/aura triggers (`spell-zones`, `anchored-zone.ts`: saves and attacks of terrain/anchored zones) — their crits are never offered to the DM (berserk gets a random effect, zones none).
- **Pending:** setting on and triggers found → nothing is applied; `battle_scenes.pendingCritChoice` stores `{ action, actorId, triggers, request, seed, userId, isDM }` (the requester: the replay runs as them, so a player's `free: true` stays ignored), `version` grows, the response is `{ pendingCritChoice: true }` with no events. Previews / `dryRun` never create it. The same path serves the DM's own attacks.
- **Projection:** clients only get `PendingCritChoice` (`toPublicPendingCrit`: no `request`/`seed`) on `BattleScene.pendingCritChoice` and in the delta scene.
- **Resolve:** `POST …/crit-choice` (DM only, body `{ choices: Record<key, effectId | "random"> }`) replays the stored request as its original requester with the stored seed and the choices, then clears pending. Body `{ cancel: true }` drops the action without any state change (one log line «ДМ скасував дію»); the dialog offers it as «Скасувати дію».
- **Guard:** while pending, every other mutation answers 422 `crit_pending` (`run-battle-mutation.ts`; only `crit-choice`, rollback, reset and `complete` opt out). Rollback, reset, start and complete clear it. A DM who is offline stalls the battle — roll back or reset.
- **Client:** `useCritChoiceDialog` + `CritChoiceDialog` (DM, `ResponsiveDialog hud`, not dismissible) and `CritChoiceWaitingBanner` (everyone else) are mounted in `BattleScreen`. The attack/spell wizards stay in `submitting` with `waitingCrit` (`WAIT_CRIT` in `attack-flow`/`spell-flow`) when the response is `pendingCritChoice`, and finish through the usual result path once `scene.pendingCritChoice` becomes null (new log entries by the actor since the pause are read via `readBattle`; `useCritPause`). If the pending clears with no such entries (cancel, rollback, reset) the wizard shows «Дію скасовано ДМом» instead of a result.
- **Save crits:** on a save, nat 20 forces success and nat 1 forces failure (when a picker is present), so log, damage factor and effect table agree; both only apply when `rules.criticals.effects` is on (as for attack crits), and an auto-failed save (`autoFail`) never counts as a natural 1. «Контратака» / «Другий вдих» grant `extra_action`: a one-turn `actionsPerTurn +1` effect that lives through the target's next turn.
