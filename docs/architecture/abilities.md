# Abilities

Skills, races, artifacts, sets and units share one model in `lib/utils/abilities/` (schema, registry, `runAbilities`, `collectModifiers`, `read.ts`).

- Engine code fires typed events into `runAbilities` (limits, chance, `lethalDamage` → `kill`) and reads every stat/damage/resistance/flag bonus via `collectModifiers` — never from raw skill JSON.
- Owners have an `abilities JSONB` column (`NOT NULL DEFAULT '[]'`). Read it only with `lib/utils/abilities/read.ts`.
- Edit forms write `abilities` directly through `AbilityListEditor` (`components/abilities`).
- Old-format converters live only in `scripts/import/legacy-convert/` (for `import-skills-library`).
- Етап 4a (5e): прапорці `saveAdvantage` (`abilities | "all"`, `vsSpells`), `saveDisadvantage`, `autoFailSave`, `saveProficiency`, `autoCritAdjacent` (влучання з 5 фт — крит), `proneDefense` (з 5 фт перевага, здалеку — перешкода); стат `savingThrow` у `DYNAMIC_STATS`/`TIMED_STATS` (`modifyStat`, flat). `applyCondition` приймає ключі 5e (`CONDITION_5E_KEYS`) і додаткові `saveEnds: { ability }` (повторний кидок наприкінці ходу цілі проти СК накладача) та `levels` (1–6, лише `exhaustion`); `conditionImmunity` приймає й ключі 5e. Стани 5e розгортаються в наявні маркери + `abilityEffects` — рушій читає їх через `collectModifiers`, як будь-які прапорці. Деталі рушія — [battle.md](battle.md).
- Етап 4b (5e): прапорці `checkAdvantage`/`checkDisadvantage` (`skills | "all"`) і `skillProficiency { skills }` — читає `rollCheck` (`checks/roll-check.ts`); майстерність також береться з `Character.skills`. Додаткове з 4b: маркери ефектів `disengaged`, `hidden`. Деталі — [battle.md](battle.md).
- Етап 4c-1 (класи): джерело `AbilitySource.type: "class"` (`id` класу або підкласу). `collectCharacterAbilities` додає вміння класу з `feature.level ≤ рівень у цьому класі` і вибраного підкласу поруч із расою (лише в режимі класів). `LimitsSchema.perRest { rest: "short" | "long"; uses }` у бою рахується лічильником `abilityUsage[key].battle` (як `perBattle = uses`); при `rules.outOfCombat.persistResources` використання переживають бій (`resources.charges` з видом відпочинку) і відновлюються коротким (`rest: "short"`) або довгим відпочинком. Деталі — [battle.md](battle.md).
- Етап 4c-2 (5e): стат `attacksPerAction` (додаткові атаки за дію «Атака», flat; читає `attack/attacks-left.ts`) і прапорець `twoWeaponFighting` (модифікатор характеристики до шкоди атаки другою рукою; читає `attack/ability.ts`). Редактор і підписи — `registry/labels.ts`. Деталі — [battle.md](battle.md).
- Етап 4e (5e): `LimitsSchema.legendaryCost` (1–3, лише `trigger: action` без `aim`) — таке вміння використовується лише легендарною дією (`core-action` `legendary`), у звичайному ході приховане (`abilityOptions`, відмова в `runAbilityUse`). Мультиатака юніта з CR — синтетичне пасивне вміння `modifyStat attacksPerAction`. Дія лігва — тригер `roundStart` + `perRound: 1` (підказка в редакторі). Деталі — [battle.md](battle.md).
- Етап 4f-2 (5e): умови `armorWorn { categories: none|light|medium|heavy, shield?: with|without }` (статична — дозволена на запечених статах), `attackRollMode { mode }`, `allyAdjacent`; прапорець `evasion`; значення з таблиці класу `{ scale: "<ключ колонки>" }` у `Flat`, `Amount` і `perRest.uses` (також `{ formula }`) — лише у вміннях класу/підкласу, поза ними — проблема в редакторі (`validateAbilities(list, { classColumns })`, `columnRefIssues`) і 0 у рушії; `limits.pool { key, cost }` — спільний пул класу; змінні формул `str_mod`…`cha_mod`, `prof`, `class_level` (`FORMULA_VARIABLES`). Деталі — [battle.md](battle.md) «5e: броня, числа класів, пули».
- Етап 4f-3 (магічні предмети): умова `withThisItem` (атака події зроблена предметом-джерелом уміння; `ConditionContext.sourceId`), прапорець `critImmunity`, `modifyStat … atLeast: N` (лише характеристики, без `flat`/`percent`; у `bakePassives` після пласких бонусів — `max(власне, N)`), ключ пулу `charges` у вміннях артефакта з `charges`/`consumable` (`validateAbilities(list, { itemCharges })`; при збиранні → `pool:item:<ref>` або `pool:consumable:<itemId>`). Деталі — [battle.md](battle.md) «5e: магічні предмети».
- Етап 4f-4 (риси й вибори): джерело `AbilitySource.type: "feat"` (`id` риси); вміння з виборів — `collectCharacterAbilities({ choiceGroups })` після класових (опції раси — `race`, опції класу — `class` з масштабом класу, синтетичні навички — `character:choices`); прапорець `skillExpertise { skills }` — `checkBonus` подвоює майстерність навички, лише якщо вона є; `read.ts` — `featAbilities`, `readChoiceList` (вміння опцій виборів). Деталі — [battle.md](battle.md) «5e: риси й вибори».

- Етап 4f-5a (монстри): `perform: { kind: "attack", attack } | { kind: "spell", spellId }` — посилання на конкретну дію, дозволене лише з `limits.legendaryCost` або `limits.lair`; `limits.lair: true` — ручна дія лігва з тригером `action`. Посилання перевіряються на наявність атаки/заклинання; редактор має поле «Виконує». Прапорець `{ flag: "sense", sense, range }` додає чуття через `collectModifiers` без прямого читання JSON у рушії. Деталі грантів, опорів і лігва — [battle.md](battle.md) «5e: повні монстри й площі».

## Refactor constants та read projection

Rule default values належать `DEFAULT_RULES`; rules schema зберігає validation/fallback/patch semantics, `MECHANIC_REGISTRY` — перелік механік і labels. Domain constants не об'єднано за самим числом; gameplay defaults/formulas не змінено.

`abilities.sources/get` у content operation service підтримує campaign-scoped class/feat owners. Клас віддає прямі abilities base/subclass features через canonical class reader; опційні choices і level eligibility далі належать character derivation. Ця read projection не є другим ability registry чи writer.

Class/feat джерела копіювання підтримуються наскрізно: `AbilitySourceRef`, labels у `AbilityCopySourcePicker`, discovery/owner service та OpenAPI descriptions. Client callback передає abilities; class/feat picker regressions і guarded content-storage SQL перевіряють ці межі окремо.

## Premerge refactor (part 2, 2026-10)

`collectModifiers` accepts several flags in one pass; aura de-duplication per `auraKey` sums strength over the requested flags. Item limits live in `ITEM_LIMITS` (read by `readStats` and the zod schema alike); `itemStatsFromRow` caches by row object (WeakMap), so callers must not mutate its result. Choice owners (class/subclass/feat/race/background) are walked by `forEachChoiceOwner` (`visit` gives both state `path` and `legacyPath`); `plan.ts` uses it only for the class loop. Edition and dice parsing use `RULES_EDITIONS`, `normalizeDiceText` and `DICE_PATTERN`; remaining ad-hoc dice regexes are listed in the findings register (A23).

## Spell engine coverage (P1)

- **Спел-only ефекти** — `SpellEffectSchema` (`lib/utils/spells/model/schema.ts`) = `BASE_EFFECTS` + `randomOf` + `chooseOne` + `inputDice`; їх приймають спел-схеми (форма, REST, OpenAPI `SpellEffect`), але не `AbilitySchema` (вміння `chooseOne`/`inputDice` відхиляє). Ці види не мають `EFFECT_REGISTRY`-запису: `castSpell` розгортає їх до рушія (`expandChosen`); у `describeEffect` лише підпис. Новий спел-only вид — Zod у `SPELL_ONLY_EFFECTS` + розгортання в `expandChosen`/`flatEffects`. **Редактор (P6):** `SpellEffectCard` (`components/spells/form/effects/`) показує форму кожного виду, `SPELL_ONLY_EFFECT_KINDS` (`lib/utils/spells/editor/spell-only.ts`) — єдине джерело переліку видів (тест звіряє його з дискримінаторами `SPELL_ONLY_EFFECTS`), `newSpellOnlyEffect` дає дефолт, що проходить схему; «Невідомий ефект» лишився лише для справді невідомих `kind`. Вкладені ефекти (`chooseOne`, `grantCast.cast`, тригери зон) — `NestedEffectsEditor`; round-trip тест гарантує, що редактор не губить опційні поля. `setAtPath` (`lib/utils/abilities/editor`) прибирає порожні вкладені об'єкти (очищення останнього поля `delayIfBeyond` видаляє весь об'єкт). Редактор `targeting.zone`-тригерів поза P6.
- **`help`** — ефект у `BASE_EFFECTS` (`registry/effects/state.ts` `applyHelp`, той самий `helpEffect`, що й дія «Допомога»): ціль отримує перевагу на наступну атаку.
- **`push`** — `registry/effects/push.ts` (`feet` 5..30, `from: "caster"`); логіка геометрії в `battle/grid/push.ts`; без мапи не застосовується.
- **`dealDamage.delayIfBeyond`** — `{ feet, perRoundFeet }` (кратні 5, ≤120), лише в заклинаннях: далека ціль отримує удар на початку ходу кастера (`battleData.pendingHits`, див. battle.md); поля немає у формі `AbilityListEditor`.
- **`dealDamage.byDistance`** — таблиця дальностей (`maxFeet` кратне 5, зростає), працює лише в заклинаннях (у вмінні без `spellRoll`-контексту береться `amount`).
- **`modifyStat.atLeast`** — нижня межа стату; окрім характеристик (`build/bake.ts`) діє для `armor` і `speed` (до 120) з тривалістю: `collectModifiers` повертає максимум `atLeast`, `statWithModifiers` його застосовує.
- **`damageBonus.flat: { spellRoll: ±N }`** — відсоток від кидка заклинання (наприклад −100 = мінус кидок); лише в ефектах заклинань (`validateAbilities` відхиляє у вміннях), `freezeSpellRoll` підставляє кидок перед застосуванням.

## Spell engine coverage (P2)

- **`applyCondition.condition`** — 5e-ключ, маркер із `CONDITION_KEYS` або власний `custom:<slug>` (`CUSTOM_CONDITION_KEY_RE`, `isCustomConditionKey`); визначення живе в `rules.conditions.custom`, розібрані правила спільні (`parseRulesCached`) — не мутувати. `abilityEffects` власного стану — `StaticEffectSchema` (`modifyStat`/`damageBonus`/`flag`). `AnyConditionKey` не розширено: `conditionImmunity` і умови вмінь власних ключів не бачать.
- Маркери `no_hostile_spells` і `no_damage_dealt` читаються через `hasEffectMarker` (це не модифікатори, `collectModifiers` їх не повертає); докладно — [battle.md](battle.md).

## Володіння бронею й зброєю (5e)

`abilities.proficiencies` збирає `classProficiencies` (`lib/utils/battle/proficiency/collect.ts`): перший клас дає повний список, наступні — лише `multiclassProficiencies` (SRD «Multiclass proficiencies»; зберігається в JSON `proficiencies.multiclass`, міграції немає; `skills: {count, from}` — навичка при мультикласі (Bard/Ranger/Rogue) віддається вибором `multiclass-skills` для класу не першим, `classChoiceDefs(cls, subclass, multiclass)`). Прапорець `proficiency { kinds: light|medium|heavy|shield|simple|martial }` (раса, риса, предмет) додається `withGrantedProficiencies` у `finalizeCharacter`. Категорія зброї — поле `weaponCategory` у `WeaponStats`/модифікаторах артефакта; опис («Martial Melee Weapon.») — лише fallback у `extract-attacks.ts`. Загальні магічні зброї SRD (Weapon +N, Vorpal, Holy Avenger…) — властивості `item.property` без категорії, окремо їх не одягти: складений ref `<base>+<property>` бере категорію бази (`composeItemRow` зберігає її й з опису, бо властивість підміняє `description`).

Arcane Recovery (Wizard): пасивка з ефектом `restoreSpellSlotLevels { budget, maxSlotLevel }` (єдиний не-статичний ефект, дозволений у пасивці; у бою не спрацьовує). Застосовується лише `POST …/characters/[id]/arcane-recovery` у вікні короткого відпочинку (`arcaneRecoveryFor`, чисті `arcaneRecoveryOffer`/`applyArcaneRecovery`): `picks` по колах слотів, сума кіл ≤ бюджет, коло ≤ `maxSlotLevel`, лише витрачені слоти; «раз на день» — запис `resources.charges[ability.key] = { used: 1, rest: "long" }` (скидається довгим відпочинком). Пропозиція для UI — `sheet.rest.arcaneRecovery`.

Cunning Strike (Rogue): `Ability.params` (`schema/params.ts`) — `sneakAttack: true` на вмінні Sneak Attack (`dealDamage` по `hit`) і пасивка `params.cunningStrike { options: [{effect, dice}], maxEffects }` (Improved додає лише `maxEffects: 2`). Запит атаки приймає `cunningStrike: ("poison"|"trip"|"withdraw")[]`; `validateAttackRequest` перевіряє пропозицію (`attack/cunning-strike.ts`: `cunningStrikeOffer`/`cunningStrikeCost`). `resolveHit` кладе `cunningDice` у подію `hit` (`applyDealDamage` знімає кубики з Sneak до кидка) і лише коли Sneak справді спрацював (`fired`) застосовує ефекти: СК = 8 + DEX + майстерність, poison (CON, `poisoned` + saveEnds), trip (DEX, `prone`), withdraw (таймерний `disengaged`). Розмір цілі для trip не перевіряється (у учасників його немає). Параметр діє лише на першу ціль залпу.

## Опис вмінь: сегменти й «потік» (ability flow, етап 1)

- Описи не рядки, а **сегменти** `Segment { key, params? }` (`lib/utils/abilities/segments.ts`; `params` можуть вкладати сегменти й `{ join, items }`). Реєстр (`registry/*`, `describeAbility*`) повертає лише сегменти з ключами ns `abilityRegistry`; текст робить `renderSegment(t, s)` / `renderSegments` / `linesText` на межі (клієнт — `useAbilityText()` у `components/abilities/use-ability-text.ts`: `effect`, `segments`, `flows`, `flowsText`, `lines`; експортується з barrel `components/abilities`). Сервер віддає в payload-ах `Segment[][]`/`AbilityFlowSummary[]`, мова не потрапляє в кеш-ключі (кеш info-reference піднято до `v5`).
- `summarizeAbility(a)` (`summary.ts`) → `AbilityFlowSummary { when, if, then: Segment[][], limits }`; `abilitySummary(kind, row)` / `withAbilitySummary` додають його власникам (скіли, юніти, артефакти, сети, прогресія, лист героя, довідник). `flowSegments(f)` розгортає в плаский список (пошук, звичайний текст).
- UI: `AbilityFlow` / `AbilityFlowList` (`components/abilities`, замінили `AbilitySummary`) показують чіпи «Коли → Якщо → Тоді + ліміти» (`abilities.flow.*`, токени `--flow-when/if/then/limit` у `app/globals.css`); у редакторі `AbilityPanel` чіп скролить до секції й підсвічує її. Простий текст (`flows()`) лишено у дрібних пікерах: NodeSheet, OfferList, SlotPicker, SetList, ItemDetails.
- Тригери згруповано: `TriggerDefinition.group` + `TRIGGER_GROUPS` (`registry/triggers.ts`), `TriggerSection` рендерить групи у `SelectField`, підказки й назви груп — `abilities.*` uk/en.
- `describeEffect` приймає й спел-only ефекти (`registry/effects/describe-spell-only.ts`, ключі `summary.spellOnly.*`); нові ефекти/прапори/стани з main мають описуватись сегментами (фікстури `__tests__/describe-fixtures.ts` вимагають покриття всіх видів).
- `logText` (`log-text.ts`) — синхронний uk-рендер лише для рядка логу бою; текст логу рушія (`abilityText.log.*`) — ключами, див. [i18n.md](i18n.md) (ч.6).
