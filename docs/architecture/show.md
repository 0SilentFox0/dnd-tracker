# Slide show («Показ») and music

- `slide_decks`: DM decks, `slides JSONB`. PUT with `expectedUpdatedAt` → 409 on a stale editor.
- `campaign_shows`: one row per campaign, **never deleted** — `seq`/`audio.seq` only grow, otherwise open pages would drop a restarted show as «old».
- Pure commands in `lib/utils/show/show-command.ts` (on top of `applyAudioCommand`), routes `app/api/campaigns/[id]/{decks,show}`, Pusher `private-show-<campaignId>` / `show-state`. Players get only the current slide + `nextImageUrl`.
- Images go to bucket `scene-slides` (client resizes to WebP ≤ 2560 px, signed upload).
- The music player is host-agnostic (`AudioHost` in `lib/hooks/audio`, components in `components/audio`): battle and show each pass their own host.
- **Заглушка:** `campaign_shows.cover` (знімок обраного слайда без треку, задається на рівні кампанії) і `curtain`. Команди `curtain {on?}` (без `on` — перемикання), `setCover`, `clearCover`; що бачать гравці — `lib/utils/show/player-view.ts`. Під `curtain` гравці бачать заглушку, позиція в наборі й музика не скидаються; будь-яке перемикання слайда знімає `curtain`, `end` зберігає `cover`. Без показу гравці теж бачать заглушку, а не «ДМ ще не почав показ». Знімок не оновлюється при редагуванні набору.
- **Керування для ДМ:** `ShowTransport` (‹ n/m ›, заглушка, завершити) і `ShowDeckStrip` (набір, спершу набори сцени; стрічка слайдів; ☆ — зробити заглушкою) спільні для `/show` і панелі сценарію. Клавіші (`useShowKeys`): ←/→, `B` — заглушка; сценарій додає `N` — наступний рядок через `extraKeys` (літери за `e.code`, бо українська розкладка). У рядку сценарію `current` — показ стоїть на слайді, `active` — і гравці його бачать.
- **Кубики гравця:** на `/show` у гравця кнопка 🎲 (`components/dice/DiceRoller.tsx` + `useDiceRoller`): d4–d20, 1–6 штук, криптографічний генератор і ті самі 3D-кубики, що в бою (`DiceStage`). Кидок локальний — нікуди не пишеться і ДМ його не бачить.
- **Сценарій:** прив'язки рядка (мініатюра слайда, бій зі статусом) стоять над текстом; слайд показується кнопкою або подвійним кліком по рядку. Панель мінімальна: іконки без підписів, клік по мініатюрі «на екрані» — до рядка; чіп плеєра в панелі, розгорнутий плеєр плаває над нею.
- **Музика розділу:** `ScenarioSection.trackId` (JSON `content`, без міграції; Zod `trackId` у `scenarioContentSchema`). Вибір — `SectionTrackDialog` (той самий `TrackPicker`, що й у слайда) у `SectionHeaderEditor`; чіп із ▶ — `SectionTrackChip`. У режимі гри `showSlide` після `open` шле `audio play` для треку розділу, якщо `sectionTrackToPlay` (`lib/utils/scenario/play.ts`) каже: трек є, не збігається з поточним і слайд рядка не має власного `trackId` (слайд перебиває розділ). Скрол/`useActiveSection` і бій-рядки трек не перемикають; ▶ у заголовку — `playSectionTrack`.
- **Сторінка сценарію («Рукопис»):** зміст ліворуч (≥ 1200 px, без відкритої AI-панелі; інакше «☰ Розділи» відкриває його в `ResponsiveDialog`), поточний розділ — `useActiveSection`. Іконка розділу — `sectionIcon` (`lib/utils/scenario/section-icon.ts`): ручне `section.icon` (JSON `content`, без міграції) → назва «Підготов…» → прив'язаний бій → виноска «Тіньова лінія»/«Таємне» → «Вибір гравців» → сцена. «Зіграно» для сцени і «відкрито» для героя — одне правило `sectionDone` (`reveal.ts`) для кнопки, змісту й згортання. Зіграні розділи згорнуті (рядки лишаються в DOM із `hidden`, друк показує все); щойно позначений лишається розгорнутим до перезавантаження; «⋯ → Розгорнути зіграні» — localStorage `scenario-show-played`.
- **Режим карти:** `ShowState.world` (`world`/`worldOff`) замінює слайд на карті світу, `stageMode` вирішує, що малювати; гравець дочитує власний відфільтрований вигляд. Деталі — [world-map.md](world-map.md).
- **Puzzle:** a slide with `Slide.kind = "puzzle"` carries `Slide.puzzle` (`PuzzleSpec`: `cut` classic/organic/straight, `count` 4–60, `seed`, image size); the editor adds it via «Додати пазл» and tunes cut/count/seed in `SlideDialog`. Pieces come from `generatePuzzle(spec)` (`lib/utils/puzzle/generate.ts`), deterministic by `seed` on both server and client; the real piece count can differ from `count` (grid rounding in classic/straight, clamped to the max). `ShowState.puzzle` (`PuzzleState`: piece positions, rotation, tray/board, `correct`, `solved`) is stored with no migration inside the slide JSONB as `slide.puzzleState` (`splitSlide` / `writeShowState` in `show-store.ts`); `moveTo` initialises it (`initPuzzle`), `refreshShowSlide` keeps it while the spec is unchanged. Players and the DM send `PuzzleCommand`s to `POST /api/campaigns/[id]/show/puzzle` (rate-limited, retried on `seq` conflicts), applied by `applyPuzzleCommand`; DM-only: `puzzleRelease`, `puzzleReset`. A grabbed piece is held 30 s (`PUZZLE_HOLD_MS`) and the client sends `puzzleKeepAlive` every 10 s (`PUZZLE_KEEPALIVE_MS`); expired holds are dropped lazily on the next command. A player holds one piece at a time (a second `grab` auto-returns the previous one to the tray); player commands are rejected while the curtain/world/battle hides the puzzle. Coordinates are integer image pixels (Pusher payload limit). Only `grab`/`drop`/`return` (and rotation inside `drop`) go over the wire — moving a piece in the hand is local. A drop snaps (`correct`) only at rotation 0 and within `PUZZLE_SNAP` of the piece size from home. UI: `components/show/puzzle`, drag logic in `usePuzzleDrag` (pointerId-bound; tap on a board piece = +45° drop; wheel/Q/E/buttons rotate; touch on the tray: long press 200 ms or a vertical move picks, horizontal scrolls).
- **Слайд лише для героїв:** `Slide.audience` (id героїв; відсутнє = усім, не для пазла; JSON слайда, без міграції). Серверна колонка `campaign_shows.trail` (`ShowState.trail`, **ніколи не йде клієнтам**) — знімки слайдів без `kind`/`puzzle`: `open` → `[ціль]`, `end` → `[]`, `next/prev` дописують (дедуп, `SHOW_TRAIL_MAX`), слайд без `audience` скидає все до нього (`nextTrail`); `refreshShowSlide` оновлює запис поточного. `playerShowView(show, heroIds)` (`lib/utils/show/player-view.ts`): поточний слайд доступний → як є (без `audience`), інакше останній доступний зі стежки (`nextImageUrl: null`, без `puzzle`), інакше `slide: null` → заглушка/очікування; працює і під `curtain`/`world`. Музика: якщо `audio.trackId` збігається з треком прихованого слайда — `audio: null` (окремої синхронізації fallback-треку немає; ручний play того ж треку теж мовчить). `nextImageUrl` на сервері `null`, якщо наступний слайд обмежений. Слайд з `audience` не може бути заглушкою (`SHOW_COVER_RESTRICTED`).
- **Транспорт обмеженого слайда:** `publishShow` шле `{campaignId, seq}` (без `show`), якщо `isRestricted` (`show.slide.audience`); `usePusherShowSync` при більшому `seq` інвалідовує `showKeys.state` — один `GET /show`. Усі HTTP-виходи показу проходять через `showForViewer` (`lib/server/show/viewer-show.ts`: ДМ → `toClientShow`, гравець → `playerShowView` з героями `activePlayerHeroes({controlledBy})`, пошук героїв лише для обмеженого стану) або `toClientShow` (ДМ-команди). Нова відповідь/публікація з `ShowState` без цих функцій витече `trail`. UI: `AudiencePicker` у `SlideDialog` (лише `PLAYER`-герої), 🔒 у `ShowDeckStrip`.

## Player view (DM)

On `/show` the DM can switch the page to the player view: per-window flag (`usePlayerView({kind:"show",id})`, `sessionStorage`, key `player-view:show:<campaignId>`), button in the stage corner and `P`. It is pure visualization: control panel, scenario, dm notices and the `DiceRoller` widget are not rendered (dice FX animation stays). Slides/hidden items are filtered as for a player. The world-map stage does not use the DM payload: `useShowWorld` in `readOnly` makes one request `/world/view?asParty=1` covering all active heroes of the campaign (`worldKeys.partyView`, no retry/polling after an error; `mergePartyViews`: union of markers and reveals, no notes, `dmNote` null); while loading nothing is shown, with no heroes the fallback is `sanitizeDmDetail` (only always-visible markers). Puzzle stage is `readOnly`. Like in battle, the client still holds the DM payload; hiding is UI-only (so a slide limited by `audience` shows as the real current slide in this mode). The DM window in the mode does not host battle music, and the `/show` sound is muted there (`AudioHost` `silent`).
