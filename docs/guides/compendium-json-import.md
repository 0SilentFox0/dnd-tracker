# Імпорт JSON-компендіуму в кампанію

ДМ відкриває «JSON-компендіум» у кампанії (`/campaigns/[id]/dm/compendium`) та обирає власний файл. Потрібна сесія ДМ цієї кампанії; звичайного API-токена недостатньо. CSV, TSV і простий табличний JSON мають чинний окремий потік імпорту.

## Форма файлу

Потрібен UTF-8 JSON object з масивами категорій у форматі 5etools. Мінімальний синтетичний приклад:

```json
{
  "_meta": {
    "edition": "one",
    "sources": [{ "json": "MYBREW", "full": "Мій світ", "authors": ["Автор"] }]
  },
  "spell": [{
    "name": "Уявний промінь",
    "source": "MYBREW",
    "level": 0,
    "school": "V",
    "entries": ["ДМ визначає дію цього заклинання вручну."]
  }]
}
```

`source` посилається на `sources[].json`, а не на скорочену назву. Назва, джерело та edition формують ідентичність: однакові назви різних джерел можуть співіснувати; перейменування створює нову ідентичність. Для відсутнього джерела майстер пропонує явне прив’язування. Повний дозволений приклад: [синтетичний fixture](../../lib/server/compendium-import/__tests__/fixtures/universal.synthetic.json).

| Категорії JSON | Результат |
|---|---|
| `spell` | Заклинання з описом, спочатку ручне застосування |
| `monster` | Юніти, числові характеристики та текстові дії в межах підтримки |
| `item`, `baseitem` | Предмети/артефакти |
| `race`, `subrace` | Раси й вкладені опції |
| `class`, `subclass`, `classFeature`, `subclassFeature` | Класи, підкласи, описи та вибори рівнів |
| `optionalfeature` | Опції визначеного власника; без власника не стають довільними рисами |
| `feat`, `background` | Риси й походження; підтримувані ASI/origin feat та вибори |
| `book` + `bookData`, `adventure` + `adventureData` | Явно обрані розділи як приватні нотатки ДМ; manifest і data пов’язуються за `id`/джерелом |
| `table`, `reward`, `condition`, `skill`, `language`, `itemProperty`, `itemType` | Довідкові матеріали, без створення нового рушія механік |

Непідтримані категорії/поля показуються в coverage та діях. Foundry automation, fluff/media, `copy`/`inherits` DSL не виконуються. Посилання не відкриваються автоматично; зображення завантажуються окремо — див. «Зображення». Імпорт не створює активних боїв чи персонажів із пригоди.

Файл — до 3 MiB, до 10000 кореневих записів, 2000 обраних domain/nested записів і 100 джерел за імпорт. Глибина до 32; є окремі обмеження вузлів, рядків та доменних полів. Запит з обраними даними — до 3000000 байтів. Якщо обсяг завеликий, оберіть менше категорій/розділів; обрізання без повідомлення немає. ZIP, PDF, JSON5 та імпорт за URL не підтримуються.

## Налаштування сервера

Preview і confirm підписують токен ключем `COMPENDIUM_PREVIEW_SECRET` (випадковий рядок щонайменше 32 символи; `openssl rand -base64 32`). Без нього сервер відповідає `503 PREVIEW_SECRET_REQUIRED`, а ДМ бачить повідомлення, що імпорт недоступний через відсутній ключ. Задайте його в `.env.local` або змінних середовища та перезапустіть сервер.

## Preview, підтвердження та звіт

1. Оберіть файл, категорії та окремо потрібні матеріали ДМ/розділи. Повний файл перевіряється локально у Worker; обрані дані надсилаються серверу для preview. На цьому кроці записи кампанії не створюються.
2. Перевірте sources, edition, coverage, create/update/unchanged, конфлікти та зміни правил кампанії. Механічні посилання (заклинання, класи, риси…) preview зв’язує автоматично за назвою без урахування регістру: спочатку із записами кампанії, потім з SRD-шаблоном (редакція має збігатися або має бути дозволене змішування), потім із записами самого файла. Посилання, яке лишилося неспівставленим, названо у звіті разом із записом-власником; його можна зв’язати вручну (preview перерахується), додати залежність або виключити заблокований запис разом із залежними. Якщо звіт радить режим класів 5e, під заголовком звіту є прапорець, що застосовує це правило разом з імпортом.
3. Edition `classic` та `one` зберігається з файла/запису. Змішування відомих різних editions вимагає окремого підтвердження і не конвертує правила. Невідому edition перевіряє ДМ.
4. Підтвердьте право використати файл та натисніть імпорт. Confirm повторно перевіряє права й стан кампанії та записує обраний план атомарно. Застарілий або прострочений preview (15 хвилин) потребує нового перегляду; часткового імпорту немає. Retry з тим самим ключем підтвердження повертає збережений результат без дублів.
5. Звіт доступний після оновлення сторінки без повторного вибору файла: бібліотеки, coverage, source notes/attribution і «Що далі» з переходами до редакторів. Експорт звіту містить метадані й ідентифікатори, без книжкового тексту.

Повторний імпорт незміненого файла дає unchanged. Локальні правки за замовчуванням зберігаються; overwrite потребує явного вибору. Відсутні в новому файлі записи автоматично не видаляються; окремий список missing-in-new-file поки не реалізовано.

## «Можна імпортувати» та «Готовність до гри»

`readyToImport` означає, що план можна записати без блокувальних помилок. `readyToPlay` — окрема оцінка звіту: успішний імпорт може залишати ручні дії й неперенесені правила. Перегляньте кожну таку дію перед грою:

- Типові заклинання (шкода з кидком чи рятівним, стан, зниження швидкості) імпортуються як `native`; `SPELL_RIDER_MANUAL` — додаткові ефекти лишились в описі, `SPELL_NARRATIVE_ONLY` — без бойової механіки. Для `MANUAL_SPELL_*` (причина в коді: `SUMMON`, `WEAPON`, `ZONE_OR_TRIGGER`, `VARIABLE_DAMAGE`, `SELF_DAMAGE`, `BUFF_OR_TRANSFORM`, `UNSUPPORTED_CONDITION`, `UNMODELED_EFFECT`) перейдіть до редактора заклинання, налаштуйте цілі, ефекти, кидки й ресурси та лише після перевірки явно увімкніть механічне застосування. До цього доступний опис, а автоматичний cast блокується до витрат ресурсів.
- Для часткових монстрів/предметів звірте stats, дії, заряди та гранти у відповідній бібліотеці. Текстовий опис не гарантує автоматизацію.
- Перевірте ручні prerequisites і class/subclass features у редакторі та листі героя. Невідомі навички/інструменти ведіть вручну.
- `additionalSpells` DSL залишається `UNSUPPORTED_FIELD`/ручними source notes. Для spell pick ДМ явно налаштовує чинний native Choice у ресурсі рис; далі працюють звичайні Picks. Автоматичну конвертацію довільного DSL не заявлено.
- Походження не видає спорядження/золото: додайте їх героям вручну. Біографія не перезаписується. Classic без ASI/origin feat не отримує їх штучно.
- Створіть персонажів, зробіть потрібні вибори та прочитайте неперенесені правила й приватні матеріали ДМ.

Bundle/clone переносить контент, provenance та нотатки з remap посилань. Source-sync переносить лише обрані native scopes: **ScenarioPage не підтримується**, тому нотатки оновлюйте явним JSON reimport або вручну. У клонованих нотатках повнотекстовий searchText наразі містить лише заголовок.

## Права та приватність

Використовуйте лише файл, на використання якого маєте право. Metadata джерела не є ліцензією чи дозволом на поширення. Authors, convertedBy, version, URL і сторінки за наявності зберігаються в attribution/source notes; credits доповнюються. Імпорт не надає official visibility і сам по собі не публікує матеріал.

Payload тримається в пам’яті вкладки, без localStorage, AI mapping, analytics чи запису тексту в operational logs. Сервер зберігає імпортований контент, нормалізовані source notes, attribution і звіт; цілий оригінальний файл та unsupported media/Foundry bodies не зберігаються. Матеріали пригоди стають приватними нотатками ДМ, а не player story. Доступ до звітів і source notes обмежено ДМ кампанії.

## Зображення

Після підтвердження записи зберігаються одразу, а зображення з файлу (`fluff.images`, `image`/`gallery` у `entries`, іконки й аватари) завантажуються у фоні сторінки з шкалою прогресу; сторінку тримайте відкритою. До 1000 унікальних зображень за імпорт, до 1 МБ кожне, лише `https` і png/jpeg/webp/gif (перевірка за вмістом, SVG не приймається). Файли стискаються у webp і зменшуються (до 512 px для іконок/аватарів, до 1600 px для картинок книг і пригод) та лежать у публічному бакеті `compendium-media`.

Портрети й іконки заповнюють лише порожні поля; поле, змінене вручну, лишається як є й іде у звіт як пропущене. Картинки книг і пригод стають вузлами `image` у сторінках сценарію. Невдачі (недоступний хост, завеликий файл, не зображення тощо) згруповані у звіті за причиною; «Продовжити» і «Повторити невдалі» запускають обробку знову, звіт можна відкрити пізніше. Чекбокс «Маю право…» стосується й зображень; оригінальний URL зберігається в атрибуції.
