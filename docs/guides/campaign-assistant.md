# Асистент кампанії

Асистент призначений для Dungeon Master. Він працює з даними поточної кампанії, а доступність дій визначають права поточної сесії або API-токена. Асистент не замінює нативні редактори для завантажень, імпорту, облікових даних і операцій, що потребують окремого людського рішення.

## Де відкрити

- `/campaigns/{campaignId}/dm/assistant` — чат кампанії, черга пропозицій, перегляд змін, підтвердження й відновлення стану.
- `/campaigns/{campaignId}/dm/ai` — ключі провайдерів, API-токени, постійні інструкції кампанії та налаштування MCP.
- Сценарний редактор також показує спільну чергу перегляду для пропозицій сценарію.

Для черги й підтвердження не потрібен ключ AI-провайдера. Ключ потрібен лише для виклику чату або платної генерації. Ключ провайдера зберігається на сервері; інтерфейс показує маску.

## Як виконуються дії

Читання повертає дані або сторінку даних. Запис у режимі **Перегляд** створює пропозицію зі статусом `pending`; зміна ще не застосована. Відкрийте картку, перегляньте цілі, значення до/після, попередження та залежні зміни, після чого підтвердьте або відхиліть її у застосунку. Підтвердження виконує сервер після повторної перевірки доступу та актуальності даних. Якщо дані змінилися, пропозиція стає застарілою й повертається конфлікт замість часткового запису.

Режим **Авто** можна ввімкнути лише явною дією DM у налаштуваннях власного треду або власного токена. Він застосовує звичайні дії без черги підтвердження. Видалення, очищення/скидання прогресу, відкат, зміна доступу, session-only та платні дії й далі вимагають людської участі у відповідному UI або повертають захищене перенаправлення до нього. Ввімкнення авто не застосовує раніше створені пропозиції.

Модель не може підтвердити власну пропозицію або ввімкнути авто. Підтвердження і відхилення доступні тільки автентифікованому DM у session UI. Звичайне повторення того самого запиту повертає ту саму дію/квитанцію; невідомий результат зовнішньої платної операції не запускається повторно автоматично.

## MCP і права

На сторінці `/dm/ai` створіть API-токен для потрібної кампанії та надайте лише необхідні scopes. Значення токена показується один раз. Передавайте його MCP-клієнту як Bearer secret і не вставляйте в повідомлення асистенту.

Каталог доступних операцій можна прочитати через `assistant_capabilities`; структуру — `assistant_schema`; дані/безпечне перенаправлення — `assistant_read`; підготовку дії — `assistant_action`; стан пропозиції — `assistant_status`; відхилення власної пропозиції без виконання — `assistant_reject`. HTTP і MCP використовують один серверний каталог та dispatcher. Токен визначає identity і scopes на сервері: переданий моделлю `campaignId`, user, scope або nested ID не надає доступу. Запит не відкатується на cookie-сесію, якщо Bearer недійсний.

Результат MCP має envelope версії 2. Внутрішнє `data.kind: "pending"` із `reviewUrl` означає, що запис ще не відбувся; відкрийте посилання у вебзастосунку та перегляньте його. `data.kind: "handoff"` означає, що операцію треба виконати в зазначеному інтерфейсі. Лише `data.kind: "result"` містить завершений результат; помилка має `kind: "error"` і код для діагностики. Великий вміст читається сторінками, а не обрізаним JSON.

## Контекст і приватність

Перед відправленням повідомлення UI показує disclosure фактично зібраного контексту: його склад, провайдера/модель і межу історії. Нотатки джерел початково не вибрані. Їхній текст може потрапити провайдеру лише після явного вибору DM; вибір обмежений 1–5 власними нотатками та 3000 символами на нотатку. Токен MCP не може використати session-only вибір.

До відповідей і квитанцій не додаються ключі, токени, invite-коди, сирі compendium bundles чи підписані URL завантаження. Захищені операції повертають handoff до нативного UI; це не підтверджує, що файл було завантажено або імпортовано.

## Помилки та відновлення

- **401** — відсутня або недійсна автентифікація/Bearer. Перевірте токен; не підставляйте його в тіло повідомлення.
- **403** — немає потрібного scope, DM-доступу або операція доступна лише через session UI.
- **409** — дані чи стан пропозиції змінилися, дія застаріла, або повторно використано request ID з іншим payload. Перечитайте поточний стан і підготуйте нову дію.
- **429** — діє обмеження частоти; дочекайтеся дозволеного повтору.
- **5xx / перерваний чат** — не припускайте, що запису не було. Скористайтеся «Відновити стан» або GET статусу з тим самим request ID; сервер покаже збережені повідомлення, пропозиції та квитанції без blind повторного виклику моделі.
- **Застаріла/невідома зовнішня операція** — перегляньте її стан у UI; платний виклик автоматично не повторюється.

Assistant intents зберігають payload/preview до очищення: термінальні intent payloads і previews редагуються після 7 днів, а квитанції завершених операцій зберігаються до 90 днів. Retention cleanup планується щодня о 03:00 UTC після production deployment; після 90 днів цей шлях відновлення більше не гарантується.
