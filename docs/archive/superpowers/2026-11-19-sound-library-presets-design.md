# Бібліотека звуків і пресети — дизайн

Дата: 2026-11-19. Статус: чернетка на рев'ю користувача. Розвиває [саундборд](2026-11-19-soundboard-design.md).

## Мета

Звуки більше не плоский список кампанії. ДМ має **власну бібліотеку звуків (на рівні акаунта)** і **пресети** — іменовані групи до 9 звуків (сітка 3×3). Під час гри ДМ сам перемикає пресет і швидко підміняє слоти.

## Рішення користувача

- Джерела звуку: завантаження файлу, запис з мікрофона, пряме посилання на аудіофайл. YouTube — ні.
- Бібліотека й пресети — **per-DM-акаунт**, діляться між кампаніями.
- Редагування: **окрема сторінка бібліотеки** + діалог «замінити слот» у панелі «Звуки» в грі.
- Без міграції даних: стара `campaign_sounds` замінюється; стартові пресети «Бій» і «Атмосфера» з вбудованих звуків.
- Звук: іконка, підпис (необов'язковий), джерело.

## Що перевикористовуємо (і чому нове)

| Існує | Використання |
|---|---|
| `lib/server/soundboard/{sound-store,publish-play}.ts`, `lib/hooks/soundboard/*`, `components/soundboard/*`, `lib/schemas/soundboard.ts`, `lib/constants/soundboard.ts` | Основа: подія `soundboard-play`, пад, гарячі клавіші, голоси, вбудований реєстр; адаптуємо під пресети |
| `lib/supabase/audio-upload.ts`, `lib/api/upload-audio-file.ts`, `lib/utils/soundboard/validate-file.ts` | Підписане завантаження файлу в bucket `soundboard`; ті самі ліміти |
| `ResponsiveDialog`, `useConfirm`, `HudPage`/`HudCard`/`HudPanel`, `SelectField`, `useSearch` | UI сторінки й діалогів |
| `lib/utils/api` (`parseBody`, `requireAuth`, `errorResponse`), шар route → api → hook → component | Серверний каркас |
| Іконки lucide (`SoundPad` уже мапить назву → іконку) | Вибір іконки з фіксованого набору |

Нового: сторінка бібліотеки, запис з мікрофона (`MediaRecorder`), імпорт за посиланням на сервері, таблиці `sound_library_items` і `sound_presets`.

## Дані (expand-only міграція, RLS на кожній таблиці)

`sound_library_items`: `id`, `userId`, `name` (nullable, ≤ 60), `icon` (≤ 24, з набору), `color` (nullable), `volume` (0–1, def 1), `path` (у bucket `soundboard`), `durationMs`, `source` (`upload` | `record` | `link`), `sourceUrl` (nullable, для `link`), `createdAt`. Індекс `(userId, createdAt)`.

`sound_presets`: `id`, `userId`, `name` (≤ 40), `slots Json` — масив рівно з 9 елементів `soundId | null`, `sortOrder`, `createdAt`. Індекс `(userId, sortOrder)`.

`soundId` = `id` рядка бібліотеки або `builtin:<slug>`. FK на слоти немає: при видаленні звуку сервіс у транзакції замінює його на `null` у всіх пресетах акаунта.

Ліміти: 100 звуків і 30 пресетів на акаунт; файл ≤ 1 МБ, ≤ 10 с; формати як у `validate-file`.

Стара `campaign_sounds` і `Campaign.hiddenBuiltinSounds` прибираються окремою **expand-only-сумісною** міграцією після деплою коду (drop колонок і таблиці — другим кроком, за правилами `db-deploy.md`). Власних звуків на проді немає (бакет порожній), переносити нічого.

Стартові пресети: при першому читанні бібліотеки, якщо в акаунті немає пресетів, створюються «Бій» (9 вбудованих) і «Атмосфера» (решта, 8). Операція ідемпотентна.

## Джерела звуку

- **Файл** і **запис**: клієнт → підписаний URL → bucket → `POST /api/sound-library` з метаданими. Запис — `MediaRecorder`, стоп-кнопка, автостоп на 10 с, формат webm/opus (додати до дозволених у `validate-file`), попереднє прослуховування перед збереженням.
- **Посилання**: `POST /api/sound-library/import { url }`. Сервер сам завантажує файл і кладе його в наш bucket. Живе посилання не граємо.
  - Захист (SSRF): лише `https:`/`http:`; резолв імені й відхилення приватних, loopback, link-local і метаданних адрес; без редиректів на заборонені адреси (до 3 редиректів, кожен перевіряється); таймаут 8 с; читання потоку з жорстким лімітом 1 МБ; перевірка типу за вмістом (magic bytes), не лише за заголовком; тривалість ≤ 10 с.
  - Помилки — ключі в `lib/constants/api-errors.ts` з перекладами; сирий текст чужого сервера користувачу не показуємо.

## API (акаунт, `requireAuth`; усе в межах `userId`)

- `GET /api/sound-library` → `{ sounds, presets }` (з ледачим створенням стартових пресетів).
- `POST /api/sound-library` створити звук; `PATCH/DELETE /api/sound-library/[id]`.
- `POST /api/sound-library/upload-url`; `POST /api/sound-library/import`.
- `POST /api/sound-presets`; `PATCH/DELETE /api/sound-presets/[id]` (ім'я, `slots`, порядок); `POST /api/sound-presets/reorder`.
- Схеми Zod у `lib/schemas/soundboard.ts`: `slots` — рівно 9, кожен елемент або `null`, або рядок; сервіс перевіряє, що кожен id належить акаунту або є відомим builtin.
- Відтворення: `POST /api/campaigns/[id]/sounds/play { soundId, nonce }` лишається, але `requireDM` кампанії, і `soundId` перевіряється як звук **цього ДМ** (власник кампанії = автор бібліотеки) або builtin. Подія в каналі несе `{ soundId, url, volume, nonce }`, щоб гравцям не потрібен був доступ до бібліотеки ДМ. Гравці отримують підписаний/публічний URL файлу; bucket `soundboard` читається публічно за незгадуваним шляхом (як зараз).
- Старі `/api/campaigns/[id]/sounds*` (CRUD, reorder, hidden-builtin) прибираються.

## UI

**Сторінка «Бібліотека звуків»** (акаунт ДМ, маршрут `/library/sounds`, пункт у меню профілю). Дві секції:
- **Звуки**: сітка плиток (іконка, підпис, ▶ прослухати); «Додати»: файл / запис / посилання; діалог редагування (підпис, іконка з набору, колір, гучність, видалити). Вбудовані показані окремо, лише читання.
- **Пресети**: список; редактор пресету — сітка 3×3, клік по слоту відкриває вибір звуку (бібліотека + вбудовані, пошук `useSearch`); створити, перейменувати, видалити, змінити порядок.

**Панель «Звуки»** (бій десктоп/мобільний, «Показ», док сценарію — місця не змінюються): зверху вибір пресету (`SelectField`), нижче сітка 3×3 з гарячими клавішами 1–9; режим редагування замінюється кнопкою «Замінити слот», що відкриває `ResponsiveDialog` з вибором звуку та посиланням «Відкрити бібліотеку». Останній пресет кампанії в `localStorage` (`soundboard.preset.<campaignId>`), без стану на сервері.

**Мобільний вигляд**: сторінка в одну колонку; сітка пресету лишається 3×3.

## Поза обсягом

YouTube-звуки; спільні/публічні пресети між акаунтами; ефекти (fade, loop); світові/авто-тригери звуків; перенос власних звуків зі старої таблиці.

## Ризики

- SSRF в імпорті — головний (див. захист). Окремий набір тестів на заборонені адреси.
- Запис мікрофона: дозвіл браузера, відсутність `MediaRecorder` на частині мобільних → ховаємо кнопку, лишаються файл і посилання.
- Видалення звуку, що стоїть у пресеті: очищення слотів у транзакції; тест на це.

## Тести

Схеми Zod (9 слотів, чужий id); сервіс (ліміти, очищення слотів, ледаче створення стартових пресетів, ідемпотентність); імпорт (приватні IP, редиректи, ліміт, тип за вмістом); route-тести авторизації по акаунту; хуки; компоненти (панель з перемиканням пресету, діалог слота, сторінка). Перед merge — один повний `test:run`, перевірка в браузері на реальному Pusher: два вікна (ДМ + гравець), пресет → пад → звук у гравця.
