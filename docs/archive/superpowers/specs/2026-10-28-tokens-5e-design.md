# Токени 5e: іконки й токени юнітів у шаблоні SRD 5.2

Гілка `feat/tokens-5e`. Дата: 2026-10-28.

## Мета

Записи офіційного шаблону «5e SRD» (юніти, заклинання, артефакти) мають власні зображення, а не порожню іконку / значок школи. Клони й кампанії отримують їх через «Оновлення з джерела».

## Вхідні дані

Джерело: `~/Downloads/fantasy-tokens/output/v2` (поза репо, 1579 PNG 768², ~670 МБ).

- `catalog.csv`: `record_id` (`spell:srd-2024_…`, `unit:…`, `artefact:…`), `image_path`.
- Беремо лише `icons/spell`, `icons/artefact`, `tokens/unit`. `raw/` і `metadata/` ігноруємо (prompt/seed потрібні лише для довідки).
- `slug` рядка шаблону = `record_id` без префікса виду. Види: `spell`→`spells`, `unit`→`units`, `artefact`→`artifacts`.

Збіг: юніти 331/331, заклинання 488/498 (10 `dragonborn-breath-*` без іконки), артефакти 248 прямих із 333.

## Рішення

1. **Ліцензія.** Зображення — власні AI-генерації користувача (`generate.py`), не сторонній набір. Це не суперечить рішенню 2026-10-23 «сторонніх іконок немає». Прапорця `--allow-official` немає; `credits` залишається SRD-атрибуцією, змін немає. Рядок у `content-api.md` «Іконки — сторонніх наборів немає» уточнюється.
2. **Артефакти-«шаблони властивості»** (в шаблоні один запис, у каталозі варіанти `<slug>-<база>`): варіант береться лише для них: кандидат, чий slug сам є slug шаблону того ж виду (базова зброя/обладунок, магічний предмет з власним записом), пропускається; серед решти перевагу має `<slug>-plus-1`, інакше перший за алфавітом. Базовий предмет ніколи не бере арт іншого предмета. Прямий збіг має пріоритет.
3. **Обсяг:** лише шаблон SRD + source-sync. Скрипта для наявних кампаній немає. Іконки, які ДМ поставив у клоні, source-sync не перезаписує за наявними правилами `conflict`.
4. **Формат і вага (egress).** `sharp` → webp: заклинання й артефакти 256 px, юніти 384 px, ціль ≤ 40 КБ/файл, загалом ~30 МБ. Завантаження в наявні бакети `spell-icons`, `artifact-icons`, `unit-icons` через `staticAssetUploadOptions` (cacheControl рік, immutable). Ім'я об'єкта `<templateId>/<kind>/<slug>-<sha1>.webp`. Відображення через `next/image`.
5. **Джерело правди про URL** — `data/templates/srd-5.2/icons.json` (`{ spells|units|artifacts: { slug: url } }`), у репо без самих картинок. Завантажувач `constructor:srd-template` підмішує `icon` (units — `avatar`) у рядки перед `importContent`, тож повторний `srd:build`/завантаження іконки не втрачає.
6. **Прод.** Спочатку локальна БД / `prodcopy`. Завантаження в прод-бакети, прод-імпорт і мердж/пуш — лише після явного підтвердження користувача. Кеш довідника оновиться за `REFERENCE_REVALIDATE_SECONDS` = 300 с.

## Reuse-аудит

| Є | Використовуємо |
|---|---|
| `scripts/assets/attach-lib.ts`: `ICON_FIELD`, `ASSET_BUCKET`, `IMAGE_TYPES`, `objectPath` | так, без копіювання; `objectPath` отримує ключ за slug |
| `staticAssetUploadOptions`, `ensureBucket`, `createAdminClient` | так |
| `importSrdData` / `readSrdData` у `scripts/srd/lib` | розширюємо підмішуванням `icons.json` |
| `matchAssets` (збіг за назвою файлу) | ні: тут точний збіг за slug із каталогу |

Нове: `scripts/assets/tokens-5e/` (чиста логіка: розбір каталогу, мапінг slug→файл, вибір варіанта; CLI: конвертація+завантаження+запис `icons.json`), підмішування в `scripts/srd/lib/load-template.ts`.

## Скрипт `pnpm assets:tokens-5e <templateId> [--dir <v2>] [--dry-run] [--allow-remote]`

1. Парсить `catalog.csv`, відкидає не-`spell|unit|artefact`.
2. Мапінг на slug-и `readSrdData()`; звіт: у каталозі без шаблону, в шаблоні без каталогу.
3. sharp → webp, upload (пропуск, якщо об'єкт уже є: ім'я містить хеш), запис `icons.json` (стабільне сортування ключів).
4. `assertSeedTarget`; `templateId` має бути кампанією-шаблоном `SRD_TEMPLATE_NAME`; `--dir` без значення — помилка. Слаги без вибору видаляються з `icons.json`. Прапорця `--allow-official` немає (власні іконки).

## Тести

- Парсер каталогу, мапінг slug (прямий і варіантний), детермінований вибір першого варіанта, звіт про відсутні.
- `icons.json` → підмішування в рядки (`avatar` для юнітів, `icon` для решти; без запису — рядок незмінний).
- Цілісність: кожен slug в `icons.json` існує в шаблоні; URL з очікуваного бакета; `data-integrity` залишається зеленим.

## Перевірка вживу

Локальна БД → `pnpm constructor:srd-template` → у шаблоні видно іконки; клон → «Оновлення з джерела» показує оновлення й застосовує. Розмір завантаженого за одним файлом (≤ 40 КБ) і загальний звіт.
