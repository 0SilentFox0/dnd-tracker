# Вибір ефектів крита/провалу ДМом (нат. 20 / нат. 1)

Дата: 2026-10-28. Статус: чернетка на рев'ю.

## Мета

Опціональне налаштування кампанії: коли випадає нат. 20 або нат. 1, ефект обирає ДМ у модальному вікні зі списку. Вимкнено — ефект обирається випадково зі списку (як зараз для атак). Додатково з'являються крит-ефекти для заклинань (рятівні кидки цілей).

## Рішення, прийняті в брейнстормі

- Налаштування живе в блоці «Правила» діалогу «Налаштування кампанії».
- «Кастомні» = вибір ДМа з готового списку, власні ефекти не створюються.
- Атака (або каст) **чекає** на вибір ДМа: ефекти «×2 / макс. урон» застосовуються до цієї ж дії.
- Для заклинань тригер — нат. 20 / нат. 1 на **рятівному кидку цілі**; для них окремі таблиці ефектів. Кидків на влучання заклинаннями немає і не додаються.
- При вимкненому налаштуванні нат. 20/1 на спасках теж дають випадковий ефект (зміна поведінки для всіх кампаній).

## Реюз

`lib/constants/critical-effects.ts` (таблиці, `getRandomCriticalEffect`), `lib/utils/battle/attack/critical.ts` (`applyCriticalEffect`, `critFlavorFor`), патерн `pendingMoraleCheck` (`turn/pending-morale.ts`, `store/*`, `pipeline/client-delta.ts`, `client/apply-delta.ts`), `runBattleMutation`, `ResponsiveDialog hud`, діалог налаштувань кампанії. Нове потрібне лише для: таблиць спасків, збереженого запиту з сідом, роута `crit-choice`, модалки.

## 1. Налаштування

- `campaigns.critChoiceByDm Boolean @default(false)` — expand-only міграція (нова колонка, нових таблиць немає, RLS не потрібен).
- Додати в Zod-схему оновлення кампанії, `types/api.ts` (поруч із `friendlyFire`), `lib/api/campaigns`, форму налаштувань (чекбокс «ДМ обирає ефекти крита/провалу»), `store/types.ts` + `loadBattle` (прапор доступний у пайплайні).

## 2. Тригери та таблиці

**Атаки** — без змін у тригерах (`critThreshold` + нат. 1), таблиці `CRITICAL_SUCCESS_EFFECTS` / `CRITICAL_FAIL_EFFECTS`.

**Спаски цілей** — `finalRoll` у `rollSavingThrow` (`spell/cast/outcome.ts`): нат. 20 → «успіх спаска», нат. 1 → «провал спаска». Ефект діє на ціль, що кидала.

Нові таблиці `SAVE_SUCCESS_EFFECTS` / `SAVE_FAIL_EFFECTS` (`lib/constants/save-critical-effects.ts`, та сама форма `CriticalEffect` з `flavor`). Пропозиція вмісту (на рев'ю):

| # | Успіх (ціль) | Тип |
|---|---|---|
| 1 | Повне уникнення: шкода 0 навіть при «половині» | новий `negate_damage` |
| 2 | Контр-ритм: advantage на наступну атаку | `advantage_next_attack` |
| 3 | Вільна атака по кастеру | `free_attack` |
| 4 | Гарт: +2 КЗ до кінця раунду | новий `ac_buff` |
| 5 | Скидання: заклинання не накладає статусів | новий `negate_effects` |
| 6 | Другий вдих: додаткова бонусна дія | існуючий helper `grantExtraActions` |

| # | Провал (ціль) | Тип |
|---|---|---|
| 1 | Подвійна шкода від заклинання | `double_damage` (множник на цю ціль) |
| 2 | Збитий з ніг | `prone` |
| 3 | Збентеження: disadvantage на наступну атаку | `disadvantage_next_attack` |
| 4 | Прогалина в захисті: −2 КЗ | `ac_debuff` |
| 5 | Втрата реакції | `lose_reaction` |
| 6 | Втрата бонусної дії | `block_bonus_action` |

Нові типи додаються в `CriticalEffectType` і в `SPECS`/обробку `critical.ts`; точна реалізація — у плані.

## 3. Потік і стан

`battle_scenes.pendingCritChoice Json?` (міграція expand-only):

```ts
interface PendingCritChoice {
  action: "attack" | "spell";
  request: unknown;        // вихідне тіло запиту (з кидками клієнта)
  seed: number;            // сід rng серверних кидків
  actorId: string;
  triggers: Array<{ key: string; source: "attack" | "save"; kind: "success" | "fail"; targetId: string }>;
}
```

1. Клієнт шле звичайний запит (`attack` / `spell`; `preview`/`dryRun` pending не створюють).
2. Мутація рахує дію з сідованим rng. Якщо `critChoiceByDm` увімкнено, є тригери і в запиті немає `critChoices` — нічого не застосовується: пишеться `pendingCritChoice`, піднімається `version`, delta по Pusher; відповідь запиту = «очікує вибору». Інакше дія застосовується як зараз; ефекти — з `critChoices[key]` або випадково (сід).
3. Роут `app/api/campaigns/[id]/battles/[battleId]/crit-choice/` (Zod `{ choices: Record<key, effectId | "random"> }`, `runBattleMutation`, доступ лише `dm`): бере збережений запит і сід, повторює мутацію з вибором, чистить pending.
4. Поки pending є, інші дії бою відхиляються (`BattleRuleError`, як `assertMoraleResolved`). Відкат (`rollback`) і `reset` чистять pending.
5. Атаки самого ДМа йдуть тим самим шляхом (одна логіка, без локальної гілки); його клієнт бачить pending і відкриває модалку.
6. Прапор, змінений посеред pending, на нього не впливає — pending розв'язується у будь-якому разі.

**Сід:** усі серверні кидки (NPC, cleave, другий d20, кубики шкоди) мають іти через `rng`, який у плані перевіряється аудитом і покривається тестом «повтор із тим самим сідом = той самий результат». Якщо знайдеться кидок поза `rng` — виправити в межах цієї фічі.

## 4. UI

- `components/battle/crit-choice/CritChoiceDialog` на `ResponsiveDialog hud`, не закривається без вибору; один рядок на тригер (хто/проти кого, список ефектів: назва, опис, успіх/провал), кнопка «Випадково» для рядка й для всіх. `Підтвердити` у `footer` з `form=`.
- Hook `useCritChoice` у `lib/hooks/battle` (читає `scene.pendingCritChoice`, викликає mutation з `lib/api/battles`); компоненти не імпортують `@/lib/api/*`.
- Гравці (не ДМ) бачать банер «ДМ обирає ефект…» без дій. ДМ офлайн — бій стоїть; вихід: відкат/reset.
- Wizard атаки/заклинання (`useAttackWizard`, spell flow) обробляє відповідь «очікує вибору»: показує стан очікування і підхоплює результат із delta/логу після розв'язання.

## 5. Налаштування кампанії (UI)

Чекбокс у блоці «Правила» поруч із «Дозволити гравцям редагувати персонажів», із підказкою одним рядком про поведінку.

## 6. Тести

- Таблиці: id унікальні, `flavor` непорожній, всі типи мають обробник.
- Спаски: нат. 20/1 → тригер; ефекти застосовуються до цілі; `negate_damage` прибирає й «половину».
- Пайплайн: прапор вимкнено → випадково без pending; увімкнено → pending, повтор із сідом дає ідентичний результат, `crit-choice` лише для `dm`, відхилення дій під час pending, відкат чистить pending.
- Компонент: модалка (вибір, «Випадково», кілька тригерів), банер для гравця.
- Міграції: `migrations-rls` лишається зеленим (нових таблиць немає).

## Ризики

- Детермінізм повтору (див. сід) — основний технічний ризик.
- Зміна поведінки для всіх кампаній: випадкові ефекти на спасках.
- Зупинка бою при офлайн-ДМі — прийнято.
- Багатоцільові заклинання/волеї дають кілька тригерів в одній модалці — тестується окремо.

## Поза обсягом

Власні ефекти, створені ДМом; кидок на влучання для заклинань; різні налаштування для атак і заклинань окремо.
