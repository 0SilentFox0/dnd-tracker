# Слайд лише для визначених героїв («Показ»)

Гілка `feat/slide-audience` (worktree `../dnd-tracker-audience`). Підхід A із завдання.

## Мета

DM позначає слайд набору як «лише для героїв X, Y». Інші гравці бачать **останній слайд зі стежки, доступний їхнім героям**. Приховування справжнє: прихований слайд не потрапляє в payload Pusher і відповіді `GET /show` для героїв поза аудиторією.

## Дані

- `Slide.audience?: string[]` — id героїв; відсутнє = усім. Zod (`lib/schemas/show.ts`, `slideSchema`): `z.array(slideIdLike).min(1).max(AUDIENCE_MAX)`, унікальні; `refine`: слайд із `kind: "puzzle"` не може мати `audience` (`show.validation.puzzleAudience`). Існування героя в кампанії не перевіряємо (id лише порівнюються; видалений герой = ніхто не бачить слайда, у UI показуємо лічильник).
- Міграція (expand-only, нова таблиця не створюється → RLS не потрібен): `campaign_shows.trail JSONB NULL`.
- `ShowState.trail?: SlideTrailEntry[]` — **лише серверне**; `SlideTrailEntry = { slide: Slide }` (знімок слайда без `kind`/`puzzle`, `audience` зберігається). Ніколи не залишає сервер: усі виходи (`GET`, відповіді команд, Pusher) проходять через `toClientShow`/`playerShowView`, які знімають `trail`.

## Стежка (`applyShowCommand`)

Стежка містить лише те, що може знадобитись як fallback:

- `open` → `[target]`; `end` → `[]`.
- `next`/`prev` (слайд змінився) → додати цільовий слайд; попередні входи з тим самим `id` прибрати.
- **Компактація:** слайд без `audience` скидає все, що було до нього (хід назад від будь-чого після нього все одно зупиниться на ньому). Тому стежка = `[останній публічний, обмежені після нього…]`, зазвичай 1–3 записи; додатково ліміт `TRAIL_MAX = 30` (найстаріші відкидаємо; герой, що спирався на відкинуте, бачить заглушку).
- Команди `curtain`/`world`/`battle`/`audio`/`setCover` стежку не змінюють.
- `refreshShowSlide` (збереження набору): оновлює останній запис стежки знімком поточного слайда (створює `[slide]`, якщо порожньо); `sameSlide` порівнює і `audience`. Старіші записи не оновлюються (знімки).
- `nextImageUrl` на сервері = картинка наступного слайда **лише якщо той публічний**, інакше `null` (запобігає витоку через prefetch; ціна — немає прелоаду для обмежених слайдів).
- `setCover` для слайда з `audience` → 422 `SHOW_COVER_RESTRICTED` (заглушка публічна). У UI ☆ для 🔒-слайдів прихована.

## Вигляд гравця

`playerShowView(show, heroIds): ShowState` у `lib/utils/show/player-view.ts`; чиста, `trail`/`audience` зі свого результату знімає.

1. `curtain`, `world`, відсутній слайд, пазл — як раніше (пазл завжди публічний; `world`/`battle`/`cover` теж).
2. Поточний слайд публічний або `audience ∩ heroIds ≠ ∅` → віддаємо як є (`nextImageUrl`, `audio`, `puzzle` — без змін).
3. Інакше йдемо стежкою від кінця назад до першого доступного запису; знайшли → `slide = той запис` (пазл-знімок уже без `kind`), `nextImageUrl: null`, `puzzle` прибрано.
4. Не знайшли → `slide: null` → клієнт уже вміє: заглушка кампанії (`cover`) або екран очікування.
5. `deckId`/`deckTitle`/`seq` лишаємо (не секретні). `seq` — реальний.

### Музика

Гравець синхронізується з тим самим `audio`-станом (позиція за `startedAt`, окремої синхронізації немає). Єдина зміна: якщо `audio.trackId` збігається з `trackId` слайда, який герой **не бачить** (поточний прихований слайд або прихований слайд між ним і fallback-слайдом, береться зі стежки), гравцеві віддаємо `audio: null` — мовчить і `trackId` не витікає. Інакше `audio` як є: трек доступного слайда, що вже грає, продовжує грати; окремо запускати для гравця трек fallback-слайда не потрібно (це складніше: власний годинник позиції). Відомий компроміс: ручний `audio play` DM того самого треку, що й у прихованого слайда, теж мовчить для гравця.

## Транспорт

- `publishShow` сам вирішує: **якщо останній запис стежки має `audience`** (поточний слайд обмежений) → Pusher `show-state` шле `{campaignId, seq}`; інакше повний payload, як зараз. Завдяки компактації пазл-ігри та звичайні слайди ніколи не потрапляють у thin-режим.
- Клієнт (`usePusherShowSync`): подія без `show`, але з числовим `seq` більшим за кешований → `invalidateQueries(showKeys.state)` → один `GET /show` (його відповідь вже відфільтрована для цього користувача). Менший/рівний `seq` ігноруємо. Подій більше не стає; на кожну зміну слайда — один GET на гравця.
- `GET /show` (`readShow`, його ж використовує prefetch у `app/campaigns/[id]/show/page.tsx`): ДМ → повний стан без `trail`; гравець → `playerShowView(show, heroIds)`, `heroIds` читаємо з БД лише коли стан обмежений (є `audience` у стежці). Демо-глядач без героїв → `heroIds = []`.
- Відповіді `POST /show` (ДМ) — повний стан без `trail`; `POST /show/puzzle` (гравець) — через `playerShowView` (поточний слайд пазла публічний, але `nextImageUrl`/`trail` у відповідь не повинні піти без фільтра).
- Assistant `runtime-effects` публікує через той самий `publishShow`; перевірити в плані, що `trail` переживає JSON-серіалізацію ефекту.

## UI

- `SlideDialog`: секція «Бачать герої» — «Усі» (за замовчуванням) / «Лише обрані» + чекбокси героїв кампанії (`useCharacterRoster`, лише `PLAYER`-герої). Для пазла секція не рендериться. Помилка валідації «оберіть хоча б одного».
- `ShowDeckStrip`: значок 🔒 (`Lock`, aria-label) на мініатюрі, тултип зі списком імен. Поруч із `Music`.
- ДМ-режим «Вигляд гравця»: лишається клієнтським (ДМ-payload повний), тож показує реальний слайд; зафіксовано як обмеження в `show.md`.
- Тексти — `messages/{uk,en}/show.json`, `errors.json`, `validation` (Cyrillic у коді заборонена). Запис у `whats-new` і hint не потрібен: фіча DM-інструмент без нового екрана — **питання до тебе** (див. нижче).

## Тести

- `playerShowView`: публічний слайд; доступний; недоступний → fallback зі стежки; порожній збіг → `slide: null`; кілька героїв одного гравця (перетин хоч з одним); `curtain`; `world`; пазл; музика (прихований трек → `audio: null`, публічний → як є); `trail`/`audience` у результаті відсутні.
- `applyShowCommand` + `trail`: open скидає, next/prev додають, компактація на публічному слайді, дедуп, `TRAIL_MAX`, `refreshShowSlide` оновлює останній запис, `nextImageUrl` null перед обмеженим, `setCover` відхиляє обмежений.
- Схема: `audience` порожній/дубль/пазл → помилка.
- `GET /show` для героя поза аудиторією: у тілі немає прихованого `imageUrl`/`caption`/`trackId`/`nextImageUrl`; ДМ бачить усе; герой у аудиторії бачить.
- `publishShow`: thin payload для обмеженого поточного слайда, повний — для публічного.
- `usePusherShowSync`: thin-подія → refetch лише при більшому `seq`.
- Компонентні: `SlideDialog` (вибір героїв, пазл без секції), `ShowDeckStrip` (🔒).

## Поза обсягом

Окремий годинник музики для fallback-треку; оновлення знімків старих записів стежки при редагуванні набору; приховування в режимі «Вигляд гравця» ДМ; обмеження для `world`/`battle`/`cover`.
