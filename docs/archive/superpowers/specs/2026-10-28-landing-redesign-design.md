# Редизайн лендінгу (v2)

## Мета

Переписати публічний лендінг `/` під ДМів як головних покупців. Головний меседж — **кастомні механіки + автоматизований тактичний бій** в одному середовищі (підготовка → правила → бій). Не «універсальний рушій»: фокус — D&D-подібні покрокові настільні RPG. Продукт незалежний, жодної афіліації з D&D / Wizards of the Coast.

## Рішення (узгоджено)

- Мови: англійська (основна) + українська. `/` — EN, `/uk` — UK. Спільні компоненти, тексти в `content.en.ts` / `content.uk.ts` за одним типом `LandingCopy` (відсутній ключ = помилка tsc). `alternates.languages` (hreflang), перемикач — звичайне посилання.
- Візуал: еволюція наявної HUD-естетики (`hud.css`, золотий метал, темні поверхні), не нова дизайн-система.
- Бренд: назва не фіналізована. Одна константа `BRAND` (`lib/constants/site.ts`): `name`, `short`, `mark` (текст у «d20»-знаку). Метадані, JSON-LD, шапка, футер, OG беруть її звідти. Без чужих торгових марок у назві/заголовку; «D&D 5e» лише як сумісність («5e-style rules»).
- `/` лишається статичним: root layout без cookies, `SessionSwitch`, `.ld-lazy`, inline CSS. Ціль — Lighthouse не гірший за поточний (mobile ≥ 90).
- Без нових залежностей. Індексація як і раніше керується `SITE_INDEXING`.

## Reuse (CLAUDE.md)

`components/landing/*` (LandingHero, LandingSections, SessionDemo, SessionSwitch, AiMock, landing.css), `components/hud`, `SITE_URL`, `app/robots.ts`, `app/sitemap.ts` (додати `/uk`), наявні `public/landing/*`. Нове: dictionary-розділення текстів, `BRAND`, секції «Custom mechanics» і «World & prep», нові скріни.

## Структура сторінки

1. **Hero** — заголовок: «Your world. Your rules. Combat that runs itself.» (UK: «Ваш світ. Ваші правила. Бій, що рахує сам.»). Підзаголовок: DM-платформа, що поєднує підготовку кампанії, власні механіки й тактичний бій. Primary CTA — «Start a campaign» → `/sign-up` (член сесії → «My campaigns»); secondary — «See how it works» (якір). Реальний скрін бою + наявне CSS-демо (SessionDemo) за потреби.
2. **Problem** — коротко: нотатки, листи, ініціатива, мапа, музика, показ у різних інструментах. Прибрати лічильники-стати («0 сервісів», «53 анімації»).
3. **Tactical combat** (найсильніша): ініціатива/черга, атаки, заклинання, зони, стани й рятівні, укриття/стрільба, мораль, ДМ-вибір критів, синхронізація DM↔гравці в реальному часі, журнал бою, FX і 3D-кубики, баланс зустрічі (`computeFairScaling` / XP-бюджет 5e), мобільний доступ гравців. Скрін бою + 2–3 ключових тези.
4. **Custom mechanics** — раси, класи, юніти, вміння, заклинання, артефакти, власні атрибути/прогресія, тригерні механіки й формули (abilities), перемикачі правил (мораль, крити, ініціатива, відпочинки). Імпорт CSV/TSV/JSON. Відкрите API (OpenAPI/MCP). Подавати як налаштування, не як IDE. Скріни конструктора/вміння.
5. **Campaign prep** — редактор сценарію (рукопис, глави/сцени, нотатки ДМ, секрети, зображення), прив'язка слайдів і боїв до рядків, «Зіграно», бібліотеки, шаблони, карта світу (туман, маркери, подорож героїв, нотатки), дашборд «Що далі», збережений стан кампанії.
6. **AI assistant** — на власному ключі (Claude/OpenAI/Gemini); бачить сценарій/сцену й інструкції кампанії; пропозиції правок із переглядом перед застосуванням; живий чат під час сесії; генерація зображень для показу; MCP для зовнішніх агентів. Явно: не «пам'ятає все», ДМ приймає кожну правку.
7. **Player experience** — телефон, свій герой/хід/заклинання, показ сцен і музика синхронно, пазл, довідник дозволеного ДМ, чернетки героїв. ДМ у центрі наративу.
8. **How it works** — 4 кроки: створити/імпортувати контент → підготувати сценарій і механіки → запросити гравців кодом → вести сесію.
9. **FAQ + Final CTA** — стисло; без цін, trial, лічильників користувачів, відгуків. FAQ оновити (редакції/сумісність, чи потрібні інші програми, що потрібно гравцям, як працює AI/ключі, як із імпортом).

## Правдивість (обмеження копірайту)

Джерело правди — код і `docs/architecture`. Не писати:
- «безкоштовно» / `offers.price` у JSON-LD — прибрати; ціни не фіналізовані.
- «пам'ятає всі події», «імпорт працює ідеально», відео, «усі RPG-системи».
- **Готові офіційні шаблони (HOMM5/5e SRD/Порожня) на prod ще не створені** (STATUS.md) — до їх публікації писати «start from scratch or import content», згадку шаблонів тримати за прапором `LANDING_TEMPLATES` (false за замовчуванням, вмикається разом з сидингом).
- Генерація зображень на prod не перевірена (потрібен платний ключ) — формулювати «з вашим ключем провайдера», без обіцянок якості.
- Імпорт Obojima не готовий до гри ([план](../plans/2026-10-28-obojima-import-fixes.md)) — не згадувати Obojima; імпорт описувати як «структурований імпорт із перевіркою по рядках».
- Перед фіналом пройтися по кожній тезі проти коду; список «тверджень → файл-доказ» додати в PR.

## Скріншоти

Нові скріни з реального продукту (локальна prodcopy, браузер-субагент на Sonnet, 1440 і 390 px): бій, лист героя, сценарій, показ, карта світу, конструктор (вміння/правила), AI-панель, телефон гравця. WebP, ≤ ~100 KB кожен, `next/image`, осмислені `alt`. Імена/токени у стилі 5e, без HOMM-арту (як і раніше). `AiMock` лишається, якщо реальний скрін AI недоступний — без вигаданих відповідей, що суперечать реальному UI.

## Метадані й SEO

`app/page.tsx` (EN) і `app/uk/page.tsx` (UK): title, description, canonical, `alternates.languages`, OG/Twitter (+ `locale`), JSON-LD `WebApplication` + `FAQPage` з відповідної мови, без `offers`. `sitemap.ts` — обидві URL. `lang` ставиться на обгортку лендінгу (`<div data-landing lang=…>`); root `<html lang="uk">` не чіпаємо, щоб не ламати статичність і не реструктурувати route-групи.

## Доступність і продуктивність

Семантичні `h1/h2`, контраст AA на темних поверхнях, `prefers-reduced-motion` для CSS-анімацій, без горизонтального скролу на 360–1440 px, фіксовані розміри зображень проти CLS. Нижні секції — `.ld-lazy`.

## Тести й перевірка

- Vitest: ключі `LandingCopy` EN/UK збігаються (tsc + тест на непорожні рядки), JSON-LD без `offers`, `BRAND` єдине джерело (grep-тест на зашиту назву в `components/landing` і `app/page.tsx`).
- tsc, `pnpm lint`, `pnpm test:changed`, `pnpm build` (перевірити `○ /` і `○ /uk` статичні).
- Браузер (Sonnet-субагент): 1440/768/390, перевірка CTA, якорів, перемикача мов, відсутності overflow; Lighthouse mobile/desktop.
