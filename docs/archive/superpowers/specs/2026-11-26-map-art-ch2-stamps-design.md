# Карти бою — Ч2: штампи + пайплайн ассетів

Епік: `2026-11-26-map-art-epic-design.md`. Ч1a/Ч1b (ребра гексів, арт-сцена, запікання) злито в `main`. Ч2 заповнює зарезервоване поле `stamps` сцени і дає пайплайн ассетів. Далі: Ч3 (генератор), Ч4 (AI-полірування).

## 1. Рішення власника (2026-11-26)

- Штампи — вільні екземпляри (позиція, поворот, масштаб, flip, порядок), не прив'язані до клітинки; працюють на квадраті й гексі.
- **Механіка:** прапорець у реєстрі. Штамп із `blocks` блокує клітинки під своїм footprint; решта — чистий декор. Механіка виводиться зі сцени (як для стін).
- **Обсяг ассетів:** усі 4 біоми (підземелля/печери, будівлі, природа, поселення); промпти для всіх, генерація власником лише P1 кожного біому, P2 додається пізніше без коду.
- Ассети генеруємо AI за нашими промптами в єдиному стилі; DM-завантаження — поза Ч2.
- Перші штампи — 35 наявних прозорих об'єктів тайлового редактора (`public/assets/battle-tiles/objects`).

## 2. Поточний стан (main cd5701cd6)

- `types/battle-map.ts MapArtScene.stamps: []`; `lib/schemas/map-art.ts` — `stamps: z.tuple([])`, ліміт тіла `MAP_ART_LIMITS.bodyBytes` 2 MB.
- Painter `lib/utils/canvas/map-art/` (`paint-scene.ts`: підлоги → стіни → отвори → світло; `assets.ts`: `ArtAssets`, `PaintEnv`, `artTextureUrls`/`loadArtAssets`). Той самий код для прев'ю й запікання (`bake.ts`).
- `lib/utils/battle/map-art/derive.ts deriveMechanics(scene, grid)` → `walls/bars/doors/blocked`; `blocked` береться лише зі `scene.blocked`.
- Редактор: `components/maps/editor/art/*`, `lib/hooks/battle-maps/useMapArtEditor.ts` (історія, `ArtTool`, матеріали), `useMapArtSave`.
- Тайлові об'єкти (35) досі живуть у шарі `objects` тайлових chunk'ів і малюються `components/battle/map/tiles/painter.ts`; `scripts/maps/convert-tiles-to-art.ts` переносить лише ground/wallfill (об'єкти «stay»).
- Конвенція промптів: `docs/assets/tile-prompts/` (CSV + MD + README, `#FF00FF`-ключ), скрипт `pnpm assets:tiles` (`scripts/assets/tiles/{validate,upload,upload-lib}.ts`).

## 3. Модель даних

```ts
interface MapArtStamp {
  id: string;            // унікальний у сцені, ≤40
  asset: string;         // id із реєстру штампів
  x: number; y: number;  // центр, map units (UNIT = 1 клітинка), у межах карти
  rot: number;           // градуси 0..359.9
  scale: number;         // 0.25..4
  flip: boolean;         // віддзеркалення по X
  z: number;             // ціле, порядок усередині шару реєстру
}
```

- `scene.stamps: MapArtStamp[]` (замість `tuple([])`). Порожній масив сумісний із наявними рядками, тому `v` лишається 1 і міграція БД не потрібна.
- Ліміти: `MAP_ART_LIMITS.stamps = 2000`; тіло залишається ≤2 MB (перевіряється наявним `bodyBytes`).
- Валідація (`refineSceneForMap`): невідомий `asset`; `x/y` поза картою; дубль `id`; для `blocks`-штампів — ліміт сумарної кількості виведених блокованих клітинок `MAP_LIMITS.maxTerrainCells`.
- `clipScene` відкидає штампи, центр яких поза новим розміром карти.

## 4. Реєстр штампів

`lib/constants/map-art/stamps.ts` (+ `stamps-data.ts`, згенеровані дані). Запис:

```ts
interface StampDef {
  id: string; biome: 'dungeon'|'building'|'nature'|'settlement';
  category: string;           // furniture, plant, rock, light, decor, ...
  nameKey: string;            // i18n: maps.editor.stamps.name.<id>
  file: string;               // public/assets/map-stamps/<biome>/<id>.webp
  cols: number; rows: number; // розмір при scale 1, у клітинках (дробові)
  layer: 'decal'|'object'|'canopy';
  shadow: 'none'|'soft'|'hard';
  blocks?: { shape: 'rect'|'ellipse'; w: number; h: number }; // footprint у клітинках
}
```

- `layer`: `decal` — під стінами (калюжі, плями, килими); `object` — звичайні; `canopy` — над стінами (крони, прапори, балки).
- Дані (`stamps-data.ts`) генеруються з маніфесту `docs/assets/stamp-prompts/stamps.csv` скриптом (див. §7), щоб CSV був єдиним джерелом правди; тест перевіряє, що згенероване збігається з CSV.
- 35 наявних об'єктів реєструються з `file`, що вказує на їхні теперішні файли (без дублювання); `blocks` — за колишнім `passable`/footprint каталогу тайлів. Імена і ключі i18n перевикористовуються з `maps.editor.tiles.name.*`.

## 5. Механіка

`deriveMechanics(scene, grid)` отримує `map` (розміри) замість голого `grid` лише там, де потрібно (сигнатура `deriveMechanics(scene, map)`, grid береться з `gridOf(map)`). Блоковані клітинки = `scene.blocked` ∪ клітинки зі штампів `blocks`:

- footprint = rect/ellipse `w×h` клітинок × `scale`, центр `(x, y)`, поворот `rot` (flip на форму не впливає);
- клітинка блокується, якщо її центр (`cellCenter`) лежить усередині фігури; клітинка, що містить центр штампа, блокується завжди;
- одне правило для квадрата й гекса; клітинки поза картою відкидаються;
- штамп не зберігає клітинок: при зміні/видаленні штампа вони зникають після наступного Save.

Чиста функція `stampBlockedCells(stamps, map): Set<string>` у `lib/utils/battle/map-art/stamp-cells.ts`; `deriveMechanics` її викликає. Бій, snapshot і мутації не змінюються (читають `map.blocked`).

## 6. Painter

Новий `lib/utils/canvas/map-art/paint-stamps.ts`; `paint-scene.ts` викликає в порядку:

підлоги → `decal` → стіни й отвори → `object` → `canopy` → світло.

- Сортування всередині шару: `z`, потім `y`, потім `id` (детерміновано).
- Малювання: `translate(px,py) rotate scale (flip)`, `drawImage` з центром у `(x,y)`; розмір — `cols/rows × cellPx × scale`.
- Тінь за `shadow`: силует спрайта (offscreen-шар через `createLayer`, `source-in` заливка чорним), зсув і blur ∝ `cellPx` (`soft` — великий blur, малий зсув; `hard` — малий blur, більший зсув); тінь малюється під спрайтом того ж `layer`.
- `clip` (прев'ю по chunk'ах) враховується: штамп малюється, якщо його повернутий bbox перетинає `clip`.
- Завантаження: `loadArtAssets` отримує URL'и штампів сцени (лише використані). У бою ассети не вантажаться (карта запечена); їх вантажить лише редактор і запікання.
- `dirty.ts`: штампи враховуються в обчисленні брудних chunk'ів (bbox → chunk'и).

## 7. Пайплайн ассетів

Тека `docs/assets/stamp-prompts/` за зразком `tile-prompts`: `README.md`, `stamps.csv` (колонки `file,name,biome,category,layer,cols,rows,shadow,blocks,prompt,priority`), `stamps.md`.

- 4 біоми × 40–60 штук, P1/P2. Приблизні P1: підземелля/печери (колони, сталагміти, кістки, ланцюги, саркофаги, багаття, калюжі), будівлі (столи, ліжка, шафи, бочки, каміни, килими, колони), природа (дерева, кущі, каміння, пні, квіти, струмки-декали, огорожі), поселення (лавки, ящики, вози, колодязі, ліхтарі, намети, прилавки, бруківка-декали).
- Єдиний стиль — ядро з `tile-prompts`: painterly fantasy, вигляд суворо зверху, лише м'яка тінь під об'єктом (запечена тінь вимкнена: її малює painter), фон рівний `#FF00FF`.
- **Аркуші:** модель генерує аркуш 3×3 (6–9 об'єктів) на магентовому фоні; скрипт нарізає. Правило: проміжки між об'єктами ≥ 8% сторони, об'єкти не торкаються.
- Скрипт `pnpm assets:stamps <теку|файл-аркуш> [--sheet] [--biome ...] [--upload]` (`scripts/assets/stamps/{slice,validate,build,upload}.ts`):
  - `slice`: пошук зв'язних компонент не-магентового пікселя, bbox з відступом, пошук за порядком у CSV (по рядках зверху вниз, зліва направо) або за ручним мапінгом;
  - ключ кольору: прозорість за відстанню до `#FF00FF` з порогом + зняття магентової каймисті (erode 1 px, despill);
  - нормалізація: масштаб до 256 px на клітинку за `cols/rows` з CSV, обрізання по прозорих краях, WebP, ≤200 KB;
  - `validate`: альфа-канал, відсутність магентової каймисті, розмір, ліміти, унікальність id, відповідність CSV;
  - `build`: генерує `stamps-data.ts` з CSV;
  - `upload`: за зразком `assets:tiles` — лише за прапорцем; ассети йдуть у репо (`public/assets/map-stamps/`), тож «завантаження» = перевірка + копіювання у `public/`.
- Пілот перед масовою генерацією: 6–8 штампів різних біомів (колона, стіл, бочка, дерево, камінь, ліхтар, килим-декаль) → перевірка нарізки, ключа й єдності стилю.

## 8. Редактор

Інструмент «Штампи» у `ArtToolBar` (`ArtTool` += `'stamp'`, `'stamp-select'`):

- **Палітра** (`StampPalette`): вкладки біомів, категорії, пошук; прев'ю = мініатюра; клік обирає ассет.
- **Розстановка:** клік кладе штамп у `(x,y)` (snap до центру клітинки перемикається), привид-прев'ю під курсором; `R`/Shift+R — поворот на 15°, `F` — flip.
- **Вибір і трансформація:** клік по штампу виділяє (hit-test: найвищий за порядком малювання, прозорі пікселі ігноруються через маску `alphaHit`); перетягування, ручка повороту, ручка масштабу (колесо в режимі вибору), `Delete`, `Cmd+D` дублювання, `[` / `]` — z назад/вперед.
- **Оверлей блокування:** для виділеного (і за перемикачем — для всіх) `blocks`-штампів показати виведені клітинки.
- Дані й дії — у `useMapArtEditor` (історія 50 кроків і coalesce для перетягування/повороту вже є); окремий хук `useStampSelection` для стану вибору й жестів; UI-компоненти лише рендерять.
- Прев'ю — той самий painter; оновлення перемальовує chunk'и за bbox штампа (`dirty.ts`).
- Desktop-only, як решта вкладки «Арт»; i18n `maps.editor.stamps.*` (uk/en) у `messages/*/maps.json`; запис в `whats-new` не потрібен (функція редактора, прапорець `mapLibraryEnabled`).

## 9. Міграція наявних об'єктів

`scripts/maps/convert-tiles-to-art.ts` розширюється: шар `objects` → штампи (`asset` = id реєстру за ключем тайла, центр штампа = центр footprint, `rot=0`, `scale=1`). Після конвертації `objects` прибираються з CURRENT chunk'ів (за логікою наявного скрипту: новий snapshot, `mapVersion+1`, старі snapshots недоторкані). Тайловий painter об'єктів лишається, поки лишаються карти без арт-рядка. Dry run за замовчуванням; `--apply` на проді лише після «так» власника і резервної копії; перед планом перевірити read-only, скільки карт мають `objects`.

Увага: `fix/map-art-tails` (`../dnd-tracker-mapart`) теж стосується цього скрипта (прод-конвертер ground/wallfill, ще не застосований). Ч2 розширює його **після** застосування тієї частини або узгоджує зміни; порядок — погодити з власником перед merge.

`lib/utils/battle/grid/{layout,geometry}.ts` (`cellCenter`, `unitOf`, `gridOf`), `map-art/{scene,dirty,derive}.ts`, `canvas/map-art/{assets,paint-scene,bake}.ts` (`createLayer`, `clip`), історія/coalesce в `useMapArtEditor`, `useMapArtSave` і API `art/route.ts` (схема розширюється, маршрут без змін), `tile-prompts` (конвенція, префікси), `scripts/assets/tiles/{validate,upload-lib}.ts` (перевірки альфи/розмірів/MIME), каталог тайлів (імена, footprint 35 об'єктів), i18n-ключі `maps.editor.tiles.name.*`, `lib/utils/api` (`parseBody`, `loadOwned`, `requireDM`).

## 11. Тести

- `stampBlockedCells`: rect/ellipse × масштаб × поворот на квадраті й гексі; клітинка з центром штампа завжди блокується; поза картою; round-trip `deriveMechanics`.
- Схема: невідомий asset, дубль id, межі `x/y/scale/rot`, ліміт штампів і тіла.
- Painter: порядок шарів (`decal` < стіни < `object` < `canopy`), сортування `z/y/id`, `clip`, тінь (smoke на мок-канвасі, кількість `drawImage`/`rotate`).
- `dirty`: bbox повернутого штампа → chunk'и.
- Реєстр: згенеровані дані збігаються з CSV, файли існують, `blocks` footprint розумний (не більший за спрайт).
- Пайплайн: нарізка синтетичного аркуша, ключ кольору без каймисті, нормалізація розміру, валідатор відхиляє непрозорий/неправильний розмір.
- Редактор: хук (додати/перемістити/повернути/видалити/дублювати/z, undo/redo), hit-test за альфою.
- Конвертер: `objects` → штампи, ідемпотентність, dry run.

## 12. Ризики

- **Стильова єдність аркушів.** Мітигація — пілот на 6–8 штампах, якорі й style reference із власних зображень, одна сесія на біом.
- **Нарізка аркушів** ламається, якщо об'єкти торкаються → правило проміжків у промптах + валідатор, що відхиляє злиті компоненти.
- **Вага запікання** на великих картах (тисячі штампів із тінями) → кеш силуетів тіней по ассету й масштабу; ліміт 2000.
- **Перетин зі скриптом конвертера** з `fix/map-art-tails` → див. §9.
