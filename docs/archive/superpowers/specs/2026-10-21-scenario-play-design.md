# Гра зі сценарію: слайди, музика і бої з абзаців (дизайн)

## Context

Є три окремі інструменти DM: «Сценарій» (сторінки → розділи → рядки, режим гри з прогресом), «Показ» (набори слайдів, синхронний показ гравцям, трек на слайді, спільний плеєр через `AudioHost`) і бої. Під час сесії DM перемикається між вкладками. Мета — вести сесію з однієї сторінки сценарію: клік по абзацу показує гравцям прив'язаний слайд (і вмикає його трек), кнопка в абзаці запускає прив'язаний бій, а гравці на екрані показу одразу бачать «До бою!».

**Рішення користувача:**
- керування показом — панель у самому сценарії (сторінка `/dm/show` лишається для редагування наборів);
- набір прив'язується до сцени, абзац — до конкретного слайда (спершу пропонуються набори сцени, далі будь-які);
- старт бою: у гравців на показі з'являється велика кнопка приєднання, музика показу зупиняється, DM іде в бій у новій вкладці;
- окрема прив'язка лише треку до абзацу не потрібна — для цього плеєр у панелі.

## Підхід: прив'язки в JSON сценарію

`ScenarioRow` отримує необов'язкові `slide?: { deckId, slideId }` і `battleId?`. Вони зберігаються тим самим автозбереженням, потрапляють у версії сторінки, міграції для рядків не треба.

Відкинуто: окрема таблиця `scenario_row_links` зі справжніми FK — довелося б синхронізувати її з рядками, що створюються/видаляються в редакторі, плюс окремий API. Висячі посилання в JSON (слайд чи бій видалено) обробляються в UI.

## Модель даних (міграція expand-only)

- `slide_decks."scenarioPageId" TEXT NULL` → FK на `scenario_pages(id)` `ON DELETE SET NULL`, індекс. Prisma: `SlideDeck.scenarioPageId`, зворотне `ScenarioPage.decks`.
- `campaign_shows."battle" JSONB NULL` — `{ id, name }` бою, до якого кличуть гравців.
- Нові таблиці не створюються (RLS-тест не зачіпається).

Типи:
- `types/scenario.ts`: `ScenarioRowSlide { deckId: string; slideId: string }`; `ScenarioRow.slide?: ScenarioRowSlide`, `ScenarioRow.battleId?: string`.
- `types/show.ts`: `ShowBattle { id: string; name: string }`; `ShowState.battle?: ShowBattle` (відсутнє = нікого не кличемо); `ShowCommand` + `{ action: "battle"; battleId: string }`; `SlideDeck`/`SlideDeckSummary` + `scenarioPageId: string | null`; `BattleBrief { id, name, status }` у `types/battle.ts`.

Схеми:
- `lib/schemas/scenario.ts`: рядок — `slide` (`{ deckId: idSchema, slideId: idSchema }`) і `battleId` (`idSchema`), обидва optional.
- `lib/schemas/show.ts`: команда `battle`; `deckSceneSchema` для окремого `PATCH /decks/[deckId]` `{ scenarioPageId: string | null }` — сцена зберігається одразу при виборі і не чіпає `updatedAt` (інакше відкритий редактор набору ловив би 409). Сервер перевіряє, що сторінка належить кампанії і має `kind = "scene"`, інакше 400.
- `GET /battles?brief=1` → `BattleBrief[]` (без лобі `participants` — менше egress).

Гравцям прив'язки не потрапляють: сторінки сценарію читає лише DM, а `openChapters` (історія героя) віддає тільки `story` рядка — це фіксує тест.

## Команди показу (`lib/utils/show/show-command.ts`)

- `ctx` отримує `battle: { id, name, status } | null` (handler вантажить бій кампанії лише для команди `battle`).
- `battle`: бою немає в кампанії → handler віддає 404 `NOT_FOUND` ще до чистої функції; статус не `active` → 422 `SHOW_BATTLE_NOT_ACTIVE` (новий текст в `api-errors.ts`: «Бій ще не почався або вже завершений»). Інакше: `battle = { id, name }`, аудіо → `stop` через `applyAudioCommand`, `seq + 1`. Якщо показ не запущений (`prev` null або без `deckId`) — стан створюється з `slide: null`, `deckId: null`.
- `open` / `next` / `prev` / `end` скидають `battle` у `null`.
- `toShowState`/`writeShowState` пишуть і читають колонку `battle`.

## Редактор

**Набір** (`/dm/show/[deckId]`): поле «Сцена» — селект сторінок `kind = "scene"` (з порожнім варіантом). Список наборів показує назву сцени на картці.

**Рядок сценарію** (режим редагування): у рядку дві кнопки-іконки:
- «Слайд» → `ResponsiveDialog` з мініатюрами: групи наборів цієї сцени, потім «Інші набори» (згорнуто). Клік по мініатюрі ставить `row.slide`.
- «Бій» → діалог зі списком боїв кампанії (назва + статус), `completed` у кінці.

Прив'язаний рядок показує чип: мініатюра + назва слайда або «⚔ назва бою», з хрестиком «відв'язати». Дані для діалогів — наявні хуки списку наборів/набору і боїв; нові запити лише через `lib/api` + хуки.

## Гра (режим читання сценарію, DM)

- Рядок із `slide` клікабельний (курсор, рамка на hover); кліки по посиланнях-згадках і кнопках усередині рядка не перехоплюються. Клік → `show open { deckId, slideId }`. Трек слайда вмикається наявною логікою `autoTrack`.
- Активний рядок (його `slide` = поточний слайд показу) підсвічений.
- Рядок із `battleId` має кнопку за статусом бою:
  - `prepared` → «⚔ Почати бій»: `POST …/battles/[battleId]/start`, потім команда показу `battle`; після успіху рядок переходить у стан `active` з посиланням «Перейти до бою ↗» (`target=_blank`; автоматичний `window.open` після `await` блокують браузери);
  - `active` → «⚔ Покликати в бій» (лише команда `battle`) і посилання «Перейти до бою»;
  - `completed` → неактивне «Бій завершено».
- Висяче посилання (набору/слайда/бою немає) → бейдж «недоступно» замість дії, без запиту.
- Внизу сторінки в режимі гри — закріплена панель показу (наявний `ShowControlPanel` + плеєр через show-`AudioHost`): мініатюра поточного слайда, ‹ / ›, плеєр (DM перемикає трек), «Завершити показ». Панель підписана на `private-show-<campaignId>`, як сторінка показу. Логіка — в хуку (`lib/hooks/scenario` або `lib/hooks/show`), компоненти лише рендерять.
- Помилки команд/старту → `useNotify`; 409 показу → рефетч стану (як на `/dm/show`).

## Гравці (`/campaigns/[id]/show`)

Якщо `show.battle` не null — поверх слайда (або екрана очікування) велика кнопка «До бою!» з назвою бою, посилання на сторінку бою. Зникає, коли DM перемикає слайд або завершує показ. Кнопка JOIN BATTLE у шапці лишається як є.

## Тестування

- `show-command`: команда `battle` (активний / не активний / без показу), скидання `battle` на `open`/`next`/`prev`/`end`, зупинка музики.
- API: `PATCH` набору з `scenarioPageId` (своя сцена / чужа / не scene), команда `battle` (404, 422, успіх, публікація), схема контенту з `slide`/`battleId`.
- `openChapters` не віддає `slide`/`battleId`.
- Компоненти (happy-dom): клік по рядку шле `open`, клік по згадці — ні; кнопка бою за статусами; чип прив'язки в редакторі; кнопка «До бою!» на показі.
- Ручна перевірка в браузері на локальній prodcopy: DM у сценарії + гравець на показі.
