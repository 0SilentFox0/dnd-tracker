# Підсумок персонажа + персонаж від гравця — дизайн

Дата: 2026-10-22. Гілка `feat/stash-and-player-drafts` (worktree `../dnd-tracker-stash`).

## Мета

1. Кожен персонаж має **«Підсумок»** — місце для речей, набутих за кампанію: невдягнені артефакти, особливі (сюжетні/одноразові) речі та гроші, з механікою витрат і журналом.
2. Гравець без персонажа в кампанії може **створити свого** (скорочена форма) або **згенерувати**; персонаж стає активним лише після схвалення DM.

## Що перевикористовується

- `CharacterInventory` (`equipped`, `items`, `gold/silver/copper`) — сховок живе тут, нової таблиці інвентарю немає.
- `lib/utils/artifacts/ownership.ts` (`findHolder`, `planTransfer`) і `lib/server/artifacts/lock.ts` (`lockCampaignArtifacts`, `ensureInventory`) — унікальність і блокування.
- Маршрут передачі `characters/[characterId]/artifacts/transfer` — розширюється на сховок.
- `create-character.ts` — розрахунок КБ/хітів/слотів для чернетки (спільна функція, не копія).
- Форма: `HudFormPage`/`HudForm`/`HudSection`/`HudTab`, `components/characters/basic` і `stats` там, де поля збігаються.
- Діалоги `ResponsiveDialog hud`, `useConfirm`/`useNotify`, `QueryState`/`EmptyState`, `HudPanel`/`HudTile`.
- AI: наявний провайдер кампанії (`lib/ai`), ключ лишається на сервері.

Нове: колонка `stash`, таблиця `inventory_log`, поля `Character.status`/`reviewNote`, генератор персонажа, маршрути сховку й чернетки.

## Частина 1 — Підсумок

### Дані (міграція expand-only)

- `CharacterInventory.stash Json @default("[]")` — масив `artifactId` невдягнених артефактів.
- `CharacterInventory.items` типізується як `SpecialItem[]`: `{ id: string; name: string; description?: string; quantity: number; consumable: boolean }`. Старі записи без `id`/`consumable` нормалізуються при читанні.
- Нова таблиця `inventory_log` (+ `ENABLE ROW LEVEL SECURITY`):
  `id, campaignId, characterId, actorUserId, kind, delta Json, note String?, createdAt`, індекс `(characterId, createdAt desc)`.
  `kind`: `money_spend | money_gain | money_set | item_add | item_use | item_edit | item_remove | artifact_stash | artifact_equip | artifact_grant | artifact_revoke | artifact_transfer`.
  Записи лише додаються.
- `CharacterInventory.backpack` не чіпається (не використовується).

### Правила

- **Унікальність:** `findHolder` і `planTransfer` враховують і `equipped`, і `stash`. Артефакт у сховку належить персонажу, але бонусів не дає (рушій читає лише `equipped`).
- **Вдягнути:** у слот артефакту; зайнятий слот → вдягнений іде в сховок (обмін). Артефакти зі слотом `ITEM` (без клітинки в сітці) лишаються тільки в сховку — дії «Вдягнути» для них немає.
- **Зняти:** з сітки «Речі» → у сховок.
- **Передати:** зі сховку або з сітки іншому персонажу кампанії → у його сховок (не в слот).
- **Гроші:** витрата в будь-якій монеті з автоматичним розміном старшої (1 зм = 10 см = 100 мм); не вистачає загалом → 400 з текстом «Недостатньо коштів». Примітка «на що» обов'язкова для витрати.
- **Одноразова річ:** «Використати» → `quantity − 1`; на 0 річ видаляється.
- Зміни сховку посеред бою діють з наступного бою (snapshot береться на старті) — підказка в діалозі, без заборони.

### Права

| Дія | Гравець-власник | DM |
|---|---|---|
| Гроші: витратити / отримати | так | так |
| Гроші: задати точну суму | ні | так |
| Особливі речі: додати / редагувати / використати / видалити | так | так |
| Артефакт: вдягнути / зняти / передати свій | так | так |
| Артефакт: видати зі вільних / забрати | ні | так |
| Журнал: перегляд | свій | усі |

### API

`app/api/campaigns/[id]/characters/[characterId]/stash/`:
- `GET` — сховок (гроші, речі, артефакти сховку з даними артефакту).
- `POST` — одна дія, Zod discriminated union за `action` (`spend`, `gain`, `setMoney`, `addItem`, `editItem`, `useItem`, `removeItem`, `stash`, `equip`, `grant`, `revoke`). Під `lockCampaignArtifacts` у транзакції: зміна інвентарю + запис у `inventory_log`. Логіка — у сусідніх `stash-*.ts` (чисті функції в `lib/utils/inventory/`).
- `log/route.ts` — `GET ?cursor=` по 20 записів.
- Передача — наявний `artifacts/transfer` (оновлений під сховок, пише лог).

Клієнт: `lib/api/inventory.ts`; хуки `lib/hooks/characters/use-stash.ts` (`useStash`, `useStashAction`, `useInventoryLog`), ключі в `keys.ts`.

### Інтерфейс

Профіль персонажа (`CharacterProfile`): нова вкладка **«Підсумок»** після «Речі».
- **Гаманець:** зм/см/мм; «Витратити» (сума, монета, на що), «Отримати» (сума, монета, примітка); DM — «Задати суму».
- **Артефакти в сховку:** `HudTile` (іконка, рідкість, слот); «Вдягнути», «Передати», DM — «Забрати»; DM — кнопка «Видати артефакт» (вибір із вільних артефактів кампанії).
- **Особливі речі:** назва, кількість, опис, позначка «одноразова»; «Використати», «Редагувати», «Видалити»; «Додати річ».
- **Журнал:** останні 20, «Показати ще»; рядок: дата · хто · що · примітка.
- Вкладка «Речі»: біля вдягненого артефакту дія «Зняти в підсумок».
- Перші дані — через `PrefetchedQuery`, як решта профілю.

## Частина 2 — Персонаж від гравця

### Дані

- `Character.status` (`ACTIVE` за замовчуванням | `PENDING`), `Character.reviewNote String?`.
- `PENDING` виключається з: підбору учасників бою, балансу (`computeFairScaling`), AI-списку групи (`lib/ai/tools/party.ts`), будь-якого списку героїв поза профілем власника й DM-чергою.

### Порожній стан

`app/campaigns/[id]/character/page.tsx`: замість `EmptyState` без дій — дві кнопки: **«Створити персонажа»** і **«Згенерувати»** → `/campaigns/[id]/character/new` (друга — з `?generate=1`).

### Форма гравця (`/campaigns/[id]/character/new`, і редагування чернетки)

- Основне: ім'я, аватар, раса (раси кампанії), клас, архетип, світогляд, передісторія, характер, цілі.
- Характеристики: перемикач «Стандартний масив» (15,14,13,12,10,8 — розкласти по характеристиках) / «Point-buy (27)» (8–15, вартість за 5e); расові бонуси додаються автоматично.
- «🎲 Згенерувати ще раз» — уся форма або блок (ім'я / характеристики / передісторія).
- «✨ Оживити передісторію (AI)» — лише якщо в кампанії є AI-ключ; повертає передісторію/характер/цілі, механіку не змінює.
- Решта (рівень 1, КБ, хіти, ініціатива, швидкість, мораль, слоти) — автоматично; вміння/заклинання/імунітети — DM при схваленні.

### Генератор (`lib/utils/characters/generate/`)

Чисті функції з rng, що приймає seed (тести детерміновані):
- раса — випадкова з рас кампанії;
- архетип — випадковий з `HERO_ARCHETYPE_KEYS`, клас — відповідний архетипу;
- характеристики — стандартний масив під основну характеристику архетипу;
- ім'я — склади за расою (таблиці за ключовими словами назви раси) + загальний набір як запасний;
- передісторія/характер/цілі — шаблони.

### API

- `POST app/api/campaigns/[id]/characters/draft` — лише учасник з роллю PLAYER, у якого немає персонажа (`type=PLAYER`, будь-який статус) у кампанії. Сервер перевіряє, що характеристики отримано зі стандартного масиву або point-buy + расових бонусів. Створює `PLAYER`/`PENDING`, `controlledBy = userId`, рівень 1; розрахунок КБ/хітів/слотів — спільна функція з `create-character.ts`.
- `PATCH …/characters/[characterId]/draft` — власник редагує, доки `PENDING` (ті самі обмеження).
- `POST …/characters/[characterId]/review` — DM: `{ action: "approve" }` → `ACTIVE`, `reviewNote = null`; `{ action: "return", note }` → лишається `PENDING` з `reviewNote`. Видалення — наявний DM-шлях.
- `POST …/characters/draft/backstory` — AI-передісторія (лише учасник кампанії з ключем у кампанії).

### Інтерфейс DM

- Список персонажів DM: блок «Очікують схвалення»; лічильник на панелі DM.
- Чернетка відкривається в повному DM-редакторі; кнопки «Схвалити», «Повернути з коментарем», «Видалити».

### Інтерфейс гравця під час розгляду

Профіль з позначкою «На розгляді в DM», кнопка «Редагувати чернетку», коментар DM (якщо повернуто). Вкладка «Підсумок» порожня до схвалення.

## Тестування

- Юніт: розмін монет, use/edit/remove речей, `findHolder`/`planTransfer` зі сховком, обмін при «Вдягнути», валідація стандартного масиву/point-buy, генератор (seed), фільтр `PENDING`.
- Маршрути: права (гравець не може `grant`/`revoke`/`setMoney`, чужий персонаж → 403), лог пишеться в тій самій транзакції, друга чернетка → 400.
- Міграція: `migrations-rls.test.ts` покриває `inventory_log`.
- Браузер наприкінці: гравець витрачає/використовує/знімає/передає; гравець без персонажа генерує → DM схвалює → персонаж у бою.
