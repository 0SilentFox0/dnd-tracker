# Етап 3c: digest конспектів у промпті асистента

Епік: `2026-10-30-scenario-graph-epic.md` (останній етап; Obsidian-експорт скасовано). Залежить від 3b (`2026-10-30-scenario-summaries-design.md`): `summariesDigest`, таблиця `scenario_page_summaries`.

## Мета

У `buildInstructions` (`lib/ai/context/prompt.ts`) додати необов'язковий блок `digest` — по рядку на сторінку з конспектом, щоб асистент бачив зміст усього сценарію без читання кожної сторінки. Повний текст і далі лише інструментами читання.

## Reuse

- `summariesDigest` (`lib/utils/scenario/summary/digest.ts`, 3b) — єдина логіка порядку/бюджету/позначки stale; розширюється полем `id`.
- `fitContext` / `ContextBlock` (`lib/ai/context/budget.ts`) — бюджет і обрізання без змін.
- `summary-store.ts` — новий `loadDigestItems` поруч із `loadSummaries` (той тягне весь JSON конспекту й не віддає title/sortOrder, тож не підходить).
- `AI_LIMITS` (`lib/constants/ai.ts`), `ContextBlockId` (`types/ai.ts`), `messages/*/ai.json` `context.blocks.*` (підпис блоку в розкритті контексту).
- Нового UI, API, міграцій, запису в whats-new немає.

## Рішення

| Питання | Рішення |
|---|---|
| Джерело | Один `$queryRaw` по `scenario_page_summaries` JOIN `scenario_pages`: `title`, `sortOrder`, `summary->>'digest'`, `stale = s.version < p.version`. Текст сторінок і решта JSON конспекту не читаються (egress). Порожній digest пропускається. |
| Бюджет | `AI_LIMITS.digestChars = 4000`; `summariesDigest` обрізає по рядках цілими (без розрізання посеред), блок `maxChars: 4000`. |
| Порядок у `fitContext` | Блок стоїть ОСТАННІМ серед необов'язкових (після `focusPage`/`focus`): `fitContext` віддає залишок бюджету по черзі, тож digest стискається першим. Обов'язкові блоки (система, постійні інструкції, mode) і текст фокусної сторінки не страждають. |
| Сторінки без конспекту | Мовчки пропускаються. Заголовок блоку каже, що це лише сторінки з конспектом, решта — інструментами. |
| Режим | Лише `scenario`. У `live` відповіді короткі й про поточну сцену; 4 кБ на кожен хід даремні. |
| Ідентифікатор | Рядок має вигляд `- Title [pageId]: digest (stale)`, щоб модель могла викликати `read_scenario_page`. |
| Порожньо | Немає жодного digest → блок не додається. |
| `get_campaign_brief` | Без змін: це опис кампанії й постійні інструкції; digest — контекст чату, зовнішній MCP-клієнт читає сценарій інструментами. |

## Межа доступу

`buildInstructions` кидає 403 для `actor.via !== "session"` та не-ДМ (`caller.actor.campaignId`, `revalidateAssistantCaller`); його викликають лише `run-chat.ts` і `context-http.ts` (ДМ-маршрути). Digest додається лише тут, тож гравцеві AI-маршрути й MCP-токенам не віддається (тест: токен-актор → 403 ще до запиту digest). Digest може містити секрети, бо модель їх бачила — це ДМ-контекст, як і конспект.

## Тести

- `summariesDigest`: рядок містить `[id]`; існуючі кейси (порядок, бюджет, stale).
- `loadDigestItems`: мапінг рядків, пропуск порожнього digest (мок `$queryRaw`).
- `buildInstructions`: scenario → блок є, в кінці, після `focusPage`; live → блоку нема; без конспектів → нема; малий бюджет → digest скорочується, `standing` і `focusPage` цілі; токен-актор → 403 і `$queryRaw` не викликано.
- i18n-ключі `context.blocks.digest` в обох мовах (існуючий тест на ключі).

## Сценарій тесту «чи ШІ радить краще» (відкладено, не запускати)

Кампанія HOMM5 після деплою всієї гілки, у ДМа ключ AI, згенеровані конспекти. Запитання в режимі `scenario` без фокусу: (1) «Які сторінки сценарію згадують [героя/фракцію X]?» (2) «Де в сюжеті є суперечність у хронології?» (3) «Запропонуй, куди вписати новий побічний квест». Порівняти A (digest є) і B (блок вимкнено локальним прапором/гілкою до 3c): чи називає модель правильні сторінки без `search`/`read` викликів, кількість tool-викликів, токени вхід/вихід. Критерій: A знаходить сторінки з меншою кількістю викликів і не вигадує сторінок.

## Відкрито

Digest не оновлюється при правці сторінки до перегенерації конспекту (лише позначка `(stale)`); кампанії з сотнями сторінок бачать лише перші за `sortOrder` у межах 4 кБ.
