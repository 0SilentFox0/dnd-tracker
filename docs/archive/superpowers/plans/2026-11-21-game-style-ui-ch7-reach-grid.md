# Ч7 — тип сітки карти й візуал дальності

Статус: робота за уточненим рішенням власника 2026-11-21: квадратна та гекс-сітка — окремі варіанти створення карти; старі й нові карти без вибору лишаються квадратними. Зміна поля конфігурації карти дозволена власником у цій сесії.

## Межі

- Додати `gridType: 'square' | 'hex'` до конфігурації карти; поле необов'язкове для читання старих карт і нормалізується до `square`.
- У діалозі створення бібліотечної карти додати вибір геометрії. Під'єднати це поле до типізованого payload та JSON-конфігурації карти. Клонування/імпорт зберігають геометрію джерела; відсутнє поле означає square.
- Для hex-карт рендерити flat-top гекси в узгодженій axial геометрії, hit-testing, token anchors, клітинкові позначки та movement adjacency/відстань мають використовувати той самий grid type. Square лишається з точною поточною геометрією й алгоритмами.
- Оновити відображення дальності: холодна низькоальфа заливка й тонкий контур руху; загроза/атака — легкий тон і пунктирний контур. Недосяжні клітини лишаються приглушеними. Видимість тільки для активного або вибраного учасника не розширюється.
- Додати лінію попереднього маршруту та відстань біля вказівника лише якщо наявний view/action state надає достовірний маршрут і вартість; не дублювати розрахунок домену у presentation.
- Desktop/phone: однакова геометрія й взаємодії; `prefers-reduced-motion` вимикає fade.

## Не входить

Туман (друга половина Ч7, окремий план), дашборд (Ч2), список і журнал (Ч3), світ (Ч4), лист (Ч5), бій (Ч6, виконується до цієї частини), інші екрани (Ч8), зміни темпу/дальності/правил, rule-system специфічні гілки, масштабний рефакторинг редактора мап. Жодних умов за ID rule system.

## Розвідка й reuse

- `CreateMapDialog` і `useMapLibrary`: існуючий потік створення, валідація і навігація лишаються; додається одне поле до форми.
- `BattleMapConfig`, `BattleMapInput`, `battleMapInputSchema`, JSON header/payload: карта вже зберігає гнучку конфігурацію; поле має бути backward-compatible й проходити наявний API.
- `GridLayer`, `GridMarks`, `GridHit`, `GridStatic`: лишаються SVG-шарами для grid, marks, кліків і terrain; geometry береться з gridType, логіка інструментів залишається.
- `WallsLayer`, `DoorsLayer`, `EdgeEditor`, `edge-chunks`: повторно використовуються для стін, ґрат і дверей; гекс додає третю орієнтацію ребра зі зворотно сумісним кодуванням квадратних чанків.
- `MapStage`, `BattleMap`, `useBattleMapFrame`, `MapTransformLayers`: повторно використовуються для SVG coordinate space, camera, responsive map і token layers.
- `geometry`, `layout`, `path`, `occupancy`, `terrain`, `edges`, `line-of-fire`, `template`, `map-view`: єдині джерела grid math; square behavior має лишитися byte-for-byte еквівалентним за замовчуванням, hex behavior додається через map-aware helpers.
- `GridHit` зберігає `BattleMapActions` та наявний callbacks; не змінювати payloadи ходів чи дозволи.

## Кроки

1. Завершити карту викликів grid geometry та класифікувати використання на спільні, square-only редакторські та бойові.
2. Додати backward-compatible `gridType` у тип/схему карти й у форму створення; перевірити імпорт/клонування/завантаження.
3. Додати pure geometry helpers для flat-top axial hexes: cell center/polygon, point-to-cell, neighbors, distance, bounds/map size; не змінити square helper результати.
4. Під'єднати геометрію до grid SVG, hit testing, токенів, клітинкових позначок і бойових шляхів/загрози.
5. Перестилізувати рух і загрозу, підтримати легку появу/зникнення та reduced motion; показати шлях/вартість лише з наявного canonical state.
6. Перевірити ESLint `ui-layers/zone`, i18n uk/en, типи й diff; вручну оглянути локальний prodcopy stage на desktop і phone, обидва типи сітки, square regression та світлу/темну тему.

## Інваріанти

Лише явно обрана нова карта отримує `hex`; усі старі карти читаються як square. Не міняються доступи, правила, руховий бюджет, витрата ресурсів, мутації, дії, адреси чи поведінка модулів. Гекс-сусідство та крокова відстань залежать лише від `gridType`, а не від rule system. У Ч3 не змінювати туман та інші частини епіка.
