# План: Obojima імпортується в повністю робочу кампанію

> Джерело: тест імпорту 2026-10-28 (HOMM-шлюз, частина 3), підсумок — `docs/archive/superpowers/plans/2026-10-27-homm-gate-report.md`, розділ «Obojima». Виконувати **в окремій сесії після мерджу `feat/constructor`** (дефекти в `lib/server/compendium-import/`, етап 4f-6). Файл-приклад: `~/Downloads/1985 Games; Obojima - Tales from the Tall Grass.json` (5etools homebrew, edition `classic`, 2,3 МБ; **не копіювати в репо**, у тестах — мінімальні синтетичні фікстури).

## Критерій готовності (acceptance)

Файл завантажується через UI (upload → preview → confirm) у нову кампанію без ручної правки JSON, і після цього без коду:

1. Імпорт без помилок, повторний імпорт ідемпотентний (0 дублів, без хибних `LOCAL_CONFLICT`).
2. Усі 11 підкласів і їхні фічі імпортовані; їхні батьківські класи резолвляться через SRD-залежність (явний вибір шаблону й edition, mixed-edition підтверджено).
3. Лист героя збирається з імпортованих раси + підраси + бекграунду + фіта (режим класів увімкнено, бонуси раси видно на листі).
4. Усі 77 монстрів стають юнітами, які **грають у бою**: атаки (включно з Multiattack), правильна шкода без подвоєного модифікатора, швидкість (літуни рухаються), імунітети/опори/рятівні кидки, легендарні дії, HP (у т.ч. `hp.special`).
5. Усі 50 заклинань кастуються в бою (ціль, DC/атака, шкода/ефект, слоти), без ручного налаштування ДМ для типових випадків; нетипові — явно `manual` із поясненням у звіті.
6. Предмети: зброя/броня з механікою, магічні — з ефектами там, де вони виражаються правилами; зілля `consumable`.
7. Звіт покриття чесно показує, що лишилось вручну (пригоди, книга, foundry*, fluff — за дизайном), і `readyToPlay` відповідає дійсності; next-actions містять «увімкнути режим класів / додати базові класи», коли це потрібно.
8. Живий прогін: ДМ імпортує файл, створює бій монстрів Obojima проти героя, гравець кастує заклинання Obojima — без помилок у консолі.

## Порядок робіт

Кожна фаза — окремий комміт(и) з тестами (TDD, синтетичні фікстури). Імпортер лишається generic: **без book-specific overrides** (правило з handoff 4f-6).

### Фаза A — блокери завантаження
- **A1. Ліміт розміру запису** (`lib/server/compendium-import/parse.ts:178`, `lib/constants/compendium-import.ts:1`, `lib/utils/compendium-import/file.worker.ts`): `recordBytes` не застосовувати до `book`/`adventure`/`*Data` (міряти окремі розділи `data[]` або загальний ліміт файла) і до unsupported/необраних категорій; ліміт діє на етапі вибору/надсилання (лише обрані записи). Тести: запис 730 КБ у `bookData` не кидає `RECORD_SIZE`; звичайний запис > ліміту в обраній категорії — кидає; воркер і `previewImport` поводяться однаково. Перевірити клієнтський розмір запиту до API (ліміт тіла).
- **A2. Порожній `classSource` в UID** (`lib/server/compendium-import/feature-resolution.ts:31`): у 5etools порожній `parts[2]` = типове джерело edition (PHB для classic, XPHB для one); те саме для `subclassSource`. Тести: UID `Name|Druid||Petal|Source|2` резолвиться до класу/підкласу edition; явне джерело не міняється; невідомий клас — `FEATURE_REF_UNRESOLVED` як раніше.
- **A3. Хибний `LOCAL_CONFLICT`** при reimport вкладеного підкласу SRD (identity вкладених сутностей, дослідити `source-aware identity`). Тест: reimport без змін → 0 конфліктів.
- **A4. Режим класів у звіті** (`service.ts` `reportOf`): якщо імпорт містить раси/бекграунди/риси, а `rules.classes.enabled=false` або класів немає — next-action «увімкнути режим класів і додати базові класи (SRD-залежність)» і рекомендований `rulesPatch` у preview; `readyToPlay=false` з причиною.

### Фаза B — монстри (`lib/server/compendium-import/adapters/content.ts`)
- **B1. Подвоєння модифікатора:** `damageDice` без «±N», що дорівнює модифікатору характеристики атаки (СИЛ/СПР), коли рушій додає модифікатор через `cr`; якщо «±N» інший — лишати. Тест: `1d4 + 2` зі СИЛ 14 → `1d4`; рахунок шкоди в рушії збігається зі statblock.
- **B2. Парсер дій:** розширити регулярку: `one creature`, «plus»/додаткова шкода, DC-атаки (`{@dc}`), диапазон/reach, кілька типів шкоди; `Multiattack` → `multiattack` зі структурою (які атаки і скільки), а не лише текст; нерозпізнані — явне `manual` у звіті з назвою дії. Ціль: ≥ 95 % `{@atk}`-дій Obojima розпізнано (виміряти на локальному файлі, у тестах — синтетика).
- **B3. Захисти й ресурси:** `resist/immune/vulnerable/conditionImmune` → `immunities` (і resist/vuln, якщо модель їх має — інакше розширити модель разом із рушієм); `save` → `saveProficiencies`; `legendary` → `legendaryActions`/lair; `spellcasting` → структура монстра (слоти/список заклинань, посилання на імпортовані заклинання) замість сирого JSON у нотатках.
- **B4. Швидкість:** `speed = max(walk, fly, swim, climb, burrow)` або окремі швидкості в statblock, які читає `lib/utils/battle/grid/path.ts:16` (зараз тільки `combatStats.speed`); 16 літунів Obojima мають рухатись. Тест pathing для `fly`-only.
- **B5. `hp.special`:** розбирати формулу (напр. «`N` (`XdY+Z`)») у `hp`/`hitDice`; нерозбірне — `manual`, але не блок імпорту запису.
- **B6. Перевірка:** `createBattleParticipantFromUnit` для всіх 77 + бій-симуляція (battle-sweep-стиль скрипт на імпортованих юнітах) без помилок.

### Фаза C — заклинання (найбільший обсяг)
- **C1. Cast-поля:** `time/range/components/duration` → колонки `castingTime/range/components/duration` (не нотатки); групи шкіл — повні назви (мапа кодів 5etools `A/C/D/E/I/N/T/V` → школи) або відповідні групи SRD з іконкою/кольором (`adapt/top-level.ts:33`).
- **C2. Автоматичне виведення механіки з `entries`/`damageInflict`/`savingThrow`/`spellAttack`/`scalingLevelDice`/`areaTags`:** типові заклинання (шкода з рятівним кидком або атакою, лікування, баф/дебаф зі станом з 15 станів 5e, summon) отримують `executionMode=native` з ефектами на `MECHANIC_REGISTRY`; решта — `manual` з поясненням. Дослідити, що вже є для SRD-імпорту (`pnpm constructor:srd-template`) і перевикористати (CLAUDE.md: «Reuse before writing»). Ціль: ≥ 80 % із 50 `native`, решту перелічити у звіті з причиною.
- **C3. Каст у бою:** `lib/server/battles/mutations/spell/spell-mutation.ts:67` не блокує `native`; тест на кожен тип механіки (зразок з синтетичних фікстур).

### Фаза D — раси, бекграунди, риси, предмети
- **D1. Раси:** ASI, розмір, швидкість, зір, мови → структуровані поля та `modifyStat`-здібності; бонуси видно на листі; підраси як вибір (`option`) залишаються. **D2. Бекграунди:** спорядження/гроші → стартовий інвентар (або явний next-action), інструменти, custom skills; `originFeatId`, якщо у файлі є зв'язок. **D3. Риси:** prerequisites, `additionalSpells`, `resist` → структурно.
- **D4. Предмети:** `consumable` для зілль/інгредієнтів, `unique:false` для масових; магічні ефекти → здібності там, де виражаються; зброя/броня вже ок. **D5. `optionalfeature`:** прив'язка до власника (клас/підклас) за `featureType`, а не «без власника» (34).

## Рішення користувача (2026-10-28)
1. **Резисти/вразливості монстрів:** розширювати модель (`immunities` + resist/vuln) разом з рушієм бою (B3) — так.
2. **Заклинання:** `manual` для всіх 50 — не обмеження рушія, а свідома заглушка імпортера (див. нижче); ціль ≥ 80 % `native` лишається, решту `manual` з поясненням у звіті.
3. **Mixed-edition** (SRD 2024-класи під 2014-контент): дозволено за замовчуванням, з попередженням у preview (A2/A4).

### Чому заклинання імпортуються як `manual` (відповідь на питання 2)
Рушій вміє native-заклинання (поля `executionMode`, `cost`, `targeting`, `resolution`, `dice`, `spellEffects`; SRD-шаблон їх використовує). Але адаптер `lib/server/compendium-import/adapters/content.ts` (`spell`) **завжди** повертає `executionMode: "manual", targeting: self, resolution: auto, dice: 0, spellEffects: []` і додає `MANUAL_SPELL` — переклад даних 5etools у ці поля свідомо не реалізовано на 4f-6 (generic-адаптер без механік). Тобто причина не в рушії, а в **відсутньому перекладачі** `entries/damageInflict/savingThrow/spellAttack/scalingLevelDice/areaTags/time/range` → `targeting/resolution/dice/spellEffects/cost`. Можливі обмеження рушія, які C2 має перевірити, а не припускати: заклинання зі складними/змінними ефектами (summon, transform, зони, концентрація з тригерами, вибір цілей за описом) — ті, що не виражаються `MECHANIC_REGISTRY`, лишаються `manual`. Перша дія C2: перелік 50 заклинань Obojima за «типом механіки» (шкода/сейв, атака, лікування, стан, баф, summon, інше) і порівняння з тим, як `scripts/srd/load-template.ts` будує native-заклинання SRD — перевикористати цей шлях.
