# Пазл у «Показі» — план

> **Для виконавців:** superpowers:subagent-driven-development. Спек: `docs/superpowers/specs/2026-10-28-puzzle-design.md` (читати разом із планом). Прочитати `docs/architecture/show.md` і `CLAUDE.md` (layering, мінімум коментарів, `pnpm lint --fix`).

**Мета:** вид слайда `puzzle`: карта нарізана генератором, гравці беруть шматочки з сайдбара й складають на дошці.

**Архітектура:** чиста нарізка `lib/utils/puzzle/generate.ts` (за `seed`, нічого не зберігається) → чисті команди `lib/utils/puzzle/puzzle-command.ts` над `ShowState.puzzle` → окремий маршрут `POST /api/campaigns/[id]/show/puzzle` (гравці й ДМ) → дошка/сайдбар на pointer events.

## Глобальні обмеження

- Без нових міграцій: `ShowState.puzzle` зберігається в JSONB-колонці `slide` під ключем `puzzle` (`toShowState` виймає, `writeShowState` вкладає). Слайд змінився → пазл зник.
- Layering: `lib/api/show.ts` (`sendPuzzle`) → хук `lib/hooks/show/usePuzzle*` → компонент. `route.ts` тонкий, логіка в `puzzle-handler.ts`. Помилки — `errorResponse`, тексти в `lib/constants/api-errors.ts` (українською).
- Події лише на grab/drop/return/rotate; keepAlive раз на ~10 с; утримання 30 с (`PUZZLE_HOLD_MS`).
- Нові ліміти в `lib/constants/show.ts`: `PUZZLE_MIN_PIECES=4`, `PUZZLE_MAX_PIECES=100`, `PUZZLE_HOLD_MS=30000`, `PUZZLE_SNAP=0.25`.
- Rate limit: новий scope `puzzle` в `BATTLE_RATE_LIMITS` (`{ limit: 30, windowSeconds: 10 }`).

## Що перевикористовуємо

`useSlideUpload`/`resizeImageToBlob`/`uploadSlideImage` (завантаження в `scene-slides`), `ShowState`+`mergeShow`+`writeShowState`(seq-CAS)+`publishShow`, `usePusherShowSync`/`useShowState`/`writeShowSnapshot`, `player-view.ts` (`stageMode`), `ShowDeckStrip`/`SlideGrid`/`SlideDialog`, `ResponsiveDialog`, `useConfirm`/`useNotify`, `requireCampaignAccess`/`requireDM`, `parseBody`, `checkRateLimit`. Нове: генератор, команди, маршрут, дошка, сайдбар.

## Review Focus

- Гравець бере шматочок, закриває вкладку → утримання спливає через 30 с (тест на `now`).
- Два одночасні `grab` одного шматочка → переможе один, інший 422 (CAS-конфлікт 409 повторюється до 3 разів).
- Перемикання слайда посеред пазла → `puzzle` зникає, повернення на слайд → нова партія за `seed`.
- `count` не квадрат/просте число → сітка все одно без дірок.
- Пазл-слайд як заглушка (`setCover`) → показується звичайною картинкою.
- Гравець (не ДМ) шле `puzzleRelease`/`puzzleReset` → 403.

### Task A: генератор нарізки

**Files:** Create `lib/utils/puzzle/generate.ts`, `lib/utils/puzzle/__tests__/generate.test.ts`; Modify `lib/constants/show.ts`, `types/show.ts`.

**Produces:**
```ts
export type PuzzleCut = "classic" | "organic" | "straight";
export interface PuzzleSpec { cut: PuzzleCut; count: number; seed: number; imageWidth: number; imageHeight: number }
export interface PuzzlePiece { id: string; path: string /* SVG path у піксельних координатах imageWidth×imageHeight */; bbox: {x:number;y:number;w:number;h:number}; home: {x:number;y:number} /* центр bbox */ }
export function generatePuzzle(spec: PuzzleSpec): PuzzlePiece[]
export function pieceSize(pieces: PuzzlePiece[]): number // середня сторона bbox, для допуску
export function mulberry32(seed: number): () => number
```
Типи `PuzzleCut/PuzzleSpec` живуть у `types/show.ts`, генератор їх імпортує.

- `classic`: сітка cols×rows з `count` ≈ cols·rows (cols = round(sqrt(count·W/H)), rows = max(1,round(count/cols)); реальна кількість = cols·rows, у межах ±), кожне ребро між сусідами — крива з виступом/западиною (знак за rng), спільне ребро в двох шматочках з протилежним напрямом.
- `straight`: ті ж cols×rows, прямі ребра, але вузли сітки зсунуті rng у межах ±25 % клітинки (багатокутники).
- `organic`: Вороной від count точок (відносаксація Ллойда 2 кроки), обрізання по прямокутнику карти (Sutherland–Hodgman); шматочки — опуклі багатокутники.
- Тести (TDD): сума площ полігонів (для classic/organic/straight рахувати за bbox-клітинками/полігонами з пробного растеризування сіткою 200×200 точок: кожна точка належить рівно одному шматочку, ±1 %) = карта; детермінізм за `seed`, інший `seed` — інший результат; межі `count` (клемп до `PUZZLE_MIN/MAX_PIECES`); `count=7` (просте) і `count=100`; id унікальні й стабільні.
- Commit: `feat(puzzle): slicing generator`.

### Task C: команди, маршрут, ShowState.puzzle, player-view (2–3 задачі в один запуск)

**Files:** Create `lib/utils/puzzle/puzzle-command.ts`, `lib/utils/puzzle/__tests__/puzzle-command.test.ts`, `app/api/campaigns/[id]/show/puzzle/route.ts`, `.../puzzle/puzzle-handler.ts`, `lib/schemas/puzzle.ts`; Modify `types/show.ts`, `lib/server/show/show-store.ts`, `lib/utils/show/show-command.ts`, `lib/utils/show/player-view.ts`, `lib/api/show.ts`, `lib/constants/api-errors.ts`, `lib/utils/api/rate-limit.ts`, `lib/hooks/show/index.ts`.

**Types:**
```ts
export interface PuzzlePieceState { x: number; y: number; rot: number; place: "tray" | "board"; correct: boolean; holder?: { userId: string; name: string; until: number } }
export interface PuzzleState { pieces: Record<string, PuzzlePieceState>; solved: boolean }
ShowState.puzzle?: PuzzleState
export type PuzzleCommand =
 | { action: "puzzleGrab"; pieceId: string } | { action: "puzzleKeepAlive"; pieceId: string }
 | { action: "puzzleDrop"; pieceId: string; x: number; y: number; rot: number } | { action: "puzzleReturn"; pieceId: string }
 | { action: "puzzleRelease"; pieceId?: string } | { action: "puzzleReset" }
```
**puzzle-command.ts:** `initPuzzle(spec): PuzzleState` (усі `tray`, порядок/кути кратні 45° з `mulberry32(seed)`); `applyPuzzleCommand(prev: ShowState | null, cmd: PuzzleCommand, ctx: { now: number; user: { id: string; name: string; isDM: boolean } }): Result<ShowState>`. Перед командою ліниво знімає прострочені `holder` (`until <= now`). Правила: grab — відмова (`PUZZLE_PIECE_TAKEN`), якщо тримає інший; свій повторний grab ок; шматочок із `correct` теж можна взяти (без блокування) і тоді `correct=false`; ставить `holder{until: now+PUZZLE_HOLD_MS}`; keepAlive/drop/return — лише власник (`PUZZLE_NOT_HOLDER`); drop: `rot` нормалізується до кратного 45 у [0,360), `place="board"`, координати клемпляться в межі карти; правильність = відстань до `home` ≤ `PUZZLE_SNAP·pieceSize` і `rot===0` → x,y = home, `correct=true`; прибирає holder; `solved = усі correct`; return → `tray`, rot зберігається, без holder; release/reset — лише ДМ (`FORBIDDEN`); reset = `initPuzzle` зі `slide.puzzle`. Кожна змінна команда піднімає `seq`. Пазл відсутній/слайд не puzzle → `PUZZLE_NOT_ACTIVE`. Генератор потрібен для `home`/`pieceSize`: викликати `generatePuzzle(slide.puzzle)`.
- `puzzle` ініціалізується у `moveTo` (`show-command.ts`), коли цільовий слайд `kind==="puzzle"`; `without()` не потрібен — `moveTo` будує новий об'єкт без `puzzle`. `refreshShowSlide` не чіпає `puzzle`, але якщо `seed/count/cut` слайда змінилися — перевидати `initPuzzle`.
- `show-store.ts`: `SHOW_SELECT` без змін; `toShowState`: `slide` JSON → `{puzzle, ...slide}` розділити (`const { puzzle, ...rest } = row.slide`); `writeShowState`: `slide: json(next.slide && next.puzzle ? { ...next.slide, puzzle: next.puzzle } : next.slide)`. Тест на round trip.
- `player-view.ts`: `stageMode` → `"puzzle"` коли `show.slide?.kind === "puzzle"`, не curtain/world; `visibleSlide` для cover лишається картинкою (cover знімок: `setCover` відкидає `kind`/`puzzle`).
- Маршрут: `requireCampaignAccess` (будь-який учасник; `isDM` з результату), ім'я користувача з доступу/`campaignMember` (перевірити, що вже є в `CampaignAccessResult`; інакше `select` імені), rate limit `puzzle`, `parseBody(puzzleCommandSchema)`, `readShowState` → `applyPuzzleCommand` → `writeShowState` (CAS; 409 → до 3 повторів перечитавши стан) → `after(publishShow)`. `lib/api/show.ts`: `sendPuzzle(campaignId, cmd)`; хук `usePuzzleControl(campaignId, onFailure)` у `lib/hooks/show/` (як `useShowControl`, `writeShowSnapshot`, 409/422 → invalidate).
- Тести: `puzzle-command` (блокування, спливання 30 с через `now`, правильність+притягування, solved, чужий drop/return/keepAlive відхилено, DM-права, reset, init детермінований, прострочений holder знімається при будь-якій команді); `show-command` (open puzzle-слайда ініціалізує puzzle; next знімає); `show-store` round trip; `player-view`; handler (мок prisma/store за зразком існуючих handler-тестів show).
- Commit по частинах: `feat(puzzle): commands and state`, `feat(puzzle): player route`.

- Тести (happy-dom): сайдбар показує тільки `place==="tray"`, дошка — `board`; чужий шматочок приглушений з ім'ям; correct має клас підсвітки; solved ховає лінії; grab відмова повертає; кнопки обертання змінюють rot у `puzzleDrop`; DM-кнопки лише в режимі DM.
