# Карта світу, частина 3 — live-прогін (2026-10-28)

Середовище: dev `:3100` (`feat/world-map-3`), локальна БД `worldmap_dev`, кампанія «World UI Brief» (світ Ашан уже засіяно: 9 карт, 31 маркер). ДМ — silentfox@databet.space (Chrome «Browser 2»), гравець — aspizhav@gmail.com (Chrome «Browser 1»). Pusher — справжній cloud (EU). Тестові дані мають префікс «ТЕСТ».

## Обмеження прогону

- Вікно гравця не вдалося розтягнути: `resize_window` не змінює його ширину, тож гравця перевірено лише при 606 px (мобільний макет), а не при 1512 і 500 px. Вікно ДМ при 1500 px працювало; 500 px для ДМ перевірено у вкладеному iframe 500 px (медіа-запити працюють), частково.
- `prefers-reduced-motion` не можна ввімкнути з цього інструмента, тому емульовано підміною `matchMedia`. Справжню CSS-гілку `@media (prefers-reduced-motion)` не перевірено.
- Payload `world-changed` знято окремим підписником `pusher-js` на `private-show-<campaignId>` (авторизація серверним ключем із `.env.local`). Рівень мережі браузера не підслуховувався.
- Створення маркера, нотаток і сценарію, а також переміщення героїв, частково робилося через API з сесії відповідної ролі. Ці виклики відтворюють ті самі запити, що й UI. Діалог подорожі, редактор, вибір карти й фокусу в `/show`, видалення маркера й нотатки пройшли через UI. Прив'язку маркера в сценарії через `MarkerPickerDialog` не тестовано: JSON розділу й рядка записано напряму.

## Баги

1. **Десктоп `/dm/world`: ДМ не бачить і не може видалити публічні нотатки гравців.**
   Repro: гравець додає публічну нотатку на Talonguard; ДМ відкриває `/dm/world?marker=<id>` у вікні ≥ lg. Панель — лише `WorldInspectorBar` (назва, іконка, «Відома локація», «Створити карту», «Нотатка» (`dmNote`), «Видалити»), блоку «Нотатки гравців» немає. На мобільній ширині (`WorldMarkerPanel` у `ResponsiveDialog`) блок і кнопка «Видалити нотатку» є. Причина: `app/campaigns/[id]/dm/world/page-client.tsx` для `isDesktop` рендерить `WorldInspectorBar`, а `WorldMarkerPanel` з `WorldNotesPanel` — лише в ній.

2. **Видалення маркера не завжди знімає фокус показу.** Спроба 1 (UI, «Видалити» → підтвердження): `DELETE …/world/markers/<id>` → 200, маркер видалено, але `campaign_shows.world.focusMarkerId` лишився, `seq` не змінився, у Pusher не прийшло ні `world-changed`, ні `show-state`; чіп у сценарії лишився «Місце недоступне» + «На екрані». Спроба 2 (API: створити маркер, `world` з фокусом, `DELETE`): фокус знято, `seq` +1. Не відтворено стабільно; у логу dev немає помилок `[show]`. Підозра: `after()` не відпрацював (у логу dev у цей час з'являлися нові воркери, ймовірно перезапуск HMR). Варто перевірити на production-збірці.

3. **Помилка гідратації на `/dm/world` (консоль, індикатор «1 Issue»).** `Hydration failed … <aside> vs <header>` усередині `<OnboardingHint id="dm.world">`: на сервері рендериться `HudPageHeader`, на клієнті — `aside` підказки (стан підказки береться клієнтом). З'являється при кожному завантаженні `/dm/world`, дерево перебудовується на клієнті. На гравцевій `/world` індикатор «1 Issue» теж видно, але консоль гравця не вдалося прочитати.

4. **Незвіряне спостереження.** Одного разу `POST /show` дав 422 «Показ не запущено» (діалог на `/dm/world`) одразу після JS-`click()` по посиланню `@Місце` у рядку сценарію. Справжній клік мишею не повторив помилку. Імовірно, подія спливла до обробника рядка; сказати наперед, чи це справжній баг, не можна.

5. **Інше.** Нотатки DM через `POST /world/notes` віддають 403 (по дизайну: нотатки пишуть гравці). `ДМ пише публічну/приватну нотатку` перевірити не вдалося.
