## Seam-пілоти після генерації за уточненими промптами

Уточнені версії з Downloads — `ground/tiles_wood-planks_1.png` і `walls/tiles_wall-stone.png` — перевірено в повторі 3×3 при 64 px на клітинку та скопійовано в репозиторій. Перевірка підтвердила покращення стику ліворуч/праворуч, але обидва тайли й далі показують горизонтальну межу.

Крайовий RGB-різницевий замір (середнє абсолютне значення сусідніх крайніх пікселів, порівняне з різницею між сусідніми внутрішніми пікселями):

| Пілот | Лівий/правий край | Внутрішній горизонтальний крок | Верхній/нижній край | Внутрішній вертикальний крок |
| --- | ---: | ---: | ---: | ---: |
| Дошки | 10.56 | 7.85 | 8.11 | 1.72 |
| Кам’яна стіна | 14.01 | 8.11 | 34.40 | 13.68 |

Візуально у дошках залишається горизонтальна смуга на межі повтору; у кам’яній стіні верхній/нижній край має помітно більшу різницю за внутрішню текстуру. Це підтверджені дефекти, тому промпти оновлено ще раз лише для `tiles_wood-planks_1` і `tiles_wall-stone`: додано прямі вимоги не розміщувати горизонтальний стик/ряд на межі та оцінювати повтор 3×3. Жодні інші промпти не змінювалися. Фінальні результати повторної генерації наведено нижче.

Door source має розмір 256×64; Canvas тепер показує edge-art у центрованій смузі 4:1 шириною 1.5 клітинки, щоб двері було краще видно. У палітрі редактора є окреме велике прев’ю вибраної текстури.

## Canvas та пам’ять

Перевірено справжній `TileCanvas` у локальному браузерному harness, який роздавав assets із `public/`, без production API:

| Параметр | Результат |
| --- | --- |
| Браузер | Headless Chrome 157.0.0.0 |
| Browser viewport | 1366×980 CSS px |
| DPR | 1 |
| Cell size | 64 CSS px |
| Canvas viewport | 1280×896 CSS px, 20×14 клітинок |
| Видимі чанки | 6 (3×2), плюс запас для межі чанка |
| Завантажені пілоти | 6/6: ground 3, wallfill, object, edge-art |
| Cold paint | 9.77 ms у середньому за 10 рендерів із новими cache keys |
| Warm repaint | 0.066 ms у середньому за 100 cache hits; 0 повторних растрових draw calls |
| JS heap після вимірювання | 9 175 592 B (~8.75 MiB) |

При DPR 1 один 18×18 raster chunk для клітинки 64 px займає 1 152×1 152×4 B = 5.06 MiB; шість чанків для цього вікна — 30.38 MiB. Visible Canvas backing store — 1 280×896×4 B = 4.38 MiB. Це оцінка піксельних backing stores без overhead браузера, декодованих image surfaces і GPU-пам’яті. Реальний raster LRU має жорстку межу 64 MiB. `performance.memory` показує JS heap і не включає canvas backing store.

Заміри описують одну конфігурацію DPR 1 та cell 64. Вони не замінюють вимірювання інших DPR/масштабів і повного editor route на фізичному телефоні.
