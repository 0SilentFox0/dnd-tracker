# Дослідження: формати покупних паків карт

Дата: 2026-10-22. Статус: дослідження, рішення не ухвалене.

Мета: зрозуміти, що потрібно, щоб ДМ міг завантажити покупний пак карт (Czepeku, Tom Cartos, AAD Maps, Baileywiki, Etsy тощо) у бойову карту.

## Які формати бувають у паках

Від найпоширенішого до рідшого.

1. **Звичайні картинки** — JPG, PNG, рідше WebP. Є майже в кожному паку.
   - Варіанти однієї карти: із сіткою і без, день/ніч, зима, «порожня» без меблів, версія для друку.
   - Розмір від 1920×1080 до 4K і більше. Масштаб — пікселі на клітинку: 70 (стандарт Roll20), 100, 140, 200, 256.
   - У файлі масштаб не записаний: його вказують у назві (`Tavern_30x20_140ppi.jpg`) або в описі товару.
2. **Анімовані карти** — MP4 (H.264) і WebM, 1080p або 4K, часто з нерухомим кадром у JPG. Сітка буває вбудована у відео або окремим варіантом. Приклад: AAD Maps, Advanced Battle Maps (4480×2520, 140 px на клітинку).
3. **Universal VTT** — `.dd2vtt`, `.uvtt`, `.df2vtt`. Фактичний стандарт обміну між програмами: експортують Dungeondraft і Dungeon Scrawl, приймають Foundry, Roll20, Arkenforge. Czepeku продає їх поруч із PNG/JPG. Один JSON-файл:
   - `format` — версія;
   - `resolution` — `map_origin`, `map_size` (у клітинках), `pixels_per_grid`;
   - `line_of_sight`, `objects_line_of_sight` — стіни-ламані, координати в клітинках;
   - `portals` — двері й вікна: позиція, межі, поворот, `closed`, `freestanding`;
   - `environment` — `baked_lighting`, `ambient_light`;
   - `lights` — позиція, `range`, `intensity`, `color`, `shadows`;
   - `image` — PNG або WebP у base64.
4. **Модулі Foundry VTT** — преміум-сегмент (Tom Cartos, Czepeku, Baileywiki): сцени зі стінами, дверима, світлом, звуком. Структура: `module.json`, папка з картинками/відео, пакети сцен. З Foundry v11 пакети — LevelDB (бінарна база в папці); до v11 — текстовий `.db`, один JSON-запис на рядок. AAD Maps кладе окремо JSON зі стінами для Foundry.
5. **Рідше** — сцени Roll20 і Fantasy Grounds (`.mod`, це ZIP з XML), вихідні файли редакторів (`.dungeondraft_map` тощо), які відкриває лише рідний редактор.

## Що вже є в коді

- **Фон завантажується.** `ImageUpload` з `maxSide={2400}` (`components/battle/setup/BattleFormMap.tsx`) стискає файл у браузері до 2400 px по довшій стороні, віддає data URL; сервер через `resolveMapBackgroundForPersistence` (`lib/supabase/battle-map-storage.ts`) кладе його в бакет `battle-maps`. Формати JPG/PNG/WebP/GIF, вихідний файл до 15 МБ.
- **Масштаб задається вручну.** `BattleMapConfig.backgroundCols` (повзунок «Розмір клітинки») і `gridOffset` (`types/battle.ts`). Бракує лише автозаповнення.
- **Стіни двох видів:** клітинка-стіна (`terrain.kind = "wall"`) і стіни на ребрах `"x:y:e"` / `"x:y:s"` — лише в режимі лабіринту (`lib/utils/battle/modes/maze/walls.ts`). Ядро не може імпортувати режим (ESLint, `docs/architecture/map-modes.md`).
- **Пряме завантаження в Storage оминаючи Vercel** є для слайдів і музики (`createSignedUploadUrl` у `lib/supabase/scene-slide-storage.ts`, `battle-music-storage.ts`), для карт — ні.
- **Відеофон** досліджували, не реалізували: `docs/archive/superpowers/research/2026-10-19-video-background-and-music.md`.
- **Ризик, не перевірений:** серверний ліміт data URL — 7 МБ (`MAX_DATA_URL_CHARS` у `lib/supabase/image-storage.ts`), а тіло запиту до Vercel — максимум 4,5 МБ. Велика PNG після стискання може не пройти.

## Що потрібно для кожного формату

| Формат | Що зробити | Обсяг |
|---|---|---|
| JPG/PNG/WebP | Масштаб із назви файлу (`30x20`, `140ppi`/`140px`) → `cols/rows/backgroundCols`. Пряме завантаження через signed URL замість data URL. | малий |
| ZIP-пак | Розпакування в браузері (`fflate`), список картинок-варіантів (з сіткою/без, день/ніч), за замовчуванням версія без сітки. На сервер — тільки вибраний файл. | малий |
| UVTT | Розбір JSON у браузері: `image` → фон, `map_size` → `cols/rows`, `pixels_per_grid` → масштаб, `map_origin` → зсув. Стіни з `line_of_sight` прив'язати до ребер сітки. | середній |
| Стіни UVTT у рушії | Перенести реброві стіни з лабіринту в ядро (`BattleMapConfig.walls`); навчити рух (`grid/path.ts`), лінію стрільби (`grid/line-of-fire.ts`), шаблони заклинань і редактор карти. Лабіринт користується спільними стінами. | середній–великий, головна частина |
| Двері (`portals`) | Ребро зі станом відчинено/зачинено: нова мутація бою (Zod + `runBattleMutation` + дельта), кнопка ДМ, значок на карті. | середній |
| Світло (`lights`, `environment`) | Лише візуальний шар поверх фону. Справжній зір і туман війни — окремий епік (зараз є тільки `dark`/`fog` лабіринту). | великий, відкласти |
| MP4/WebM | Шар `<video>` під сіткою, нерухомий кадр як резерв, пряме завантаження через signed URL. Головне обмеження — трафік. | середній + інфраструктура |
| Модулі Foundry | v11+ — бінарний LevelDB. Хіба що старий `.db` або окремий JSON стін від AAD. Картинки з модуля підхопить звичайний імпорт ZIP. | не варто |
| FG `.mod`, Roll20, файли редакторів | `.mod` технічно розбирається (ZIP + XML), але рідкісний. Файли редакторів — нічим. | не варто |

## Обмеження

- **Трафік Supabase (free):** 5 ГБ трафіку, 50 МБ на файл. Відео 4K — 100–500 МБ, качає кожен гравець; квота закінчиться за кілька сесій. Для відео: обмежити 1080p/WebM і ~50 МБ або винести в інше сховище (R2, Vercel Blob).
- **Стискання до 2400 px:** для 4K-карти при 140 px на клітинку — ~75 px на клітинку. Для екрана достатньо; ліміт береже трафік, лишити.
- **Режими карти:** спільні стіни мають жити в ядрі, не в лабіринті.

## Рекомендований порядок

1. Картинки + ZIP + масштаб із назви + пряме завантаження в Storage.
2. UVTT: фон, масштаб, стіни (перенесення ребрових стін у ядро). Двері спершу імпортувати як стіни.
3. Двері, що відчиняються.
4. Відео — після рішення, де його зберігати.
5. Світло, зір і Foundry поки не робити.

Наступний крок, коли повернемося: специфікація для пунктів 1–2 у `docs/superpowers/specs/`.
