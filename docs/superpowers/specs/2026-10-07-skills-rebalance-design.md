# Скіли: ребаланс під D&D, іконки з M&M wiki, покриття механік

- **Дата:** 2026-10-07
- **Гілка:** `feat/skills-rebalance` (D, A, C — окремі гілки від неї за потреби; B — окремий brainstorming)
- **Джерело:** Notion «D&D HOMM5 → Скіли ✅» (дамп — `2026-10-07-skills-notion-source.txt`, публічний API
  `notion.so/api/v3`).

## 1. Мета

Скіли кампанії існують лише в Notion; у репо бібліотеки немає (`import-skills-library` чекає неіснуючий
`docs/SKILLS.md`), прод порожній. Потрібно:

1. Збалансувати скіли під 5e і реалії апки: юніти зі 100+ HP, автобаланс ворогів (`lib/utils/battle/balance`), бій
   без сітки.
2. Іконки перків Heroes V з mightandmagic.fandom.com зберегти у власному Supabase Storage (без CORS і без навантаження
   на wiki).
3. Закрити прогалини двигуна абілок, потрібні скілам.

**Критерії успіху**

- `data/skills-library.ts` — єдине джерело правди; кожен скіл проходить Zod-схему абілок; на гілку 3 рівні + слоти 3/2/1.
- `pnpm seed-skills-library <campaignId>` наповнює кампанію гілками й скілами з іконками зі Storage.
- Кожна механіка зі списку §4 працює в бою (тести рушія + кроки `pnpm simulate-battle`).
- Жодного запиту до `static.wikia.nocookie.net` для скілів у рантаймі.

## 3. Загальні правила балансу

- **Шанси** лишаються: сервер кидає їх сам (`run-abilities.ts:52`); у лозі при спрацюванні — «(шанс N %)».
- **Рівні фізичних гілок:** +10/20/30 % (Напад — шкода ближнього бою, Стрільба — дальнього, Захист — опір фізичній).
- **Пряма шкода абілок** (кровотеча, підпал, отрута, Хмара стріл, Готовність, Вибух мани) — у % від середньої шкоди
  основної атаки героя (`percentOf: "ownerAttack"`), щоб рости з героєм і мати вагу при 100+ HP.
- **Мораль:** додатковий хід лишається (≤ 1 за раунд, у додатковому ході перевірки моралі немає). Нерфимо скіли
  Лідерства, а не механіку моралі; бонуси — відсотками.
- **Магія:** рівень-1 «Повелитель X» → закляття переліку/школи діють по області (до 3 цілей); рівень-3 Світло /
  Темрява / Природа → на всіх союзників/ворогів. Закляття 5-го рівня не стають масовими. Хаос лишає Пірокінез.
- **Призив → Природа (друїд):** без механік сумонів; Кора-шкіра відкинута (дубль Кам'яної шкіри).
- **Дерево = списки Notion** (3/2/1). Табличні додатки та випалі скіли — у бібліотеку з `slot: "spare"`.

## 5. Двигун (A)

Кожен пункт: Zod-схема + лейбл у `registry/` + поле в `AbilityListEditor` + тести в сусідніх `__tests__/`. Без
міграцій (усе в JSONB).

1. **spellCast із даними закляття.** Подія несе `spellId`, `school` (spellGroupId), `level`
   (`types/abilities.ts:49`, емісія в `lib/utils/battle/spell/process.ts`). Тригер `spellCast` отримує опційні
   фільтри `spellIds`, `school`, `spellLevels`.
2. **Режим цілей заклять від скілів.** Static flag `spellTargeting { spellIds? | school?, mode: "area" | "all",
   maxTargets?, maxLevel? }` через `collectModifiers`. Споживачі: `spell/participant-spell-target-mode.ts`
   (мультивибір до `maxTargets`) і спел-мутація (розгортання `all` на всіх союзників/ворогів, серверна перевірка
   кількості цілей). Мертве поле `spellTargetChange` не використовується.
3. **Мітки на цілі.** Ефект `mark { markId, duration }` кладе на ціль стак із `sourceId`; `damageBonus.perMark`
   читає кількість міток власника на цілі (`battle/damage/impl.ts:76-81`).
4. **Варта.** Ефект `guard { percent, filter, duration }` на союзника з `guardianId`; після опорів частина шкоди
   переходить на вартового; окремий рядок у лозі.
5. **Скасування атаки.** Після `attack before` перевіряти, що атакуючий живий (`battle/attack/process/run.ts:49`).
6. **Тимчасова мораль.** `morale` додається до `TIMED_STATS`; `effectiveMorale` враховує тимчасові `modifyStat morale`
   з `activeEffects` (кап ±3). Натхнення = `modifyStat morale +1` на союзника з `duration`.
7. **Формула в `percent`.** `damageBonus.percent` / `modifyStat.percent` приймають `Flat` (Відплата: `3*morale`).
8. **`percentOf: "ownerAttack"`.** Середня шкода основної атаки власника (кубики + модифікатори; спільна функція з
   attack-розрахунків) — `engine/amount.ts`.
9. **Шанс у лозі.** Повідомлення абілок з `limits.chance` отримують «(шанс N %)» (`run-abilities.ts`).
10. **cleanse з умовами.** Опція `includeConditions` знімає й `condition`-ефекти (`effects/state.ts:67,146`).
11. **Мертва ціль бонусної дії.** Умова `targetDead` (новий тип у `schema/conditions.ts`); сервер перевіряє її в
    `bonus-action-mutation.ts:36`, UI пропонує мертвих юнітів як цілі лише для таких абілок.


### 5b. Друга хвиля (раси й персональні)

12. **Тригер `action`** — активна абілка за основну дію ходу (за зразком бонусної дії: мутація, ліміти, вибір цілі зокрема мертвої, кнопка в ході гравця).
13. **Ефект `summon { group, tier | count }`** — призив юнітів з бестіарію кампанії (випадковий юніт групи заданого Tier або N юнітів), через механіку `append-summoned-unit`; призвані знають власника. Заряд — ліміт абілки, незалежно від слотів.
13b. **Ефект `raiseDead { count, hpPercent }`** — повалені юніти (не герої) з обраних цілей переходять на бік власника й оживають з `hpPercent` max HP; вибір цілей — як у 14 (до N, лише мертві).
14. **Бонусна дія по кількох цілях** (`maxTargets` абілки, до N) + прапор `advantageForAttackers` (дзеркало `disadvantageForAttackers`).
15. **Опір `damageType: "all"`** у `matchesDamageType`.
16. **`maxStacks` у абілки** (ліміт стаків тимчасового ефекту) + тимчасовий стат `actionsPerTurn` (додаткові дії на початку кожного ходу).
17. **Прапор `minMorale { value }`** — нижня межа ефективної моралі.
18. **Умови `hasMark { who, markId, bySelf }` і `not`** — «ще не атакував мене цього раунду» (мітка на атакуючому, 1 р.).

## 7. Бібліотека скілів (C)

- `data/skills-library.ts`: гілки (`key`, `name`, `color`, `iconKey`, `spellSchool?`) і скіли (`key`, `branch`,
  `slot: "basic" | "advanced" | "expert" | "outer" | "middle" | "inner" | "spare"`, `name`, `abilities: Ability[]`,
  spell-поля, `iconKey`). Опис скіла генерується з абілок (registry-лейбли), щоб текст збігався з механікою.
- `data/__tests__/skills-library.test.ts`: Zod-схема абілок для кожного скіла, унікальні ключі, 3 рівні + слоти
  3/2/1 на гілку, кожен `iconKey` є в `skill-icons.ts`.
- `scripts/seed-skills-library.ts <campaignId>` + скрипт у `package.json`: upsert `MainSkill`/`Skill` за назвою в
  кампанії, `icon` = public URL Storage, закляття за назвою (не знайдено → попередження, скіл без прив'язки).
  Дерево раси DM збирає в наявному редакторі (`lib/utils/skills/progression`).

## 8. Перевірка

- `pnpm test:run`, `pnpm lint`, `pnpm exec tsc --noEmit`.
- `pnpm simulate-battle` + нові кроки: мітки, варта, скасування атаки, закляття «на всіх», шанс у лозі.
- D: кількість webp = кількість ключів; кілька public URL відкриваються; повторний запуск нічого не качає.
- C: seed у локальну Docker-БД (`pnpm db:local`), DM → Скіли та прокачка в браузері, тестовий бій зі скілами кожної
  гілки.
