# Механіка стрільби: перешкоди, ланцюг, мультицілі — дизайн

Дата: 2026-10-21 · Гілка: `feat/ranged-combat` (worktree `../dnd-tracker-shooting`)

## Мета

1. Перешкода між стрільцем і ціллю (союзник, ворог, стіна, барʼєр) рахується **автоматично** і дає штраф шкоди ×0.5 — без ручного чекбокса.
2. Атаки по кількох цілях працюють коректно і з анімацією по кожній цілі: ланцюговий постріл обирає наступні цілі сам, додаткові цілі від скілу/артефакту — на вибір гравця, багатоголові ближні юніти справді бʼють кілька ворогів.

## Поточний стан (що зламано)

- Перешкода — ручний чекбокс у `RollStep.tsx`, один прапорець `obstacle` на всю атаку (усі цілі залпу), доступний і для ближньої атаки.
- «Ланцюговий постріл» Демониці = `targets: 3` + `multiTargetFalloff`; усі 3 цілі обирає гравець.
- Ближні юніти з `targets > 1` (Цербер, Гідри, дракони, Фея, Танцюючий зі смертю, Ракшаси, Фенікс, Фурія крові…): клієнт дає обрати N цілей, сервер (`attack-phase/targets.ts`) відхиляє «Забагато цілей. Максимум: 1».
- Ліміт цілей: клієнт бере `attack.maxTargets ?? combatStats.maxTargets`, сервер для дальньої — лише `combatStats.maxTargets`; скіл «Постріл по 2 цілям» (`attackKind: "ranged"`) при запіканні (`abilities/build/bake.ts`) підіймає ліміт і для ближньої.
- «Стріла сили» (`target: "otherEnemy"`) — перший ворог за ініціативою, без карти, дальності, видимості, може взяти «сплячого».
- Жертви вогняної хвилі й «Стріли сили» не мають FX; їхні число шкоди і HP зʼявляються одразу, до влучання снаряда; у картці результату їх немає.
- Великий залп обрізається лімітами `MAX_FX_BATCH` (6), `MAX_FX_QUEUE` (12, обрізає окремі специфікації), `RECENT_ACTIONS` (6) — ранні снаряди губляться, їхні числа зʼявляються миттєво.
- Картка результату майстра будується з `state.strikes` — без цілей, доданих сервером (пробивний, «бʼє всіх»).

## Перевикористовуємо

- `cellLine`, `apexOf`, `closestCell`, `footprintDistance`, `cellsOf`, `isOnMap`, `blockedSet`, `isPlayable` (`lib/utils/battle/grid`).
- `applyObstacle` / `obstacleStep` (`lib/utils/battle/damage/obstacle.ts`) — множник і крок розкладу шкоди без змін.
- Хуки режимів `lib/utils/battle/modes/engine.ts` (`modeSees`); лабіринт: `wallSet` / `canStep` (`modes/maze/walls.ts`).
- `isTargetable` / `isActive` (`abilities/engine/core/participants`), `enemiesInReach` (`grid/attack-reach.ts`).
- Падіння шкоди по цілях — `strike-rolls.ts` (fractions), прапорець `multiTargetFalloff`.

Нове лише там, де аналога немає: функція лінії вогню, вибір цілей ланцюга/ближнього розщеплення, спільний ліміт цілей.

## 1. Лінія вогню і перешкода

**`lineOfFire(map, participants, attacker, target): { blocked: boolean; cells: string[] }`** — новий файл `lib/utils/battle/grid/line-of-fire.ts`.

- Відрізок: від клітинки стрільця, найближчої до цілі (`apexOf`/`closestCell`), до найближчої клітинки цілі; клітинки — `cellLine`. Клітинки footprint стрільця і цілі не перевіряються (велика істота не заважає сама собі).
- Перешкода на клітинці відрізка:
  - `terrain[key].kind` ∈ {`wall`, `barrier`} (`hazard` — ні);
  - клітинка в `blocked` або поза межами;
  - клітинку займає будь-який учасник на карті з HP > 0 (союзник чи ворог; «сплячі» теж — вони фізично стоять).
- Лабіринт: тонка стіна між сусідніми клітинками відрізка — перешкода. Ядро не імпортує режим, тому новий хук `modeLineBlocked(map, cells: GridPoint[]): boolean` у `modes/engine.ts` + реєстр режимів; `normal` → `false`, `maze` → перевірка `canStep` по парах сусідніх клітинок.
- `cells` — ключі клітинок, які заважають (для підсвітки на карті).
- Без карти або без позиції в когось із двох → `{ blocked: false, cells: [] }`.

**Сервер.** `run-attack-phase` для кожної цілі, яку обрав гравець (і для цілей «бʼє всіх»), рахує `obstacle = attackKind === ranged && lineOfFire(...).blocked` і передає в `processAttack`. Не рахується для: ближніх атак, стрибків ланцюга, вторинних цілей пробивного пострілу, вогняної хвилі, «Стріли сили». Повідомлення `🧱 перешкода: шкода ×0.5 → N` лишається.

**API.** Поле `obstacle` прибирається з Zod-схеми `attack-mutation.ts` (Zod без `.strict()` проігнорує його від старого клієнта), з `types/api.ts`, `attack-phase/request.ts`, `flows/attack-flow.ts` (`TOGGLE_OBSTACLE`, `state.obstacle`), `useAttackWizard.toggleObstacle`.

**Майстер атаки.** Чекбокс зникає. На кожній цілі зі штрафом — позначка «🧱 Перешкода · ×0.5»; передбачуваний крок `obstacleStep` у розкладі шкоди будується з `lineOfFire` для поточної цілі. На карті при виборі цілі клітинки з `cells` для наведеної/обраної цілі отримують нову позначку `BattleMapMark` `"cover"` (стиль — у CSS карти).

## 2. Ланцюговий постріл

- Новий прапорець здібності `chainShot { jumps: number; percent: number }` (схема прапорців + мітка в реєстрі + будівник у `data/library/unit-abilities.ts`). Демониця: `attacks[0]` без `targets`, `abilities: [chainShot("Ланцюговий постріл", 2, 50), rangedRetaliation(...)]`. Перевірка бібліотеки (`library.test.ts`) — `targets > 1` вимагає falloff; `chainShot` цього не потребує.
- Гравець обирає 1 ціль (ліміт = 1). Після **влучання** сервер додає стрибок:
  - кандидати — вороги стрільця, `isTargetable`, ще не вражені цим пострілом, видимі стрільцю (`modeSees`), на відстані ≤ дальності атаки від попередньої цілі (`footprintDistance` між footprint-ами);
  - обирається найближчий до попередньої цілі; нічия — перший за ініціативою;
  - кожен стрибок кидає власний d20; **промах обриває ланцюг**; без кандидатів ланцюг завершується.
- Шкода: множник `percent/100` у степені номера стрибку (100% → 50% → 25%), без перешкоди.
- Без карти: кандидати — вороги за ініціативою (як інші безкартові запасні варіанти).
- Кожен стрибок — окрема `BattleAction` з `actionDetails.chainFromId` = id попередньої цілі. Відповідний удар — лише від першої цілі (як зараз для першого удару залпу).
- Реалізація: `lib/utils/battle/attack/process/chain.ts` (`nextChainTarget`), цикл у `run-attack-phase` (бо наступна ціль залежить від результату попереднього кидка).

## 3. Ближнє розщеплення (Цербер та ін.)

- Даних не змінюємо: `targets: N` + `multiTargetFalloff`.
- Ближня неплощинна атака з `maxTargets > 1`: гравець обирає 1 ціль; сервер додає до `N − 1` ворогів, що стоять поруч **і** з атакуючим, **і** з ціллю (`footprintDistance ≤ 1` до обох), `isTargetable`, видимих (`modeSees`, без `modeMeleeBlockedText`); порядок — за ініціативою. Шкода — fractions з falloff (100% / 50% / 50%).
- Кидки: кожна додаткова ціль — свій d20 (як у залпі). Відповідний удар — лише від основної цілі.
- Реалізація: `lib/utils/battle/attack/process/cleave.ts` (`cleaveTargets`), викликається з `resolveAttackTargets` (цілі відомі до кидків). Тест «melee without the flag is one target» переписується під нову поведінку.

## 4. Спільний ліміт цілей

- `attackMaxTargets(attacker, attack): number` у `lib/utils/battle/attack/max-targets.ts`:
  - `aoe` → `attack.maxTargets || combatStats.maxTargets || 1`;
  - ланцюг (`chainShot`) або ближнє розщеплення → 1 (автоцілі поза лімітом);
  - дальня → `attack.maxTargets ?? combatStats.maxTargets ?? 1`;
  - ближня → 1.
- Використовують і `useAttackWizard.describe`, і `resolveAttackTargets`. «Бʼє всіх» і пробивний — як зараз (розширення поза лімітом).
- Окремо фікс у `bake.ts` не потрібен: `combatStats.maxTargets` після цього впливає лише на дальні атаки.

## 5. «Стріла сили» (`otherEnemy`)

- З картою: найближчий до цілі події ворог (`footprintDistance`), `isTargetable`, видимий для власника (`modeSees`), не ціль події; нічия — за ініціативою. Engine має доступ до `map` через контекст події — якщо ні, передати `map` у контекст `resolveTargets`.
- Без карти: перший за ініціативою, `isTargetable` (пропускає «сплячих»).

## 6. Анімація і картка результату

- **Вторинні жертви.** `mapAction`: для кожного `hpChanges` з `participantId ∉ targets`, `newHp < oldHp` і не самого актора — додатковий FX-спек `ranged`-снаряд (`key: ${id}:splash:${pid}`) з `originId` = перша ціль дії. `impact.ts` / `useFxImpacts` збирають цілі з усіх специфікацій дії (а не лише `main.targetIds`), тож число і HP вторинних жертв зʼявляються після їхнього влучання.
- **`originId`.** Нове необовʼязкове поле `FxSpec.originId`; анімація `ranged` стартує від токена `originId ?? actorId`. Для стрибків ланцюга `originId = actionDetails.chainFromId`.
- **Ліміти.** `MAX_FX_BATCH` → 16 і `RECENT_ACTIONS` = `MAX_FX_BATCH` (одна константа); `MAX_FX_QUEUE` → 32 і обрізка черги відкидає **цілі дії** (усі специфікації з одним `actionId`) від найстаріших, поточну не чіпає. Захист від програвання довгої історії після перепідключення лишається (обрізка свіжих дій).
- **Картка результату.** `useAttackWizard` будує список результатів з дій, які повернула мутація (по `actionId` відповіді), а не з `state.strikes`: усі цілі (вибрані, автоматичні, стрибки), вторинна шкода окремими рядками, загальний підсумок — сума.

## Тести

- `grid/__tests__/line-of-fire.test.ts`: вільна лінія; союзник/ворог між; стіна, барʼєр; hazard не заважає; `blocked`; велика істота-ціль/стрілець; сусідні клітинки; без карти.
- Лабіринт: `modeLineBlocked` — тонка стіна на лінії.
- `run-attack-phase`: перешкода для однієї цілі залпу і не для іншої; не для ближньої; не для стрибків ланцюга.
- Ланцюг: найближчий до попередньої, нічия за ініціативою, промах обриває, поза дальністю — кінець, не бʼє двічі, множники 1 / 0.5 / 0.25.
- Розщеплення: лише вороги поруч з обома, ліміт N−1, falloff, без кандидатів — одна ціль.
- `attackMaxTargets`: таблиця випадків; клієнт і сервер дають однаковий результат.
- `otherEnemy`: найближчий, пропуск «сплячих», невидимих.
- FX: `mapAction` для вторинних жертв і `originId`; `impact` чекає вторинних; обрізка черги цілими діями.
- Наприкінці: `pnpm test:run`, `battle-sweep` на `prodcopy`, браузер — Демониця (ланцюг + анімація), Цербер (3 цілі), постріл крізь союзника й стіну, «Стріла сили», вогняна хвиля.
