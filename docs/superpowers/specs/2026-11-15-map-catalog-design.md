# Швидкий вибір карт із VTT Maps та власний імпорт

## Намір

Дати DM швидкий вибір готової бойової карти з `mbround18/vtt-maps` у бібліотеці карт кампанії. Власні `.dd2vtt`/`.uvtt` файли мають і надалі імпортуватися тим самим редактором, щоб клієнт міг завантажити свою карту.

## Підходи

1. **Лише вдосконалити ручний імпорт.** Найменший обсяг, але кожну карту з каталогу доведеться знаходити й завантажувати вручну.
2. **Лише каталог GitHub.** Швидкий вибір, але не покриває карти клієнтів.
3. **Каталог і локальний імпорт — обраний підхід.** Каталог спрощує типове додавання карт, а наявний локальний імпорт залишається окремим рівноправним шляхом.

## Цілі

- У швидкому виборі карт у налаштуванні бою показувати каталог репозиторію з категоріями та доступними картами.
- Дозволити переглянути карту й додати її до кампанії; після додавання вона з'являється у звичайному списку бібліотечних карт і вибирається для поточного бою.
- У бібліотеці карт також залишити доступ до каталогу для попереднього наповнення кампанії.
- Показувати джерело та attribution карти відповідно до CC BY-SA 4.0; зберігати attribution разом із бібліотечною картою.
- Залишити вибір уже доданих бібліотечних карт у налаштуванні бою.
- Зберегти імпорт локального `.dd2vtt`/`.uvtt` як шлях для власних карт; покращення його сумісності й збереження великих карт входить у цей етап.

## Не входить

- Масове встановлення набору карт, фонове оновлення карт, редагування карт у сторонньому каталозі.
- Генератор карт і шаблони генератора.
- Бойові виправлення, зокрема заклинання, мораль, ілюзії, темрява в лабіринті та ближні атаки.
- Додавання музики з програвача.
- Production-запуск, деплой або зміни віддаленої бази/сховища.

## Поведінка та межі

- Джерело: публічний asset-only репозиторій `mbround18/vtt-maps`; сайт і API проєкту живуть окремо. Його карти ліцензовані CC BY-SA 4.0.
- DM може відкрити каталог зі швидкого вибору карти в setup або з бібліотеки карт, переглянути категорії та прев’ю, після чого додати одну карту.
- Із setup додана карта стає звичайною картою кампанії та автоматично обирається для поточного бою. Сам каталог не змінює активний бій і не додає карту без явної дії DM.
- Зовнішня карта не стає доступною гравцям до завершення звичайного збереження в кампанії.
- Власні карти завантажуються локальним файлом; помилка імпорту має називати конкретну несумісність, не змінюючи поточний draft.
- Бібліотека репозиторію містить 64 `.dd2vtt` файли; 23 перевищують 12 MiB, найбільший — 89 MiB, із PNG 10240×10240. Каталог має завантажувати UVTT напряму в браузер з фіксованого raw GitHub origin (його CORS підтверджено), не проксувати файл крізь Vercel Function (межа запиту/відповіді 4.5 MiB). Локальний імпорт лишається незалежним шляхом.
- UVTT input limits: файл до 96 MiB; embedded PNG/WebP до 72 MiB; до 12000 px на бік і 120 MP загалом. Перш ніж декодувати зображення, перевірити розміри. Зображення більші за 2400 px або 8 MiB зменшувати/стискати в браузері; фоновий URL кампанії має бути в її Storage через signed upload, не зовнішнім URL.
- Геометрія, яку редактор не може точно представити (зокрема діагональні стіни), не повинна мовчки зникати. Для такого імпорту потрібен явний зрозумілий результат до збереження.

## Реалізований результат

- DM відкриває кешований каталог у бібліотеці карт або з вибору карти бою; каталог має пошук за назвою й категорією, попередній перегляд і явне додавання однієї карти. Додавання з setup створює карту кампанії та вибирає її для бою.
- Індекс фіксує джерело `mbround18/vtt-maps`; UVTT напряму завантажується браузером лише з перевіреного `raw.githubusercontent.com` шляху. Повторне завантаження між прев’ю й імпортом не потрібне.
- Provenance зберігається в header карти, а фон стає об’єктом campaign Storage через DM-only signed upload. Створення карти, яке не вдалося після upload, прибирає невикористаний фон.
- Локальні UVTT-файли і далі імпортуються в редактор без залежності від каталогу; під час збереження великий фон нормалізується і завантажується напряму.
- Перевірено 66 цільових тестів у 13 файлах, TypeScript та ESLint для змінених файлів. Код наразі в ізольованій робочій копії; ще не змерджено й не розгорнуто.

## Виконавчі рішення

- Каталог відкривається зі швидкого вибору карт у setup і зі сторінки бібліотеки; після імпорту setup вибирає кампанійну копію карти.
- Використати наявні UVTT parser, draft, збереження карти, фонове сховище, API права DM і вибір карти в setup; окремий спосіб зберігання карт не створювати.
- Каталог має мати контрольований список джерел і кешований індекс, щоб UI не залежав від повного обходу GitHub на кожному відкритті. Тимчасова помилка індексу або недоступний raw GitHub не блокує локальний імпорт чи доступ до вже доданих карт.
- Під час імпорту зовнішньої карти завантажувати лише файл обраної карти, перевіряти його тим самим parser і показувати, що саме буде збережено (фон, сітка, стіни/двері, attribution).
- Локальний імпорт зберігає поточний сценарій: імпорт у draft → перегляд/правка → явне Save.

## Критерії приймання

- DM може знайти карту в каталозі, переглянути прев’ю та додати її до кампанійної бібліотеки; після збереження вона доступна у звичайному виборі карти бою.
- Зовнішній файл, що не проходить валідацію або має непідтриману геометрію, не змінює draft і повертає зрозуміле пояснення.
- Власний локальний `.dd2vtt`/`.uvtt` імпортується без залежності від доступності GitHub.
- Великі карти репозиторію до 96 MiB завантажуються безпосередньо з raw GitHub у браузер; фон нормалізується до 2400 px / 8 MiB і завантажується в Storage без перевищення ліміту запиту застосунку.
- Збережена бібліотечна карта має attribution і джерело.
- Тести покривають формати каталогу/індексу, валідацію та draft-import; інтеграційний сценарій покриває додавання, збереження і подальший вибір карти в бою.

## Послідовність епіка

1. Каталог карт і сумісний локальний імпорт (цей дизайн).
2. Виправлення бойових багів: заклинання героїв; закриття модалки моралі; лише одна пара ілюзій між двома героями; коректні цілі ближніх атак без відповіді; темрява лабіринту не пропускає ходи й не зсуває шкалу ініціативи.
3. Огляд UI генератора карт та автогенерація/шаблони.
4. Опція додати музику з програвача під час бою.

Наступні етапи матимуть власні короткі дизайни після завершення попереднього; ця специфікація не затверджує їхню реалізацію чи балансні числа.
