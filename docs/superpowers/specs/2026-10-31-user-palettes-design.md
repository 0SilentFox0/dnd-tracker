# Палітри користувача

Погоджено в розмові: шість палітр — Таверна, Опівніч, Ліс, Пергамент, Аметист, Крига. Селект у хедері змінює оформлення платформи та книги магії в профілі й бою. Перші три й Аметист — темні, Пергамент та Крига — світлі. Вибір зберігається в акаунті.

## Підхід

Використовуємо спільні CSS-змінні для палітр, HUD, компонентів shadcn та книги. Локальна лише зміна акценту не охопила б книгу й світлі теми; окремі теми для кожного екрана дублювали б оформлення. Обраний підхід дає одне налаштування для всіх екранів.

Повторне використання: `Select`, `HudPortalClassProvider`, `SpellBookPages`, `ResponsiveDialog`, API `request`, `requireAuth`, `parseBody`. Нові модулі потрібні для реєстру палітр, збереження та синхронізації персонального вибору.

## Поведінка

- `User.palette` — nullable поле; відсутній або невідомий вибір означає `tavern`.
- API читає/змінює лише профіль поточного користувача. Немає налаштування палітри кампанії.
- Локальний кеш прив'язаний до користувача; скрипт до першого малювання застосовує останню палітру. Після входу профіль є джерелом істини; вихід скидає активну палітру.
- Зміна відбувається одразу, помилка збереження показується й повертає попередню палітру. Повторні запити не можуть перезаписати новіший вибір.
- Селект має назви українською й англійською та зразки кольорів, компактний вигляд на телефоні.
- Книга: обкладинка, сторінки, текст, рамки, виділення, кнопки, вибір комірок та прев'ю. Темні палітри мають темні сторінки. Кольори шкіл і бойових станів зберігають значення, текст має читатися в обох режимах.
- Друк лишається світлим; публічний лендинг зберігає власне оформлення. Не змінюємо механіку заклинань чи гри.

## Перевірки

API: авторизація, валідація шести значень, ізоляція користувачів. Клієнт: відновлення, зміна акаунта, помилка запису, застаріла відповідь. Регресійні тести книги профілю та бою; lint змінених файлів, перевірка типів, браузерна перевірка палітр і мобільного селекта.
