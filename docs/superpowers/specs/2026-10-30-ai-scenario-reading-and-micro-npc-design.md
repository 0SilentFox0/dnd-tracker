# AI-помічник: читання великих сцен і мікро NPC через пропозицію

Етапи 1–2 епіку «граф сценарію» (етапи 3–5 — [епік](2026-10-30-scenario-graph-epic.md)).

## Проблема

ДМ попросив помічника позначити всі згадки Беатріс у сцені 1 мікро NPC. Не вийшло з двох причин:

1. **Не бачить сцену цілком.** `read_scenario_page` повертає сцену одним рядком; `define.ts` обрізає вивід до `AI_LIMITS.toolResultChars` (25 000) з хвостом `…[truncated]`, пагінації нема. Локальні сцени мають 55–111 тис. символів JSON. `search_scenario` дає ≤ 20 збігів. Результати інструментів поза останніми 6 повідомленнями стискаються до `[tool result compacted]` (`lib/ai/compact.ts`), кроків ≤ 8.
2. **Не вміє створити мікро NPC.** Мікро NPC = рядок `acquaintances` (`kind: "micro"`), а в тексті на нього вказує чіп `[@Name](acquaintance:id)`. Інструментів для знайомств у `lib/ai/tools` немає; `propose_scenario_edit` описує лише чіпи `character:id`.

## Що перевикористовуємо

| Існує | Для чого |
|---|---|
| `contentToMarkdown`, `sectionToMarkdown`, `loadPageForAi` (`lib/ai/tools/scenario-read.ts`) | основа читання по частинах |
| `searchScenarioPages`, `lib/utils/scenario/search-text.ts` | нормалізація тексту для пошуку згадок |
| `resolveAiOps` / `applyAiOps` (`lib/utils/scenario/ai-ops.ts`), `ScenarioAiOp` (`types/ai.ts`) | нові операції — розширення, не новий механізм |
| `proposals.ts` apply: транзакція, `snapshotIfDue(force)`, `before`/`stale` | атомарне застосування |
| `createAcquaintanceHandler` + `ACQUAINTANCE_INCLUDE` (`lib/server/acquaintances`) | **логіку створення виносимо в сервісну функцію** і викликаємо з handler-а й з apply |
| `docToMarkdown` / `markdownToDoc`, вузол `mention` `{id,label,type}` | обгортання згадок у чіпи |
| `MENTION_TYPES` вже містить `acquaintance` | розбір/серіалізація чіпів без змін |

Нове потрібне, бо: пагінації читання немає; створення знайомства сидить усередині route-handler-а; обгортання тексту в чіпи на рівні `RichDoc` ніде не робиться.

## Рішення

### Етап 1. Читання без втрат

- `read_scenario_page` + `offset?: number`. Відповідь — текст порції плюс `[next offset N of TOTAL]` у кінці (останній рядок). Порція ріжеться **по межі рядка сценарію** (row), не посеред блоку (`:::`, таблиця, `||`), розмір ≤ `toolResultChars − 2000`. Один рядок більший за ліміт — окремою порцією з позначкою `[row split]` (виняток, у тестах).
- Новий інструмент `outline_scenario_page` (scope `ai`): секції `[id]`, рядки `id`, розмір story/notes у символах, перші ~80 символів. ≤ 3–4 тис. символів на сцену.
- Новий інструмент `find_scenario_mentions` `{ query, pageId?, sectionId? }`: усі рядки (story і notes), де зустрічається ім'я. Повертає `{ sectionId, rowId, field, snippet, forms[], inMention }`, **без ліміту 20** (пагінація `offset`, ≤ 100 за виклик), `forms` — реальні форми слова (відмінки), знайдені за основою (префікс ≥ 4 символів без закінчення, нормалізація `search-text.ts`), `inMention` — уже чіп.
- Стискання: результати `read_scenario_page`/`find_scenario_mentions` не стискаються в межах поточного запиту (`compactToolOutputs` приймає `keep` за іменем інструмента), загальний ліміт збережених ≈ 60 000 символів. Відкрите питання: заміряти токени на реальній сцені; якщо дорого — лишити стискання, а помічнику давати право перечитувати.

### Етап 2. Мікро NPC через пропозицію

Нові вхідні операції `ScenarioAiOpInput`:

- `createAcquaintance { ref, name, description? }` — `ref` локальний ідентифікатор у межах пропозиції.
- `linkMentions { acquaintance: { ref } | { id }, forms: string[], sectionId?, rowIds?, fields?: ("story"|"notes")[] }` — обгорнути в чіпи всі входження `forms` у вибраних рядках.

Резолв (`resolveAiOps`, чиста функція):
- `linkMentions` розкривається в `replaceRow` з `before`/`after` для кожного зміненого рядка — старий механізм `before`/`stale` працює без змін. Входження всередині вже наявного чіпа, посилання чи `code` пропускаються; збіг по межах слова (Unicode-aware), у `||секреті||` чіпи ставляться теж.
- Для `{ ref }` у вузол `mention` пишеться тимчасовий `id = "@ref:<ref>"`; операція `createAcquaintance` зберігається в пропозиції як є.
- Якщо жодного входження не знайдено — помилка `assistant.scenarioOps.noMentions`, пропозиція не створюється.

Apply (`proposals.ts`, та сама транзакція, що й запис сторінки):
1. Для кожної `createAcquaintance`: якщо в кампанії вже є знайомство з тим самим `name` (без регістру) — використати його (як для персонажів: «той самий — одне знайомство»), інакше створити `kind: "micro"`, `sourcePageId` = сторінка пропозиції, `sourceSectionId` = перша секція зі змінених рядків.
2. Замінити `@ref:<ref>` на справжні `id` у змінених рядках.
3. Далі звичайний шлях: перевірка `before`, знімок версії, запис, `appliedVersion`.
Збій на будь-якому кроці відкочує все (створення знайомства теж).

Обмеження й помилки: `acquaintancesEnabled` кампанії вимкнено → пропозиція відхиляється з ключем помилки (`ACQUAINTANCES_DISABLED` вже є); ліміт кількості змін і розміру сторінки — наявні перевірки apply.

UI пропозицій: картка операції `createAcquaintance` («Новий мікро NPC: Беатріс») + перелік змінених рядків; наявний diff для `replaceRow` лишається. Тексти — `messages/{uk,en}` (`assistant.scenarioOps.*`, ns пропозицій), запис у `lib/onboarding/whats-new.ts` + `whatsNew.<id>` у обох локалях, рядок у довідці ШІ.

Опис інструмента `propose_scenario_edit` доповнюється: чіпи `acquaintance`, нові ops, правило «спершу `find_scenario_mentions`, потім `createAcquaintance` + `linkMentions`, не `replaceRow` для масової розмітки».

## Поза обсягом

Digest/граф/візуалізація/Obsidian — етапи 3–5. Автоматичне розпізнавання NPC без запиту — ні. Знайомства виду `character` через `linkMentions` — підтримуються лише за наявним `{ id }`, створення — ні.

## Безпека й межі

AI не пише у сценарій і не створює знайомств напряму: усе через `ai_proposals` + підтвердження ДМа (правило [ai.md](../../architecture/ai.md)). Ключ провайдера нікуди не потрапляє. Інструменти читання — лише для ДМ (`scope ai`), `||секрети||` помічник бачить, як і раніше.

## Перевірка

- Юніт: розрізання по рядках (рядок > ліміту, межі `:::`), `find_scenario_mentions` (відмінки, `inMention`, пагінація), `resolveAiOps` для `linkMentions` (чіп у чіпі, секрети, нуль входжень), підстановка `@ref`.
- Інтеграція (локальна БД): apply створює знайомство + чіпи в одній транзакції; збій посеред → нічого не змінено; повторне застосування → `stale`; дубль імені → існуюче знайомство.
- Живий прогін з ключем ДМа на великій сцені (Беатріс у кількох відмінках).
