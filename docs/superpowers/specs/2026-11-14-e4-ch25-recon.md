## Головні висновки

1. **Більшість «фіч» d20 вже мають рубильник у правилах кампанії**: `deathSaves.enabled`, `concentration.enabled`, `criticals.effects`, `conditions.enabled`, `actions.enabled`, `classes.enabled`, `outOfCombat.inspiration` (`lib/utils/rules/defaults.ts:6-47`, пресет d20 вмикає їх: `systems/d20/rules/rules-preset.ts:3-21`; HOMM: deathSaves/concentration вимкнено, `criticals.effects: true` — `data/templates/heroes-homm/rules.json`). Тож розбиття на модулі — це про **власність коду/секцій і нейтральність бази**, а не про нову можливість вимикати. Варто вирішити, чи модуль *заміняє* прапорець `enabled`, чи лише володіє ним (див. питання 1).
2. **`dnd5e` — ключ самої бази, не пресет** (`systems/d20/meta.ts:7`; `presetsOf` дає базі `modules: []`, `lib/utils/rules/systems/catalog.ts:51-56`). Щоб «пресет `dnd5e` = d20 + модулі», треба або (а) новий `systems/dnd5e/meta.ts` (`kind: preset`) і інший ключ у бази (контракт вимагає ≥1 ключ: `lib/__tests__/helpers/system-contract.ts:26`; `systemServerUnion` бере `base.keys[0]`: `lib/server/systems/lookup.ts:82`), або (б) мале розширення core: `SystemMeta.defaultModules` бази, яке `presetsOf` віддає для її ключів (рекомендую (б): ключі в даних, `RULE_SYSTEM_KEYS`, превʼю й контракт не змінюються).
3. **Флангінгу в коді немає** (grep `flank` = 0; лише видалений експеримент) — це новий модуль, не винесення.
4. **Бекфіл можна майже уникнути**: рядок без `modules` бере набір пресета (`catalog.ts:85-88`), тож якщо нові модулі додати в набори `dnd5e` **і** `homm`, такі рядки (усі 14 на момент Ч13, 0 явних `modules`) поводяться так само. Ризикові лише рядки з **явним** `modules` (майстер Ч24 і `withModule` завжди пишуть повний набір: `catalog.ts:221-235`) і `modules: []` — для них «голий» d20 стане біднішим.

## 2. Бекфіл `rules.system.modules`

- **Де:** `campaigns.rules.system` і замороженá копія `battle_scenes.rules` (бій читає правила сцени, `lib/server/battles/store/load-battle.ts:174`, пише при старті `start-mutation.ts:56`). Ч13 охопив обидві таблиці (14 рядків, 0 `modules`).
- **Читання відсутнього `modules`** = набір пресета (`catalog.ts:85-88`); `[]` = голий base; невідомий id → `parseRules` мовчки скидає весь `modules` до пресета (`lib/utils/rules/schema.ts:120-125`).
- **Варіант без бекфілу (рекомендую):** нові модулі в `defaultModules` `dnd5e` і в пресет `homm`; поведінка рядків без `modules` незмінна, бо логіку всередині все одно гейтять `enabled`-прапорці. Перед деплоєм — read-only звіт (новий скрипт на зразок `scripts/db/classless-d20-report.ts`): скільки рядків `campaigns`/`battle_scenes` мають явний `modules`. Якщо 0 — бекфіл не потрібен (гейт `--expect-zero`). Якщо >0 — бекфіл лише цих рядків (дописати нові id), відновити CLI з git `0b16405c8:scripts/db/backfill-rule-system.ts` (dry-run / `--apply` / `--revert`, одна транзакція, знімок), видалений у `c19b10d82`.
- **Ледачий варіант (на читанні)** вимагає нового поля (`system.rev`) у `strictObject` (`lib/utils/rules/section-shapes.ts:106-112`) → поріг відкату (як D3) і вічний код міграції. Не рекомендую.
- **Порядок:** бекфіл — **після** деплою коду, що знає нові id (старий код на невідомих id скине `modules` до пресета, тобто відкат після бекфілу ≠ еквівалент; відкат — через `--revert`).
- **Еквівалентність:** sweep на prodcopy (`scripts/db/prodcopy-db.sh`, 4 профілі) до/після; **профіль `srd-5.2+morale` має явний `modules: ['morale']`** (`scripts/sim/battle-sweep/profiles/srd-5.2-morale.ts:15`) — після розбиття він втратить рятунки/… і дасть дифи: оновити профіль (це і є тест ризикового випадку). D12-тест колонок `lib/server/characters/__tests__/d12-columns.test.ts`; ~49 тестових файлів з явним `modules: [...]` треба переглянути. Шаблони: `manifest.system` лише ключ, `rules.json` без `modules` — без змін (D14 `import --dry-run` ×5 = 0/0/0).
- **Активні бої:** з `rules` сцени без `modules` — без змін; зі явними — втратять фічу посеред бою → деплой з `active-battles-report --expect-idle` або бекфіл і `battle_scenes`. `battleData`/`ext` не зачіпаються, якщо стан лишається в полях бази.

## 4. Ризики (ймовірність × вплив)

1. **В×В** Ефекти критів: фолбек `effects: true` і потік `rng` — тихі зміни бою в d20/HOMM. → не в першій частині; спершу зробити фолбек `critRulesOf` нейтральним (`effects: false`) окремим комітом з golden-тестом.

4. **С×В** iv-b: хеші контенту юнітів → дифи sync для всіх кампаній. Тому iv-b відкласти.
5. **Н×С** `namespacesIn` (див. п. 5): модуль, що оголосить core-namespace, зламає `global.d.ts`.
6. **Н×С** Відкат після бекфілу — модулі скидаються до пресета (не падіння).
