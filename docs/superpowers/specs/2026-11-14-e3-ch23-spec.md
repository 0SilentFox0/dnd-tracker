# E3 Ч23 — specification (reuse + scope)

Source of decisions: `docs/superpowers/plans/2026-11-14-e3-plan.md`, section Ч23 (Р23.1–Р23.4). This file records reuse, refinements found while reading the code, and execution rules. Branch `feat/e3-ch23` is cut from `feat/e3-ch22` (Ч22 not merged yet).

## Reused (not rewritten)
- **`SystemUi.dmPages` + `SystemDmPage` + `dm/system/[section]`** (wfrp `careers`): already a `section → component` slot keyed like `SystemMeta.dmSections`. The content-page slot extends it instead of adding a parallel `contentPages` slot.
- **`dmSectionLayout(section)`** (`lib/server/campaigns/dm-section-layout.ts`): already 404s a section outside the composition; every `app/campaigns/[id]/dm/<kind>/layout.tsx` keeps it.
- `SystemMeta.dmSections` (`systems/{d20,skilltrees,artifactsets}/meta.ts`), `composeUi` dictionaries, `PrefetchedQuery`, `requireCampaignDMOrDemo`.
- Test infra: `scripts/shared/source-files.ts`, `scripts/shared/ui-layers.mjs` (`UI_LAYER_ZONES`, `SYSTEM_UI_KIT`), `lib/__tests__/ui-layers.test.ts`, `lib/__tests__/helpers/source-files.ts`, `docs/architecture/ui-layers.md`.
- Morale FX sources: `lib/utils/battle/fx/dice/from-morale.ts`, `lib/hooks/battle/morale-dice.ts`, `components/battle/fx/runtime/badge-labels.ts`.

## Refinements to the plan
- Slot name stays `dmPages` (widened): `ComponentType<DmPageProps>` with `DmPageProps = { campaignId; canEdit; view?: { type: 'list' } | { type: 'new' } | { type: 'edit'; id: string } }`. `view` is optional → wfrp `CareersPage` unchanged. Sub-routes (`[classId]`, `new`, …) keep their `page.tsx` for server data/prefetch and render the core `SystemDmPage`-style wrapper with the right `view` (a sibling export `SystemContentPage` may be added to `components/systems` if clearer). Reason: `app/**` may not import `@/systems/*`, and detail pages import the same components as list pages.
- `app/**` keeps server-side prefetch/gates (backgrounds' `classes.enabled`, skills/artifact-sets `PrefetchedQuery`); only the client body moves.
- Hooks: stay in `lib/hooks/<domain>` when core reads them (assistant, import, `CharacterProfile`, `components/artifacts`, `DmEntityCard` tests); otherwise leave in place — do **not** move hooks in Ч23 (smaller blast radius).
- Moved components that are still imported by core (`components/skill-tree/**` used by `CharacterProfile`, `components/skills` used by `dm/print/skills`, `components/artifact-sets` used by `components/artifacts`, `DmEntityCard` test, `scripts/constructor/assistant-check`): move only the **page bodies** (list/form/dialog trees used solely by the DM page); leave shared pieces in `components/**` and add them to `SYSTEM_UI_KIT` if a system needs them. Do not create import cycles.
- Morale FX slot: `SystemUi.fx?: { dice?(event): DiceFx[]; badges?(event): BadgeLabel[] }`, composed by concatenation in `composeUi` (new `lists` entry). Core queue/impacts hooks lose the word "morale".
- `props-budget`: counts destructured/declared props of exported function components in `components/**` and `systems/**/ui/**`; `components/ui/**` exempt.

## Execution rules
- Packages: A (dmPages content) ∥ C (props budget) → B (morale FX; after A merged because both edit `components/systems/{types,compose}.ts`) → D (fx move, alone, own commit, only if `../dnd-tracker-map-editor` has no overlapping files).
- Agents write tests, do NOT run the full suite. Allowed: `pnpm exec tsc --noEmit`, `pnpm test:related <files>`, `pnpm cycles`, `pnpm exec eslint --fix <touched files>`, `pnpm systems:index` if a systems folder's roots change.
- Use `git mv` for moves (history). Never revert others' edits in shared files. Agents do NOT commit, push, stash or switch branches; the controller commits.
- No Prisma migrations. i18n keys stay (namespaces unchanged). User-visible URLs unchanged. Code comments minimal (global CLAUDE.md).
- Group props into objects (`feedback-grouped-objects`): `{ data, set }`, `actions`, status flags.
