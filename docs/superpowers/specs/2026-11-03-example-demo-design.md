# Example Demo — дизайн

Дата: 2026-11-03

## Мета

Зробити для кожного авторизованого акаунта одну готову 5e кампанію Demo, в яку можна зайти й пройтися по наповнених можливостях застосунку. Це спільна демо-кампанія, а не шаблон і не кампанія-копія на користувача.

## Критерії готовності

- Є один стабільний запис кампанії Demo і один набір пов'язаних з нею записів кампанійного вмісту.
- Користувач знаходить Demo зі свого інтерфейсу кампаній і відкриває напряму.
- У демо доступне читання й перегляд сцен, графа, конспекту, карт, NPC, музики та двох боїв.
- Не можна створювати, редагувати чи видаляти вміст кампанії.
- Відкриття бою створює чистий пробний стан; хід, HP, черга, ефекти та результат не зберігаються в кампанію. Повторне відкриття починає бій спочатку.

## Запропонований вміст

Оригінальний короткий ваншот для 5e за мотивами пригодницького гачка «дослідити таємничий ліс і знайти стародавнього голема» з [Divine Golem Expedition](https://www.worldanvil.com/w/one-shot-adventures-kefkejaco/a/divine-golem-expedition-article). Сюжет, NPC і текст для Demo написати самостійно; джерело вказати в кредитах.

У кампанії будуть YouTube-трек для атмосфери, кілька NPC, глобальна мапа з трьома точками та двома зонами, внутрішня мапа для кожної точки, щонайменше одна пазлова сцена з повним використанням редакторських блоків/опцій, звичайний бій і бій у режимі лабіринту. Додати граф зв'язків і окрему сторінку-конспект сценарію.

Для карт розглянути безкоштовні позиції з галереї [Racooze](https://racooze.de/gallery), де окремо позначено free/premium, та/або інші карти з явними умовами повторного використання. Перед завантаженням перевірити умови ліцензії/атрибуції кожного конкретного файла; зберігати посилання на автора та джерело в кредитах Demo. Не копіювати карту з платного набору.

## Доступ і збереження

Demo має окрему ознаку/ідентифікатор, за яким застосунок надає авторизованому користувачу режим перегляду. Не додавати кожного користувача як учасника, не створювати кампанію чи bundle на акаунт. Дозвіл Demo має застосовуватися на серверних API до операцій запису, а не лише ховати кнопки в UI.

Взаємодія з боєм є тимчасовою сесією. Дані бою ініціалізуються з незмінного сценарію під час відкриття і зникають після виходу/перезавантаження. Не зберігати бойові зміни у спільних рядках. Персональні налаштування користувача (наприклад, мова/тема) лишаються поза станом кампанії.

## Межі

- Немає клонування Demo, створення персонажів, редагування контенту або спільного збереження стану бою.
- Це не новий формат шаблону і не окрема кампанія кожного гравця.
- Сюжет і карти не копіювати дослівно з джерел; використати сюжетний гачок та лише матеріали, дозволені для повторного використання.

## Технічне уточнення до реалізації

Перед реалізацією перевірити всі шляхи запису кампанії та потік збереження бою. Якщо бойовий режим наразі завжди пише стан на сервер, для Demo потрібен ізольований transient state, який повторно використовує наявний UI бою без запису в БД. Офіційна visibility `OFFICIAL` сама по собі не вважатиметься достатнім read-only захистом без серверної перевірки.

Перевірка доступу має охоплювати UI/API та MCP (`/api/mcp`): Demo не повинна відкривати інструменти запису для цієї кампанії навіть тоді, коли запит має MCP-токен. Перевірити MCP handshake/`tools/list`, доступне читання та відмову запису. У поточному робочому середовищі немає окремого підключеного D&D MCP-сервера; перевіряти локальний endpoint самого застосунку.
