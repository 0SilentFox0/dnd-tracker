# Погода й музика в бою — специфікація

Дата: 2026-10-19. Блок епіку «Бойова карта» (після блоку 4). Дослідження: `docs/superpowers/research/2026-10-19-video-background-and-music.md`.

## Мета
ДМ задає атмосферу бою: анімовану погоду на карті й фонову музику, однаково для всіх учасників у реальному часі.

## Рішення користувача (не переглядати без нього)
- Погода — лише атмосфера, без механіки.
- Погода показується **лише на карті**. Бій без карти й вигляд «Колонки» — погоди немає, перемикача теж.
- Ефекти першої версії: дощ, гроза (дощ + рідкісні спалахи блискавки), сніг, хуртовина (сніг з вітром), туман, вогонь (жар, іскри знизу вгору, дим).
- Музика: **бібліотека кампанії** (MP3-файли й YouTube-посилання) + відтворення в бою. Ліцензії не важливі (продукт для себе).
- Обраний трек грає **по колу**, доки ДМ не перемкне чи не поставить паузу.
- Плеєр видимий у правому нижньому куті сторінки бою, синхронний для всіх. Гравець лише змінює свою гучність і вимикає звук у себе (запамʼятовується на пристрої); трек і паузу керує ДМ.
- Кожен гравець один раз за відкриття сторінки натискає «Увімкнути звук» (вимога браузерів до автоплею).
- Синхронізація музики — **підхід A**: окремий легкий канал, без підвищення версії бою.

## Погода

### Дані
`BattleMapConfig.weather?: WeatherKind | null`, де `WeatherKind = "rain" | "storm" | "snow" | "blizzard" | "fog" | "embers"`. Живе в JSON карти бою (`battle_scenes.map`) — міграція не потрібна. Zod-схема карти доповнюється опційним полем.

### Зміна погоди
- Маршрут `POST /api/campaigns/[id]/battles/[battleId]/map-weather` → `runBattleMutation` (`access: "dm"`, `requireStatus: "active"`), тіло `{ weather: WeatherKind | null }`. Без карти — `BattleRuleError("action_rejected", "У цьому бою немає карти")`.
- Зміна йде звичайною дельтою (`scene.map`), як місцевість; запис журналу не створюється. Версія бою підвищується — зміна рідкісна.
- Клієнт: `lib/api/battles.ts` → мутація в `lib/hooks/battles` через `useBattleAction` → кнопка «Погода» у панелі інструментів карти ДМ (поруч із «Розставити» / «Місцевість»), вибір із 6 ефектів + «Ясно».

### Рендер
- Один `<canvas>` поверх карти всередині `[data-fx-clip]`, **поза** шаром повороту/зуму: частинки рухаються в екранних координатах (дощ падає вниз екрана навіть на поверненій телефонній карті). `pointer-events: none`, над токенами з помірною прозорістю, щоб не заважати читати HP.
- Кожен ефект — окремий модуль (як анімації FX): ініціалізація частинок за розміром рамки, `step(dt)`, `draw(ctx)`; кількість частинок масштабується від площі (ліміт для телефонів).
- `requestAnimationFrame` зупиняється, коли вкладка прихована або погода `null`; при `prefers-reduced-motion` — статичний відтінок (туман/холодний/теплий), без руху.
- Гроза: спалах — короткий білий відтінок усієї рамки раз на 6–15 с випадково.

## Музика

### Бібліотека кампанії
- Таблиця `campaign_tracks` (міграція expand-only з `ENABLE ROW LEVEL SECURITY`): `id`, `campaignId` (FK, cascade), `title`, `kind` (`"file" | "youtube"`), `url` (Storage URL для файлу), `youtubeId` (для YouTube), `durationSec?`, `sortOrder`, `createdAt`.
- Файли: бакет Supabase `battle-music`, MP3 (і M4A) до 10 МБ, унікальне імʼя, `cacheControl` 1 рік; до 40 треків на кампанію. Перевірка розміру й типу на клієнті й сервері.
- YouTube: посилання `youtu.be/…`, `watch?v=…`, `shorts/…` → `youtubeId` (Zod-regex), назва — введена ДМ або з oEmbed за потреби.
- Сторінка ДМ `app/campaigns/[id]/dm/music` (HUD-сторінка): список, завантажити MP3, додати YouTube, перейменувати, видалити (з підтвердженням), змінити порядок. API: `app/api/campaigns/[id]/tracks/...` → `lib/api/tracks.ts` → `lib/hooks/tracks`.

### Стан відтворення в бою
- Колонка `battle_scenes.audio JSONB NULL` (міграція expand-only): `{ trackId: string; playing: boolean; offsetSec: number; startedAt: number /* ms сервера, коли почалося відтворення з offsetSec */; seq: number }`.
- Маршрут `POST .../battles/[battleId]/audio` (лише ДМ): `{ action: "play", trackId } | { action: "pause" } | { action: "resume" } | { action: "next" } | { action: "prev" } | { action: "stop" }`. Оновлює колонку **без** підвищення `version` бою й без запису журналу; після відповіді шле Pusher-подію `battle-audio` з новим станом. `GET /` бою повертає `audio` у сцені (пізнє приєднання).
- Клієнт тримає стан аудіо окремо від кешу сцени (свій query key у `lib/hooks/battle`), оновлює з події `battle-audio` і з першого завантаження сцени.

### Плеєр
- Компонент у правому нижньому куті сторінки бою (desktop і телефон; на телефоні — над смугою ходу, згортається в кнопку з назвою).
- Позиція = `offsetSec + (now + clockOffset − startedAt) / 1000` за модулем тривалості (трек по колу). `clockOffset` — з заголовка `Date` відповіді API. Корекція: якщо розбіжність > 1,5 с — перемотка; інакше не чіпати.
- Файл: один `<audio loop>`. YouTube: IFrame Player API (`youtube-nocookie.com`), **видимий** міні-плеєр не менше 200×200 (правила YouTube: не ховати, не відокремлювати звук), повтор через `loop=1&playlist=<id>`, перемотка `seekTo`.
- Гравець: назва треку, гучність, вимкнути звук (localStorage), «Увімкнути звук» — кнопка-жест після кожного відкриття сторінки; до натискання події лише оновлюють стан, звук не грає.
- ДМ: те саме + вибір треку з бібліотеки, грати/пауза, наступний/попередній, «Стоп».

## Обмеження й ризики
- Egress Supabase: файли кешуються браузером (`cacheControl` 1 рік); MP3 ≤ 10 МБ.
- iOS: автоплей лише після жесту; YouTube на заблокованому екрані зупиняється — допустимо.
- Pusher без серверних ключів — події не йдуть; плеєр синхронізується при наступному завантаженні сцени (повільний polling бою вже є).

## Тести й перевірка
- Unit: розрахунок позиції й дрейфу, парсинг YouTube-посилань, валідація файлів, редʼюсер стану аудіо, схеми маршрутів.
- Маршрути: лише ДМ, без карти — відмова для погоди, `audio` не змінює `version`.
- Компоненти: плеєр (гравець/ДМ, «Увімкнути звук»), панель погоди, canvas-шар (reduced-motion).
- Браузер: дві вкладки — синхронна зміна погоди й треку; телефон (iframe 390 px); YouTube міні-плеєр.
