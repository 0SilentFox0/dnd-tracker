# Саундборд швидких звуків — дизайн

Дата: 2026-11-19. Статус: чернетка на рев'ю користувача.

## Мета

ДМ натискає пад — **усі гравці кампанії одразу чують короткий звук** (двері, меч, грім, вибух…). Працює в бою і на «Показі» поруч із музичним плеєром, але не є його частиною.

## Рішення користувача

- Звук чують усі гравці (подія в каналі, без стану в БД про відтворення).
- Джерело: **вбудований CC0-набір + власні завантаження ДМ**.
- Розбір по інших пунктах списку (глобальна карта, редактор карт, аудит канону) — окремі spec.

## Що перевикористовуємо (і чому нове)

| Існує | Використання |
|---|---|
| bucket-завантаження треків: `tracks/upload-url`, `track-handlers.ts`, `lib/constants/music.ts` (`MAX_TRACK_BYTES`, `TRACK_FORMATS`) | Той самий потік підписаного URL для власних звуків, окремий bucket `soundboard` і менший ліміт файлу |
| канали `private-show-<campaignId>`, `private-battle-<id>`, `safePusherTrigger`, `after()` | Транспорт події `soundboard-play` |
| `usePusherShowSync`, `usePusherBattleSync` | Підписка на подію (одна підписка на канал, не нова) |
| `UnlockSoundButton`, `usePlayerAudio().sound.unlock` | Розблокування автоплею; AudioContext створюється в тому ж жесті |
| `AUDIO_VOLUME_KEY`/`useAudioPrefs` | Зразок локальних налаштувань (власні ключі для саундборду) |
| `lib/utils/api` (`parseBody`, `requireDM`, `errorResponse`), `lib/api/<domain>.ts`, ключі-фабрики | Шар route → api → hook → component |

Нового, чого немає: короткі накладані звуки (WebAudio-буфери), картка-пад, статичний реєстр вбудованих звуків. Музичний плеєр (`AudioHost`, drift-sync, паузa/seek) для цього не підходить: один потік і синхронізація позиції.

## Дані

Нова таблиця `campaign_sounds` (expand-only міграція, `ENABLE ROW LEVEL SECURITY`):

- `id`, `campaignId` (cascade), `name`, `url`, `durationMs`, `volume` (0–1, за замовчуванням 1), `color`, `icon`, `sortOrder`, `createdAt`.
- Індекс `(campaignId, sortOrder)`.
- Шари контенту (`*_base`, `sourceId`) **не потрібні**: звуки належать кампанії, не шаблону. Вбудований набір — не рядки БД.

Вбудований набір: статичний реєстр `lib/constants/soundboard.ts` — `{ id: "builtin:<slug>", nameKey, icon, url }`; файли в `public/` або bucket (CC0, 20–30 штук, до 100 КБ кожен, mp3). Приховування вбудованого звуку в кампанії — нова колонка `Campaign.hiddenBuiltinSounds String[] @default([])` у тій самій міграції. Видалити вбудований не можна.

Ліміти: `MAX_SOUNDS_PER_CAMPAIGN = 60`, файл ≤ 1 МБ, ≤ 10 с, формати mp3/m4a (ті самі `TRACK_FORMATS`).

## API

- `GET /api/campaigns/[id]/sounds` — власні звуки (будь-який учасник; ETag за версією списку, egress).
- `POST …/sounds/upload-url`, `POST …/sounds` (створення), `PATCH/DELETE …/sounds/[soundId]`, `PUT …/sounds/order` — лише ДМ.
- `POST …/sounds/play` `{ soundId, nonce }` — лише ДМ. Перевіряє, що звук існує (вбудований або власний), і публікує подію. Тіло події: `{ soundId, nonce, volume }`, **без URL й назв**; клієнт бере URL зі свого кешу списку (вбудований реєстр + `GET sounds`).
- Помилки: `{ error, issues? }` з `lib/constants/api-errors.ts`.

## Транспорт

Подія `SOUNDBOARD_PLAY_EVENT = "soundboard-play"`.

- Публікується в канал показу кампанії завжди й додатково в канал активного бою кампанії (якщо є). Сторінка бою й сторінка «Показ» підписані кожна на свій канал; клієнт, що тримає обидва, дедуплікує за `nonce` (LRU на 50).
- **Відкрите питання для плану:** чи підписується сторінка бою на show-канал; якщо ні — достатньо публікації в обидва канали, окремих підписок не додаємо.
- Не змінює `campaign_shows.seq` і `battle.version`.
- Втрачену подію не відтворюємо: звук ефемерний, перепідключення не програє пропущене.

## Клієнт

- `lib/utils/soundboard/`: `resolveSound(id, library)`, `dedupe(nonce)`, `effectiveVolume(sound, userPrefs)` — чисті, з тестами.
- `lib/hooks/soundboard/`: `useSounds(campaignId)` (запит, ключі `soundKeys`), мутації ДМ, `useSoundboardPlayback()` — один `AudioContext`, кеш декодованих `AudioBuffer`, попереднє завантаження списку при розблокуванні, до 8 голосів одночасно (старіший глушиться), обробник події з `nonce`-дедупом. Гучність гравця й mute — `localStorage` (ключі в `lib/constants/soundboard.ts`).
- Компоненти (`components/soundboard/`): `SoundboardPanel` (сітка падів, кнопка «Тільки мені» для локального прев'ю без розсилки, режим редагування), `SoundPad`, `SoundEditDialog`, `SoundUploader`. Компонент лише викликає хук і рендерить.
- ДМ: панель у бою (док ДМ) і на «Показі»; гарячі клавіші 1–9 на перші пади (вимкнено, коли фокус в інпуті, і під діалогами).
- Гравець: окремого UI немає, крім гучності/mute в існуючому аудіо-доку; розблокування звуку — наявною кнопкою.
- Режим гравця-перегляду ДМ (`usePlayerView`): панель не рендериться, звук глушиться за тим самим правилом, що й музика на `/show`.

## i18n і онбординг

- `messages/{uk,en}/soundboard.json` (назви вбудованих звуків і тексти UI), запис у `lib/onboarding/whats-new.ts` + `whatsNew.soundboard` в обох мовах, стаття довідки.
- Вбудовані назви — ключі, не літерали (ESLint: кирилиця заборонена).

## Безпека та egress

- Гравець не може викликати `play` (403). Публікація тільки з сервера в `after()`.
- Подія без URL; URL лише з автентифікованого `GET sounds` / статичного реєстру.
- Rate limit на `play` (наприклад 5/с на ДМ) — на сервері, щоб не засмітити Pusher; клієнт додатково гасить подвійний клік (250 мс).
- Файли звуків — довготривалий кеш (`TRACK_CACHE_SECONDS`), завантаження лише при першому розблокуванні/першому використанні, `<audio>` не використовується.

## Тестування

- Юніт: реєстр і `resolveSound`, `dedupe`, ліміти схем (розмір, тривалість, формат).
- Route: DM-only, 404/403 для чужої кампанії, `play` з невідомим id → 404, rate limit.
- Хук: `useSoundboardPlayback` (мок AudioContext): дедуп, ліміт голосів, mute.
- Компонент (`happy-dom`): сітка, гарячі клавіші, режим редагування.
- Повний `test:run` — раз перед merge. Перевірка в браузері на stage: два вікна (ДМ і гравець), натиснути пад — гравець чує; перевірити розблокування автоплею.

## Поза обсягом

Петлі, фейди, мікшер, YouTube-звуки, імпорт із сервісів, звуки в шаблонах/шарах контенту, пропущені події для перепідключених клієнтів.

## Ризики

- Автоплей: гравець, що не клікнув «розблокувати», нічого не чує — відомо, та ж поведінка, що в музики.
- Pusher-ліміти повідомлень: помірні (ручні натискання), rate limit захищає.
- Міграція йде на prod разом із деплоєм (за правилами db-deploy).
