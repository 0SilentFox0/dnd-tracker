## Refinements to the plan
- Base step only in **creation** (`NewCampaignForm`) and, on the rules page, read-only once `systemLocked` (as now). The wizard on the rules page therefore starts at "modules" for locked campaigns and shows the base as a fixed header.
- Wizard is a controlled **local draft** (`SystemSelection`) over `moduleToggles`/`withModule`; "apply" computes `moduleChange(current, draft)` and sends **one** PATCH through the existing hook path (setup confirmation preserved). Dirty-rules-form guard (`dirty` disables toggles) stays.
- Summary step lists, for the draft composition: sheet sections, content kinds, DM sections, combat actions, plus added/removed modules from `moduleChange`. Computed with the same helpers the runtime uses, so a mismatch is a bug in the test (`preview === composeSystem(base, modules)`).
- Core stays system-agnostic: no `=== "wfrp"`, no module ids in components; everything via the catalog and registry accessors. New components obey `ui-layers` zones and the `props-budget` ratchet (group props: `{ data, set }`, `actions`).
- Package C (experiment) runs on a throw-away branch `exp/e3-ch24-flanking` cut from the merged A+B state and is deleted afterwards; only the research note and doc fixes return to `feat/e3-ch24`.
