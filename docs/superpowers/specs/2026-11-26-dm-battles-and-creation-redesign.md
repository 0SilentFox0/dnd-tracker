# DM: список битв і створення битви — редизайн

Дата: 2026-11-26. Автор: дизайнер D-A (Opus). Пункти власника 4 і 5 з `owner-batch-2026-11-26.md`.
Візуальна мова: `2026-11-25-design-system.md` з поправкою «вайб таверни» (`2026-11-25-design-system-migration-design.md`): теплий коричневий + золото `--hud-accent`, малиновий лише для HP/небезпеки/помилок/деструктиву; радіуси 8 (контроли) / 12 (панелі); м'які тіні `--hud-sh` замість рамок; hover на кожному інтерактивному елементі; перехід при зміні сторінки/вкладки. Палітри tavern і parchment.

Документ лише проєктує. Доменна логіка (`useBattleSetup`, `useBattleParticipants`, `useBattleMapEditor`, `useBattleLibraryMap`, баланс, `useBattleForm`) і API битв не змінюються, якщо нижче прямо не сказано інакше.

## 1. Аудит поточного стану

### 1.1 `/campaigns/[id]/dm/battles` (`page.tsx` → `BattleSections` → `BattleListCard`)

| # | Проблема |
|---|---|
| L1 | Активний бій — така сама картка, як і решта, лише з плашкою. Головну дію DM («повернутися в бій») треба шукати. |
| L2 | На кожній картці червона кнопка «Видалити» поруч із основною дією: на екрані 6–12 червоних кнопок, ризик випадкового кліку, шум. |

| L4 | Картка без змісту: лише назва, опис, «Учасників: N». Не видно, хто проти кого, чи є мапа, коли бій створено/завершено. |

| L6 | Широкий екран: сітка обмежена `lg:grid-cols-3`; на 1920 картки розтягуються до ~600 px і стають порожніми смугами. |
| L7 | Немає фільтра за статусом; лише пошук. |
| L8 | Картка не клікабельна цілком; hover лише на кнопках. |

### 1.2 Створення/редагування битви (`BattleSetupForm`, 5 вкладок)

| # | Проблема |
|---|---|
| S1 | **Вибір і результат розірвані.** Героїв обирають на вкладці «Герої», істот — на «Істоти», а склад сторін і баланс видно лише на «Склад». DM постійно перемикає вкладки, щоб зрозуміти, що вийшло. |

| S3 | Картки сутностей величезні (аватар 56 px, рядок на всю ширину, одна колонка) у прокрутці всередині прокрутки (`max-h-[600px] overflow-y-auto`). 150 істот HOMM5 = нескінченний список. |
| S4 | Баланс (fair/xp) і автопідбір розкидані: автопідбір на «Істоти», вердикт на «Склад». |
| S5 | «Основне» — майже порожня вкладка (назва, опис, таймер), але це перша вкладка, і назва обов'язкова. |
| S6 | **«Створити мапу» — головний біль.** Три високі картки-вибори, потім ще перемикач «Мапа увімкнена» (дубль вибору «Створити»), потім ліва колонка 20 rem з ~25 контролами підряд: тип сітки, розміри, ползунки клітинки/зсуву, калібрування, прозорість, фон, поля (4 інпути + «Порівну»), інструменти клітинок, небезпеки, інструменти країв, двері, рух, режими (лабіринт), пояснення «недоступно на гексах/на дотику». Мапа праворуч прокручується разом із формою, тож під час малювання панель інструментів виїжджає з екрана. |
| S7 | Існує **другий, кращий редактор** (`components/maps/MapEditorScreen` + `EditorSidebar`: мапа на всю висоту + бічна панель з вкладками-панелями), побудований на тому самому `useBattleMapEditor`. Форма битви його не використовує — два різні UX для однієї дії. |
| S8 | Вибір мапи з бібліотеки — `SelectField` з текстом «Назва · 20×15». Без прев'ю DM не пам'ятає, яка мапа яка. |
| S9 | Нижня панель дій не показує підсумку: скільки союзників/ворогів, чи обрано мапу, чи бій збалансований. |
| S10 | Ширина `max-w-6xl` (1152 px): на 1600/1920 мапа і списки тісні, з боків порожньо. |
| S11 | Phone: 5 вкладок не влазять, список істот + склад на різних вкладках, мапа 55vh під 25 контролами. |

## 2. Список битв — нове рішення

### 2.1 Структура

1. **Шапка** (`HudPageHeader`): назва + підзаголовок; дії: основна «Нова битва» (`Button` default — після п.2 власника золота) і меню `⋯` (`ActionsMenu` з `components/common/entity`) з пунктом «Видалити всі битви…» (деструктив, підтвердження як зараз через `DeleteAllButton` логіку). Для демо — без дій.
2. **Банер «Зараз триває»** — лише коли є активні бої. Широка панель на всю ширину: фон — прев'ю мапи бою (затемнене віньєткою) або візерунок сітки; ліворуч назва (`hud-sc`, 24 px), «Раунд 4 · почався 18:40»; по центру смуга «союзники VS вороги» (стопки аватарів по 5 + «+N», лічильники); праворуч велика основна кнопка «Продовжити бій» (`data-tour="battle.open"`) і другорядна «Зупинити». Кілька активних — банери один під одним (рідкісно).
3. **Панель інструментів**: `SearchInput` + `HudChipTabs` фільтра статусу «Усі · Підготовлені 5 · Завершені 12» (активні вже в банері, у фільтрі не дублюються). Фільтр — локальний стан `useBattleListSections` (розширення, див. §2.5).
4. **«Підготовлені»** — сітка карток `grid-cols-[repeat(auto-fill,minmax(17rem,1fr))]`, без обгортки `HudPanel`; заголовок секції — `HudSectionTitle` з лічильником.
5. **«Завершені»** — щільний список рядків у `Disclosure` (згорнутий за замовчуванням, якщо є підготовлені; розгорнутий, якщо фільтр = «Завершені»).

### 2.3 Картка підготовленої битви `BattleCard`

- Уся картка — посилання на редагування (`Link` поверх, кнопки над ним через `relative z-10`); hover: підйом на 2 px, тінь глибша, золота внутрішня обвідка 1 px; `focus-visible` — кільце `--hud-accent`.
- Прев'ю 16:9: фон мапи (`next/image`, `sizes` під колонку) з накладеною сіткою з CSS (`background-image: linear-gradient` під тип сітки; для гексів — SVG-патерн); без фону — візерунок сітки на `--hud-inset` та іконка `Grid3x3`; без мапи взагалі — `Swords` і «Без мапи». У куті — пігулка розміру «20×15» і значок режиму (лабіринт), якщо є.
- Тіло: назва (`hud-sc` 17 px, 1 рядок), опис `line-clamp-2` muted, рядок «союзники VS вороги» (`SidesStrip`), дата створення faint.
- Дії: основна «Почати» (`data-tour="battle.open"`), outline «Редагувати», `⋯` → «Видалити» (з підтвердженням через `useDeleteBattleCard`, як зараз). Червоної кнопки на картці більше немає.
- Демо (`canEdit=false`): лише «Відкрити».

### 2.4 Рядок завершеної битви `BattleRow`

`[мініпрев'ю 40×40] Назва · «N раундів» · дата завершення · SidesStrip(compact)` | «Переглянути» (outline; для демо — «Відкрити») · «Переграти» · `⋯` (Видалити). Hover — підсвітка рядка `--hud-panel-2`. Phone: дії ховаються в `⋯`, рядок — посилання на перегляд.

### 2.5 Стани

- **Порожньо** (0 битв): `EmptyState` у `ds-panel` з ілюстрацією (схрещені мечі в колі з орнаментом `.orn`), заголовок, підказка в одне речення, кнопка «Створити першу битву»; `OnboardingHint id="dm.battles"` лишається над ним.
- **Пошук без результатів**: `SearchEmptyState` (як зараз).
- **Фільтр без результатів** (напр. «Завершені» = 0): тиха панель «Ще немає завершених битв».
- **Завантаження**: сторінка SSR — даних до гідратації вже досить; у `loading.tsx` маршруту — скелетон банера + 4 скелетон-картки (через `SectionLoading`), без стрибка висоти.
- **Помилка**: стандартний `error.tsx` сегмента.
- Мутації (видалити, зупинити, переграти) — кнопка в стані pending, після — `router.refresh()` (як зараз у хуках).

### 2.6 Дані списку

Поточний `battleSceneListSelect` віддає лише `participants` (JSON) і `currentRound`. Потрібно:

- `createdAt`, `startedAt`, `completedAt`, `mapId` — звичайні колонки, додати в select.
- **Прев'ю мапи**: лише `background`, `cols`, `rows`, `gridType`, `maze` (чи є) з JSON `map`. Тягнути весь `map` (стіни, terrain, spellZones) заради прев'ю не можна (egress). Рішення: серверний хелпер `lib/server/battles/list-cards.ts` → `loadBattleListCards(campaignId)` з одним `$queryRaw` (`map->>'background'`, `(map->>'cols')::int`, …) для полів мапи, плюс для `mapId` без власного фону — `header->>'background'` з `battle_maps` (той самий запит через `LEFT JOIN`). Фон проходить `isPreviewSafeBackground`, інакше `null`.
- **Обличчя сторін**: з `participants` зібрати id за типом, двома запитами `character.findMany` / `unit.findMany` (`id, name, avatar`, `where: { campaignId, id: { in } }`) підтягнути аватари; віддати `sides: { ally: { count, faces: Face[≤5] }, enemy: {…} }`, де `count` враховує `quantity`.
- Тип `BattleListCardData` у `types/battle.ts` (доменний файл уже є).
- `useBattleListSections` отримує `status`-фільтр: повертає `{ search, filter: { value, set, counts }, active, prepared, completed }`. Активні не фільтруються пошуком.

Нових API-маршрутів немає: сторінка — серверний компонент, дані передаються пропсами.

## 3. Створення/редагування битви — нове рішення

### 3.1 Нова структура: 2 кроки замість 5 вкладок + шапка

```
Шапка форми:  [← До битв]  Назва битви [_______________________] (обов'язкова)   [⚙ Деталі]
Вкладки:      ( Учасники  4 VS 7 )  ( Мапа  ✓ 20×15 )
Тіло вкладки
Нижня панель: 4 союзники · 7 ворогів · ⚖ Рівно · Мапа 20×15     [Скасувати] [Створити битву]
```

- **Назва** переїжджає в шапку як великий інпут (`hud-sc` 22 px, без рамки, підкреслення `--hud-rule`, на фокусі — золоте). Помилка «обов'язково» — під ним; `onInvalidCapture` більше не мусить перемикати вкладку.
- **«Деталі»** (опис, таймер ходу) — кнопка в шапці відкриває `Popover` (desktop) / `ResponsiveDialog` (phone) з тим самим `BattleFormBasicInfo` без заголовка секції. Якщо опис заповнено або таймер увімкнено — на кнопці крапка-індикатор і підказка «Таймер 60 с».
- **Вкладка «Учасники»** об'єднує «Герої», «Істоти», «Склад» і автопідбір (§3.2).
- **Вкладка «Мапа»** (§3.3).
- Лейбли вкладок несуть стан: «Учасники 4 VS 7», «Мапа ✓ 20×15» / «Мапа —». Перехід між вкладками — наявна анімація `HudTabs` (`useTabDirection`, slide 160 мс), з `prefers-reduced-motion` — без зсуву.
- **Нижня панель** (`ActionBar`, sticky): ліворуч підсумок (`SetupSummary`): лічильники сторін, вердикт балансу кольоровою пігулкою (рівно — зелений приглушений, слабко/надмір — бурштиновий; не малиновий, бо це не помилка), мапа. Праворуч: «Видалити» (лише редагування, ghost-деструктив у `⋯`, не поруч із основною), «Скасувати», основна «Створити битву» / «Зберегти». Для DM із порожньою стороною ворогів — основна кнопка активна (чернетка дозволена, як зараз), але підсумок показує «Немає ворогів» бурштиновим.
- **Ширина**: замість `HudFormPage max-w-6xl` — `HudFormPage` з новим пропсом `width="wide"` → `max-w-page` (min(90vw,160rem)); див. ризики.

- **Каталог** (`ParticipantCatalog`): сегмент «Герої | Істоти» з лічильниками; пошук спільний; для істот — чіпи рас (`HudChipTabs`, наявний `useSetupUnitsFilter`) і групи-розділи `Disclosure` за расою (замість `Accordion`, згортання групи пам'ятається в `sessionStorage` через try/catch).
- **Рядок каталогу** (`CatalogRow`, висота 52 px, аватар 36 px): ім'я, «р.8» / «T2», `DPR · HP · KPI` (muted, `tabular-nums`), підказка-розклад DPR для героїв (наявний `DprBreakdownTip`, перенести в окремий файл). Праворуч:
  - не обрано → дві малі кнопки `[+ Союзник]` `[+ Ворог]` (іконки `Shield` / `Swords` + текст на ≥ xl, лише іконки з `aria-label` нижче);

  - Рядок обраного має ліву смугу 3 px кольору сторони та фон `--hud-panel-2`.
  - Клік по самому рядку (не кнопках) для **героя** = «+ Союзник» / прибрати (герої майже завжди союзники); для **істоти** = «+ Ворог» / прибрати. Це замінює `cycleUnit` у UI (сам `cycleUnit` лишається в хуку, просто не використовується; прибрати — окремим завданням при `/simplify`).

- **Баланс** зверху складу (`BalanceMeter`): одна смуга-терези (сила союзників vs ворогів, DPR×HP), вердикт, множники HP/шкоди; `[?]` відкриває повний `BalanceSummary`/`XpBalanceSummary` у `Popover`. Для xp-режиму — бюджет XP і складність замість терезів.
- **Автопідбір** — згорнутий `Disclosure` під складом (лише при створенні, як зараз); вміст — наявний `AutopickCard` без власного заголовка секції.

### 3.3 Вкладка «Мапа»

#### 3.3.1 Вибір джерела

Замість трьох високих карток — компактний сегмент у верхньому рядку вкладки:

```
Мапа:  ( Без мапи )( ✎ Своя мапа )( ▦ З бібліотеки )            [⛶ На весь екран]
```
- Сегмент — `role="radiogroup"`, стиль чіпів `HudChipTabs`. Окремий перемикач «Мапа увімкнена» (`ToggleRow`) зникає: «Своя мапа» = `setEnabled(true)`, решта — `false` (як уже робить `chooseMap`).
- «З бібліотеки» видно, лише якщо `libraryMap.visible`; інакше сегмент із двох пунктів.
- **Без мапи**: тиха панель з іконкою «Бій без мапи: лише ініціатива і дистанції словами» + дві кнопки-підказки «Намалювати свою» / «Обрати з бібліотеки».

#### 3.3.2 «З бібліотеки» — сітка прев'ю

```
[🔍 Пошук мап…]                         [⤓ Каталог мап] [Керувати бібліотекою ↗]
┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
│▓ прев'ю│ │▓ прев'ю│ │▦       │ │▓ прев'ю│ │ (недоступна: │
│Вежа    │ │Брід    │ │Печера  │ │Ліс     │ │  більша за 60)│
│30×20 ✓ │ │20×15   │ │40×40   │ │…       │ │              │
└────────┘ └────────┘ └────────┘ └────────┘ └────────┘
Обрано: Вежа (30×20). Мапа прив'язана до бібліотеки: зміни в бібліотеці підтягнуться до старту.
```
- `LibraryMapGrid`: картки `BattleMapThumb` (спільний із §2.7), `auto-fill minmax(11rem,1fr)`; обрана — золота обвідка 2 px і «✓»; занадто великі — приглушені, `aria-disabled`, підказка `tooltip` з `t('tooLarge')`; заблоковано (бій не prepared) — уся сітка disabled з текстом `t('locked')`.
- Рядок статусу під сіткою — ті самі тексти `battleSetup.library.*` (linked/chosen/ownFromLinked/locked).
- Обрана мапа показується великим прев'ю праворуч (≥ 1280) — read-only `BattleMap`, щоб DM бачив стіни/двері.
- «Відкрити в редакторі ↗» для обраної мапи — посилання на `/dm/maps/[mapId]` у новій вкладці (зміни бібліотеки підтягнуться через версію, як зараз).
- Дані: `BattleMapBrief` отримує `thumb: string | null` (з `header.background`, лише preview-safe) — зміна в `lib/server/battle-maps/library-service.ts` select і типі; клієнтський хук `useBattleMaps` без змін.

#### 3.3.3 «Своя мапа» — робочий стіл (головна зміна)

Принцип: **той самий макет, що й у редакторі бібліотеки** (S7). Виділяємо спільну оболонку `MapWorkbench` з `MapEditorScreen`: мапа займає всю доступну висоту, праворуч бічна панель з вкладками-панелями, активний інструмент — плаваюча плашка над мапою. Обидва екрани використовують її; бічні панелі різняться набором.

Панелі (`BattleMapPanel = 'size' | 'background' | 'cells' | 'edges' | 'mode' | 'motion'`):

| Панель | Вміст (перевикористання) | Коли прихована / пояснення |
|---|---|---|
| Розмір і сітка | `GridTypeChoice`, стовпці/рядки (`BoundedNumberInput`), поля — у `Disclosure` «Поля (відступи)» з «Порівну» | завжди |
| Фон | `UvttImportSection` (з редактора бібліотеки; `replaceMapFromImport` уже є в `BattleMapEditor`), `ImageUpload`, «Стандартний фон», ползунки клітинки/зсуву/прозорості, `GridCalibration` — **усе з `MapBackgroundSection`** | завжди |
| Клітинки | `MapCellToolsSection` (блок/стіна/небезпека/гумка + пензель небезпеки) | режим з `hidesTerrain` → панель disabled з поясненням `edgesDisabledMode` |
| Стіни й двері | `ToolButtons EDGE_TOOLS`, `DoorToolOptions`, `OnboardingHint dm.map-walls` | гекс → `hexEdgesOff`; дотик → `edgesDesktopOnly`; `hidesTerrain` → `edgesDisabledMode`. Вкладка лишається видимою, але приглушеною з поясненням усередині (DM розуміє, чому) |

- Вкладки панелі — той самий стиль, що `EditorSidebar` (сітка 2×N, групи «Мапа / Малювання / Особливе»), але кольори за поправкою: активна — `--hud-accent` обвідка + `--hud-panel-2`, не `bg-primary`.
- Перемикання панелі **знімає** активний інструмент, якщо він належить іншій панелі (клітинки ↔ краї) — як `panel === 'edges' ? edgeEditing : null` у редакторі бібліотеки. Це прибирає ситуацію «малюю стіни, а клікаю — ставляться блоки».
- **Плаваюча плашка інструмента** (`ActiveToolChip`) у лівому верхньому куті полотна: назва інструмента, для небезпеки — «1d6 вогонь», кнопка ✕; `Esc` знімає інструмент (keydown на полотні).
- **Повідомлення** `editor.notice` — тост унизу полотна (`role="status"`), замість рядка над мапою, що стрибав висотою.
- **На весь екран** (`⛶`): `MapWorkbench` рендериться у `FullscreenOverlay` (modal) з тією ж бічною панеллю і кнопкою «Готово»; стан не губиться, бо `editor` той самий. Для великих мап (≥ 40×40) і ноутбуків 1280×720.
- **Перший вхід** (мапа ще стандартна 20×15 без фону): поверх полотна картка «Як почати» з трьома великими діями: «Завантажити зображення мапи» (відкриває панель «Фон» і файловий діалог), «Імпорт UVTT (.dd2vtt)», «Порожня сітка — малювати вручну» (панель «Клітинки»). Зникає після першої дії; не показується при редагуванні наявної мапи.
- **Від своєї мапи до бібліотеки** (опційно, див. питання 2): кнопка «Зберегти в бібліотеку» в шапці бічної панелі.

### 3.5 Стани форми

- **Завантаження**: `SetupLoading` → скелетон тієї самої геометрії (шапка, вкладки, дві колонки), без стрибка.
- **Немає героїв** у кампанії: каталог «Герої» — порожній стан з посиланням «Створити героя».
- **Немає істот**: порожній стан з посиланням на бібліотеку істот і «Імпорт SRD» (тексти `units.hintEmpty/empty` наявні).
- **Помилка збереження**: `ActionBar error` (як зараз).
- **Бій не prepared** (редагування активного/завершеного): каталог і мапа read-only, банер зверху «Бій уже почався — склад і мапу змінити не можна» (тексти `library.locked` + новий ключ).
- **Невалідна назва**: фокус і підсвітка інпута в шапці.

### 3.6 Клавіатура та a11y

- Вкладки — наявні `Tabs` (стрілки). Сегменти сторони й джерела мапи — `radiogroup`/`aria-pressed`.
- `Esc` на полотні — зняти інструмент; у повноекранному режимі `Esc` без інструмента — вийти з повного екрана.
- Кнопки «+С/+В» в іконковому вигляді мають `aria-label` з ім'ям сутності («Додати Скелет до ворогів»).
- Колір сторони дублюється іконкою (щит/мечі) і текстом, не лише кольором.
- Цілі дотику ≥ 40 px на phone (степер, сегмент).

## 4. i18n

Namespace `battleSetup` (у `BATTLE_NAMESPACES`, бюджет scope близький до нуля; паралельна сесія ділить scope за маршрутами — `battleSetup` має піти в окремий scope `dm/battles`, бо в бою не потрібен). Орієнтовно:

| Група | Нові ключі | Видаляються |
|---|---|---|

| `map.*` (джерела, панелі ×6 + описи, quick start ×3, тост, повний екран) | ~20 | `mapChoice.*.description` (−3), `enabled` (−1) |
| `balance.*` (терези) | ~4 | — |

Разом ≈ +64 / −12 ключів (обидві мови). Якщо до старту реалізації scope ще не розділено — реалізацію смуги з i18n блокує тест `scope-size`; тоді першим кроком перенести `battleSetup` з `BATTLE_NAMESPACES` у layout `dm/battles` (він уже `ExtendLocaleScope`), перевіривши, що play-сторінки не читають `battleSetup` (зараз читають лише `MapTerrainToolbar`, `EditorHeader` і серверні схеми — їм лишити потрібні ключі через `maps`).

## 6. Ризики

1. **i18n scope** (§4) — найімовірніший блокер; узгодити з сесією розділення scope.
2. **`$queryRaw` для прев'ю** — перший raw-запит у списку; тримати в `lib/server/battles/list-cards.ts` з тестом на форму результату (локальна БД). Альтернатива без raw — окрема колонка `map_thumb` (міграція expand-only) — не потрібна зараз.
3. **Висота полотна** `calc(100dvh − …)` залежить від `--app-header-h`; у `MapEditorScreen` вона вже так рахується — винести в `MapWorkbench` одну константу.
4. **Вкладений `<form>`**: `UvttImportSection`/`ImageUpload` у формі битви не повинні сабмітити форму (усі кнопки `type="button"`; перевірити `FileButton`).
5. **`MapWorkbench` спільний з редактором бібліотеки** — регресія в `/dm/maps/[mapId]`; покрити тестом рендеру обох.
6. **Пропс-бюджет ≤ 7** — `RosterBoard` близько до межі; групувати в об'єкти.
7. **`keepMounted` вкладок** — полотно мапи змонтоване на прихованій вкладці; Canvas має не рахувати розмір у `display:none` (зараз так само; перевірити ресайз при показі вкладки).

## 7. Тести

- `BattleList`: банер лише для active; фільтр-чіпи рахують і фільтрують; completed у `Disclosure`; демо без дій; порожній стан; `data-tour` на місцях.
- `BattleCard`/`BattleRow`: «Видалити» лише в `⋯` з підтвердженням; клік по картці веде на редагування; прев'ю без фону → плейсхолдер.
- `loadBattleListCards`: поля мапи з JSON, fallback на `battle_maps.header`, `count` з `quantity`, faces ≤ 5, unsafe background → `null`.
- `useBattleListSections`: фільтр статусу + пошук, активні не фільтруються.
- `ParticipantCatalog`/`CatalogRow`: «+С»/«+В» викликають `addToSide` з правильною стороною; сегмент перемикає `setSide`; степер — `setQuantity`; клік по рядку героя → союзник, істоти → ворог; aria-label.
- `RosterBoard`: дві колонки, ⇄ і ✕, резерв; порожня колонка; автопідбір лише при створенні.
- `BalanceMeter`: fair і xp; `[?]` відкриває деталі.
- `SetupHeader`: required-назва, індикатор «Деталі».
- `BattleMapStep`: сегмент → `setEnabled`/`library.select`; без бібліотеки — два пункти; locked.
- `LibraryMapGrid`: обрання, занадто велика — disabled, thumb/плейсхолдер.
- `BattleMapSidebar`: видимість/disabled панелей для hex, touch, hidesTerrain, без режимів/руху; зміна панелі знімає чужий інструмент.
- `MapWorkbench`: рендер у редакторі бібліотеки та у формі; повноекранний режим; `Esc`.
- Перенести наявні: `battle-setup-form.test`, `BattleFormMap*.test`, `setup-participant-row.test`, `BattleMapLibraryPicker.test`, `BattleListCard.test`, `setup-intl.test`.
