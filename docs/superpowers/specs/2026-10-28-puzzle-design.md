# Пазл у «Показі» — дизайн

## Мета

Новий вид слайда «пазл»: карта нарізана на шматочки фіксованого розміру, гравці беруть їх із сайдбара й складають на спільній дошці. Правильно поставлений шматочок підсвічується легким зеленим. Одночасно шматочок тримає лише один гравець, поки не поверне його в сайдбар.

## Рішення користувача

- Нарізка: генератор із параметрами (тип, кількість, перемішування). Ручний редактор контурів — пізніша стадія.
- Типи нарізки: `classic` (сітка з виступами/западинами), `organic` (Вороной), `straight` (прямі зрізи).
- Обертання по 45° (8 положень); правильний кут — 0°.
- Дошка — порожня рамка розміром із карту, без контурів-підказок. Правильність — допуск ~чверть розміру шматочка + кут 0°; шматочок притягується до місця, підсвічується зеленим, але лишається рухомим (без блокування).
- Пазл — вид слайда в наборі (`Slide.kind = "puzzle"`), а не режим поверх слайда.
- Синхронізація: події лише на grab / drop / return (обертання їде всередині `drop`), без руху під час перетягування. Утримання спливає через 30 с без активності.

## Дані й нарізка

- `Slide` (набір, `slide_decks.slides JSONB`) отримує `kind: "puzzle"` з полями: `imageUrl`, `imageWidth`, `imageHeight`, `cut` (`classic | organic | straight`), `count`, `seed`.
- `lib/utils/puzzle/generate.ts` — чиста функція: параметри слайда → шматочки `{ id, path, bbox, home }` у пікселях зображення (`imageWidth` × `imageHeight`). Усі координати в стані цілі (payload Pusher ≤ 10 КБ), `count` ≤ 60. Нічого не зберігається, клієнти й сервер перераховують за `seed`. «Перемішати» міняє `seed`.
- Гарантії: без дірок і перекриттів, однакова нарізка за однаковим `seed`, межі `count`.
- Редактор слайда (DM): завантаження в бакет `scene-slides` (клієнтське зменшення в WebP), вибір типу й кількості, прев'ю нарізки.

## Живий стан і правила

`ShowState.puzzle`: для кожного шматочка `{ x, y, rot, place: "tray" | "board", correct, holder?: { userId, name, until } }` і `solved`.

Один гравець тримає не більше одного шматочка: `grab` іншого в тій самій команді повертає попередній у сайдбар. Поки показ закритий завісою/світом/боєм, команди гравців відхиляються (DM `release`/`reset` працюють). Id шматочка — `p{r}-{c}` / `p{i}`.

Початок: усі в сайдбарі, порядок і кути (кратні 45°) випадкові за `seed`.

Команди (окремий маршрут, бо їх шлють гравці; решта команд показу — тільки DM):

- `puzzleGrab { pieceId }` — відмова, якщо тримає інший і `until` не минув.
- `puzzleKeepAlive { pieceId }` — клієнт раз на ~10 с, поки тримає; продовжує до 30 с.
- `puzzleDrop { pieceId, x, y, rot }`, `puzzleReturn { pieceId }` — лише власник утримання.
- DM: `puzzleRelease { pieceId? }` (без id — усі), `puzzleReset`.

`drop`: сервер сам рахує правильність (центр у межах ~0.25 розміру шматочка від `home` і `rot % 360 === 0`) → притягує до `home`, `correct = true`. Усі `correct` → `solved`.

Конкуренція: команди через `seq` показу з повтором при конфлікті; перший `grab` виграє, інший отримує відмову, клієнт повертає шматочок у сайдбар. Прострочені утримання знімаються ліниво при наступній команді/читанні. Pusher: `show-state`, без подій під час перетягування.

## Інтерфейс

- Дошка: рамка розміру карти, шматочки через SVG `clipPath`, без контурів-підказок.
- Сайдбар: зліва на десктопі, знизу на телефоні.
- Перетягування pointer events (миша/дотик); обертання ±45° кнопками, клавішами Q/E, колесом миші, поки шматочок у руці; короткий тап (рух ≤ 5 px) по шматочку на дошці обертає його на +45° і шле `drop` на тому ж місці. На дотику стрічка сайдбара гортається (`touch-action: pan-x`), шматочок береться довгим тапом (200 мс) або рухом переважно вгору/вниз; жест слідкує лише за своїм `pointerId`, `pointercancel` = повернення.
- Шматочок, який тримає інший, — приглушений із іменем.
- Правильний — легка зелена підсвітка; при `solved` лінії між шматочками зникають, видно цільну карту.
- DM бачить ту саму дошку + «відпустити» / «скинути».

## Перевикористання

Бакет `scene-slides` + клієнтське зменшення; `ShowState`, `merge-show`, `player-view`, `show-command.ts`; Pusher-хук показу; `ShowDeckStrip`, прив'язки сценарію; `ResponsiveDialog`. Нове: генератор, вид слайда, команди й маршрут пазла, дошка й сайдбар.

## Тести

- Генератор: сума площ = карта, детермінізм за `seed`, межі `count`.
- Команди: блокування, спливання 30 с, правильність і притягування, `solved`, відмова чужому, права DM.
- `player-view` для пазла; компонентні тести дошки й сайдбара.

## Поза межами

Ручний редактор ліній розрізу; живі позиції під час перетягування (Pusher client events); блокування правильних шматочків.
