# «Показ» і «Сценарій»: редизайн під широкі монітори (D-C, 2026-11-26)

Пункти 9 і 10 з `owner-batch-2026-11-26.md`: огляд DM-сторінки «Показ» (UX і вигляд) та адаптація «Сценарію» (рукопис, граф, прив'язки гри) до 1600/1920/2560 без поломки телефона.

Візуальна мова — DESIGN.md (`2026-11-25-design-system.md`) з поправкою «вайб таверни»: акцент — золото `--hud-accent*` (червоне лише HP/небезпека/помилки/деструктив), радіуси 8/12, м'які тіні замість рамок, hover на кожному інтерактивному елементі, переходи на зміні сторінки/вкладки. Кіт: `components/ui/*`, `components/hud/{form,page}/*`, `.ds-panel/.ds-inset/.ds-raised`.

**Логіка, API, Pusher-протокол, `ShowCommand`, модель даних не змінюються.** Лише компонування, стилі, кілька нових презентаційних компонентів.

# Частина 1. «Показ»

Три екрани: список колод `/dm/show`, редактор колоди `/dm/show/[deckId]`, живий показ `/show` (DM-режим). Попередній перегляд `/dm/show/[deckId]/preview` (демо) — лише токени.

## 1.1 Аудит (що не так)

**Список колод (`app/campaigns/[id]/dm/show/page-client.tsx`, `DeckCard`)**
1. Три рівноважні кнопки на картці (Редагувати / Почати показ / Видалити), «Видалити» — звичайна outline-кнопка поруч із головною дією; головна дія не очевидна.
2. Не видно, яка колода **зараз на екрані** у гравців; немає швидкого «повернутись до показу».
3. Колоди не згруповані за сценою, хоча `scenarioPageId` відомий (сцена лише дрібним текстом).
4. Сітка `lg:grid-cols-3` у `max-w-page` — на 1920/2560 три великі картки, решта простору порожня.
5. Обкладинка не клікабельна; hover-стан відсутній.

**Редактор колоди (`[deckId]/page-client.tsx`, `SlideGrid`, `AddSlidesBar`, `SlideDialog`)**
1. `HudFormPage max-w-3xl` — на 1920 робоча зона 768 px, мініатюри по ~240 px, 2/3 екрана порожні.
2. Кожен слайд редагується в модальному діалозі: щоб пройтись по 20 слайдах — 20 відкрить/закрить; не видно сусідів.
3. `AddSlidesBar` — п'ять різнорідних контролів в одному рядку (файли, пазл, URL-інпут, «Додати», «Згенерувати»), на телефоні — стовпчик із 5 елементів над сіткою.
4. Немає drag-and-drop файлів, хоча головний сценарій — «накидати картинок».
5. «Зберегти» внизу форми; на довгій колоді треба прокручувати; стан «є незбережені зміни» не видно.
6. Перестановка — лише кнопки ←/→ по одному кроку.

**Живий показ (`app/campaigns/[id]/show/page-client.tsx`, `ShowControlPanel`)**
1. DM бачить сцену на всю ширину, а керування — під нею, нижче за саундборд: на 1080p стрічка слайдів часто під згином, на 1440p+ — сцена гігантська, керування дрібне (`text-xs`, кнопки 28 px).
2. Немає «що далі» (`nextImageUrl` уже є в `ShowState`, DM його не бачить) і немає підпису/аудиторії поточного слайда поруч із транспортом.
3. Транспорт — чотири однакові іконки 28 px; «Завершити» поруч із «Шторкою» без відступу.
4. Панель `bg-black/60 border-t` — старий матеріал, не tavern; поточний слайд підсвічено через `SHOW_TONE.accent`.
5. Гарячі клавіші (← → B N) ніде не підказані.

# Частина 2. «Сценарій» на широких екранах

Екрани: індекс `/dm/scenario` (`ScenarioIndexPageClient`), сторінка сцени `/dm/scenario/[pageId]` (читання, гра, редактор), граф `/dm/graph`.

## 2.1 Аудит

1. **Жорсткі максимуми.** `.sb-layout` 1460, `.sb-content`/`main`/`header.title` 1180, `.sb-index` 980, `.sb-show-bar/.sb-show-body` 1180. На 1920 — ~230 px порожнечі з кожного боку, на 2560 — ~550 px; на 2560 текст 19 px дрібний для відстані до монітора.
2. **Нотатки DM 320 px** — найщільніша інформація в найвужчій колонці; таблиці й маркери в нотатках переносяться в «стовпчик слів».
3. **Док показу знизу** (`sticky bottom`, `max-height 40vh` у розгорнутому стані) з'їдає висоту саме тоді, коли DM читає текст; на широкому екрані праворуч вільно 300–500 px.
4. **Зміст ховається при відкритому AI** (`tocInline = wide && !ai.isOpen`), навіть на 2560, де місця на все вистачає.
5. **Індекс** — один вузький список 980 px; немає «де ми зараз / наступна сцена», хоча статус `played` відомий.
6. **Граф**: інспектор — оверлей поверх полотна (`absolute w-72`), список — `w-64`; старі токени (`border`, `bg-card`) замість tavern.
7. Акцент активного пункту змісту й фокус — `--blood` (червоний), що суперечить правилу «червоне — лише небезпека».

Книга сценарію — **окремий матеріал** (папір/нічний папір, Alegreya) і таким лишається; HUD-панелі сюди не переносимо. Міняється сітка, ширини, кегль, місце доку.

## 2.2 Рішення: сторінка сцени

Сітка `.sb-layout` переходить з flex на CSS grid з іменованими областями. Колонка тексту лишається ≤ 72ch (читабельність), простір віддається нотаткам і новій **рейці показу**.

```
desktop 1200–1599 (як зараз)
│ TOC 220 │ story ≤68ch │ notes 320 │                      макс 1460, док показу — знизу

wide 1600–2199, сцена у режимі гри
│ TOC 240 │ story ≤70ch        │ notes 380   │ ▌РЕЙКА ПОКАЗУ 360 │     макс 1880
│ ▸Акт I  │ Читати вголос…     │ DM: КС 14…  │ Зараз: «Таверна»  │
│ ▸Сцена  │                    │ [таблиця]   │ ‹ 3/14 ›  B  ■    │
│         │                    │             │ стрічка (grid)    │
│         │                    │             │ ▸ Мапа ▸ Звуки ▸♪ │

wide, без гри (індекс-сторінки, герої, нотатки) або рейку згорнуто
│ TOC 240 │ story ≤72ch          │ notes 420     │                  макс 1640

ultra ≥2200
│ TOC 280 │ story ≤72ch @20–21px │ notes 460     │ РЕЙКА 400 │      макс 2280; кегль: clamp(19px, 0.25vw+14px, 21px)

tablet 860–1199: story + notes 320 (як зараз), TOC — шухляда, док знизу
phone ≤ 860: один стовпець (як зараз), нотатки під текстом рядка, док знизу (як зараз)
```

- **`.row`** — `grid-template-columns: minmax(0,1fr) var(--sb-notes-w)`; змінна `--sb-notes-w` = 320 / 380 / 420 / 460 за брейкпоінтом і наявністю рейки. `gap` 40 → 48 на wide.
- **Рейка показу** (≥1600, лише `playEnabled`): `ScenarioShowDock` отримує `placement: 'dock' | 'rail'`. `rail` — `position: sticky` у правій області grid, висота `calc(100dvh - header - bar - footer)`, власний скрол; вміст — **той самий `ShowControlRail`** з частини 1 (`layout: 'rail'`), обгорнутий у змінні `--show-*` книги (папір/ніч, не tavern) — один компонент, дві теми через CSS-змінні, як уже працює `sb-show-dock`. Кнопка «⇥» згортає рейку в док знизу (стан у `useShowDockExpanded` → розширити до `'rail' | 'dock'`, збереження в `localStorage` як зараз).
- **AI + зміст**: `tocInline = wide && (!ai.isOpen || ultraWide)` де `ultraWide = useMediaQuery('(min-width: 1900px)')`. Коли AI-панель відкрита на ≥1600, рейка показу згортається в док (AI займає праву смугу; одночасно дві праві панелі не показуємо).
- **Прив'язки рядка** (`RowBindings` над текстом рядка — рішення власника з «Scenario play UI») **не переносимо**. На ≥1600 чипи отримують `max-width` імені 220 замість 160.
- **Редактор** (`ScenarioEditor` + `ScenarioToolbar`): та сама сітка (без рейки), тулбар `max-width` = макс сітки; редагування нотаток у ширшій колонці дає більший `RichTextEditor`. Логіка редактора не змінюється.
- **Шапка `.sb-bar-in`** — `max-width` = макс сітки поточного брейкпоінта (змінна `--sb-max`), щоб назва й кнопки стояли над текстом, а не над порожнечею.
- **Акцент**: активний пункт TOC, `:focus-visible`, hover-заголовки → `--gold` (у світлій книзі — затемнене золото з контрастом ≥ 4.5:1 на `--page`, новий токен `--gold-ink`); `--blood` лишається для «Читати вголос», буквиці, маркера `event` (небезпека) і помилок.

## 2.5 Стани (сценарій)

- Рейка показу без колоди для сцени: секція «Колода» з `SelectField` (групи «Ця сцена / Інші») — як у доці зараз.

# Ризики

1. **Дві теми рейки** (tavern на `/show`, папір у книзі). Пом'якшення: рейка стилізується лише через `--show-*` змінні (як `sb-show-dock` сьогодні), без жорстких `hud-*` класів усередині.
2. **Sticky-висоти**: книга вже рахує `--app-header-h`, `--sb-bar-h`, `--sb-toolbar-h`, `--sb-dock-h`; рейка додає ще один стовпець — у режимі `rail` `--sb-dock-h` має бути 0, інакше TOC обріжеться.
3. **AI-панель** (`position: fixed`, `padding-right`) + рейка — взаємовиключні на ≥1600; тест на перемикання.
4. **Drop файлів** у редакторі конфліктує з браузерною поведінкою «відкрити файл» поза зоною — `preventDefault` на `dragover` лише в межах лівої колонки.
5. **Тури** (`data-tour="show.*"`) — зберегти атрибути на нових місцях (`show.decks`, `show.deck-card`, `show.start`, `show.present`, `show.stage`, `show.nav`); `demoTours` перевірити.
6. Бюджет пропсів — `ShowDeckStrip` має 4 + 1, `ScenarioShowDock` 4 + 1 — у межах.

# Відкриті питання до власника

1. Пульт ведучого на `/show`: DM зазвичай тримає `/show` на своєму моніторі (тоді рейка доречна) чи виводить його на окремий екран/проектор для гравців (тоді потрібен режим «чиста сцена» за замовчуванням і пульт в іншій вкладці)?
2. Drag-and-drop перестановки слайдів — потрібен зараз (додає залежність, напр. `@dnd-kit`) чи достатньо кнопок і `Alt+←/→`?
3. Рейка показу в сценарії на ≥1600 — увімкнена за замовчуванням чи док знизу лишається дефолтом, а рейка — опція?
4. Акцент у книзі сценарію: замінити червоний активний стан на золото (як у решті застосунку) чи книга лишається зі своїм «кров'яним» акцентом як окремий матеріал?
5. На 2560 збільшувати кегль книги (до ~21 px) чи лишити 19 px і віддати простір лише колонкам?
