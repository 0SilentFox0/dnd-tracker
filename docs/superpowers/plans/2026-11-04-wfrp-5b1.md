# WFRP 5b-1: рушій бою — план

> **Для виконавців:** superpowers:subagent-driven-development (рекомендовано) або executing-plans. Кроки з чекбоксами. Виконавці — Sonnet; без рев'ю після кожної задачі, один фінальний Opus-review; повний `test:run`/lint — один раз наприкінці (перед цим `ps` на важкі процеси).

**Мета:** бій у кампанії `rules.system.key = wfrp` стартує й проходить на сервері: opposed melee, ranged-тест, локація, AP, шкода, Wounds, крити, ініціатива, Move+Action, Momentum, `cellFeet`, SL-баланс; `battle.supported = true`.

**Архітектура:** системні хуки в `RuleSystemDefinition.combat` — **необов'язкові** (у d20 їх немає → наявний шлях без змін, жодних обгорток). Місця виклику: `if (hook) … else <старий код>`. Чиста логіка — `lib/utils/rules/systems/wfrp/combat/`. `AttackRollResult` отримує необов'язкове поле `percentile` (не union — менший радіус змін; відхилення від чернетки spec, spec оновлено).

**Spec:** [2026-11-04-wfrp-5b1-design.md](../specs/2026-11-04-wfrp-5b1-design.md). Архітектура: [rule-systems.md](../../architecture/rule-systems.md), [battle.md](../../architecture/battle.md) — **прочитай battle.md перед задачами 4–7**.

## Global Constraints

- Ядро не імпортує `lib/utils/rules/systems/wfrp*` (ESLint) — лише `ruleSystemOf(rules)`.
- Нові ідентифікатори англійською; користувацькі тексти — ключі в `messages/{uk,en}/*.json` (кирилиця в коді заборонена), лог — `textRef("battleLog.…")`.
- Усе, що пише `battle_participants.snapshot`, пише `snapshotHash`; шкода → `applyDamageConsequences` одразу після примітива; відповіді — дельти (`ClientBattleDelta`).
- Тести: сусідні `__tests__/`; під час роботи `pnpm test:related <files>` + `pnpm exec eslint --fix <files>`; ніяких repo-wide lint.
- Коміти `feat(wfrp): …` + `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Константи правил wfrp — тільки в `wfrp/combat/constants.ts` (позначка «звірити з книгою 5e»).
- d20-поведінка не змінюється: наявні тести без правок; у кінці `battle-sweep` на prodcopy.

## Review Focus

1. Дубль на кидку атаки в **промаху** (fumble-подібний): крит-таблиця застосовується лише до влучань; промах-дубль — лише лог.
2. Атака по цілі з 0 Wounds / Unconscious: не падає, не створює другого крита.
3. Шкода менша за TB+AP → рівно 1 (не 0, не від'ємна).
4. `characteristics` порожні/дефолтні (`{}`) у юніта → дефолти `readCharacteristics`, не NaN.
5. Збережений `scene.rules` без `combat`-хуків (старі d20-бої) → шлях без змін.

### Task 1: Чисті утиліти `wfrp/combat/`

**Files:** Create `lib/utils/rules/systems/wfrp/combat/{constants,opposed,location,damage,crit-table,index}.ts` + `__tests__/`.

**Interfaces — Produces:**
- `constants.ts`: `OUTNUMBERING_BONUS`, `MOMENTUM_SL_BONUS`, `MIN_DAMAGE = 1`, `LOCATIONS = ["head","arm","body","leg"] as const`, `type HitLocation`.
- `opposed.ts`: `resolveOpposed({ attackerTarget, defenderTargets: {kind:"parry"|"dodge"|"shield", target:number}[], attackerSlMod?, rng, presetRolls? }): { attacker: PercentileTestResult; defender: PercentileTestResult & {kind:string}; isHit: boolean; netSl: number; attackerWon: boolean }` — автовибір найкращої цілі захисника; більший SL виграє, нічия → атакувальний; авто-провал атакувального (96–00) = промах.
- `location.ts`: `hitLocation(roll: number): HitLocation` (реверс кидка: 01–09 голова, 10–24 рука, 25–44 рука, 45–79 тіло, 80–89 нога, 90–00 нога — зафіксувати таблицею в коді й тесті).
- `damage.ts`: `computeWfrpDamage({ weapon: number, sb: number, netSl: number, tb: number, ap: number }): { total: number; steps: {key:string; value:number}[] }` = `max(1, weapon + sb + netSl − tb − ap)`.
- `crit-table.ts`: `rollCrit(location, rng): { id: string; textKey: string; bonusDamage: number; markerKey?: string }` — d100, 4 таблиці по ~5 рядків, ключі `battleLog.wfrp.crit.<loc>.<n>`.

- [ ] Табличні тести (rng з `presetRolls`): авто успіх/провал, дублі, нічия, більший SL, мін. шкода 1, межі локацій (01,09,10,…,00), кожен рядок крит-таблиці досяжний.
- [ ] Реалізація, `pnpm test:run lib/utils/rules/systems/wfrp/combat`, eslint, коміт.
- [ ] Ключі `battleLog.wfrp.crit.*` у `messages/{uk,en}/battleLog.json` (власний grimdark-текст, без бренду).
