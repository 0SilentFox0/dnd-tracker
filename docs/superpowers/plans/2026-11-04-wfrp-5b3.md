# WFRP 5b-3: UI бою — план

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Кроки — `- [ ]`. Задачі згруповано в диспетчі (D1–D6): один implementer на диспетч.

**Goal:** wfrp-бій проходить з UI без d20-артефактів: Wounds, d100 (ручний ввід пари d10 / серверний), Momentum до кидка, SL/локація в підсумку, пара d10 на сцені; d20-системи без змін.

**Architecture:** прапорці беруться з `RuleSystemDefinition` через `useBattleRules()` (з `scene.battle.rules`, без окремого запиту); візард атаки отримує d100-варіант `RollStep`/результату; сервер лише розширює валідацію `d20Roll`; 3D-кубики будуються з `actionDetails.percentile` у `from-action.ts` (без змін сервера й `diceRolls`).

**Tech Stack:** Next.js 16, React 19, TanStack Query, next-intl, vitest (+happy-dom), three (рушій кубиків).

**Spec:** `docs/superpowers/specs/2026-11-04-wfrp-5b3-design.md` (+ 5b-2 spec, `docs/architecture/rule-systems.md` «Межі 5b-2»).

## Review Focus

1. Пара d10 «00»+«0» = 100; порожнє/неповне поле (лише десятки без одиниць) не дає кидка; запасне поле 1–100 і пара дають однакове значення (`composePercentile`).
2. `d20Roll`/`attackRoll`/`attackRolls` = 0, 101, 12.5 відхиляються в wfrp; 21 відхиляється в dnd5e/homm (регресія межі); 100 у d20-бою — 400, не тихий clamp.
3. Поки правила не завантажені (`useRuleSystem` без `system`) жоден d20-вигляд (AC, бонус атаки, d20-сітка) не мигає й не рендериться у wfrp.
4. Багатоцільова атака wfrp: кожен `attackRolls[i]` ≤ 100, а режим `advantage`/`disadvantage` примусово `normal` (UI їх не показує, сервер ігнорує).
5. Гравець, який бачить ціль не «exact»: ні Momentum/SL захисника, ні ціль захисту не витікають у d100-результат (лише те, що вже показує d20-варіант для AC).
