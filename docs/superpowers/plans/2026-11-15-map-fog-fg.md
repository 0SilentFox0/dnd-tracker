# Map Fog F/G Implementation Plan

> Inline execution in the current `main` checkout. Tasks are implemented in order with focused tests before behavior changes.

**Goal:** Implement battle fog mode A (DM reveals areas) and mode B (player vision with persistent client memory) using the existing `battle_map_state` layer.

**Architecture:** Keep mutable fog in `BattleMapState.fog`; add compact row-run encoding and partial fog deltas to the existing map-state pipeline. A reusable canvas overlay renders unrevealed cells below participants; a core `fogView` filters participant visibility without changing server payloads. Mode B computes symmetric grid-ray line-of-sight from viewer-owned heroes using edge walls and map opacity sources, and stores explored cells in browser storage keyed by battle and viewer. This implementation is not recursive symmetric shadowcasting; retain that as a follow-up if profiling or visual review shows a need.

**Tech Stack:** TypeScript, React, existing battle mutation pipeline, `battle_map_state` JSON, Canvas 2D, localStorage, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-13-map-editor-design.md`, §§3 F/G, 6, 7.1.

## Global Constraints

- Do not create or apply migrations; existing `battle_map_state.fog Json?` is the storage target.
- Do not change production, remote Storage/assets, or push/merge.
- Maze keeps its existing fog and vision; generic fog is ignored for maze maps.
- Player hiding is UI-only; server payload and authorization boundaries remain unchanged.
- Use deltas for map state; never broadcast the full reveal set on each stroke.
- No new dependencies; no browser route run until final editor browser pass.

## Review Focus

- Large 200×200 reveal sets stay compact and edits stay within grid bounds (row-run codec tests).
- Edges and diagonal corner leaks do not expose cells through walls (shadowcast symmetry and edge tests).
- Missing/dead/hidden player viewpoints do not reveal tokens, while DM always sees all (fogView tests).
- Maze maps bypass generic fog (integration tests).
- Applying a fog delta preserves unrelated removed-edge and door state (map-state delta tests).

## Task 1: Fog model and compact reveal runs

**Files:** `types/battle.ts`; create `lib/utils/battle/fog/revealed-runs.ts` and tests; modify `lib/utils/battle/map-storage/effective-map.ts` and tests.

- Define `FogMode`, `FogState`, `RevealedRun = readonly [y, startX, endX]` (end exclusive), and typed `BattleMapState.fog`.
- Implement normalization, membership, add/remove, and set-diff for sorted non-overlapping row runs. Clip/validate against `{cols, rows}` at public mutation boundaries.
- Extend `MapStateDelta.fog` to patch mode/radius and add/remove revealed runs; `diffMapState` and `applyMapStateDelta` must preserve unrelated map state and return null for no-op deltas.
- Tests cover adjacent/overlapping merge, subtraction/split, bounds, round-trip, mode/radius changes, and doors/removed edges surviving fog patches.

## Task 2: Flood-room geometry and edge-aware reveal editing

**Files:** create `lib/utils/battle/fog/reveal.ts` and tests.

- Implement `floodRoom({map, start, blocked})` as bounded four-neighbor fill, stopping at map edges, blocked cells, and walls/bars/closed doors.
- Implement pure brush/rectangle operations that add or remove cells and return normalized runs; use existing `cellLine` and edge helpers where appropriate.
- Tests cover enclosed rooms, openings, blocked terrain, boundaries, rectangle clipping, and erase.

## Task 3: Battle mutation and map-state persistence path

**Files:** create `lib/server/battles/mutations/map-fog/`; modify operation registry, battle schemas/types, API action hooks, and focused mutation/route tests.

- Add a DM-only `map-fog` operation. Its validated actions set mode/radius or add/remove reveal runs; merge against current `ctx.meta.mapState` and emit `scene.mapState` only.
- Include grid limits, maximum run count/payload size, reject malformed/out-of-map intervals, and ensure map-state version/snapshot/rollback paths use existing pipeline semantics.
- Add `useMapFog` client mutation using current battle operation hooks; invalidation is not used for normal deltas.
- Tests cover permissions, invalid runs, mode/radius changes, reveals, erases, snapshot rollback, and no-op behavior.

## Task 4: Mode A editor controls and fog overlay

**Files:** create `components/battle/map/fog/MapFogLayer.tsx`, `components/battle/dm/...` fog controls, and tests; modify BattleMap/MapStage integration and DM battle controls.

- Render a DPR-aware canvas in map viewport coordinates, clipped to the visible grid window and beneath tokens. `off` draws no veil; `reveal` veils unrevealed cells; newly revealed areas may fade in; `vision` consumes the visible set from Task 5.
- DM can select off/reveal, brush, rectangle, room fill, erase, and set vision radius. Tools are disabled in maze and when the user is not DM.
- Add reveal edits as compact patches and keep the active mode/state synchronized from battle scene deltas.
- Tests cover viewport clipping, draw-layer ordering, maze bypass, tool routing and visible state controls.

## Task 5: Symmetric grid-ray visibility and opacity sources

**Files:** create `lib/utils/battle/vision/shadowcast.ts` and tests.

- Compute visible cells within a bounded radius from a source. Opaque transitions include blocking edge walls, `blocksSight` objects, `obscured` terrain and closed doors. Walls block passage between cells rather than making either adjacent cell itself opaque.
- Use symmetric grid-ray visibility with explicit corner behavior; union views from multiple viewer tokens and optional allied sharing.
- Tests cover open room radius, wall shadow, edge walls, diagonal corner blocking, symmetry, multiple sources, map bounds and 200×200 cap.

## Task 6: Player fog view, explored memory, and DM viewpoint

**Files:** create `lib/utils/battle/fog/fog-view.ts`, `lib/hooks/battle/useFogMemory.ts` and tests; modify BattleMap participant filtering and DM viewer controls.

- `fogView` returns visible/explored cells and visible participant IDs for the chosen viewer. DM sees all; maze bypasses generic fog. Hidden opponents and non-visible objects are filtered only from client rendering.
- Persist explored row runs in localStorage under a versioned key containing battle ID and viewer ID; merge newly visible runs, tolerate corrupted/old values, cap storage to map bounds and expose a “remember explored” toggle.
- DM may inspect as a selected player; no client memory is shared across viewer IDs. Player view uses the authenticated participant's heroes; optional allied sharing unions them.
- Tests cover DM bypass, own/enemy visibility, hidden/dead tokens, memory merge/reload/corrupt data, sharing toggle, viewer switch and maze.
