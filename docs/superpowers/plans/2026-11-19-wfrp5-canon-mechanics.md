# План: Grim d100 (5e) за каноном WFRP 5e — механіки, потім контент і іконки

Джерело розбіжностей: `docs/superpowers/research/2026-11-19-wfrp5-canon-audit.md` (ID `A/Mxx` механіка, `B/…` персонаж, `C/…` магія/спорядження/бестіарій). Канон — PDF власника (витяг поза репо `~/Work/wfrp-extract/out/wfrp5/`, у репо лише перефраз і номери сторінок). Шаблон лишається оригінальним (без IP GW, `forbidden-terms.ts`).

## Принципи

- **Параметризувати, не хардкодити.** Усе, що відрізняється між 4e і 5e (крок просування, ініціатива, модель Momentum/Advantage, XP-таблиці, створення), — дані в `rules`-пресеті/`rules.json`, а не `if`. Тоді шаблон 4e (етап 2) бере спільний код і свій пресет. Ядро не називає систему (CLAUDE.md, rule-systems).
- **Канонічний тест на кожну правку:** тест цитує сторінку книги в назві/коментарі `// p131` (англ.), на прикладах з книги (приклад на с. 132 тощо).
- **Expand-only міграції** даних персонажів/станів; старі герої мають перераховуватись або мати міграційний скрипт (прод: HOMM5/SRD не зачіпати).
- **Перед кожним пакетом:** reuse-пошук у `systems/wfrp/rules`, `lib/utils/battle`; **наприкінці пакета:** `pnpm test:related`, eslint по папках; повний `test:run` + battle-sweep homm/dnd5e на prodcopy — раз на хвилю (пакети W1–W4 чіпають спільний бойовий пайплайн).
- Агенти не запускають тести; виконавці Sonnet, фінальне рев'ю Opus (feedback-model-roles / review-cadence).

## Хвилі та пакети (залежності → вниз)

### W0 — Перейменування й підготовка (S)
- Показувана назва → «Grim d100 (5e)» (`manifest.names`, `lib/utils/templates/registry.ts`, `messages/*/{gameTerms,help,whatsNew}.json`, `template-tiles.test.tsx`). **Ключ `grim-d100` лишається**; шаблон 4e — новий ключ в етапі 2 (див. «Рішення власника»).
- Винести редакційно-залежні числа в пресет-перемикач (легасі ↔ 5e-канон; нові кампанії = 5e, існуючі лишаються на легасі до явного перемикання): `advanceStep`, `initiative.mode`, `momentumModel`, `xpTables`, `creation.mode`.
- Каркас канон-тестів: `systems/wfrp/__tests__/canon/*.test.ts` + хелпер «приклад з книги».

### W1 — Ядро тесту (A/M01, M02, M36, M11, M37)
- `percentile/resolve.ts`: `finalSl = tens(target) − tens(roll) + mods`; успіх = `finalSl > 0` (0 SL: за кидком ≤ ціль, с. 130); крит/фамбл лише за дублями (старі правила чіпаємо лише тут).
- `combat/opposed.ts`: перемагає вищий SL, успіх не потрібен, рівність — ініціатор; виправити `win-chance.ts`, `hit-model.ts`.
- `skillTarget(chars,'melee',group)` для цілі атаки/парирування (Advances навичок враховуються).
- Ініціатива: `bonus(I)+d10`, тай-брейк за I (`initiative.mode='roll'` у пресеті WFRP).
- Прибрати «verify» у таблиці складності; перевірити числа таблиці (+6/+4/+2/0/−1/−2/−3).
- Acceptance: приклади с. 131–132; регрес `battleWfrp` тестів; нічого в d20/homm.

### W2 — Advantage, Momentum, Fate/Fortune (M05–M08; після W1)
- Advantage/Disadvantage: збір джерел у `resolveAttack` і sheet-тестах, парне скасування, ±1 SL за надлишок; Momentum дає Advantage (не +1 SL).
- Momentum — per-participant (`momentum: boolean` у слоті учасника), знімається станом/шкодою, витрата на Disengage/другу атаку.
- Fate і Fortune — два пулі: `fortuneMax` окремо від `fate` (дані видів); Fortune = Advantage/перекид/зняття стану; операції `spendFate` (3 режими) з журналом, видимість лише власнику (`ext[wfrp]`, delta-відповіді).
- Міграція: поточний єдиний пул → Fate (=Fortune max) для існуючих героїв.

### W3 — Рани, крити, стани (M03, M10, M20, M21, M22, M23, M35, **M04** — після W1/W2)
- 0 Wounds без авто-Unconscious; Critical Wound лише при `damage > currentHp`; кожне влучання на 0 HP → крит, +10 за кожну зайву Wound; лічильник критів > TB → смерть за TB раундів.
- Схема таблиць до `max > 100` + ефект `death`; тривалі травми; крит-кидок за подвоєнням захисника; Bleeding тест (с. 185).
- Стани: штраф у SL (`mod = −max(level)` між станами, не сума), Stunned = ½ Move без втрати дії, Prone/Blinded/Surprised/Ablaze/Poisoned за с. 184–187; тік Poisoned, хуки переходів, SL-зняття.
- Локації: розвести arm/leg на L/R. Міграція: відсоткові модифікатори станів → SL у даних/стані.

### W4 — Дії, рух, модифікатори бою, розмір (M09, M12, M13, M14, **C/size damage** — після W2/W3)
- Єдиний список SL-модифікаторів у `resolveWfrpAttack` (дальність-смуги, surrounded, Helpless, called shot, розмір ±1 SL лише для дальніх, парирування −2 SL проти більшого, Outnumbering).
- Шкода розміру: +SB за крок (а не ×(1+крок)) — **C Critical**; профілі вже містять SB; формула Wounds Small/Tiny.
- Дії: «захищаюсь» +2 SL, Charge→Momentum, Disengage, Reach/Defensive (чи покриває core d20 — перевірити, `systems/wfrp` опцій немає).
- Фамбл у бою: таблиця Oops (`rules.tables`) + Misfire порохової зброї.

### W5 — Психологія (M24–M26, **C Fear/Terror** — після W2)
- Terror: будь-який успіх проходить; Broken = рейтинг + `max(0,−SL−1)`; Fear: без Momentum + Advantage замість Broken, розширений тест накопичення SL по раундах (с. 183–184, 358, 362); Frenzy/Hatred/Animosity.

### W6 — Створення, просування, простій (M15, M16, M17, M18, M39, B/Critical+Major, M07 дані — після W2)
- Просування +5 (характеристики), таблиці XP за каноном (характеристики/навички/таланти: плоска ціна таланту), ліміти, тики 10/12/14, кар'єра: перехід/зміна 100 / 100–200 XP.
- Покрокове створення 5e: advances виду/кар'єри, мови, кар'єрний талант, спорядження, +6/+3 до характеристик, Fate/Fortune +1, ліміт 4–16; прибрати старт 50/25 XP (це 4e-логіка → піде в пресет 4e).
- Просте: дохід за Status tier, ендевори ≤3, одужання (Endurance, Heal = IB+SL).
- Міграція: перерахунок `xpSpent`/просувань існуючих героїв скриптом `scripts/` (dry-run → apply); `rulesHashes` baseline для просування.

### W7 — Магія й релігія (M19, M27–M33, **C magic** — після W2/W3)
- Petty CN 0; Miracle без CN (або налаштування); overcast за таблицею с. 236 (межа IB+WPB, вибір напряму); Dispel; Malignant Influence замість Major miscast на 99/00; крит-каст бонуси; канальність; штраф броні `max` по локаціях; інгредієнти знижують ступінь miscast.
- Sin/Wrath: тригери (фамбл, одиниці ≤ Sin), +10 за Sin, `sin −= 1`.
- Шкода заклинань: WPB/TB/AP за каноном. Корупція: мутація за таблицями Body/Mind, межі TB/WPB.

### W8 — Спорядження (C gear; після W4)
- Якості зброї (Penetrating, Hack, Impale, Pummel, Fast, Undamaging…) за с. 304–305, щит +1 SL, Defensive/Impenetrable/Weakpoints/Partial/Blackpowder, Reach 2 yd для довгої, дальність/шкода стрілецької зброї (с. 303), навантаження → Move/Ag (не лише відображення).

### W9 — Хвіст (M34, M38, M40)
- Додати за бажанням тест корупції; прибрати d20-залишки в шаблоні; Info-назви (IP) без змін.

## Контент-хвиля (після механік; обсяг канону з аудиту)

Не «механіка», але потрібна для повного канону 5e і є вхідним для іконок. Дані пишуться оригінальними назвами (IP-політика), числа/структура — з книги:

| Категорія | Зараз | Канон | Примітка |
|---|---|---|---|
| Раси | 4 | 5 | +1 вид |
| Кар'єри | 16 | 64 (8×8) | схеми розвитку по кар'єрах — з картинок сторінок (у витягу втрачені) |
| Навички | 40 | 45 | +Animal Training, Bribery, Charm Animal, Play, Sail (оригінальні назви) |
| Таланти | 50 | ~166 | макс. рівні/ефекти звіряти за книгою |
| Заклинання | 30 | ~141 + 19 благословень + 60 чудес | мінімально — повний набір кола |
| Спорядження | 56 | ~290 рядків | |
| Юніти | 30 | ~45 | + шаблони істот, навички/таланти в статблоках, ~60 рецептів трейтів |

Порядок: скелет типів/полів → пакет даних (JSON + i18n en/uk, переклад обов'язковий для офіційного шаблону) → `pnpm template` валідація (`scripts/templates/grim-d100/validate.ts`) → публікація локально → прод лише за «так».

## Іконки: догенерація всіх необхідних (окремий пункт, I)

Стан: 186 іконок (feats 50, careers 16, races 4, spells 30, units 30, artifacts 56), `data/templates/grim-d100/icons.json`, промпти `docs/assets/icon-prompts/grim-d100/*.csv`, генератор `scripts/assets/grim-icons/{cli,prompts}.ts`, зображення генерує власник (`generate_grim.py` у `~/Downloads/fantasy-tokens`, 768 px), завантаження `pnpm assets:grim-icons upload` / `pnpm template icons grim-d100 --dir <images>`.

1. **Інвентар (S).** Скрипт-diff: рядки шаблону без запису в `icons.json` → список «потрібно» по kind. Орієнтовно нових: кар'єри ~48, таланти ~116, заклинання ~111+благословення/чуда, спорядження ~230, юніти ~15, раса 1 — **порядку 500+**; уточнити після контент-хвилі.
2. **Не-контентні іконки (S).** Інвентар UI/механік 5e, яких бракує: стани (Fatigued, Stunned, Poisoned, Broken, Ablaze, Bleeding, Prone, Surprised…), Advantage/Momentum/Fate/Fortune, локації/крит-травми, трейти-бейджі (Fear/Terror, Size…), психологія. Перевірити, які вже є в `components/systems/wfrp`/спільному наборі, перш ніж замовляти (reuse).
3. **Промпти (S).** `pnpm assets:grim-icons prompts` для відсутніх рядків; дотримання стилю й правил (`assertCleanPrompt`, без тексту/логотипів, без IP GW; круглий токен для юнітів, квадрат для навичок); дедуп файлів (`assertUniqueFiles`); розбити на пачки по ~50 для генерації власником.
4. **Генерація (власник).** Пачки → `output-grim/icons/<kind>/`; перевірка розміру/назв.
5. **Завантаження (S).** `pnpm template icons grim-d100 --dir … --dry-run`, потім реальне; `icons.json` оновити й закомітити; відра хмарного сховища за ключем шаблону.
6. **Перевірка (S).** Тест «усі рядки шаблону мають іконку» (аналог існуючих template-тестів) + огляд у браузері на dev/preview-стенді (на шаблоні й в кампанії).

Іконки залежать від контент-хвилі (щоб не генерувати зайве), але пункти 1–3 по вже відомих категоріях можна робити паралельно з W5–W9.
