# Карти бою Ч1b — сцена арту + запікання: план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** DM малює в редакторі бібліотеки карт сцену арту (підлоги без швів, стіни-ланцюги з кутами й тінями, вікна/ґрати/решітки, завали, світло) на квадраті й гексі; на Save сцена запікається у WebP-фон рівно під сітку, а `walls/bars/doors/blocked` карти виводяться зі сцени. Бій, snapshot і мутації не змінюються.

**Architecture:** нова таблиця `battle_map_art` (сцена JSONB + версії запікання). Чиста логіка сцени — `lib/utils/battle/map-art/*` (derive, clip, room, floors, wall-runs, bake-size); painter — `lib/utils/canvas/map-art/*` (той самий код для прев'ю й запікання на `OffscreenCanvas`). Один ендпоінт `PUT /maps/[mapId]/art` в одній транзакції пише сцену й зберігає карту через наявний `saveMap` (механіка виведена сервером, фон = запечений URL). Редактор: вкладка «Арт» замість «Текстури»; тайловий редактор звужується до шару `objects` (до Ч2).

**Tech Stack:** TypeScript strict, Prisma 6 + PostgreSQL, Zod, TanStack Query, React 19 + Canvas 2D / OffscreenCanvas, Vitest, next-intl.

**Spec:** `docs/superpowers/specs/2026-11-26-map-art-ch1-foundation-design.md` (розділ 3; перевикористання — 4; ризики — 5; перевірка — 6). Епік: `docs/superpowers/specs/2026-11-26-map-art-epic-design.md`. Попередня частина: `docs/superpowers/plans/2026-11-26-map-art-ch1a.md`.

**Гілка / worktree:** `feat/map-art`, `../dnd-tracker-mapart` (від main `6ce1b0fdf`, Ч1a вже в гілці). Усі шляхи нижче — відносно worktree.

## Review Focus

1. **Гекс-карта 200 колонок після запікання.** `backgroundCols` для гекса = `cols + 1/3` (200.33), а `battleMapObject.backgroundCols` має `.max(200)` → 400 на Save. Очікування: збереження проходить. Тест у Task 1 (схема) і Task 2 (`bakedBackgroundSpan`).
2. **Карту зменшили після малювання.** Стіни/підлоги/світло поза новими `cols×rows` мають тихо обрізатись (`clipScene`), а не давати 400. Тести в Task 2 і Task 8.
3. **Сцена породжує невалідну карту.** Завали з'їдають ігрову площу, дверей > `doorsMax`, стін > `libraryMaxEdges`, отвір без стіни → 400 з перекладеним issue, не 500 і не тихий запис. Тести в Task 1 (схема сцени) і Task 5 (route).
4. **Запікання не вміщується.** WebP > 4 MB або браузер не виділив canvas 8192² → px/клітинку зменшується (≤ 3 спроби), далі зрозуміла помилка; сцена все одно зберігається (незапечена), кнопка «Запекти» лишається активною. Тести в Task 4 (`bakeScene`) і Task 7 (`useMapArtSave`).
5. **Дві вкладки зберігають одночасно.** Друга отримує 409 (за `sceneVersion` або `mapVersion`), щойно завантажений WebP прибирається `discardBattleMapBackground`, редактор показує `conflict`. Тести в Task 5 і Task 7.

Відоме обмеження v1 (не тестуємо, документуємо в Task 12): стіна, прибрана в бою (`removedEdges`), лишається намальованою на запеченому фоні.

## Припущення, які варто підтвердити власнику

1. Gate 0 = 0 рядків (базовий варіант без конвертера).
2. Шар `objects` лишається тайловою палітрою до Ч2 (у spec — «objects-ассети стають матеріалами»; тут лише завали беруть спрайти `rubble-pile/boulder/rock-small`).
3. Конкурентність PUT — через `expectedSceneVersion` у тілі (значення ETag), а не заголовок `If-Match`; конфлікт → 409.
4. Прев'ю — dirty-регіони по chunk'ах на одному полотні замість окремих chunk-растрів (`TileRasterChunkCache`).
5. Seed текстури — на регіон (зв'язну область одного матеріалу); межа матеріалів — смуга 0.3 клітинки з шумом.
6. При активному арті вкладки «Фон» і «Стіни» ховаються; «Від'єднати арт» (DELETE) повертає їх, фон і механіка лишаються.
7. У отвору-дверей є поле `open?` (поза spec), щоб `sceneFromMap` не губив відчинені двері.
8. `next/image` віддає фон шириною ≤ 3840 px (типові `deviceSizes`), тож запечені 8100 px на 100×100 у бою показуються з ~38 px/клітинку; якщо на живому прогоні при зумі розмито — окреме рішення власника (ширші `deviceSizes` або `unoptimized` для запечених фонів).
9. Стіна, прибрана в бою (`removedEdges`), лишається намальованою на запеченому фоні (обмеження v1).
10. Колонки `TIMESTAMP(3)` замість `timestamptz` (конвенція репо); номер міграції `20261226000000` може зіткнутись з паралельною сесією — звірити перед мерджем.
