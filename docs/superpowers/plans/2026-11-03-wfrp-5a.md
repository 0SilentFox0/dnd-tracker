# WFRP 5a Implementation Plan — шов рульової системи, percentile-тести, характеристики

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** рушій знає рульову систему кампанії (`homm`/`dnd5e`/`wfrp`); HOMM і 5e — паритет; з'являються d100-тест, характеристики WFRP, тести з листа, «Нова сесія», базовий лист і порожній шаблон «Grim d100 (empty)». Бій на wfrp — 5b.
**Architecture:** секція `rules.system` + реєстр `lib/utils/rules/systems/{d20,wfrp}` за зразком режимів карти (ядро не імпортує систему напряму, ESLint). `d20/` — тонкі обгортки над наявним кодом, `wfrp/` — нова чиста логіка (percentile, characteristics, skills, sheet-test, session). Гейти в ядрі: `characterBaseHp`, `rollForSheet`, `restParty`, `resources-handler`, старт бою, fair-баланс. Клієнт: `components/systems/` зі слотами UI за ключем системи.
**Tech Stack:** наявні Next.js 16, React 19, Prisma 6, Zod 4, Vitest (happy-dom для UI), ESLint flat config, `tsx`-скрипти.
**Spec:** `docs/superpowers/specs/2026-11-03-wfrp-5a-design.md` (дослідження: `docs/superpowers/research/2026-11-03-wfrp-rule-system.md`). Гілка `feat/wfrp`, worktree `../dnd-tracker-wfrp`, локальна БД `wfrp`.

## Global Constraints

- Ключі систем: `"homm" | "dnd5e" | "wfrp"`; дві реалізації: `d20/` (homm + dnd5e) і `wfrp/`. Система — кампанійна, не учасника.
- `system` **не механіка**: `MechanicKey = Exclude<keyof Ruleset, "system">`, `MECHANIC_REGISTRY` без неї (sync шаблон→кампанія і вкладки правил її не бачать).
- Паритет d20: наявні тести без правок, крім тих, що читають змінені сигнатури (`characterBaseHp`/`from-character`, `SheetRollResult.kind`, `restSchema.kind`, snapshot `DEFAULT_RULES` у `schema.test.ts`). Інша правка старого тесту = сигнал зміни поведінки — зупинитись і доповісти.
- `pnpm battle-sweep --mode all --consistency` на БД `wfrp`: 0 нових помилок/попереджень у `battle-sweep.md` до першого коміту й після останнього (кидки не порівнюються — рушій не приймає seed).
- Міграція одна, expand-only, без бекфілу: `characters.characteristics JSONB NOT NULL DEFAULT '{}'`, `units.characteristics JSONB NOT NULL DEFAULT '{}'`.
- `CELL_FEET` і його споживачі не чіпаються (масштаб клітинки — 5b). Жодних змін у `lib/utils/battle/` окрім `participant/from-character.ts` (один рядок HP) і `lib/server/battles/mutations/start/*`, `lib/server/battles/balance/balance-post.ts` (гейти).
- Імена навичок/спеціалізацій — загальні англійські слова, без текстів GW. Терміни UI: characteristics/«характеристики», skills/«навички», Wounds/«рани», Fate/Fortune/«Доля/Удача», SL/«рівні успіху». i18n `uk` + `en`, Cyrillic у коді заборонена (ESLint), ключі перевіряються `label-keys` тестами.
- Шлях нового коду: `lib/utils/rules/systems/**` (чиста логіка, без `@/lib/db`), `lib/hooks/systems/**`, `components/systems/**`. Імпорт `@/lib/utils/rules/systems/wfrp*`, `.../d20*`, `@/lib/hooks/systems/wfrp*`, `@/components/systems/wfrp*` поза цими теками — помилка ESLint.
- Тести: `pnpm test:related <files>` під час роботи; повний `pnpm test:run` і repo-wide lint — один раз у фіналі. Перед ними — `ps -Ao pid,pcpu,command -r | grep -E "eslint|vitest|next"`.
- Коміти після кожного завдання (`feat(wfrp): …` / `test(wfrp): …`), укр. або англ. тіло — як у гілці.

## Review Focus

1. **Удача проти цілі**: кидок 96–100 при `target > 100` — провал; кидок 01–05 при `target = 0` — успіх; SL на авто-успіху не від'ємний. → тест у Task 2 (`resolve.test.ts`, рядки «auto»).
2. **Лок системи не блокує решту правил**: PATCH `morale` у кампанії з персонажами проходить; PATCH `system.key` з тим самим ключем проходить; зміна ключа → 409. → Task 1 (`rules-lock.test.ts`).
3. **Чужі поля в тілі**: d20-кампанія ігнорує `characteristics`; wfrp-кампанія ігнорує `strength…charisma`, `armorClass`, `level`, `archetype`, `initiative`, `speed` і не падає на перевірці діапазону ініціативи. → Task 3 (`system-fields.test.ts`).
4. **Старі правила без `system`**: `{classes:{enabled:true}}` → `dnd5e`; `{}` → `homm`; явний `system` важливіший за `classes`; невалідний `system` (`{key:"x"}`) → fallback, не дефолт `homm`. → Task 1 (`schema-system.test.ts`).
5. **Session на d20 і під час бою**: `kind:"session"` у d20-кампанії → 409 без запису в лог; у wfrp під час активного бою → блокується як інші rest-дії; короткий/довгий відпочинок у wfrp зберігає `fortune`. → Task 4 (`session.test.ts`, `rest-handler` тест).

**Interfaces (produces):** точно §2 spec (`TestMode`, `PercentileTestInput`, `PercentileTestResult`, `rollPercentile`, `reverseRoll`, `resolvePercentileTest`, `DIFFICULTY_KEYS`, `DIFFICULTY_SL`, `type DifficultyKey`). `Rng` з `@/lib/utils/common/rng`; `rollPercentile(rng, preset?)` = `preset ?? rollDie(100, rng)` (`rollDie` з `@/lib/utils/common/dice`, «00» = 100).

**Правила (одне місце — `resolve.ts`):**
- `tens(n) = Math.floor(n / 10)` (100 → 10); успіх `roll <= target`; `auto`: `roll <= 5` → success, `roll >= 96` → failure (перекриває порівняння з ціллю).
- `sl = tens(target) − tens(roll) + slModifier`; успіх → `max(0, sl)`, провал → `min(0, sl)`.
- дублі: `roll === 100 || (roll >= 11 && roll % 11 === 0)`; при `doubles` успіх → `critical`, провал → `fumble`; 05 — не дубль.
- `reverseRoll(n)`: `n === 100 ? 100 : (n % 10) * 10 + Math.floor(n / 10)` (71→17, 20→2, 7→70).
- advantage/disadvantage: порахувати `{rawRoll}` і `{reverseRoll(rawRoll)}`, порядок `critical > success > failure > fumble`, потім `sl` більший кращий; обрано перевернутий → `reversed: true`, `roll` = перевернуте значення, `rawRoll` — початкове.
- `DIFFICULTY_SL = { veryEasy: 6, easy: 4, average: 2, challenging: 0, difficult: -1, hard: -2, veryHard: -3 }` з коментарем в один рядок «4e-модифікатори/10; звірити з книгою 5e».

**Тест-кейси** (`it.each` таблиця ~25 рядків, `presetRoll`): (target 45) roll 5→success auto, 6/target 3→failure (не auto), 95→failure не auto, 96→failure auto; target 120 roll 96→failure auto, roll 100 doubles→fumble, roll 100 без doubles→failure; 11 target 45 doubles→critical sl 3, 11 без doubles→success sl 3; 55 target 45 doubles→fumble sl −1; 5 target 0→success sl 0; slModifier −3 roll 20 target 45→success sl 0 (не провал); slModifier +4 roll 60 target 45→failure sl 0 (не успіх); advantage raw 71 target 45→reversed 17 success; disadvantage raw 17→reversed 71 failure; advantage raw 50 target 45 → 05 auto success reversed; `rollPercentile` з `mulberry32(1)` 1000 кидків у 1..100; `reverseRoll` 20→2, 2→20, 100→100, 44→44; `DIFFICULTY_KEYS` 7 і порядок.

- [ ] Тести → RED. — [ ] `roll.ts`, `difficulty.ts`, `resolve.ts` → GREEN. — [ ] i18n `difficulty` + label-keys. — [ ] Коміт `feat(wfrp): percentile test and difficulty table`.
